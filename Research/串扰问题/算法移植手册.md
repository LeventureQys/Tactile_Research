## 1. 算法目标

### 1.1 要解决的问题

触觉阵列被**单点**按压时，除真实触点外，沿某一几何轴还会出现一串"被抬起来"的虚假读数（串扰）。算法要：

1. 逐帧识别"这一帧是单点触发 + 串扰尾巴"；
2. 把这些串扰位置的数据**恢复到该通道本来的静息水平**（而不是抹成 0）；
3. 对非单点帧（大面积按压、多点接触、未触发）**一个数都不改**。

### 1.2 明确的非目标

| 不做 | 原因 |
|---|---|
| 不处理大面积/多点触发 | 用户明确要求剥离；且多点与串扰在单轴形态上无法可靠区分，动了就有误杀风险 |
| 不改变主点的值 | 实测串扰是"加法型旁路偏置"，不是从主点分走的能量，主点读数无需补偿 |
| 不修改阵列布局/掩码 | 布局由硬件决定，算法只消费它 |
| 不处理死区通道的固定偏置 | 那是另一类问题（恒定偏置通道），应由上游屏蔽或单独校正 |

### 1.3 验收指标

| 指标 | 目标值 | 参考实现实测 |
|---|---|---|
| 单点帧串扰位置被压制的幅度 | ≥ 95% | 96.1%~98.8%（残留即通道静息水平） |
| 非单点帧被改动的单元格数 | **0** | 0（全部 3 台设备） |
| 方向误判 | 0 | 0（42,347 帧） |
| 压制作用范围 | 仅主点所在的那条线 | 合成用例逐格校验通过 |
| 被压制位置的终值 | 落在该通道静息分布内 | 中位 6，与原始静息中位 6 一致 |
| 单帧耗时（57 通道） | < 100 µs | **实测 9.2 µs**（纯 Python，含判定+压制）；C 预期 < 2 µs |
| 黄金用例回归 | 16/16 | 16/16 通过（`analysis/out/check_golden.txt`） |

## 2. 背景

### 2.1 硬件与数据形态

```
阵列：rows × cols 的行列式触觉阵列
  四指指腹  device1 : 13 行 × 8 列，52 个有效格
  大拇指指腹 device1~2 : 14 行 × 8 列，57 个有效格

有效格由 layout_mask 给出：长度 rows*cols 的 '0'/'1' 字符串，行优先
数据：每帧一个长度为 n_active 的整数数组，顺序 = 按行优先遍历掩码为 '1' 的格子
      静息值约 5~8，满量程约 1500~1800（ADC 计数）

坐标术语（全文统一）：
  横向 = 行轴方向（同一行内、不同列之间）
  纵向 = 列轴方向（同一列内、不同行之间）
```

**通道顺序必须严格对齐**：`layout_mask` 中第 k 个 `'1'` 对应数组第 k 个元素。移植时第一件事就是写个自检用例确认这个映射没搞反。

### 2.2 现象

单点按压时，除主点外沿一个轴出现一串响应：

```
大拇指指腹（横向）                   四指指腹（纵向）
row5:  342  1371  363  237  172       col2:  r1=29  r2=12  r3=58
       └─主点─┘                               r4=49  r5=8   r6=58
       同行多列被抬起                           r7=8   r8=2241 ← 主点
                                              同列多行被抬起
```

### 2.3 四条决定算法形态的实测结论

| # | 结论 | 对算法的影响 |
|---|---|---|
| 1 | **串扰方向正交**：拇指恒为横向、四指恒为纵向；正交方向耦合 ≤ 0.2%（噪声级） | 可以用"哪个轴能量大"在线判方向，一套代码兼容两种设备 |
| 2 | **严格同步**：互相关峰值全部在 lag = 0 | 可以逐帧独立判定，不需要跨帧跟踪或延迟线 |
| 3 | **加法型偏置**：主点大幅变化时串扰值基本不动 | 压制用"恢复到静息水平"，不能用比例缩放 |
| 4 | **位置强相关**：同一列对在不同行上比例 12%~36% | 需要标定表（可选）；不标定也能用通用形态判据工作 |

**方向能量对比（实测中位数）**：

| 设备 | 横向 | 纵向 | 判定 |
|---|---:|---:|---|
| 四指 / device1 | 0.2% | **40.5%** | 纵向 |
| 大拇指 / device1 | **146.1%** | 3.4% | 横向 |
| 大拇指 / device2 | **153.5%** | 10.4% | 横向 |

**串扰随距离的衰减**：

| 设备 | d1 | d2 | d3 | d4 |
|---|---:|---:|---:|---:|
| 四指（纵向） | 10.5% | 4.0% | 4.1% | 3.7% |
| 大拇指 device1（横向） | 41.0% | 28.0% | 32.5% | 29.8% |
| 大拇指 device2（横向） | 46.0% | 31.8% | 27.7% | 23.4% |

**线内保护阈值的实测余量**（决定 §6 参数的取值）：

| 设备 | line_energy 阈值 3.0 | line_other 阈值 0.90 |
|---|---|---|
| 四指 device1 | p99=1.09，max=1.29 | p99=0.42，max=0.49 |
| 大拇指 device1 | p99=1.98，max=2.28 | p99=0.78，max=0.85 |
| 大拇指 device2 | p99=2.14，max=2.27 | p99=0.87，**max=0.99** |

> `line_other` 在拇指上有 7 帧突破 0.90（集中在 `(7,2)/(7,3)`，两格几乎等高），按疑似双触点放行。**该阈值不要低于 0.88**，否则会把真实双触点当串扰压掉。

## 3. 算法原理

### 3.1 一句话概括

> 逐帧找主点 → 用"正交轴是否干净 + 两轴能量比"确认这一帧只有一个真实触点 → 沿串扰轴把除主点外的所有位置恢复到各自静息水平；任何"多行多列都活跃"或"两轴能量相当"的帧一律原样放行。

### 3.2 数值域约定（★ 最容易出错的地方）

算法内部全部在**响应域**工作：

```
响应域：resp[t][k] = raw[t][k] - baseline[t][k]
数据域：raw[t][k]  = resp[t][k] + baseline[t][k]
```

| 环节 | 所处域 | 说明 |
|---|---|---|
| 输入 `resp_in` | 响应域 | 调用方先扣基线 |
| 内部判定与压制 | 响应域 | 所有阈值、能量、静息水平都是响应域量 |
| 输出 `resp_out` | 响应域 | 压制后写回本数组 |
| 写回设备/文件 | **数据域** | `raw_out = resp_out + baseline`，**这一步不能省** |

**踩坑实录**：如果漏掉第 4 步，输出的每个通道都恰好比输入低一个 baseline（约 5~8），整幅图会显得"整体偏暗"；如果把"压制目标"误设为响应域的 0 却不加回 baseline，被压制的格子会直接变成读数 0，比正常静息还低——现象是"压完之后干净得不像真数据"。

因此：**响应域的压制目标是该通道的静息水平 `rest[k]`（通常 0~3），数据域的终值是 `rest[k] + baseline[k]`（通常 6~10）。**

### 3.3 逐帧判定流程

```
第 0 步  主点        P = max(resp)，记主点通道 k0 及其 (r0, c0)
第 1 步  峰值门槛    P < max(min_peak_abs, min_peak_ratio × ref_scale, 3 × noise)
                     → mode = LOW，原样返回（未触发）
第 2 步  面积保护    按有效格数归一的行能量 / 列能量
                     活跃行数 ≥ 3 且 活跃列数 ≥ 3
                     → mode = AREA，原样返回（面状触发）
第 3 步  方向判定    e_row = 主点所在行其余格之和
                     e_col = 主点所在列其余格之和
                     max/min < direction_ratio          → mode = AMBIG，放行
                     否则 direction = 能量大的那一轴
第 4 步  线内复核    主方向线上其余格：总和 > line_energy_max × P  → 放行
                                    单点最大 > line_other_max  × P  → 放行
第 5 步  压制        主方向线上除主点外，每个通道写 rest[k]
                     → mode = SINGLE
```

### 3.4 为什么面积门槛是 3，而不是 2

**压制只作用于主点所在的那一条线。** 因此"主点 + 另一处独立接触"这种帧根本不需要保护——另一处接触不在该线上，压制碰不到它。

曾经把门槛设成 2（"多行多列同时活跃即放行"），在出现**持续背景接触**的数据上会造成大面积漏压：某一侧长期有接触时，"活跃行数"恒为 2，于是主点在其他行时本该压制的串扰尾巴全部被放行（实测漏压 666 帧）。

真正需要拦的是"**面状触发**"，那必然多行多列同时活跃；而且即使门槛判漏了，`direction_ratio`（整面按压时两轴能量比接近行/列格数比，必落在 2.0 以内 → 判 AMBIG 放行）与线内保护（整面时 `line_other ≈ 1.0 > 0.90`）会二次兜底。

合成用例 `synth_full_press`（所有有效格填 500、主点 600）验证：**零改动放行**。

### 3.5 为什么这样判定能兼容两种设备

- 拇指的串扰能量落在**行内** → `e_row >> e_col` → 判横向 → 压制同行；
- 四指的串扰能量落在**列内** → `e_col >> e_row` → 判纵向 → 压制同列。

**正交方向永远是干净的**（结论 1），所以"主点所在的正交线上只有它自己"这件事本身就证明了"这一帧只有一个真实触点"。

## 4. 参考实现

主体见 `analysis/crosstalk_portable.py`，**不依赖 numpy，只用到定长 list 与标量运算**，可直接对照翻译。本节给出等价伪代码。

### 4.1 状态与内存

| 状态 | 大小 | 何时更新 |
|---|---|---|
| `layout_mask` | rows×cols 字符 | 上电 |
| `chan[rows*cols]` | int16 | 上电 |
| `row_chans[rows][*]` / `col_chans[cols][*]` | ≤ N 个 int16 | 上电 |
| `rest[N]` | float32 / int16 | 标定 |
| `ref_scale`, `noise` | 标量 | 标定 |
| 逐帧临时缓冲 `row_energy[rows]`, `col_energy[cols]` | float32 | 每帧复用 |

N ≤ 64 时，全部状态 < 1 KB（若用浮点）。**无动态分配、无递归、无随机。**

### 4.2 接口

```
构造   Suppressor(rows, cols, layout_mask, params)
标定   set_calibration(ref_scale, noise, rest[])
逐帧   process(resp_in[N], resp_out[N]) -> info
```

`info` 至少应包含：`mode`(LOW/SINGLE/AREA/AMBIG)、`direction`(NONE/ROW/COL)、`peak`、`k0`、`suppressed` 计数。宿主用 `mode == SINGLE` 记录日志或触发下游逻辑。

### 4.3 伪代码（语言无关，可直接对照 C）

```
# ============ 上电初始化 ============
n = 0
for r in 0..rows-1:
    for c in 0..cols-1:
        if layout_mask[r*cols + c] == '1':
            chan[r*cols + c] = n
            cell_row[n] = r
            cell_col[n] = c
            row_chans[r].append(n)
            col_chans[c].append(n)
            n += 1

# ============ 逐帧处理 ============
function process(resp_in, resp_out) -> info:

    # 0) 拷贝 + 找主点
    for k in 0..n-1: resp_out[k] = resp_in[k]
    k0 = argmax(resp_in) ; peak = resp_in[k0]
    r0 = cell_row[k0] ; c0 = cell_col[k0]
    info = {mode: LOW, direction: NONE, peak, k0, suppressed: 0}

    # 1) 峰值门槛
    thr = min_peak_abs + min_peak_ratio * ref_scale
    if 3 * noise > thr: thr = 3 * noise
    if peak < thr: return info

    # 2) 面积保护
    max_re = 0
    for r in 0..rows-1:
        s = sum of max(resp_in[k], 0) for k in row_chans[r]
        row_energy[r] = s / len(row_chans[r])          # 按有效格数归一
        max_re = max(max_re, row_energy[r])
    (同样的方式算 col_energy[]、max_ce)
    ar = count of row_energy[r] > area_active_frac * max_re
    ac = count of col_energy[c] > area_active_frac * max_ce
    if ar >= area_min_rows and ac >= area_min_cols:
        info.mode = AREA ; return info

    # 3) 方向判定
    e_row = sum of max(resp_in[k],0) for k in row_chans[r0], k != k0
    e_col = sum of max(resp_in[k],0) for k in col_chans[c0], k != k0
    if params.direction is forced:  direction = forced
    else:
        hi = max(e_row, e_col) ; lo = min(e_row, e_col)
        if hi == 0 or hi < direction_ratio * max(lo, EPS): direction = NONE
        else: direction = (e_row > e_col) ? ROW : COL
    if direction == NONE: info.mode = AMBIG ; return info
    info.direction = direction

    # 4) 线内复核
    line = (direction == ROW) ? row_chans[r0] : col_chans[c0]
    s_other = 0 ; m_other = 0
    for k in line, k != k0:
        s_other += max(resp_in[k], 0)
        m_other = max(m_other, resp_in[k])
    if line_energy_max > 0 and s_other > line_energy_max * peak: info.mode = AREA ; return info
    if line_other_max  > 0 and m_other > line_other_max  * peak: info.mode = AREA ; return info

    # 5) 压制：主方向线上除主点外恢复到各自静息水平
    total = 0
    for k in line, k != k0:
        v = resp_in[k]
        if v > rest[k]: total += v - rest[k]
        resp_out[k] = rest[k]
        info.suppressed += 1
    if compensate_sum: resp_out[k0] = resp_in[k0] + total

    info.mode = SINGLE
    return info
```

## 5. 标定

### 5.1 需要标定什么

| 量 | 含义 | 不标定的后果 | 标定难度 |
|---|---|---|---|
| `ref_scale` | 参考量程 = 全录制帧峰值的 99.5 分位 | 峰值门槛失效，可能把噪声当触发 | 1 段任意录制即可 |
| `noise` | 响应域噪声底 = 静默帧响应的 99 分位 | 同上，低幅噪声可能被误判 | 同上 |
| `rest[N]` | 逐通道静息响应水平 = 静默帧响应的中位数 | 退化为统一 `rest_default`（一般取 0） | 同上 |
| 偏置表 | `(主点行/列, 源位置, 目标位置) → 串扰分布` | 只能用 `zero` 模式，无法用 `subtract` 保真模式 | 需要含单点按压的录制 |

**只做 zero 模式的话，前三项就够，一段静息+若干单点按压的录制即可。**

### 5.2 标定数据要求

| 项目 | 要求 |
|---|---|
| 时长 | ≥ 60 s |
| 内容 | 前段静置不动（≥ 10 s）；其余为**单点**逐格按压，每格至少按 3 次 |
| 覆盖 | `layout_mask` 中的每个有效格都要被单独按到（位置相关性强，没按到的位置只能回退到汇总值） |
| 采样率 | ≥ 100 Hz（20 Hz 的录制标定精度明显下降，见分析报告 §2.6） |
| 力度 | 覆盖该设备的常用工作区间，不要只做最大力 |

### 5.3 标定流程

```
1) 读入录制，逐通道扣除滚动基线（窗口 400 帧、5% 分位）
2) 计算帧峰值序列 P[t]
3) ref_scale  = percentile(P, 99.5)
4) quiet_mask = P < percentile(P, 30)
   noise      = percentile(resp[quiet_mask], 99)
   rest[k]    = median(resp[quiet_mask, k])
5) （可选）偏置表：对每个"主点在正交轴干净"的帧，
   记录主点位置 p 与同轴其余格 q 的响应绝对值，
   取低分位作为偏置 b、高分位作为上界 u，按 (线, 源, 目标) 建表
```

第 5 步的完整实现见 `analysis/run_suppress.py::cmd_calib` 与 `crosstalk_suppress.BiasTable`。

### 5.4 标定文件格式

标定结果建议以纯文本键值对烧录，便于不同平台解析：

```json
{
  "ref_scale": 2093.9,
  "noise": 3.0,
  "rest": [0.0, 0.0, 1.2, ...],
  "direction": "col",
  "bias": { "3|4|2": [12.5, 48.0, 137], ... }   // (线, 源, 目标) -> [b, u, n]
}
```

完整示例见 `analysis/out/bias_table.json`（7 台设备）与 `analysis/out/golden_cases.json` 中每台设备的 `calibration` 段。

### 5.5 在线自适应（可选）

若目标平台无法离线标定，可用一阶低包络跟踪器在线估计基线，用初始化后前 N 帧（判定为 LOW 的帧）估计 `rest` 与 `noise`：

```
# 每通道一个静息跟踪器，O(1) 内存
if raw[k] < base[k]:  base[k] = raw[k]              # 立即跟随下降
else:                 base[k] += (raw[k] - base[k]) * ALPHA   # 缓慢回升
```

`ALPHA` 取 1e-4 ~ 1e-3（时间常数 1000~10000 帧）。注意：连续长按会让基线缓慢爬升，`ALPHA` 要足够小。`rest` 可在启动后前 2 s 内用响应中位数估计一次。

## 6. 参数表与调参

| 参数 | 默认 | 含义 | 调大 | 调小 |
|---|---|---|---|---|
| `min_peak_ratio` | 0.25 | 峰值门槛系数 | 更保守，弱触发不处理 | 更灵敏，但噪声可能触发 |
| `direction_ratio` | 2.0 | 方向显著性 | 更谨慎，更多帧判"形态不明"而放行 | 更多帧被压制，误伤风险上升 |
| `area_active_frac` | 0.25 | 活跃行/列阈值 | 保护范围缩小（更激进压制） | 更多帧被判面状（更保守） |
| `area_min_rows/cols` | **3 / 3** | 面状判定门槛 | 保护范围缩小 | 调到 2 会在"有持续背景接触"时大面积漏压（见 §3.4） |
| `line_energy_max` | 3.0 | 线上总能量上限 | 更激进 | 更保守（本版本实测 max 2.28，**不要低于 2.5**） |
| `line_other_max` | 0.90 | 线上单点上限 | **不要调高**（会放过等高双峰） | 更保守，但本版本串扰 p99 已达 0.87，**不要低于 0.88** |
| `direction` | auto | 方向 | 已知设备型号时**建议写死**，可完全消除歧义 | — |
| `rest` / `use_channel_rest` | 0 / true | 压制目标 | — | 置 false 则统一用 `rest` |
| `compensate_sum` | false | 是否把压制量并入主点 | 需要总力守恒时打开 | — |

**按场景的推荐配置**

| 场景 | 配置 |
|---|---|
| 只求显示干净 | `mode=zero`（默认）+ 标定 `rest` |
| 有持续背景接触（本版本拇指 device2 的 row0） | `mode=subtract` + 偏置表：只减串扰分量，不把背景接触一起归到静息值 |
| 已知设备型号、追求确定性 | `direction=row`（拇指）/ `direction=col`（四指） |
| 追求最低误伤 | `direction_ratio=3.0`、`line_other_max=0.8`、`area_min_rows/cols=2` |
| 无标定条件 | 只给 `ref_scale`、`noise`，`rest` 全 0 |

## 7. 移植方案

### 7.1 三种移植档次

| 档次 | 内容 | 代码量 | 适用 |
|---|---|---|---|
| **L0 最小可用** | 峰值门槛 + 方向判定 + 线内压制（无面积保护、无标定表） | ~120 行 C | 快速验证概念 |
| **L1 推荐**（= 本手册主体） | L0 + 面积保护 + 线内复核 + 标定 `ref_scale/noise/rest` | ~250 行 C | 量产固件 |
| **L2 保真增强** | L1 + 偏置表（`subtract` / `bias` 模式） | +150 行 C | 需要保留弱真实触点 |

**强烈建议至少做 L1**：面积保护是"不影响整面触发"这条需求的唯一实现手段，去掉它方案就不成立。

### 7.2 C 语言实现要点

**(1) 整数化（推荐）**

原始数据本身就是整数 ADC 计数，可以全程避开浮点：

```c
/* 阈值：把系数放大 100 倍存成整数 */
#define MIN_PEAK_RATIO_PCT   25      /* 0.25 */
int32_t thr = MIN_PEAK_RATIO_PCT * ref_scale / 100;
if (3 * noise > thr) thr = 3 * noise;

/* 方向判定：e_row * 100 > e_col * 200 等价于 e_row > 2.0 * e_col */
if (e_row * 100 > e_col * DIRECTION_RATIO_PCT) direction = DIR_ROW;

/* 能量归一化：先乘后除，避免整型截断 */
energy[r] = (sum * 1000) / row_len[r];       /* 保留 3 位小数 */

/* 面积判定 */
if (energy[r] * 100 > AREA_ACTIVE_PCT * max_re) active_rows++;
```

数据范围：ADC ≤ 4096、通道数 ≤ 64 → 单帧能量和 ≤ 262144，int32 完全够用，不会溢出。

**(2) 结构体布局（避免指针追逐）**

```c
typedef struct {
    uint8_t  rows, cols, n;
    int8_t   chan[MAX_CELLS];        /* 格 -> 通道号，-1 表示无 */
    uint8_t  cell_row[MAX_CH];       /* 通道 -> 行 */
    uint8_t  cell_col[MAX_CH];       /* 通道 -> 列 */
    uint8_t  row_start[MAX_ROWS+1];  /* CSR 式行通道索引 */
    uint8_t  row_items[MAX_CH];
    uint8_t  col_start[MAX_COLS+1];
    uint8_t  col_items[MAX_CH];
    int16_t  rest[MAX_CH];           /* 静息响应水平 */
    int32_t  ref_scale, noise;
    /* 逐帧临时 */
    int32_t  row_energy[MAX_ROWS], col_energy[MAX_COLS];
} tc_sup_t;
```

行/列通道清单用 CSR 展开成一个连续数组（`row_items`），比 `int8_t row_chans[14][8]` 更省 RAM，也更好缓存。60 通道下整结构 < 512 B，可放静态区。

**(3) 无浮点降级**

若 MCU 无 FPU 且不想用软浮点：`rest` 用 int16，所有比较用整数百分比（如上）。参考实现里的 `1e-9` 保护可改为显式的 `if (lo == 0) direction = NONE;`。

**(4) 一份完整的 L1 骨架**

```c
/* tc_suppress.h ------------------------------------------------------ */
#define TC_MODE_LOW     0
#define TC_MODE_SINGLE  1
#define TC_MODE_AREA    2
#define TC_MODE_AMBIG   3
#define TC_DIR_NONE     0
#define TC_DIR_ROW      1
#define TC_DIR_COL      2

/* ---- 可调参数（整数百分比形式，见附录 B） ---- */
#define MIN_PEAK_RATIO_PCT   25     /* 0.25 */
#define DIRECTION_RATIO_PCT 200     /* 2.00 倍 */
#define AREA_ACTIVE_PCT      25     /* 0.25 */
#define AREA_MIN_ROWS         2
#define AREA_MIN_COLS         2
#define LINE_ENERGY_PCT     300     /* 3.00 倍 */
#define LINE_OTHER_PCT       90     /* 0.90 倍 */
#define DIRECTION_FORCED     TC_DIR_NONE   /* 已知型号时填 TC_DIR_ROW / TC_DIR_COL */

typedef struct {
    uint8_t  rows, cols, n;
    uint8_t  compensate_sum;
    int8_t   chan[MAX_CELLS];        /* 格 -> 通道号，-1 表示无 */
    uint8_t  cell_row[MAX_CH];       /* 通道 -> 行 */
    uint8_t  cell_col[MAX_CH];       /* 通道 -> 列 */
    uint8_t  row_start[MAX_ROWS + 1];/* CSR 式行通道索引 */
    uint8_t  row_items[MAX_CH];
    uint8_t  col_start[MAX_COLS + 1];
    uint8_t  col_items[MAX_CH];
    int16_t  rest[MAX_CH];           /* 静息响应水平（响应域） */
    int32_t  ref_scale, noise;
    int32_t  row_energy[MAX_ROWS], col_energy[MAX_COLS];   /* 逐帧临时 */
} tc_sup_t;

typedef struct {
    uint8_t mode, direction;
    uint8_t k0, r0, c0;
    int32_t peak;
    uint8_t suppressed;
} tc_info_t;

void tc_init(tc_sup_t *s, uint8_t rows, uint8_t cols, const char *mask);
void tc_set_calib(tc_sup_t *s, int32_t ref_scale, int32_t noise, const int16_t *rest);
void tc_process(tc_sup_t *s, const int16_t *resp_in, int16_t *resp_out, tc_info_t *info);

/* tc_suppress.c ------------------------------------------------------ */
#include <string.h>

static inline int32_t v_positive(int32_t v) { return v > 0 ? v : 0; }

void tc_process(tc_sup_t *s, const int16_t *in, int16_t *out, tc_info_t *info)
{
    uint8_t i, k, k0 = 0, r0, c0;
    int32_t peak, thr, e_row = 0, e_col = 0, s_other = 0, m_other = 0;
    int32_t max_re = 0, max_ce = 0, lim;

    memset(info, 0, sizeof(*info));
    for (k = 0; k < s->n; k++) out[k] = in[k];

    /* 0) 主点 */
    peak = in[0];
    for (k = 1; k < s->n; k++) if (in[k] > peak) { peak = in[k]; k0 = k; }
    r0 = s->cell_row[k0]; c0 = s->cell_col[k0];
    info->k0 = k0; info->r0 = r0; info->c0 = c0; info->peak = peak;

    /* 1) 峰值门槛 */
    thr = (int32_t)MIN_PEAK_RATIO_PCT * s->ref_scale / 100;
    if (3 * s->noise > thr) thr = 3 * s->noise;
    if (peak < thr) { info->mode = TC_MODE_LOW; return; }

    /* 2) 面积保护 */
    for (i = 0; i < s->rows; i++) {
        int32_t sum = 0;
        for (k = s->row_start[i]; k < s->row_start[i + 1]; k++)
            sum += v_positive(in[s->row_items[k]]);
        s->row_energy[i] = sum * 1000 / (s->row_start[i + 1] - s->row_start[i]);
        if (s->row_energy[i] > max_re) max_re = s->row_energy[i];
    }
    for (i = 0; i < s->cols; i++) {
        int32_t sum = 0;
        for (k = s->col_start[i]; k < s->col_start[i + 1]; k++)
            sum += v_positive(in[s->col_items[k]]);
        s->col_energy[i] = sum * 1000 / (s->col_start[i + 1] - s->col_start[i]);
        if (s->col_energy[i] > max_ce) max_ce = s->col_energy[i];
    }
    {
        uint8_t ar = 0, ac = 0;
        lim = AREA_ACTIVE_PCT * max_re / 100;
        for (i = 0; i < s->rows; i++) if (s->row_energy[i] > lim) ar++;
        lim = AREA_ACTIVE_PCT * max_ce / 100;
        for (i = 0; i < s->cols; i++) if (s->col_energy[i] > lim) ac++;
        if (ar >= AREA_MIN_ROWS && ac >= AREA_MIN_COLS) { info->mode = TC_MODE_AREA; return; }
    }

    /* 3) 方向判定 */
    for (k = s->row_start[r0]; k < s->row_start[r0 + 1]; k++) {
        uint8_t kk = s->row_items[k];
        if (kk != k0) e_row += v_positive(in[kk]);
    }
    for (k = s->col_start[c0]; k < s->col_start[c0 + 1]; k++) {
        uint8_t kk = s->col_items[k];
        if (kk != k0) e_col += v_positive(in[kk]);
    }
    if (DIRECTION_FORCED == TC_DIR_ROW)      info->direction = TC_DIR_ROW;
    else if (DIRECTION_FORCED == TC_DIR_COL) info->direction = TC_DIR_COL;
    else if (e_row * 100 > e_col * DIRECTION_RATIO_PCT) info->direction = TC_DIR_ROW;
    else if (e_col * 100 > e_row * DIRECTION_RATIO_PCT) info->direction = TC_DIR_COL;
    else { info->mode = TC_MODE_AMBIG; return; }

    /* 4) 线内复核 */
    {
        uint8_t ks = (info->direction == TC_DIR_ROW) ? s->row_start[r0] : s->col_start[c0];
        uint8_t ke = (info->direction == TC_DIR_ROW) ? s->row_start[r0 + 1] : s->col_start[c0 + 1];
        const uint8_t *items = (info->direction == TC_DIR_ROW) ? s->row_items : s->col_items;
        for (k = ks; k < ke; k++) {
            uint8_t kk = items[k];
            if (kk == k0) continue;
            s_other += v_positive(in[kk]);
            if (in[kk] > m_other) m_other = in[kk];
        }
        if (LINE_ENERGY_PCT > 0 && s_other * 100 > LINE_ENERGY_PCT * peak) { info->mode = TC_MODE_AREA; return; }
        if (LINE_OTHER_PCT  > 0 && m_other * 100 > LINE_OTHER_PCT  * peak) { info->mode = TC_MODE_AREA; return; }

        /* 5) 压制 */
        for (k = ks; k < ke; k++) {
            uint8_t kk = items[k];
            if (kk == k0) continue;
            out[kk] = s->rest[kk];
            info->suppressed++;
            if (s->compensate_sum && in[kk] > s->rest[kk])
                out[k0] = (int16_t)(out[k0] + in[kk] - s->rest[kk]);
        }
    }
    info->mode = TC_MODE_SINGLE;
}
```

### 7.3 MCU 集成位置

```
[AFE 采样] → [原始帧 raw] → [基线扣除] → [★ 本算法] → [压力/力换算] → [上报]
                                  ↑
                            rest[] / ref_scale / noise（标定参数）
```

- **基线扣除必须在本算法之前**，因为判定阈值、`rest`、`noise` 都是响应域量；
- 本算法应在**力换算之前**，否则串扰会被当成真实力参与总量计算；
- 如果上游有 IIR 滤波，放在基线扣除之前，且要确认它不会把串扰抹成拖尾（会让 lag≠0 假设失效）。

### 7.4 其他语言

| 语言 | 要点 |
|---|---|
| C++ | 直接封装成类；注意不要把 CSR 数组换成 `std::vector<std::vector<>>`（会造成堆碎片与缓存不友好） |
| Rust | 用 `[u8; MAX]` + `no_std`；`Params` 用 `#[derive(Clone, Copy)]` |
| C# / Java / Kotlin | 逐行直译即可；注意用 `int` 而非 `float`，避免 GC：所有数组在构造时分配 |
| JS / TS | 用 `Int32Array` 预分配；`argmax` 循环手写，别用 `Math.max(...arr)`（大数组会栈溢出） |
| FPGA / DSP | 逐帧流程可流水化：能量统计可并行；判定与压制是串行的，但只有 O(N) 次比较 |

### 7.5 资源开销

| 指标 | 60 通道 / 14×8 阵列 |
|---|---|
| 状态 RAM | 约 0.5 KB（全整数） |
| 单帧算术量 | 约 6×N 次加减 + 约 4×(rows+cols) 次比较 |
| 单帧耗时（**纯 Python 实测**） | **7.4 µs**（57 通道，含判定与压制） |
| 单帧耗时（Cortex-M4 @ 80 MHz，预估） | < 2 µs |
| 栈深度 | < 128 B（无递归） |
| 除法 | 每帧约 rows+cols 次（可换成移位/倒数表） |

### 8.3 现场验收检查表

- [ ] 单点按压每个格子：除主点外**该轴上不再有响应**，主点值**不下降**
- [ ] 单点按压时，静息位置读数仍在正常底噪范围（**没有变成 0**）

### 8.4 常见失败模式与排查

| 现象 | 可能原因 | 排查 |
|---|---|---|
| 所有输出值整体偏低约 5~8 | 写回时漏了 `+ baseline` | 检查 §3.2 第 4 步 |
| 被压制位置变成 0 而不是静息值 | `rest` 用了响应域的 0 却没加回 baseline；或 `rest` 未标定 | 核对 `rest[k] + baseline[k]` |
| 整面按压时被误压 | 面积保护失效 | 打印 `active_rows/active_cols` 与 `mode`，确认走的是 AREA 分支 |
| 方向判反（压了正交轴） | 通道顺序或 `row_chans/col_chans` 建错 | 用黄金用例的 `single_row`/`single_col` 两条定位 |
| 串扰只压掉一半 | `line_other_max` 触发放行，或方向判成 AMBIG | 打印 `line_others_sum`、`e_row`、`e_col` 与 `mode` |
| 静止时也在压 | 峰值门槛过低 / 噪声底标定偏小 | 检查 `thr` 与 `noise`，必要时提高 `min_peak_ratio` |
| 弱按压不处理 | 门槛过高 | 降低 `min_peak_ratio`；确认 `ref_scale` 来自本设备 |
| 结果随机跳动 | 用了未初始化的 `rest` 或 `row_energy` 缓冲 | 在 `tc_init` 里显式清零 |

## 9. 已知边界与风险

1. **同一线上的真实双触点**：两个触点落在拇指的同一行（或四指的同一列）且强度接近时，理论上会被当成"单点+串扰"。`line_other_max=0.90` 能拦下等高双峰（本版本已拦下 7 帧），强弱悬殊的拦不住。已知设备型号时建议写死 `direction` 以缩小保护面。
2. **线内保护余量变窄**：本版本拇指的串扰相邻列已达主点的 87%（p99），距 0.90 阈值只剩 3 个百分点。**若下一版串扰继续增强，需要改用串扰模板匹配来区分双峰与串扰尾**。
3. **持续背景接触**：本版本拇指 device2 的 row0 全程有接触（静息帧上仍有 19~32 响应），既会影响 `rest` 标定，也会在 `zero` 模式下削弱穿过该列的取值。推荐改用 `subtract` 模式。
4. **面状触发样本缺失**：本版本录制里没有真实的大面积触发帧，保护逻辑只能靠合成用例（整面均匀按压）回归。上线前建议补一段"整掌按压 / 多点按压"录制再验一次。
5. **相邻格边界抖动**：主点压在格交界时，相邻格的响应本身在变化，是压制后残留的主要来源。
6. **死区通道**：部分格几乎不响应且带固定偏置，会污染"活跃行/列"统计。已用 `area_active_frac=0.25` + 门槛 3 规避，更好的做法是在上游单独屏蔽。
7. **基线漂移**：算法假设基线先被扣干净。现场温漂大的话，加大基线窗口或改用自适应零点（见 §5.5）。
8. **数值域**：内部响应域、外部数据域，写回必须走 `+ baseline`。这是本方案实现上最容易踩的坑。

## 附录 C：本版本相对 v1.0.4 的算法变更

| 变更 | 内容 | 原因 |
|---|---|---|
| 面积保护门槛 | `area_min_rows/cols` 由 2 → **3** | 上一轮数据无持续背景接触，门槛 2 未暴露问题；本版本拇指 device2 的 row0 全程有接触，导致 666 帧被误放行（详见 §3.4） |
| 参数余量记录 | 新增 `line_other_max` 实测上限（0.87）与下限建议（0.88） | 本版本串扰增强后该阈值余量收窄 |
| 合成边界用例 | 新增整面按压 / 单点+尾巴 / 主点+正交独立接触三类 | 本版本录制中无真实面状触发帧，无法用真实数据回归保护逻辑 |
| 核心不变量断言 | 回归程序新增"只能改动主点所在线"的逐格校验 | 把"不影响多点/面状触发"的需求变成可自动验证的断言 |
| 目录结构兼容 | 录制加载支持 `<类别>/<deviceN-时间戳>/` 与 `<类别>/<deviceN>/<会话>/` 两种层级 | 新版录制工具的目录层级变更 |
| 偏置表匹配修正 | 按「类别 + 设备名」双键匹配，避免"四指 device1"错配给"拇指 device1" | 新版目录名带时间戳，旧的前缀匹配会串台 |
