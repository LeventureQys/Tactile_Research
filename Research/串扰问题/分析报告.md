> 数据版本：**Alpha v1.0.6**（`raw_data/`，3 段录制：四指指腹 ×1、大拇指指腹 ×2）
> 分析代码：`analysis/`　结果与图表：`analysis/out/`
> 移植请见 **[算法移植手册.md](算法移植手册.md)**

## 0. 结论摘要

| 项目 | 结论 |
|---|---|
| 串扰方向 | **大拇指指腹 = 横向**（同一行内、相邻列之间）；**四指指腹 = 纵向**（同一列内、相邻行之间）。两者正交，无例外 |
| 正交方向 | 两类设备在正交方向上的耦合都在**噪声级**（≤0.2%），这是区分"单点"与"多点"的根本依据 |
| 幅值量级 | 拇指：同行其余格之和 ≈ 主点的 **146%~154%**，相邻列单点 **41%~46%**；四指：同列其余格之和 ≈ 主点的 **40.5%**，相邻行 **10.5%** |
| 时间关系 | 串扰与主点**严格同步**（互相关峰值全部落在 lag=0），无延迟 |
| 关键性质 | 串扰幅值**几乎不随主点压力变化**——是**加法型偏置**，不是比例泄漏，因此用"恢复静息水平"而非"按比例缩放" |
| 压制不变量 | **只改动主点所在的那一条线**；其余格子（含其它位置的独立接触）与输入逐位一致 |
| 算法结果 | 3 段录制全部自动判出正确方向；单点帧串扰能量**抑制率 96%~99%**；非单点帧 **0 改动** |

## 1. 数据与坐标约定

```
装置：rows × cols 的行列阵列，layout_mask 给出有效格（行优先）
  四指指腹  device1 : 13 行 × 8 列，52 有效点，15492 帧 @100.3 Hz
  大拇指指腹 device1 : 14 行 × 8 列，57 有效点，13996 帧 @100.2 Hz
  大拇指指腹 device2 : 14 行 × 8 列，57 有效点，12859 帧 @100.6 Hz

术语：
  行轴（row）→ 横向；列轴（col）→ 纵向
  主点 p：一帧内响应最大的格（真实接触中心）
  串扰点 q：被 p "抬起来"的格
```

预处理：逐通道扣除**滚动低分位基线**（窗口 400 帧、5% 分位），得到响应 `d = raw − baseline`。

> 响应域与数据域必须成对使用：`raw_out = resp_out + baseline`。写回时漏掉这一步，会把每个通道的静息底值整体抹平。

## 2. 实测规律

### 2.1 串扰方向：两类设备正交（决定性证据）

对每帧取主点，分别累加"同行其余格"与"同列其余格"，归一化到主点值，取中位数：

| 设备 | 横向（同行列间） | 纵向（同列行间） | 判定 |
|---|---:|---:|---|
| 四指指腹 / device1 | 0.2% | **40.5%** | 纵向 |
| 大拇指指腹 / device1 | **146.1%** | 3.4% | 横向 |
| 大拇指指腹 / device2 | **153.5%** | 10.4% | 横向 |

对比度 **15~700 倍**，方向毫无歧义。见 `out/fig_方向判据证据.png`。

### 2.2 幅值分布与距离衰减

![串扰随距离衰减](analysis/out/fig_串扰随距离衰减.png)

| 设备 | d1 | d2 | d3 | d4 | 更远 |
|---|---:|---:|---:|---:|---|
| 四指（纵向） | 10.5% | 4.0% | 4.1% | 3.7% | 1%~5% |
| 拇指 device1（横向） | 41.0% | 28.0% | 32.5% | 29.8% | — |
| 拇指 device2（横向） | 46.0% | 31.8% | 27.7% | 23.4% | — |

四指是"整列均匀的小偏置"（衰减极慢）；拇指是"整行被抬起"（衰减慢，d3 仍有 ~30%）。**两者都不会跨到正交轴**。

### 2.3 时间同步性

串扰与主点**同起同落**，逐帧序列可见（`out/explore02.txt`）；互相关峰值全部落在 lag = 0，符合电学耦合特征，不是机械迟滞或滤波余辉。

### 2.4 关键性质：加法型偏置，不是比例泄漏

固定主点位置、按主点值分箱，串扰值几乎不随主点变化。这条性质决定了压制策略是"**恢复到静息水平 / 减除固定偏置**"，而不是"按比例缩放"。

### 2.5 线内保护阈值的余量（新工况核查）

| 设备 | line_energy 阈值 3.0 | line_other 阈值 0.90 |
|---|---|---|
| 四指 device1 | p99=1.09，max=1.29 | p99=0.42，max=0.49 |
| 拇指 device1 | p99=1.98，max=2.28 | p99=0.78，max=0.85 |
| 拇指 device2 | p99=2.14，max=2.27 | p99=0.87，**max=0.99** |

`line_energy` 余量充足。`line_other` 在拇指 device2 上有 **7 帧**突破 0.90，全部集中在 `(7,2)/(7,3)` 这一对上（两格几乎等高，0.93~0.99）——按"疑似双触点"放行处理是当前最安全的选择。

## 4. 压制算法

实现：`analysis/crosstalk_suppress.py`（核心）+ `analysis/run_suppress.py`（CLI）
移植蓝本：`analysis/crosstalk_portable.py`（无依赖，逐行可译 C）

### 4.1 数据模型与总策略

```
单点模式判定 → 沿判定的串扰轴，把除主点外的每个位置恢复到其静息响应水平
任何"面状触发 / 双轴形态不明确 / 主点线上存在近似等高第二峰"的帧 → 原样输出
```

### 4.2 逐帧判定流程

```
0) 主点        P = max(resp)，记 (r0, c0)
1) 峰值门槛    P < max(min_peak_abs, min_peak_ratio × ref_scale, 3 × noise) → 静默放行
2) 面积保护    按有效格数归一的行/列能量，活跃行数 ≥3 且 活跃列数 ≥3 → 放行
3) 方向判定    e_row = 主点行其余格之和，e_col = 主点列其余格之和
               max/min < 2.0 → 形态不明，放行；否则 direction = 能量大的那一轴
4) 线内复核    主方向线上：总和 > 3.0 × P 或 单点 > 0.90 × P → 放行
5) 压制        主方向线上除主点外，逐格写入该通道的静息响应水平 rest[k]
```

### 4.3 数值域约定（★ 最容易出错的地方）

```
响应域（算法内部）: resp = raw − baseline
数据域（对外）    : raw  = resp + baseline
```

- 输入/输出都是响应域；**写回时必须加回 baseline**，否则每个通道的静息底值被整体抹掉；
- 响应域的压制目标是 `rest[k]`（逐通道静息水平），**不是 0**；数据域终值是 `rest[k] + baseline[k]`（实测约 5~8）。
- 实测核对：被压制位置恢复后的取值 **最小 5 / 中位 6**，与原始静息值（中位 6）一致。

### 4.4 压制模式

| mode | 响应域动作 | 用途 |
|---|---|---|
| `zero`（默认） | `y_out = rest_ch` | 彻底清除线内串扰 |
| `subtract` | `y_out = max(y − b, rest_ch)` | 减标定偏置、保留残差（保真优先） |
| `bias` | 只有 `y > u` 才保留 `y − b` | 只在明显超出串扰上界时认为有真实接触 |

**存在长期背景接触时（本版本拇指 device2），推荐 `subtract`**：`zero` 会把穿过背景接触列的那一格一起归到 rest，`subtract` 只减掉串扰分量、保留背景接触的其余部分。

### 4.5 本版本的关键修正：面积保护门槛 2 → 3

**问题**：v1.0.4 的判据是"活跃行 ≥2 且活跃列 ≥2 即放行"。上一轮数据里没有长期背景接触，该判据几乎不触发（0~240 帧/设备）。本版本拇指 device2 的 row0 全程有接触，导致主点在其他行时"活跃行数"恒为 2，**666 帧被误放行**——这些帧的主点行本来是干净的串扰形态，应该压制。

**分析**：压制只作用于**主点所在的那一条线**。另一行上的独立接触不在该线上，**根本不会被碰到**。所以"主点 + 另一处独立接触"不需要保护。真正需要拦的是"面状触发"，那必然多行多列同时活跃，且此时 `direction_ratio` 与线内保护会二次兜底。

**修正**：`area_min_rows` / `area_min_cols` 默认由 2 提至 **3**。

**效果**：

| 设备 | 修正前压制帧 | 修正后压制帧 | 恢复 | 修正后面积放行 |
|---|---:|---:|---:|---:|
| 四指 device1 | 4587 | 4591 | +4 | 0 |
| 拇指 device1 | 2164 | 2202 | +38 | 0 |
| 拇指 device2 | 5437 | 6102 | +665 | 7 |

修正后 `非单点帧改动 = 0` 保持不变，方向判定 100% 正确。

## 6. 使用方式

```bash
PY=<python>

# 1) 从录制标定偏置表
$PY analysis/run_suppress.py calib --raw raw_data --out analysis/out/bias_table.json

# 2) 处理单个录制（auto = 彻底压制，输出恢复静息底值）
$PY analysis/run_suppress.py run --csv <csv> --out out.csv --raw raw_data --mode auto

# 2b) 保真优先（存在长期背景接触时推荐）
$PY analysis/run_suppress.py run --csv <csv> --out out.csv --raw raw_data \
    --bias-table analysis/out/bias_table.json --mode subtract

# 3) 批量处理 + 统计（自动校验非单点帧零改动）
$PY analysis/run_suppress.py batch --raw raw_data --out analysis/out/batch \
    --bias-table analysis/out/bias_table.json --mode auto
```

嵌入式集成见 **[算法移植手册.md](算法移植手册.md)**。

## 7. 参数表

| 参数 | 默认 | 含义 | 调整建议 |
|---|---|---|---|
| `direction` | `auto` | `auto`/`row`/`col`/`off` | 已知设备型号时写死可完全消除歧义 |
| `mode` | `auto`(=zero) | `zero`/`subtract`/`bias` | 有长期背景接触时用 `subtract` |
| `min_peak_ratio` | 0.25 | 峰值下限 = 系数 × 参考量程 | 噪声大的设备调到 0.3~0.35 |
| `direction_ratio` | 2.0 | 方向显著性 | 串扰弱的设备调到 1.5；误伤多则调高 |
| `area_active_frac` | 0.25 | 行/列活跃阈值 | 死区偏置大的设备调高到 0.3 |
| `area_min_rows/cols` | **3 / 3** | 面状判定门槛 | 已按"只保护面状触发"校准，一般不改 |
| `line_energy_max` | 3.0 | 线上非主点总能量上限 | 串扰极强的设备保持 ≥2.5（本版本实测 max 2.28） |
| `line_other_max` | 0.90 | 线上单点上限 | 本版本实测串扰 p99 达 0.87，**不要低于 0.88** |
| `compensate` | `keep` | 主点是否吸收被压制量 | 需要总力守恒时改 `sum` |

## 8. 边界与风险

1. **同一线上的真实双触点**：两个触点落在拇指的同一行（或四指的同一列）且强度接近时，理论上会被当成"单点+串扰"。`line_other_max=0.90` 能拦下等高双峰（本版本已拦下 7 帧），强弱悬殊的拦不住。
2. **线内保护余量变窄**：本版本拇指的串扰相邻列已达主点的 87%（p99），距离 0.90 阈值只剩 3 个百分点。**若下一版串扰继续增强，需要改用串扰模板匹配来区分双峰与串扰尾**。
3. **持续背景接触**：本版本拇指 device2 的 row0 全程有接触（静息帧上仍有 19~32 响应），这既会影响 `rest` 标定，也会在 `zero` 模式下削弱穿过该列的取值。推荐改用 `subtract` 模式。
4. **面状触发样本缺失**：本版本 3 段录制里没有真实的大面积触发帧，保护逻辑只能靠合成用例（整面均匀按压）回归。建议补一段"整掌按压 / 多点按压"录制再验一次。
5. **死区通道**：部分格几乎不响应且带固定偏置，会污染"活跃行/列"统计。已用 `area_active_frac=0.25` + 门槛 3 规避，更好的做法是在上游单独屏蔽。
6. **基线漂移**：算法假设基线先被扣干净。现场温漂大的话，加大基线窗口或改用自适应零点（见移植手册 §5.5）。
7. **数值域**：内部响应域、外部数据域，写回必须 `+ baseline`。实现上最容易踩的坑。
