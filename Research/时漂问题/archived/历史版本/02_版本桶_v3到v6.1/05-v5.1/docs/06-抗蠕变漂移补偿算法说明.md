## 0. 一句话与速览

**算法 = 快相免责期（隔离确定性快相） + 负载比例蠕变场与逐通道增益（治时漂/蠕变）**，
两者都是**严格因果**的在线滤波：任意时刻的输出只依赖当前帧与历史帧，不含未来信息。
**空载不参与补偿**：不做基线估计、也不做基线扣除，空载显示即传感器当前读数（§7）。

| 机制 | 目的 | 核心形式 |
|---|---|---|
| ① 快相免责期 | 隔离加载瞬间 0~4 s 的确定性快速爬升（机械加载 + 接触建立），不让它被误当蠕变扣除 | epoch 起点（onset / 负载内变载）后 0~3 s 内不做蠕变补偿，但**状态机照常运行**，输出 $Z-\text{carry}$ 保持连续 |
| ② 蠕变场 + 逐通道增益 | 扣除黏弹性蠕变（慢相） | $\text{creep}_i(t)=\gamma_i\,A_i\,g(t)$，$g(t)$ 为受载通道归一化残差的 **median 共识**，$\gamma_i$ 为过原点增量最小二乘的在线修正 |
| ③ 输出封顶 | 不把界面压到负值（负值会被显示层阈值钳成硬 0） | $\text{creep}_i\leftarrow\min\big(\text{creep}_i,\max(Z_i,0)\big)$，**只改输出值、不改任何内部状态** |

四项关键设计（都是实测暴露的确定性缺陷的定点修复，不是调参）：

| # | 设计 | 解决的问题 |
|---|---|---|
| D1 | 变载检测增加「短滞后电平差」判据（门限 5% 参考电平，含锁存/滞回/武装窗），与双 EMA 发散判据取**或** | 发散判据的有效识别门限被 EMA 分离增益（0.665）放大到约 27% 电平，小于该比例的加载被当蠕变扣掉，显示被"拉回"原读数 |
| D2 | 负载内变载重捕获幅度时，**先扣掉旧载已累积的蠕变**：$A_{\text{new}}=\overline{Z_{\text{pending}}}-\text{comp}$ | 旧蠕变被锁进新基线后永不再扣，每次变载留下 +5~8% 永久正偏 |
| D3 | 免责期同时挂在 **onset** 与**负载内变载**上 | 变载处「用旧幅度继续扣」的错误窗口被消掉 |
| D4 | 免责期分支插在状态机**之后**，期内输出 $Z-\text{carry}$（保留 epoch 起点已生效的扣除，再经输出封顶） | 期内不能失明（要能识别卸载）；变载瞬间显示不跳变（扣除量连续） |

**实测表现**（本节数字全部来自当前实现，来源与口径见 §10）

- **合成砝码 7 场景**（蠕变律取自实采保压段拟合）：稳态偏差 **−0.22% ~ +0.33%**（|偏差| 中位 0.14%）；
- **恒载 9 组**：时漂残余 全段 **1.86%**（无补偿 15.46%）、**慢相段 1.59%**、受载通道中位 0.91%、
  噪声比 0.71、平坦度 1.89%、阶跃保真 1.00；
- **4 份实采录制**：台阶捕获比 中位 **0.96** / 最小 0.80（理想 1.0）、
  变载窗最大偏差中位 **1426 ADC**、全程最大偏差中位 1889 ADC（占峰值 6.3%）。

**时间线（从「真实加载沿」看；完整推导与实测见 §6.4~§6.6）**

| 相对真实加载沿 | 阶段 | 显示行为 | 1 s 档 | 3 s 档（默认） | 5 s 档 |
|:--:|---|---|:--:|:--:|:--:|
| 0 ~ 0.5 s | 阶跃判据命中（检测窗；空载→负载实测 ≈0，负载内变载 0.15~0.8 s） | 空载态：输出 = 输入 | 同左 | 同左 | 同左 |
| 0.5 ~ 2.5 s | **确认**（`kStepPersistS` = 2.5 s，**与档位无关**） | 空载态：输出 = 输入 | 同左 | 同左 | 同左 |
| 2.5 ~ 2.5+FAST | **免责期**（A 采集窗是它的最后 1/3） | 输出 $Z-\text{carry}$（首次加载 carry=0 ⇒ 显示=原始） | 2.5~3.5 s | 2.5~5.5 s | 2.5~7.5 s |
| **2.5 + FAST** | **首扣**：按新幅度开始扣 | 扣除量从 0 起增长 | **3.5 s** | **5.5 s** | **7.5 s** |
| 首扣 + 3τ（τ = 3 s） | 扣除量追上当前蠕变量（95%） | 显示基本不再上漂 | 12.5 s | 14.5 s | 16.5 s |

> **两种工况的时间线不同**：首次加载（零基线 → 恒压）要等到「首扣」才开始回调；
> **负载内变载**在台阶瞬间 `carry` 已非零，显示立刻跟随真实台阶（不必等首扣），
> 首扣只决定"新幅度下重新建仓"的起点。这正是 §6.4「pending 冻结 / 免责期」分工的由来。

## 1. 问题定义与物理依据

### 1.1 要解决的两个现象

1. **零漂**：无负载时读数缓慢偏离零点，且随环境/装配变化；
2. **时漂（蠕变）**：恒定压力下读数持续缓慢上升（黏弹性蠕变），
   9 组恒载实测的原始漂移占幅度 **5.1%~33.1%**（均值 15.5%），持续到 200 s 以上仍未收敛。

两者性质不同：零漂是**加性基线**偏移，蠕变是**与当前载荷成比例**的缓变增量。
**本算法只处理后者（比例蠕变场 $\gamma_iA_ig$）**：空载基线不再被估计或扣除，
空载读数原样显示——零漂以"传感器当前读数"的形式直接呈现给用户，而不是被归零（见 §13.1）。

### 1.2 加载后的三段结构（免责期的物理依据）

对 9 组恒载数据的主通道平滑曲线做分段斜率统计（归一化轮廓按「onset+5 s 处的增量」归一化）：

| 区间 | 平均斜率 | 性质 | 累计占比 |
|---|:--:|---|:--:|
| 0 – 1 s | 0.478 /s → 0.199 /s | 机械加载 + 弹性建立 | — |
| 1 – 4 s | 0.013 /s | 接触建立（快相尾巴，4 s 完成 92%） | 快相合计 **16~33%** |
| 4 s – 120 s | 0.0043 /s | 黏弹性蠕变（慢相） | 慢相 **67~84%** |

归一化轮廓（9 组中位）：

| 加载后 | 0.15 s | 0.5 s | 1 s | 2 s | 3 s | 4 s | 5 s |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| 归一化读数 | 0.07 | 0.21 | 0.39 | 0.65 | 0.81 | 0.92 | 1.00 |

两条关键实验事实：

1. **快相形状高度可复现**：9 组归一化曲线逐点标准差**最大 0.026、均值 0.016**；
   三种指尖位置（幅度 1.27 / 1.39 / 1.74，差 37%）的曲线几乎重合
   ⇒ 快相是**确定性响应**（本质可出厂标定），不是需要在线学习的随机过程。
2. **快相与慢相在频域不可分、在时间上可分**：任何在线辨识在 0~4 s 内都无法把「机械加载」
   与「材料快相」分开；4 s 之后信号单调光滑，慢相建模难度下降一个数量级。

⇒ 把快相划为「免责区」，等价于**把两个时间尺度混叠的辨识问题降级为单尺度平滑跟踪问题**。
这是本算法在中段加入免责期的全部理由。

### 1.3 信号域与接口契约

- 输入：每帧一个时间戳（秒，单调递增）与一个 $n$ 通道显示值向量 $\mathbf v$（ADC 域或力值域均可，
  算法对幅度整体缩放不敏感，门限均为相对量）；
- 输出：同维向量（就地覆盖 $\mathbf v$），为**显示层**补偿结果；
- 通道数变化 → 自动重置；时间戳重复/回退（$\Delta t\le0$）→ 该帧只跳过状态更新（不做快照），
  $\Delta t>0.1\,\text{s}$ → 截断为 0.1 s（卡顿/暂停时不产生跳变）；
- 算法**不修改**业务 canonical 帧、录制数据、标定与 NG 判定，只作用于最终显示值。

## 2. 算法总览

```
                       ┌──────────────── 每帧 ────────────────┐
   ts, v(n)  ──►  总量 total = Σv ──► 三级 EMA（ts_smooth / fast / slow / level_ref）
                       │                          │
                       │                          ├─► ① 阶跃检测（双 EMA 发散 div）
                       │                          │      或 ② 短滞后电平差 d_lev（D1）
                       │                          │        ↓ 持续 2.5 s 确认
                       │                          ├─► 状态机：空载→负载 / 负载→负载(restep) / 负载→空载
                       │                          │        （无空载基线跟踪：不自动归零）
                       │                          │
                       └─► 电平环形缓冲（1024 帧）─┘
                                                  │
                       ┌── 快相免责期（D3/D4，插在状态机之后）──┐
                       │  u < 3 s：冻结蠕变估计，输出 Z − carry  │
                       │  u = 3 s：用免责期末段窗捕获 A，锚定 g  │
                       └───────────────────────────────────────┘
                                                  │
                       Z = v ──► 慢相蠕变估计：g_raw = median((Z−A)/A)
                                                  │  g ← 一阶平滑(τ=3 s)
                                                  ├─► γ_i ← Σ(dt·g·rel)/Σ(dt·g²) 限幅[0.3,2.0]
                                                  └─► 输出 v_i = Z_i − min(clip(γ_iA_ig,−0.5A_i,1.5A_i), max(Z_i,0))
```

三条链路的作用域互相独立、可分别验证：

| 链路 | 生效条件 | 输出贡献 |
|---|---|---|
| 空载 | 非负载段 | **无**（不扣基线、不扣蠕变 ⇒ 原样输出） |
| 快相免责 | 负载段 且 本 epoch 免责期未结束 | 无蠕变扣除，仅 $-\,\text{carry}_i$（再经输出封顶） |
| 慢相蠕变 | 负载段 且 免责期已结束 且 $A_i>0$ | $-\,\min\big(\text{clip}(\gamma_iA_ig,\,-0.5A_i,\,1.5A_i),\ \max(Z_i,0)\big)$ |

## 4. 逐帧算法流程（完整伪代码）

```text
Process(ts, v):
  if n(v) != n_: ResetFor(n(v))
  total = Σ v ;  PushLevel(ts, total)

  ── 1. 三级 EMA 与极值 ─────────────────────────────────────────
  if 首帧:
      ts_smooth = fast = slow = total ;  min_ts = max_ts = level_ref = total
      dt = 0
  else:
      dt = ts − last_ts ;  last_ts = ts
      if dt <= 0: dt = 0            # 重复时间戳：本帧不更新状态（绝不快照）
      if dt > 0.1: dt = 0.1         # 大间隔截断
      if dt > 0:
          ts_smooth += (dt/0.3)·(total − ts_smooth)
          fast      += (dt/0.7)·(total − fast)
          slow      += (dt/6.0)·(total − slow)
          level_ref += (dt/10.0)·(ts_smooth − level_ref)
  min_ts = min(min_ts, ts_smooth) ;  max_ts = max(max_ts, ts_smooth)
  eps = 1e−6·(1 + |max_ts|)

  ── 2. 阶跃检测（取值见 §5.1） ────────────────────────────────
  div = |fast − slow|
  thr = in_load ? max(0.18·max(slow,eps), 0.01·max_ts)
                : max(0.50·max(slow,eps), 0.01·max_ts)

  # 2b. 短滞后电平差判据（D1，仅负载内，与 div 取或；只增敏不降敏）
  lev_ok = false
  if in_load and lev_n > 3:
      if WinMean((ts − 0.3s, ts], &lv_now):
          if lev_latched:                                    # 已锁存：滞回判定
              lev_ok = |lv_now − lev_latch| > 0.5·lev_thr
              if not lev_ok: lev_latched = false             # 电平回到一半以内 → 解锁
          elif ts − onset_ts > lev_arm_s:                    # D1 武装窗（避开快相）
              if WinMean((ts − 0.8s, ts − 0.3s], &lv_ref):
                  lev_thr = max(0.05·max(lv_ref,eps), 0.01·max_ts)
                  if |lv_now − lv_ref| > lev_thr:
                      lev_latch = lv_ref ;  lev_latched = true ;  lev_ok = true

  step_now = in_load ? (div > thr) : (div > thr and fast > slow)   # 空载侧有方向门
  if in_load and lev_ok: step_now = true
  if step_now:
      if not pending: pending = true ;  pending_ts = ts
  elif pending and (not lev_ok) and div < 0.5·thr:
      pending = false                                   # 瞬态（手指调整/磕碰）：取消
  step_conf = pending and (ts − pending_ts > 2.5s)

  u    = in_load ? ts − onset_ts : 0
  idle = (ts_smooth < 0.10·max(level_ref,eps)) or (ts_smooth < 1.5·min_ts + eps)

  ── 3. 状态机（三种迁移 + 冻结） ──────────────────────────────
  if not in_load:
      if 首帧 and total > eps:      BeginLoad(ts) ;  AlignRefs(ts_smooth)
      elif step_conf:               BeginLoad(ts) ;  AlignRefs(fast)     # 空载→负载
      hold = false
  elif u > 3.0s and idle:                                  # 快速卸载（不等发散）
      in_load = false ;  AlignRefs(ts_smooth)
      hold = false ;  hold_comp 清空 ;  pending = false
      fast_done = true ;  lev_latched = false
  elif u > 6.0s and step_conf:
      if idle:                                             # 负载→空载
          in_load = false ;  AlignRefs(ts_smooth)
          hold = false ;  hold_comp 清空 ;  pending = false
          fast_done = true ;  lev_latched = false
      else:                                                # 负载→负载（变载重捕获）
          Restep(ts, v) ;  AlignRefs(fast)
  elif pending:                                            # 冻结：不积分 g/γ
      hold = true ;  a_new_acc += v ;  ++a_new_frames
  else:
      hold = false ;  hold_comp 清空
      if a_new_frames > 0: a_new_acc = 0 ;  a_new_frames = 0

  # （无空载基线跟踪：非负载段不估基线、不减基线、不扣蠕变）

  ── 4. 快相免责期（D3/D4；状态机之后、扣除之前） ───────────────
  if in_load and not fast_done:
      ux = ts − onset_ts
      if ux < fast_phase_s:                                # ── 免责期内 ──
          a_captured = false ;  a_acc = 0 ;  a_frames = 0 ;  g = 0
          # 刻意不动 g2_acc / g_rel_acc / gamma（γ 是器件属性，非 epoch 属性）
          if hold and hold_comp 尺寸不符: hold_comp = carry
          Zx = v
          if ux ≥ fast_phase_s − exempt_awin_s:            # 仅末段窗采样幅度
              exempt_acc += (Zx − carry) ;  ++exempt_frames
          v_i = Zx_i − min(carry_i, max(Zx_i, 0)) ;  return   # 直通 + 保留旧扣除（输出封顶）
      fast_done = true                                     # ── 免责期结束当帧 ──
      A = (exempt_frames > 0) ? exempt_acc/exempt_frames : (v − carry)
      A = max(A, 0)
      loaded_i = (A_i > 0.10·max(A))
      a_captured = true ;  g = 0
      g = clip( median_{loaded}( carry_i / (γ_i·A_i) ), 0, 1 )   # 扣除连续性锚定
      carry = 0 ;  exempt_acc = 0 ;  exempt_frames = 0
      # 不 return：当帧继续走慢相蠕变补偿

  Z = v
  if not in_load: return                                   # 空载：原样输出（不扣基线、不扣蠕变）

  ── 5. 幅度参考 A 的兜底路径（默认档被免责期覆盖，见 §6.2） ────
  if not a_captured:
      if 1.0s ≤ u ≤ 3.0s: a_acc += Z ;  ++a_frames
      if u > 3.0s:
          A = (a_frames > 0) ? a_acc/a_frames : Z
          loaded_i = (A_i > 0.10·max(A)) ;  a_captured = true
      else:
          v = Z ;  return

  ── 6. pending 冻结（**仅负载内**；空载态已在上面 return）：保持 pend 起始扣除 ──
  if hold:
      if hold_comp 尺寸不符（惰性初始化）:
          hold_comp_i = loaded_i ? clip(γ_i·A_i·g, −0.5A_i, 1.5A_i) : 0
      v_i = Z_i − min(loaded_i ? hold_comp_i : 0, max(Z_i, 0)) ;  return

  ── 7. 慢相蠕变场共识 g(t) ───────────────────────────────────
  rel_i  = (Z_i − A_i)/A_i        （i ∈ loaded 且 A_i > eps）
  g_raw  = median{ rel_i }
  g     += (dt/3.0)·(g_raw − g)

  ── 8. 逐通道增益 γ（过原点增量最小二乘的在线形式） ───────────
  if g > 0.02:
      g2_acc += dt·g²
      g_rel_i += dt·g·rel_i       （i ∈ loaded）
      if g2_acc > 1e−8:
          γ_i = loaded_i ? clip(g_rel_i/g2_acc, 0.3, 2.0) : 1.0

  ── 9. 输出（逐通道限幅 + 输出封顶；未受载通道直通） ──────────
  v_i = Z_i − min(loaded_i and A_i > eps ? clip(γ_i·A_i·g, −0.5A_i, 1.5A_i) : 0, max(Z_i, 0))
```

> **输出封顶**：`min(扣除量, max(Z_i,0))` 只作用于写回 $\mathbf v$ 的那一步，
> **不参与** $g$、$\gamma$、$A$、`hold_comp`、`carry` 的任何计算，
> 只是输出不再小于 0（负值会被显示层阈值钳成硬 0，见 §8.2）。

**各阶段动作摘要**

| 子过程 | 触发 | 动作 |
|---|---|---|
| `BeginLoad(ts)` | 空载→负载确认 / 首帧已带载 | `in_load=true`、`onset_ts=ts`、`a_captured=false`、`g=0`、`g2_acc=0`、`g_rel_acc=0`、`gamma=1`；`fast_done=false`、`lev_latched=false`、`carry=0`、`exempt_*=0` |
| `Restep(ts, v)` | 负载内变载确认且电平仍受载 | `A = mean(a_new_acc)`（无样本则用当帧读数）→ **D2：$A\leftarrow\max(A-\text{hold\_comp},0)$ 并重算 `loaded`** → $g=\text{clip}(\text{median}(\text{hold\_comp}_i/(\gamma_iA_i)),0,1)$（**分母含 $\gamma$**）→ 清 `hold/a_new_*`、`pending=false` → `fast_done=false`、`carry=CurrentDeduction()`、`exempt_*=0`、`lev_latched=false`；`gamma/g2_acc/g_rel_acc` **刻意保留** |
| `AlignRefs(lv)` | 每次迁移 | `level_ref=fast=slow=lv`、`pending=false`（发散量归零，避免迁移后立刻假触发） |
| 卸载分支 | $u>3$ s 且 idle，或 $u>6$ s 且确认且 idle | 退回空载、清 `hold/hold_comp/pending`、`fast_done=true`、`lev_latched=false` |

## 5. 关键判据的设计依据

### 5.1 为什么需要「短滞后电平差」判据（D1）

双 EMA 发散量对一次阶跃 $\Delta$ 的响应为

$$ \text{div}(t)=\Delta\left(e^{-t/6.0}-e^{-t/0.7}\right),\qquad
\max_t \text{div}=0.665\,\Delta \ \ (t\approx1.70\,\text{s}) $$

也就是说，`div > 0.18·slow` 这条判据的**名义**门限是 18%，**有效最小可识别台阶 ≈ 0.18/0.665 ≈ 27% 电平**。
低于该比例的加载不会触发 pending → 不重捕获 → 被蠕变模型当作慢相增量积分掉，
扣除量持续增长直到吃掉整个台阶 ⇒ **显示被"拉回"原读数**。

**实测台账（仅启用发散判据、未启用 D1 时的对照测量）**：

- 三份录制合并的负载内变载台账：台阶/电平比值 ≥0.29 的 **2/2 全部识别**，<0.29 的 **0/2 全部漏检**；
- `13ffca` @27.66 s：真实台阶 +4672（占电平 0.24）→ 漏检；8 s 内原始走 +4900，显示只走 +1937（41%）；
- `切换负载-快相无责` @240.86 s：台阶 +5254（0.256）→ 漏检 → 扣除量冲到 **9241 ADC**，
  显示 16600 vs 原始 25842（欠报 36%，持续到卸载）。

启用 D1 后，同一批事件（含上述两处）的台阶捕获比分别为 **0.98** 与 **0.91**，变载窗最大偏差
从数千 ADC 降到 1560 / 2210 ADC（见 §10.2）。

**新判据**：以 0.5 s 滞后差分直接测电平台阶——

$$ d_{\text{lev}}(t)=\underbrace{\overline{\text{total}}_{(t-0.3,\,t]}}_{\text{近期窗}}-\underbrace{\overline{\text{total}}_{(t-0.8,\,t-0.3]}}_{\text{参考窗}},\qquad
\text{thr}=\max\!\big(0.05\,\lvert\text{参考电平}\rvert,\ 0.01\,\text{max\_ts}\big) $$

为什么 0.5 s 滞后差分能分开「台阶」与「蠕变斜坡」：实测最快蠕变也只到 ~1%/s，
0.5 s 内变化 0.5%，远低于 5% 门限；而砝码台阶是一次性跳变，**全额**呈现在该差分里。
（用 3 s 长窗做不到：会把快相/快速蠕变误判为台阶，把恒载段切成多段 epoch。）

**门限 5% 的实测依据**（全受载段统计 $|d_{\text{lev}}|/$电平）：

| 录制 | 稳定窗 p99 | 稳定窗 max | 事件沿 max | 分离倍数 |
|---|:--:|:--:|:--:|:--:|
| 切换负载-快相无责 | 0.85% | 2.82% | 268.2% | 95× |
| 再切换负载 | 2.71% | 3.24% | 92.4% | 29× |
| 中途切换-1d9493 | 0.23% | 0.24% | 85.3% | 363× |
| 中途切换-13ffca | 6.77% | 8.67% | 435.4% | 50× |
| 恒载 9 组 | 0.30~3.37% | 0.56~6.61% | 87~133% | 13~174× |

⇒ 真实台阶 ≥85% 电平，而稳定段内的最大电平波动 ≤8.7%（多数 <3.3%，其中较大的几处经复核本就是真实加载）。
取 **5%**：既留 1.7× 余量，又把可识别台阶从 27% 降到 5%。

**锁存（latch）是必需的**：台阶发生后参考窗会被台阶本身逐步占据；若每帧重算 $|lv_{\text{now}}-lv_{\text{ref}}|$，
差值会在约 1.5 s 后掉回门限以下，而 pending 需要连续 2.5 s ⇒ **大台阶反而漏检**。
因此命中时锁存"变化前的参考电平"，只要电平未回到 $\pm0.5\times$门限以内就继续认可。
**武装窗** `lev_arm_s`（=免责期长度，默认 3 s）避免在快相与上一 epoch 暂态内重复触发。

判据组合为**或**（只增敏不降敏）：`step_now = (div > thr) or lev_ok`；
pending 复位需同时满足「未锁存」与「发散回落到 $0.5\,thr$ 以下」，兼顾灵敏度与瞬态拒绝。

### 5.2 阶跃检测的其余细节

- **只用总量**：$\text{total}=\sum_i v_i$ 对单通道噪声不敏感，且载荷变化是整阵事件；
- **方向门只加在空载侧**（`fast > slow`）：卸载后 $fast$ 快于 $slow$ 回落的 settling 发散
  （$slow>fast$）不再被误判为加载，假 onset 及其连带误 re-capture 消失；负载内侧双向（加重/减轻）都检测；
- **确认时长 2.5 s**（`kStepPersistS`）：手指调整、短暂磕碰引起的发散在 1~2 s 内回落即被取消。
  这段等待**与免责期长度无关**，是"从真实加载沿到 epoch 起点"的固定 2.5 s（4 份录制实测 2.46~2.51 s）；
  **空载态下它期间并没有"冻结"任何东西**（空载分支 `hold=false`、输出=输入），详见 §6.4；
- **首帧已带载**：首帧 `total > eps` 直接进负载段（空载时无害：$A$ 即空载偏置且 $g\approx0$），
  此后不再走比率路径（避免微小空载域抖动触发迁移）。

### 5.3 卸载判据

$$
\text{idle}=\Big(\text{ts\_smooth}<0.10\max(\text{level\_ref},\varepsilon)\Big)\ \text{或}\
\Big(\text{ts\_smooth}<1.5\,\text{min\_ts}+\varepsilon\Big)
$$

两条件取或：前者对高电平负载灵敏，后者兜底近零空载域（此时"10% 电平参考"本身趋零）。
$u>3$ s 即可快速判定（不等发散），$u>6$ s 内的第二次变化只能冻结不能重捕获（抑制窗），
避免快相内被快相自身的发散反复触发——配合免责期，这一段本就不参与蠕变估计。

## 6. 快相免责期与扣除连续性

### 6.1 免责期语义

- **适用范围**：`BeginLoad`（空载→负载）**与** `Restep`（负载内变载）**都**重起免责期（D3）。
  中途变载同样伴随一次快相（接触面积/机械柔度台阶），若用变载前的旧幅度继续扣，
  变载后 2~4 s 内会明显欠报；
- **期内不做**：不积分 $g$、不使用幅度窗、不更新 $\gamma$（`a_captured=false`、`a_acc=0`、`g=0`）；
- **期内照常**：`in_load_` 迁移、阶跃/卸载判定、pending 期 `a_new_acc_` 累积
  全部正常运行（分支插在状态机**之后**，D4）⇒ 免责期内**不会失明**，卸载/变载仍能被识别；
- **期内输出**：$\mathbf v \leftarrow \mathbf Z-\text{carry}$（再经输出封顶），其中 `carry` 是 epoch 起点已生效的逐通道扣除
  （空载→负载时 `carry=0`，输出即 $Z$）。保留旧扣除保证：
  ① 变载瞬间显示**不跳变**；② 旧载已累积的蠕变**继续被扣**（与 D2 配合）；
- **不重置 $\gamma$/$g_2$/$g_{rel}$**：$\gamma$ 是器件属性、不是 epoch 属性；
  一旦重置，紧随其后的任何一次台阶都会把 $\gamma$ 一帧拉飞（实测把两档间隔 8 s 的场景做坏成 −10.9%）。

### 6.2 幅度参考 $A$ 必须绑定在免责期末端

免责期长度**同时决定 $A$ 的采集时刻**：$A$ 取自 epoch 起点后 $[\text{fast\_phase\_s}-\text{exempt\_awin\_s},\ \text{fast\_phase\_s}]$，
即免责期的**后 1/3**；而 epoch 起点 = 真实台阶 + 2.5 s（阶跃确认滞后）。

| 免责期 | 幅度采集窗（相对 epoch 起点） | 相对真实台阶（= 台阶 + 2.5 s） | 窗内电平（实测，占本段幅度） |
|:--:|:--:|:--:|:--:|
| 3 s（默认） | [2.00, 3.00] s | 台阶后 **4.50 ~ 5.50 s** | 0.803 |
| 5 s | [3.33, 5.00] s | 台阶后 **5.83 ~ 7.50 s** | 0.812 |

- **必须显式绑定**：兜底窗 `[1.0, 3.0] s` 整段落在默认免责期内，会被冻结逻辑跳过；
  若依赖它，$A$ 将永远捕获不到 ⇒ $\text{loaded}$ 全 0 ⇒ **补偿恒为 0，算法悄悄退化为直通**。
  这就是 §12 要求「自检断言」的原因：这种退化在指标上看起来像"没有副作用"。
- **两档 A 的差别很小**：同一录制、同一次加载实测，窗内电平只差 **1.1%**（0.803 vs 0.812，占本段幅度）。
  所以 3 s / 5 s 的取舍**不是"A 偏小"**，**主因是起扣时刻**——免责期越短，越多的快相尾巴被当成蠕变扣掉
  （首扣越早，快相完成度越低），于是"全段"口径更好看、真实加载被欠报更多。实测对照见 §11.2。

### 6.3 变载时幅度参考 $A$ 必须扣除已累积蠕变（D2）

> 注：本节的"基线"指**幅度参考 $A$**（每 epoch 的载荷电平基准），不是
> "空载零点基线 $\mathbf b$"。

重捕获时若直接令 $A=\overline{Z_{\text{pending}}}$，而 pending 期的 $Z$ 里**仍含旧载已累积的蠕变**
（例如 10 N 保压 280 s 后读数已蠕变 +11.8%，加 5 N 时这 +11.8% 还在），
它就会被当成新幅度参考的一部分、此后**永不再被扣除** ⇒ 每次变载留下约等于已累积蠕变的永久正偏（实测 +5~8%）。

修正：令 $A_{\text{new}}=\overline{Z_{\text{pending}}}-\text{comp}$（$\text{comp}$ 为旧载已生效扣除的逐通道值），
并用修正后的 $A$ 重算 `loaded`。为什么这样就对了：设旧载已累积蠕变为 $c$，则
$A_{\text{new}}=\text{新电平读数}-c$ 是**无蠕变参考**；而 $Z$ 里的 $c$ 仍在，于是

$$ g_{\text{raw}}=\frac{Z-A_{\text{new}}}{A_{\text{new}}}\approx\frac{c}{A_{\text{new}}}>0 $$

扣除量自然**继续**维持在 $c$ 附近：显示既不跳变、也不再留下 $c$ 的永久偏移。

**锚定式必须含 $\gamma$**：扣除量是 $\gamma_iA_ig$，因此
$g=\text{clip}\big(\text{median}\big(\text{comp}_i/(\gamma_iA_i)\big),0,1\big)$（免责期收尾同样如此）。
漏掉 $\gamma$ 会在 $\gamma\ne1$ 时引入 $(\gamma-1)\cdot\text{comp}$ 的偏差——
本次 C++↔Python 逐帧对拍正是在这里抓到 15.5 ADC（0.10%）的差异，单看某一侧指标完全看不出来。

### 6.4 「pending 冻结」与「免责期」是两件事（首次加载时重合，变载处接力）

两个环节都表现为"一小段时间内不产生新扣除"，容易被当成一回事。它们在代码里是两处**独立分支**：

| | **pending 冻结** | **免责期** |
|---|---|---|
| 代码位置 | 状态机第 3 段 `elif pending_: hold_=true`（`drift_compensator.cpp:356-361`）+ 输出分支（`:457-478`） | 状态机**之后**的独立分支（`drift_compensator.cpp:371-425`） |
| 触发条件 | 阶跃判据命中（**尚未确认**）**且已处于负载态** | 阶跃**已确认**、进入新 epoch（`fast_done_=false`） |
| 时长 | **不定**：≥ `kStepPersistS`（2.5 s），直到确认或被瞬态取消 | **固定** 3 / 5 s（运行期可切） |
| 期内动作 | 不积分 $g$/$\gamma$；扣除量冻结在 `hold_comp_`（= pending 起始那一刻的值）；同时累积 `a_new_acc_` 供重捕获 | 不采 $A$、不积分 $g$；输出 $Z-\text{carry}$（`carry` = epoch 起点已生效的扣除） |
| 防的是什么 | **过期模型解释新输入**：不冻的话 $g$ 会把真实台阶继续当蠕变积分，扣除量越扣越大、显示被"钉"在旧电平 | **快相污染模型**：台阶后立刻建模会让 $A$ 采在快相中途、把剩余快相当蠕变扣掉 |
| 一句话 | **保护输入**（跟得上真实载荷变化） | **保护模型**（压得住虚假漂移） |
| **首次加载**（空载→负载） | **不生效**：空载分支显式 `hold_=false`（`drift_compensator.cpp:329`），且空载态本就没有扣除量 ⇒ 输出 = 输入 | **主战场**：这就是"首扣 = 台阶 + 2.5 + 免责期"的来源 |
| **负载内变载** | **主战场**：台阶后 0~2.5 s 停住旧扣除 | 接力：2.5 s 之后再不扣新段、但保留 `carry` |

⇒ **在"首次加载"这一个工况下，两者在效果上重合**（都表示"不扣"，显示都等于原始），
但机制与目的不同；**在负载内变载上它们接力**。缺任何一个都会在自己的场景里出事：

- 去掉 pending 冻结 ⇒ 首次加载**毫无变化**（空载态本就不扣），但变载处会"用旧幅度继续扣新载荷"
  ⇒ 扣除量持续增长直到吃掉整个台阶、显示被拉回原读数；
- 去掉免责期（压到 0/1 s）⇒ pending 冻结仍在，但算法会在台阶后 2.5 s（快相尚未走完）就开始扣，
  $A$ 采在快相中途 ⇒ 真实加载被系统性欠报（实测台阶只透传 0.84~0.86）。

### 6.5 完整时间线：从「真实加载沿」到补偿生效

以**真实加载沿**（物理上加压那一刻）为原点，全程是四段时延（①② 与档位无关，③④ 由档位决定）：

| # | 段 | 物理含义 | 数值 |
|:--:|---|---|:--:|
| ① | **检测延迟** | 判据要看够数据才敢置 `pending`（电平判据需 0.3 s 近窗 + 0.5 s 滞后窗；发散判据对大台阶约 0.15~0.6 s，台阶越小越慢） | 0 ~ 0.5 s（空载→负载沿实测 ≈ 0） |
| ② | **确认延迟** | `kStepPersistS` = 2.5 s 连续保持 → **epoch 起点** | **2.5 s**（实测 2.46~2.51 s） |
| ③ | **免责期** | epoch 起点后不补快相；**其末端即首扣**（A 采集窗是它最后 1/3，不额外增加时延） | **3 / 5 s**（可切） |
| ④ | **扣除爬升** | $g$ 从 0 起一阶平滑（$\tau_g$ = 3 s）：63% 在 +3 s、95% 在 +9 s | +3 / +9 s |

| 档位 | **首扣**（=①+②+③） | 扣除 63% | 扣除 95%（"扣到位"） |
|:--:|:--:|:--:|:--:|
| **3 s（默认）** | **5.5 s** | 8.5 s | **14.5 s** |
| 5 s | **7.5 s** | 10.5 s | **16.5 s** |

**怎么理解这四段**：

- ①② 是**认知代价**：不看够不敢动，否则手指调整/磕碰会被当成加载（2.5 s 的等待换的是瞬态拒绝能力）；
- ③ 是**选择代价**，不是能力不足：它**不是去"稳住跃升"，而是"不碰跃升"**——让快相原样透传，
  为的是让参考点 $A$ 落在"触面已建立"之后。副作用是"全段时漂残余"这一列偏大（快相增量没被扣），这是设计意图；
- ④ 是**平滑代价**：扣除量必须慢慢长，否则噪声直接进显示；
- 恒压下蠕变是**持续增长**的信号，补偿器永远在追、永远略落后 ⇒ 本算法**没有"回调完成"这个事件**，
  只有「开始扣 → 看得见 → 曲线走平」三个可观测点。

**两种工况的时间线必须分开看**：

- **首次加载（零基线 → 恒压）**：`carry = 0` ⇒ 0~5.5 s 显示 = 原始（快相全部透传），**5.5 s 起才开始回调**；
- **负载内变载**：台阶瞬间 `carry` 已非零，且台阶本身全额透传（输出 $Z-\text{carry}$）⇒ 显示**立刻跟随真实台阶**，
  首扣只决定"新幅度下重新建仓"的起点。合成砝码场景实测：+2.5 N 台阶后 0.5 s，显示已达 12482（理想 12500）。

## 7. 安全语义与限幅

| 机制 | 规则 | 目的 |
|---|---|---|
| 空载不归零 | 非负载段**原样输出**：不估基线、不减基线、不扣蠕变 | 零点保持传感器当前读数（不强制拉回 0） |
| 输出封顶 | 写回前 $\text{creep}_i\leftarrow\min(\text{creep}_i,\max(Z_i,0))$，**只改输出、不改内部状态** | 显示不为负（负值会被显示层阈值钳成硬 0） |
| 补偿使能 | 由开关控制；关闭时 `Process` 直接返回原值 | 可回退 |
| 受载门控 | 只有 $\text{loaded}_i$（$A_i>0.10\max A$、$A_i>\varepsilon$）才扣蠕变，其余通道直通 | 未受载通道不被误扣 |
| 蠕变扣除限幅 | $\text{clip}(\gamma_iA_ig,\ -0.5A_i,\ +1.5A_i)$ | 单通道扣除不超过幅度的 150%，且允许小幅负向 |
| 增益限幅 | $\gamma_i\in[0.3,2.0]$ | 抑制器件间异常放大 |
| 无法建立可靠估计时 | $A$ 为零、`loaded` 全 0、$g\le0.02$ ⇒ 自然退化为直通 | fail-safe |
| 通道数变化 | 自动 `ResetFor(n)` | 避免维度错配 |
| 时间戳异常 | $\Delta t\le0$ 跳过状态更新；$\Delta t>0.1$ s 截断 | 不产生跳变、不做快照 |
| 多变送目标隔离 | `DriftCompensationCoordinator` 按 key 隔离状态；显示值域**签名**变化即重置该目标 | 多设备/切换工况不串状态 |

## 8. 接口与集成

### 8.1 C++ 接口

```cpp
namespace drift {
class DriftCompensator {
public:
    void Process(double timestamp_s, Eigen::VectorXd& values_io);  // 就地补偿一帧
    void Reset();                                                  // 完全复位
    void SetFastPhase(double fast_s);                              // fast_s > 0 才生效
    double fast_phase_s() const;
    static constexpr double kFastPhaseDefaultS = 3.0;              // 默认档
    static constexpr double kFastPhaseAltS     = 5.0;              // 备选档
};

class DriftCompensationCoordinator {          // 多目标（多设备）协调
public:
    void SetEnabled(bool on);                 // 值变化 → ResetAll()
    bool enabled() const;
    void SetFastPhase(double fast_s);         // 值变化 → ResetAll()
    void Process(const std::string& key, const std::string& signature,
                 double timestamp_s, Eigen::VectorXd& values_io);
    void ResetAll();
};
}
```

- 每个目标（key）持有独立补偿器状态；`signature`（显示模式/单位/数据域/标定代等）变化即重置该目标；
- `SetFastPhase` 在每次 `Process` 时下发到当前目标，保证多设备场景参数一致；
- `SetEnabled` / `SetFastPhase` 的**值变化**都会丢弃全部目标状态（避免新旧参数混在同一段估计里）；
- 免责期长度派生：`exempt_awin_s_ = fast / 3`、`lev_arm_s_ = fast`（同步更新，无需分别配置）。

### 8.2 集成路径与运行期切换

| 环节 | 行为 |
|---|---|
| 菜单 | 「设备 → 时漂/零漂补偿（无责 3s）/（无责 5s）」两项**互斥**；再点已勾选项 = 关闭补偿 |
| 线程 | 菜单信号经 `Qt::QueuedConnection` 投递到数据线程的两个 slot（使能 / 档位），仅启用时投档位 |
| 接入点 | 数据链路在**单位换算之后、显示阈值之前**对最终显示值调用 `Process` |
| 回放 | 回放期间旁路（不参与补偿） |
| 设备切换 | `ResetAll()` |
| 状态栏 | 提示带档位（"时漂/零漂补偿已开启（无责 3s）…"） |
| 默认 | 两档均不勾选（补偿关闭） |

**注意（显示层阈值）**：后续显示流水线会把
$v<\max(0,\text{min\_show},\text{阈值})$ 一律置 0（默认阈值 0），
即**负值在界面上表现为硬 0**。算法侧已有输出封顶（§7 第 2 行）把负值挡在源头，
但排查"零点被压到 0"类现象时仍应同时看补偿输出与阈值行为（机制记录见 §13.1）。

## 9. 复杂度与资源

| 项目 | 量级 |
|---|---|
| 每帧计算 | $O(n)$；`median` 用 `nth_element`（$O(n)$），整帧含 3~4 次 median ⇒ $O(n)$ |
| 额外内存 | 环形缓冲 $1024\times2$ 个 double ≈ 16 KB/实例 + 若干 $O(n)$ 向量 |
| 动态分配 | 稳态**零分配**（`scratch_` 在 `ResetFor` 预留，环形缓冲为定长数组） |
| 数值条件 | 全部为**正向**滤波（EMA + median + 凸组合），无逆滤波器、无大规模相消 ⇒ 定点/单精度友好 |
| 群延迟 | 信号通路**零群延迟**（EMA 只影响状态估计，不进入直通路径）。补偿量的建立是一阶过程（$\tau_g$ = 3 s）：**首扣 = 真实加载沿 + 2.5 s + 免责期**，扣到位（95%）在 +14.5 s（3 s 档）/ +16.5 s（5 s 档），见 §6.5 |

### 11.2 免责期长度取舍（3 s vs 5 s，同一算法的两档）

| 指标 | **3 s（默认）** | 5 s | 谁更好 |
|---|:--:|:--:|:--:|
| 恒载 9 组 时漂残余 全段 | **1.86%** | 2.35% | 3 s |
| 恒载 9 组 时漂残余 慢相段 | 1.59% | **1.53%** | 5 s |
| 恒载 9 组 受载中位 | **0.91%** | 1.46% | 3 s |
| 恒载 9 组 噪声比 | **0.71** | 0.76 | 3 s |
| 实录 台阶捕获比 中位 / 最小 | 0.96 / 0.80 | **0.99 / 0.81** | 5 s |
| 实录 变载窗最大偏差 中位（ADC） | 1426 | **512** | 5 s |
| 实录 全程最大偏差 中位（ADC / 占峰值） | 1889 / 6.3% | **880 / 3.3%** | 5 s |
| 首次回调时刻（§6.5） | **5.5 s** | 7.5 s | 3 s 更快 |

**机理（实测，不是推测）**：免责期长度**同时决定起扣时刻**，而起扣越早，越多"还没走完的快相"
被当成蠕变扣掉（台阶后 3.5 s 起扣时快相只完成约 85~87%）：

- ⇒ **长保压口径**（全段/受载中位/噪声比）在 3 s 下更好看 —— 因为它把快相尾巴也扣掉了，
  这一列**天然奖励"扣得多"**，不能单独用来选档；
- ⇒ **变载跟踪**在 5 s 下更好（全程最大偏差只有 3 s 档的 47%）—— 它少扣了那部分真实载荷；
- 两档 **$A$ 采集窗电平只差 1.1%**（§6.2），所以差异**不是**"$A$ 偏小"造成的。

⇒ **选型建议**：以"长保压时漂"为主要验收口径 → 3 s（默认）；以"切换负载跟得上 / 绝对偏差"为主要口径 → 5 s。
切换只需一个运行期接口（`SetFastPhase`），两档实测差异已如上表，不需要重新标定其他参数。
若想两头兼顾可取 4 s（该点位尚未实测，需要时按 §14 流程对 4.0/4.5 做一次扫描）。

## 12. 验收口径与自检断言

### 12.1 建议的验收指标

| 指标 | 定义 | 本算法实测 | 目标 |
|---|:--:|:--:|:--:|
| 变载台阶捕获比 | 事件后 6 s 显示增量 ÷ 原始增量（有效事件） | **0.96**（最小 0.80） | ≥0.9，且最小 ≥0.8 |
| 变载窗内最大绝对偏差 | 事件 ±(1~12) s 内 $\max\lvert\text{显示}-\text{原始}\rvert$（中位/最大，ADC） | **1426 / 2662** | 最大 <4000 ADC |
| 全程最大偏差 | 全程 $\max\lvert\text{显示}-\text{原始}\rvert$ ÷ 峰值 | **6.3%（中位）**，单份最大 9.0% | <15% |
| 时漂残余 慢相段 | onset+5 s 起，末 10% − 首 10%，÷ 幅度（恒载 9 组） | **1.59%** | <2.0% |
| 时漂残余 全段 | 负载段末 10% − 首 10%，÷ 幅度（恒载 9 组） | 1.86% | 仅作参考（含故意放过的快相） |
| 阶跃保真 | epoch 后 0.5~2.5 s 幅度 ÷ 原始同窗 | **1.00** | ≥0.98 |
| 事件跳变超额 | 负载段内（**不含加载/卸载沿**）单帧 $\lvert\Delta\text{显示}-\Delta\text{原始}\rvert$ | **≤0.31 ADC**（9 组最大，多数组 ≤0.09） | 不产生单帧跳变（<1 ADC） |
| restep 扣除连续性 | 变载前后逐通道扣除量之差 ÷ 该通道幅度 | **<5%** | ≤5% |
| epoch 数 | 单份录制内的 epoch 段数 | 与真实载荷变化次数一致（4 份实录 13/4/4/8） | 一致 |
| 首扣时延 | 真实加载沿 → 首个可见扣除 | **7.8 s**（3 s 档；理论 5.5 s） | 记录即可，见 §6.5 |
| 零点保真 | 零负载段显示 ÷ 原始读数（均值比） | **≈1.0** | 0.8~1.2，且**不出现负值** |
| 零负载段被钳 0 时长 | 零负载段内显示 ≤0 的累计时长 | **0~0.71 s** | <1 s（卸载判定延迟，见 §13.2 第 8 条） |

> **不建议用「最坏欠报 = max|显示−原始| ÷ 本次跳变」作主指标**：它把算法**有意做出的蠕变扣除**
> 也算成"欠报"，跳变很小时比值会爆掉（本批数据中某处跳变仅 −818 ADC，比值因此高达 369%，
> 而绝对偏差只有 3020）。区分度远不如「台阶捕获比」与「绝对偏差」，建议以上表前两行为准。

### 12.2 必须实现的自检断言

1. 免责期结束后 $A$ 非零；
2. `loaded` 中为真的通道数 > 0；
3. $g$ 随慢相单调增长（非恒 0）；
4. **变载/免责期收尾后，逐通道扣除量 $\gamma_iA_ig$ 与 `carry` 之差 ≤ 该通道幅度的 5%**
   ——即"扣除量连续、旧蠕变没被丢掉"。若 `carry` 恒为 0，说明 D2 的基线修正未生效（会退回 +5~8% 正偏）。
5. **空载段输出必须逐帧等于输入**：`in_load_=false` 时 `v` 不被改写
   （实现上就是"空载分支直接 return"），且任何一帧的输出都不小于 0（输出封顶生效）。
   若空载段输出与原始读数不同，说明"不归零"没生效（会重新出现零点被拉回 0）；

> 前三条是必须的：一旦 $A$ 捕获不到，算法会**静默退化为直通**
> （症状是"变化负载上增益恰好 1.000 / 恒载上时漂与原始完全相同"，看起来像没有副作用）。

## 13. 已知限制

### 13.1 空载与零点的当前语义（为什么不归零）

- **非负载段原样输出**：不估基线、不减基线、不扣蠕变 ⇒ 零点保持传感器当前读数，**显示不会被拉回 0**；
- **扣除非但不停，反而全程连续运行**：状态机、pending 冻结、免责期 `carry`、蠕变积分与逐通道增益
  在空载/轻载时照常演进，不因读数低而停扣、停跑或重置（这是"算法一直行为"的语义）；
  > 曾评估过"空载带内一律不扣"的写法：它会把算法在空载/轻载时关掉，且让低于近期参考电平 10% 的
  > 真实轻载也完全不补偿，故未采用。
- **输出封顶保证不为负**：写回前 $\text{creep}_i\le\max(Z_i,0)$。这条只作用于输出——
  负的扣除量若直接写回，会被显示层阈值钳成**硬 0**（默认阈值 0），表现为"零点塌陷进 0"；
  封顶后显示停在 0 而不是负值，内部状态（$g/\gamma/A/\text{carry}$）不受影响。
- **代价**：零漂（空载基线漂移）**不做补偿**——空载读数就是传感器当前读数。
  若现场需要"空载必须显示 0"，应在采集/标定侧做零点标定，而不是由本显示层算法强制归零。

**影响范围**：只影响显示值；业务 canonical 帧、录制 raw ADC、标定与 NG 判定均不受影响。

### 13.2 其他限制

1. **低于 5% 电平的变载仍会被当成蠕变**（仅用发散判据时的有效门限约 27%，本算法降到 5%）。
   若现场需要更小的加载被看见，继续下调 `kLevRel` 需同时接受快速蠕变/操作抖动引发的 epoch 重启；
2. **免责期内读数高出真值约快相增量（16~33%）**：这是设计选择（不把确定性快相当蠕变扣），
   该增量平滑、单调、形状可复现（σ≈0.016），是**可出厂标定的确定性量**；
   若要消掉它，可把归一化快相曲线做成前馈项（11 点 ROM 即可，误差 <3%），属后续增强；
3. **载荷变化非常频繁时补偿跟不上**：若载荷每 ~10 s 变一次，epoch 会被反复重启，
   蠕变模型（τ=3 s）来不及收敛，该段显示基本跟随原始。
   这是"跟得上载荷"与"压得住蠕变"之间的固有取舍，本算法选择前者
   （把真实载荷吃掉比跟得不够更不可接受）；
4. **多通道 $\gamma$ 在频繁变载下不易收敛**：epoch 重启会保留 $\gamma$ 的积分，
   但在"每 10 s 一次变载"的录制里 $\gamma$ 仍可能长时间停在 1.00；
5. **短保压（<5 s）工况未验证**：首次加载后若在免责期内卸载，本次免责期作废
   （下次 onset 会重新起免责期，不影响后续）；
6. **参数标定范围**：由 4 份实采录制（ADC 域）+ 恒载 9 组标定；
   **尚未在力值域、跨载荷量级（5 N / 10 N / 20 N）与跨温度**上验证——若快相形状随载荷量级变化，
   需要重新标定免责期长度与幅度窗；
7. **零漂（空载基线漂移）不补偿**：这是"空载不归零"的直接后果；
   空载读数原样显示，若现场需要"空载必须显示 0"，应在**采集/标定侧**做零点标定，
   而不是由本显示层算法强制归零。注意菜单项名称仍沿用「时漂/零漂补偿（无责 3s）/（无责 5s）」，
   名字里的"零漂"已名不副实（是否改名待裁决）；
8. **卸载瞬间约 0.7 s 的显示为 0**：松手后读数瞬时塌到空载，而状态机判定卸载
   需要 $u>3$ s 且 `idle`（`idle` 基于 τ=0.3 s 平滑电平）⇒ 这 ~0.7 s 内旧扣除仍按原样参与计算，
   经输出封顶后显示为 0（而不是负值），判定卸载后立即回到空载读数。
   若要缩短到 1~2 帧，可让"电平判据在下降沿命中且新电平已落进空载带"直接走卸载分支
   （会改动已验证的变载路径，需要单独回归）；
9. **未做真机 / 界面手测**（按项目规范交用户执行）。

## 附录 B：术语

| 术语 | 含义 |
|---|---|
| 真实加载沿 | 物理上加压/卸载的那一刻（不是算法认账的时刻）；本文所有时延都以它为原点 |
| 快相 | 加载瞬间 0~4 s 的确定性快速爬升（机械加载 + 接触建立），占总增量 16~33% |
| 慢相 | 4 s 之后的黏弹性蠕变，占总增量 67~84% |
| 检测窗 | 真实加载沿 → 阶跃判据命中（`pending=true`）的 0~0.5 s，长度由判据窗口与台阶比决定 |
| 确认窗 | `pending` 起连续保持 `kStepPersistS` = 2.5 s 才认账；与免责期长度无关 |
| **pending 冻结** | 确认窗内（**仅负载内**）不积分 $g/\gamma$、扣除量冻结在 `hold_comp_`，防止过期模型把真实台阶当蠕变扣掉 |
| **免责期** | **epoch 起点**后不做蠕变补偿的时间窗（默认 3 s，可切 5 s）；期内状态机照常运行，输出 $Z-\text{carry}$ |
| **首扣** | 免责期结束当帧开始按新幅度扣：**真实加载沿 + 2.5 s + 免责期** = 5.5 s（3 s 档） |
| 扣到位 | 扣除量达到"当前应扣量"的 95%，即首扣 + 3τ = 首扣 + 9 s |
| epoch | 一个负载段：从 onset（或负载内变载）到下一次迁移；幅度 $A$、蠕变场 $g$ 都以 epoch 为界重建 |
| 幅度参考 $A_i$ | 本 epoch「触面已建立」的逐通道电平，作为蠕变比例基准 |
| 蠕变场共识 $g$ | 受载通道归一化残差的 median，代表"全体一致的那部分慢相增量" |
| 逐通道增益 $\gamma_i$ | 器件间蠕变差异的在线修正（过原点增量最小二乘） |
| carry | epoch 起点已生效的逐通道扣除，用于免责期内保持显示连续 |
| 空载不归零 | 非负载段的输出等于输入（不估基线、不减基线、不扣蠕变），零点保持传感器当前读数 |
| 输出封顶 | 写回前 $\text{creep}_i\le\max(Z_i,0)$，只改输出、不改内部状态，保证显示不为负 |
| 台阶捕获比 | 事件后 6 s 内显示增量 ÷ 原始增量，衡量真实加载被透传的比例 |
