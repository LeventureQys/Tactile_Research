# TactileSense 抗蠕变漂移补偿 · v4 算法说明（快相免责期版）

> 版本：v4（在现役 v3 基础上增量改造）
> 日期：2026-09-17
> 范围：**显示层**时漂/零漂补偿算法（`src/domain/drift/`）
> 参考实现：`../scripts/glm53_v3.py`（v3 基线）+ `../scripts/r_fastphase.py::GLM53v4`（原型）
> 验证数据与结论：`03-验证与实测结果.md`；代码骨架：`04-C++实现骨架.md`

---

## 1. 一句话说明

**v4 = v3 + 「快相免责期」**：器件在加载瞬间有一段确定性的快速爬升（机械加载 + 接触建立），
它不是蠕变；v4 在这段时间内**不补偿**（让读数原样通过），等快相结束后再对**后续的缓慢蠕变**建模型并扣除。

其余部分与现役 v3 **逐字相同**（卸载门控自动归零、双 EMA 阶跃检测、restep 原子迁移、median 蠕变共识、
逐通道增益 γ、各类限幅）。

---

## 2. 为什么需要这一层（物理依据）

对 9 组恒载实测数据（右拇指指尖 / 左拇指指尖 / 四指指尖各 3 组）做主通道平滑曲线的分段斜率统计，
加载后的响应明显分为三段：

| 区间 | 平均斜率（右拇指/数据1） | 性质 | 占总增量 |
|---|:--:|---|:--:|
| 0 – 1 s | 0.478 → 0.199 /s | 机械加载 + 弹性建立 | — |
| 1 – 4 s | 0.013 /s | 接触建立（快相尾巴） | **16 – 33%**（到 4 s） |
| 4 s – 120 s | 0.0043 /s | 黏弹性蠕变（慢相） | 67 – 84% |

两条关键实验事实：

1. **快相形状高度可复现**：把 9 组曲线按「onset+5 s 处的增量」归一化后逐点比较，
   标准差最大 **0.026**、均值 **0.016**；且三种指尖位置（幅度 1.27 / 1.39 / 1.74，差 37%）
   的归一化曲线几乎重合 ⇒ 快相是**确定性响应**，本质上是可标定量，不是需要在线学习的随机过程。
2. **快相与慢相在频域上不可分、但在时间上可分**：任何在线辨识算法在 0–4 s 内
   都无法把「机械加载」与「材料快相蠕变」分开；而 4 s 之后信号变得单调光滑，
   慢相建模的难度下降一个数量级。

因此把快相划为「免责区」，等于**把两个时间尺度混叠的辨识问题，降级为一个单尺度平滑跟踪问题**。

## 3. 算法定义

### 3.1 状态量与参数（增量部分）

| 名称 | 类型 | 默认值 | 含义 |
|---|---|:--:|---|
| `kFastPhaseS` | 常量 | **5.0 s** | 快相免责期长度（首次 onset 后） |
| `kExemptAWinS` | 常量 | **1.5 s** | 幅度采集窗长度，紧贴免责期**末端** |
| `fast_done_` | bool | false | 本次负载段的免责期是否已结束 |
| `exempt_acc_` | VectorXd | 0 | 免责期末段滑窗内的 ΣZ 累加器 |
| `exempt_frames_` | int | 0 | 上述累加器的帧数 |

派生量：幅度采集窗 = `[kFastPhaseS − kExemptAWinS, kFastPhaseS]` = **[3.5 s, 5.0 s]**。

> **为什么不沿用 v3 的 A 窗（名义 onset+1~3 s）**：该窗口整段落在免责期内，会被冻结逻辑跳过，
> 导致 `A_` 永远捕获不到 → `loaded_` 全 0 → **补偿恒为 0，算法悄悄退化成直通**。
> 这是原型阶段踩过的真实坑（见 `../五算法实测对比.md`、`../快相与慢相分离分析.md` §4.7），
> 因此 v4 的 A 窗必须**显式绑定到免责期末端**，并在验收清单里加自检项（§6）。

### 3.2 逐帧流程（只列出与 v3 不同的分支）

```text
Process(ts, v):
  ── 先跑 v3 原样逻辑 ────────────────────────────────────────
  （总量/三级 EMA 平滑、双阈值阶跃检测、卸载判定、基线 b 跟踪、
    以及 in_load_ 状态迁移 —— 全部与 v3 相同）

  ── v4 新增：首次 onset 的快相免责期 ──────────────────────
  if in_load_ and (not fast_done_):

      u = ts − onset_ts_

      if u < kFastPhaseS:                    # ── 免责期内 ──
          # 冻结蠕变状态：不积分 g/γ，不累积蠕变，不用 v3 的 A 窗
          a_captured_ = false
          A_.setZero(); a_acc_.setZero(); a_frames_ = 0
          g_ = 0; g2_acc_ = 0; g_rel_acc_.setZero(); gamma_.setOnes()

          # 只在紧贴免责期末端的窗口里记录幅度
          if u >= kFastPhaseS − kExemptAWinS:
              exempt_acc_ += (v − b_);  ++exempt_frames_

          v = v − b_                          # 直通：只扣零漂基线，不做蠕变扣除
          return v

      else:                                   # ── 免责期结束当帧 ──
          A_ = (exempt_frames_ > 0) ? (exempt_acc_ / exempt_frames_) : (v − b_)
          a_max = A_.maxCoeff()
          loaded_[i] = (a_max > 1e−9) ? (A_(i) > kLoadedFrac·a_max) : 0
          a_captured_ = true
          g_ = 0; g2_acc_ = 0; g_rel_acc_.setZero(); gamma_.setOnes()
          exempt_acc_.setZero(); exempt_frames_ = 0
          fast_done_ = true
          # 不 return：当帧继续走 v3 的蠕变补偿逻辑

  ── 之后完全等同 v3 ────────────────────────────────────────
```

关键点：

- **免责期内不跑 v3 的 A 窗**：显式把 `A_/a_acc_/a_frames_` 清零，避免残留；
- **免责期内 `in_load_` 与事件检测照常运行**：这样免责期结束时无需任何状态迁移，
  算法已经处在正确的负载态（卸载/变载判定不会因为免责期而失灵）；
- **`g/γ` 在免责期结束时清零**：蠕变的「epoch」从快相末开始计，
  相对残差 `rel = (Z − A)/A` 的参考点就是快相末的读数，因此慢相形状估计不被快相污染；
- **免责期只在首次 onset 生效**（`fast_done_` 一旦置真不再复位，直到下一次 `BeginLoad`）。
  但 `BeginLoad` 在 v3 里也会被 **restep（负载内变载）** 调用 —— 见 §3.3。

### 3.3 与负载内变载（restep）的关系 —— 重要

v3 的 `_begin()`/`BeginLoad()` 会在两个场合被调用：

| 场合 | v3 语义 | v4 是否起免责期 |
|---|---|---|
| 空载 → 负载（首次 onset） | 进入负载段 | **是**（`fast_done_=false`） |
| 负载 → 负载（中途变载，restep） | 原子迁移、重捕获 A | **也是**（因为同样经 `BeginLoad`） |

实测表明这样做是**正确且必要的**：中途变载同样伴随一次快相（接触面积/机械柔度台阶），
而 v3 在检测滞后期会用**变载前的旧幅度**继续扣，造成显示在变载后 2~4 s 内明显欠报。
v4 在变载后冻结补偿，使显示严格跟随原始，随后重建补偿 ——
整阵口径的**最坏欠报在 8/8 个变载事件上都不大于 v3**，均值 9.6% → 5.9%。

> 曾尝试「免责期**只**在首次 onset 生效、变载完全不冻结」的变体（记为 v7），
> 结果其输出与 v3 **逐帧完全相同**（没有任何收益），因此**不采用该限制**。

### 3.4 前置条件与安全语义

1. **首次加载需保持 ≥5 s**：若在免责期内就把负载卸掉，算法会退回空载态，
   本次免责期作废（不影响后续，因为下次 onset 会重新起免责期）。
2. **冷启动/带载使能**：沿用 v3 —— `b=0` 时不补偿，直通，绝不塌显示。
3. **免责期不做任何蠕变扣除**，因此不会出现「把真实力当蠕变扣掉」的情形；
   代价是免责期内读数**高出真值约快相增量（16~33%）**，见 §5。

## 4. 与 v3 的差异汇总

| # | 项目 | v3（现役） | v4 |
|---|---|---|---|
| 1 | 加载后 0~5 s | 从 onset 起就进入蠕变逻辑；A 窗名义 1~3 s | **冻结补偿**，显示直通（仅扣零漂基线） |
| 2 | 幅度参考 A 的采集 | 名义 onset+1~3 s（实测被 pending/抑制状态机推迟到约 onset+6 s） | **显式绑定 [3.5, 5.0] s** |
| 3 | 蠕变 epoch 起点 | onset | **快相末（5 s）** |
| 4 | 其余全部 | — | 与 v3 逐字相同 |
| 5 | 免责期适用范围 | — | 首次 onset **与**负载内变载都生效 |

## 5. 性质、代价与已知限制

### 5.1 免责期内的读数偏高（已知代价）

免责期内不扣蠕变，因此读数 ≈ 真实力 + 快相增量。实测该增量占总增量的 **16~33%**
（右拇指最大、左拇指最小）。它的性质是：

- **平滑、单调、无跳变**（不是错误振荡）；
- **形状可复现**（σ≈0.016，见 §2），因此是**可出厂标定的确定性量**；
- 若后续把 §2 那条归一化快相曲线做成 11 点 ROM 前馈项，可把这部分偏移也扣掉
  （属于 v5 级别的增强，不在 v4 范围内）。

### 5.2 免责期长度的取舍（3 s vs 5 s）

| 指标（恒载 9 组均值） | 免责 3 s | 免责 5 s |
|---|:--:|:--:|
| 时漂残余（全负载段） | **1.85%** | 2.60% |
| 时漂残余（慢相段，onset+5 s 起） | 1.74% | **0.95%** |
| 噪声比 | **0.73** | 0.79 |
| 平坦度 | **1.94%** | 2.10% |

- 免责期越长，放过去的快相增量越多 ⇒「全负载段」口径越差；
- 免责期越长，慢相蠕变模型的参考点越干净 ⇒「慢相段」口径越好；
- 两者噪声/平坦度差异很小 ⇒ **免责期长度几乎不引入额外噪声**，它主要决定
  「快相增量算不算进指标」。

**默认取 5 s**（与观测到的「4~5 s 快相基本结束」一致）。
若产品验收沿用现役的「负载段末/首之差」口径，可改 3 s 以获得更好看的全段数字。

### 5.3 已知限制

1. **快相增量未补偿**（§5.1），需要前馈表或接受该偏移；
2. **免责期内的变载**：若负载在 0~5 s 内再次变化，该变化原样透传（不被抹平），
   但补偿要等免责期结束才重建；
3. **A 的可靠性依赖第 2~3 点前置条件**，故 v4 必须带 §6 的自检断言；
4. 参数（5 s / 1.5 s）由右拇指、左拇指、四指三处指尖数据标定，**尚未在跨载荷量级
   （如 5N / 10N / 20N）的数据上验证**；若快相形状随载荷变化，需重新标定窗口长度。

## 6. 验收指标与自检项

**必须新增的指标**（现有「负载段末/首之差」口径区分不出本改造的收益）：

| 指标 | 定义 | v3 | v4（5 s） | 目标 |
|---|---|:--:|:--:|:--:|
| `时漂残余_慢相段` | onset+5 s 起，末 10% 均值 − 首 10% 均值，/ 幅度 | 1.49% | **0.95%** | < 1.1% |
| `非线性残差` | 慢相段「显示−原始」残差**去线性后**的 RMS / 幅度 | 1.29% | **1.17%** | < 1.2% |
| `变载最坏欠报` | 变载窗内 `max\|显示−原始\|` / 本次跳变 | 9.6% | **5.9%** | < 7% |
| `事件跳变超额` | 负载段内（不含卸载沿）单帧 `\|Δ显示−Δ原始\|` 最大值 | 0.03 | 0.03 | 不劣于 v3 |

**必须加的自检断言**（防止「静默退化为直通」）：

1. 免责期结束后 `A_` 非零；
2. `loaded_` 中为真的通道数 > 0；
3. `g_` 随慢相单调增长（非恒 0）。

> 这三项是原型阶段的真实教训：早期版本的 A 窗被免责期整段跳过，
> 导致 `A_=0 → loaded_ 全 0 → 补偿恒为 0`。其症状极具欺骗性 ——
> 变化负载上「增益恰好 1.000」、恒载上「时漂与原始完全相同」，
> 看起来像「没有副作用」，实际是算法没在工作。
