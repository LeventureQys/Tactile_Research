## 1. 任务目标

用户最终要的是判断：**v6 面对"1~2 s 内基线稳定且读数不漂"这个目的，到底怎么样。**
所以 T8 必须给出**不是"优缺点罗列"，而是可执行的裁决**：

1. **评估矩阵**：每条路线的每个维度都有数字（不是"较好/较差"）；
2. **可替代性判定**：v6 能在**哪类工况**上替代现役 v5.1，哪类不能，判据是什么；
3. **乐观性折扣**：把 T3 的泛化折扣、T5/T6 的抖动与失败率**折算进**指标
   （既有 v6 数字存在"用测试集自身标定形状库"的乐观上界，必须在矩阵里打折呈现）；
4. **开发方案建议**：给出 2~3 个可选方案（如"v6+滤波+gated 保底"、"v5.1 为默认 + v6 仅 onset 生效"、
   "第三条路"），每个方案给**预期指标 + 代价 + 风险 + 工作量**，供用户决策。

**T8 不做新实验为主**（除为对齐口径的必要重算），它的价值在**综合、折扣与裁决**。

## 3. 复核位（T8-2）的独立任务

> **T8-2 不得先读 T8-1 的 `分析报告.md`。** 流程：

1. 只读 T1~T7 的 `results/*.csv` 与 `00_共享/指标字典与口径.md`；
2. 独立重算以下**关键指标**（至少这 6 个）：
   - v6 与 v5.1 在恒载 9 组上的 `T_stable` 中位；
   - 变载实录上的最大偏差（ADC）；
   - epoch 数比（v6 / v5.1）；
   - 过充 `OS%` 的 p90（v6 与 v6.1）；
   - 强扰动下的基线失败率；
   - 卸载后残余偏移（%）；
3. 再读 T8-1 的报告，**逐条比对**；
4. 输出 `results/t8_audit.csv`（列：`metric, t8_1_value, t8_2_value, rel_diff, verdict`）与
   `results/t8_audit.md`（分歧说明）；
5. **任何相对差 ≥5% 的指标都必须报告**，并给出你认为哪个对、为什么；
6. 若发现 T1~T7 某份产物**本身有错**（口径不一致、算错、结论与数据不符），
   一并报告并在 `t8_audit.md` 中列出（**这是本次调研的内部质检，非常重要**）。

## 4. 方法与实现要求

1. **每个数字必须带出处三元组**：`source_task / source_file / column`。矩阵里不许有孤立数字。
2. **不许重新定义指标**；若必须换算（如 ADC ↔ %），写清算式与所用电平。
3. **版本口径要统一**：v5.1 是现役，是**默认对照基准**；v3 只在历史对照时出现。
4. **工作量估计要落到本项目**：`src/domain/drift/`（v5.1）与 `src/domain/drift_v6/`（v6）两个模块
   是落点，建议要说明改哪里（只读代码，不改）。**若需要读 C++ 代码，只读不改。**
5. **图**：至少 3 张——① `T8_01_matrix_radar.png`（多维雷达或热力图）；
   ② `T8_02_verdict.png`（可替代性裁决可视化）；③ `T8_03_discount.png`（乐观 vs 悲观）。
6. **可读性**：用户会先看 §1 结论速览，**前三条必须是**：
   ① v6 面对目标的总体判定；② 能用/不能用的工况边界；③ 推荐的开发方案。

## 6. 已知陷阱

1. **把 T1~T7 的报告摘要拼起来当成综合** → 那不是综合，是复述。综合的价值在于**折扣、权衡与裁决**。
2. **忽视 T3 的乐观性折扣** → 会系统性高估 v6 能力，这是本次调研最容易犯的错。
3. **只用中位数** → 用户要的"不能超上限"是**最差情况**判据，必须给 p90/max。
4. **把"1~2 s"当成单一目标** → restep 上物理不可达（输入本身没走完），必须分工况承诺。
5. **复核位被同化**：T8-2 若先读 T8-1 报告就会失去独立价值。**先独立重算，再比对**。
6. **工作量估计空泛**（"需要一定工作量"）→ 必须落到模块与大致规模。
