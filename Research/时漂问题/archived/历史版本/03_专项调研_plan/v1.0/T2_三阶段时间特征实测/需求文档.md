# T2 需求文档 —— 三阶段（阶跃 / 快相爬升 / 慢相爬升）时间特征实测表征

| 项 | 值 |
|---|---|
| 任务 ID | **T2** |
| 回答用户诉求 | ②「数据大概是三个阶段构成的：阶跃-快相爬升-慢相爬升，这三个阶段的时间特征我大概需要你总结明确一下」 |
| 依赖 | T1（事件表 `t1_events.csv` 与口径）。**若 T1 未就绪**：自己按 `00_共享/指标字典与口径.md` §2 建事件表，但交付后必须回对 T1 的事件表并报告差异 |
| 席位 | **1 个 SubAgent** |
| 模型 | deepseek / deepseek-v4-flash |
| 预期耗时 | 30~50 min |

---

## 1. 任务目标

把「三阶段」从一句定性描述，变成**每个事件的、带分位数的、可复现的**时间表：
每一阶段**从哪里开始、到哪里结束、持续多久、形状参数是多少**，
并给出**在多少置信度下可以这么说**（n 小就如实说 n 小）。

同时必须正面回答一个会**推翻用户前提**的问题：**"阶跃"是不是一个真实的物理阶段？**
（既有实测显示 onset 在 0.05 s 内就走完 5 s 增量的 74%，"阶跃"可能只占 1~2 帧，
那么"三阶段"在 onset 上其实是"两阶段"，而在 restep 上"阶跃"几乎不存在、只有斜坡。）
这个判定直接决定 T3/T4 的做法，所以 T2 **必须给出明确结论，不许含糊**。

## 3. 方法与实现要求

1. **形状用原始读数**（最多 3 帧中值），**禁止 τ=2 s 平滑**（07-v6 §2.1 的血泪教训）。
   若必须平滑，`k ≤ 0.5 s` 并在报告中声明，且同时给不平滑版本。
2. **基线扣除**：定义 `ΔZ(τ) = Z(t_on+τ) − Z(t_on)`，归一化 `f(τ) = ΔZ(τ)/J`；
   `J` 按 `00_共享/指标字典与口径.md` §2.1 的 `post` 窗（`t0+4~t0+6`）取，**便于与既有数字对齐**。
3. **τ 网格固定**：`[0.02,0.05,0.10,0.15,0.20,0.30,0.50,0.75,1.0,1.5,2.0,3.0,5.0,8.0,15.0,30.0]` s，
   落 `results/t2_shape_profile.csv`（列：`ds, kind, event_t, tau, f_median, f_p10, f_p90, n`），**全项目复用**。
4. **慢相拟合**：至少比三种模型（线性、对数 `a·ln(1+t/b)`、幂律 `a·t^b`），
   用**留一/跨录制**评估泛化，不要只在自身数据上报 `R²`（会骗自己）。
5. **必须做的两项反驳性检查**：
   - 把 `f(1 s)` 与既有 `07-v6` 的 **0.912** 对照：若你算出别的数，解释差异来源（平滑？基线窗？事件集？）；
   - 把 `t90` 与既有 `v6_rise_times.csv` 逐行对照（既有的 24 行是现成的，直接 merge 比对）。
6. **补采建议**：若发现阶跃段判据不足，明确写"需要什么数据才能定论"（如更高采样率、力传感器参考）。

## 5. 已知陷阱

1. **把 `t95` 当快相终点** → onset 的 `t95` 已被慢相污染（1.62 s vs `t90` 0.48 s），会把慢相当快相。
2. **只做 onset** → 13 份恒载录制里 restep 才是多数事件（n≈15 vs 9），漏掉就覆盖不了真实使用场景。
3. **用合成模型代替实测形状** → 本项目全部结论要能回溯到实机数据，合成只能做机制对照。
4. **跨域合并**：`processed_display` 与 ADC 的 `J` 量纲不同，**绝对量不可合并**，只能合并无量纲的 `f(τ)` 与时间。
5. **忽略包结构**：13 份录制时间戳都按包重复，`f(0.05)` 的组间极差 0.367 **全是量化伪影**（07-v6 §2.1 口径提醒）。
