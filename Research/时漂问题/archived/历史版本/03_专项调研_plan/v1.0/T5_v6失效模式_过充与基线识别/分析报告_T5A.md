## ① 结论速览

1. **用户现象复现成功，而且"向上过充"与"向下过冲"是两个不同的内部动作**。
   在 T4-A 的 41 个加载事件上（v6，κ = 1.30/1.12）：**onset** 的 5 s 窗瞬态过充中位
   **+4.08 %·J**（p10~p90 = −10.59 ~ +10.34，max **+12.85 %**），其中中位**向上冲高 147.5 ADC**、
   最坏 **4034.8 ADC**；而 **restep** 反过来是向下欠冲中位 **−18.59 %·J**
   （p10~p90 = −72.72 ~ +0.02），中位**下冲 2865.2 ADC**。
   ⇒ 「向上过充」= onset 的形状反演高估；「向下过冲」= 复合事件（卸载→再加压）里
   **继承的旧扣除量没被清掉**（§3.2 有逐帧证据）。**两者不是同一个动作。**
   （`results/t5a_overcharge_summary.csv` 的 `onset`/`restep` 行，列 `OS5_med / OS_med_adc / US_med_adc`）

2. **向上过充的根因已逐帧锁死，是「形状反演高估 → 滑行器把显示钉在高位 → 停滞检测一步拉回」**。
   以 `切换负载-快相无责 @185.98 s` 为例：τ = 0.20 s 时 `Â = 27 943` 而真实台阶 `J = 25 195`
   ⇒ **高估 +10.91 %**；滑行器在 **τ = 0.80 s** 就把显示钉到 `27 997`（比原始高 **+3 731 ADC**）；
   **τ = 2.32 s** 停滞判据成立、`Â` 被一步改写为实测增量 `24 759`，显示在 **0.28 s 内掉回原始**
   ⇒ 这一冲一落就是用户看到的"过充"。**同一条链在 22 个 onset 上普遍存在**：
   `Â/|J| − 1` 中位 **+3.04 %**、p90 **+6.62 %**、max **+11.33 %**，**7/22 个 onset 超过 +5 %**。
   （`results/t5a_internal_trace.csv`、`t5a_attribution.csv: H1_ahat_over_J_pct`、图 `T5A_01`）

3. **`τ_ho = 5 s` 交接本身不是原因（这一条被证伪）**。交接帧的 `|ΔΣY|` 中位只有 **2.1 ADC**
   （onset）/ **135.4 ADC**（restep），交接前后显示连续；`g` 在交接后 5 s 内的斜率中位
   **0.0024 /s**，没有"提前起扣"的跳变。
   ⇒ **归因链里可以划掉"交接跳变"与"慢相提前起扣"**，只留"形状反演高估 + 停滞回撤"。
   （`results/t5a_attribution.csv: H3_handoff_jump_abs / H4_g_slope_per_s`）

4. **v6.1 的 `ROM_SCALE=1.06` 把过充压掉了约一半，但没有清零；用户看到的更可能是 v6**。
   同一批事件：5 s 窗瞬态过充中位 **+0.02 % → −2.51 %**、最大 **+120.81 % → +74.83 %**、
   OS > 5 % 的事件数 **12 → 7**；`T_stable`(30 s 窗) 中位 **3.66 s → 0.52 s**；
   但 1 s 时刻绝对误差反而 **31.30 % → 35.90 %**（欠报代价）、`G` 中位 0.942 → 0.920。
   （`results/t5a_v6_vs_v61_summary.csv`；图 `T5A_06`）

5. **滤波只能救"约三成"，而且救的是另一件事（抖动/走廊），不是那 10 % 的系统性过冲**。
   **显示层**因果滤波的 Pareto 前沿只有 **5 档因果**（另有 2 档非因果也在前沿上），最优的两档是
   **EMA τ = 0.1 s**（过充中位 11.65 %→8.54 %、`T_stable`(5 s 窗) 3.66→0.67 s、`err1` 34.1 %→10.8 %）
   与 **因果中值 w = 0.1 s**（过充 11.53 %、`T_stable` 0.58 s、`err1` 7.5 %，但 `G_min` 从 −0.14 掉到 **−4.99**）。
   τ ≥ 1 s 之后是"时间换幅度"：过充能到 5.6 %，但 `T_stable` 涨到 **10.7 s**、`err1` 涨到 **74.8 %**
   —— 直接击穿 1~2 s 预算。**内部状态层（进补偿器之前）滤波全部更差**（`G` 掉到 0.44~0.86、
   `T_stable` 出现 NaN、过冲中位变负），**不可用**。
   （`results/t5a_filter_pareto.csv`、`t5a_filter_cost.csv`；图 `T5A_02`/`T5A_05`）

6. **非滤波手段里最有效的是"过充硬限幅 + 交接时刻 3.5 s"，代价最小的是硬限幅**。
   `显示 ≤ 原始 + 0.02·|原始|`（clip 0.02，一行代码）把**最大偏差中位 2396.7 → 555.4 ADC（−77 %）**、
   `T_med` 3.66→2.39 s，且**过冲中位不变（11.22 %）**、`G` 反而略升（0.942→0.952）；
   `HO_MIN` 5.0→3.5 s 把 `T_stable`(5 s 窗) 中位 **3.66 → 1.96 s**、`err1` 34.1→31.3 %、`G` 0.942→0.933。
   滑行器速率上限（0.4 / 0.6 / 1.2）与反向撤销窗（0.20 / 0.30 / 0.60）**基本无效**（见 §3.6）。
   （`results/t5a_nonfilter_options.csv`）

7. **【C-4】裁决：κ 是"单侧上限"，它的收益完全取决于上限是否被触发；推荐 κ_onset = 1.05 / κ_restep = 1.12。**
   原型里 κ 只在 `_inv_est` 结尾一处生效：`Â = min(A_raw, κ·inc)` ⇒ **只有 `A_raw > κ·inc` 时 κ 才起作用**。
   实测触发诊断（onset n = 22，探针补丁，补丁零差 V6/V7/V8 已证）：**`r=A_raw/inc` 的逐事件最大值
   落在 1.207~2.925（中位 1.2466）**，于是**截断时长占比**为 —— κ=1.30 **0.0 %**、1.20 0.4 %、
   1.15 1.9 %、**1.10 61.5 %**、**1.05 86.7 %**；`Â/J−1` 中位在 κ ≥ 1.15 时**一个数字都不变**（+3.514 %）。
   在**触发区间内**第一轮"同向改善"复现：κ 1.30 → **1.05** 时过充中位 **+0.02 % → −4.23 %**、
   过充 max **120.81 % → 65.21 %**、`T_stable`(5 s 窗) 中位 **3.660 → 0.790 s**（p90 **23.440 → 1.354 s**，
   **只有 1.05 的 p90 落在 1~2 s 带内**）、1 s 误差 **−21.69 % → −26.18 %**、
   MD 中位 **2396.7 → 1306.2 ADC（−45 %）**；代价是 `G` 0.952 → 0.918。
   **T4-B 的零差因此被逐字解释**：它的两臂 κ_onset **都是 1.30**（截断 0.0 %，`Â` 完全不动），
   而它变的 κ_restep 实测**不改变 OS / `T_stable` / `err1`**（39/39 逐事件相同，`dOS_absmax ≤ 0.055 pt`）
   ⇒ **"κ 无收益"只在"上限未触发"的区间成立，不能外推**。
   留一 13 折：最坏折 OS5 max **120.81 % → 65.21 %**、最坏折 `T_stable`(10 s) **78.500 → 1.960 s（40 倍）**。
   详细裁决见 §③.7b；图 `T5A_03`/`T5A_03c`/`T5A_03d`/`T5A_03b`。
   （`results/t5a_kappa_sweep.csv`、`t5a_kappa_four_metrics.csv`、`t5a_kappa_cap_summary.csv`、
   `t5a_kappa_trigger.csv`、`t5a_ahat_bias_by_kappa.csv`、`t5a_kappa_loo.csv`）

### 2.2 事件指标的四套口径（**本任务最重要的口径说明**）

任务书写死的过充定义是 `OS% = max_t(Z(t) − Z_final)/J`，`t ∈ [t_on, t_on+30 s]`，
`Z_final` = `t_on+60 s` 后中位。**这条字面规则在本批数据上不适用**，理由是实测的：

> 恒载 9 组的 onset 落在 8~15 s，而**卸载落在 115~147 s** ⇒ `t_on+60 s` 之后整段是空载，
> `Z_final ≈ 0`，于是 `OS% = (显示 − 0)/J ≈ +100 %`。实测伪影：`RT1@8.27 s OS% = +100.8`、
> `F41@10.94 s OS% = +101.1`（`results/t5a_overcharge_events.csv` 的 `v6_now__OS_pct_task_literal` 列）。

按《指标字典与口径》开头的授权（"定义 X 不适用 → 写明理由并改用 Y"），本任务改用 **`08-v6.1` 已有口径**，
并把四条口径**同时**落盘，互相对照：

| 代号 | 定义 | 量的是什么 | 用途 |
|---|---|---|---|
| **`OS_pct_5s`（主口径）** | `max_t(显示 − Zf)/J`，`t ∈ [t_on, t_on+5 s]`，`Zf` = 原始总量在 `[t_on+4.6, t_on+5.4] s` 的中位 | **阶跃瞬态过充** | 与 `08-v6.1/results/v61_overshoot.csv` 的 `over_peak` **可直接对表** |
| `OS_pct_30s` | 同 `Zf`，窗长 30 s | 瞬态 **+ 慢相平台偏差** | 《指标字典》§3 字面窗长；引用时必须说明它含慢相走廊 |
| `OS_pct_task_literal` | 任务书字面（`Z_final` = `t_on+60 s` 后中位） | 口径伪影 | 仅在恒载组暴露伪影，作反例保留 |
| `dev_pre_pct_min/max` | 显示相对**事件前电平**的有符号偏离 ÷ `|J|` | 卸载/部分卸载的过冲与欠冲 | `unload/partial_unload` 类专用（`Zf` 定义对它们不适用） |

**为什么 5 s 窗与 30 s 窗必须分开报**：30 s 窗里包含了慢相段，而慢相段的显示本来就贴着原始走
（扣除蠕变），于是 30 s 窗的"过充"里混进了**慢相走廊失配**这一与瞬态无关的成分。
对表实测：同一批事件 `08-v6.1` 的 `over_peak` 中位 **−1.32 %**、本任务 `OS5` 中位
**−0.71 %**（差 0.6 pt，**同口径**）；换成 `OS30` 中位 **11.22 %**（差 **12.5 pt**，
`results/t5a_crosscheck_v61.csv` 与 `_t5a_overcharge.log` 末段）。**引用 30 s 数字必须写明这一点。**
