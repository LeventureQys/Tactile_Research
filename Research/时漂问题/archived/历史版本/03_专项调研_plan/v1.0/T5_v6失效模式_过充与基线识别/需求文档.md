## 1. 任务目标

用户报了两个**体验级**失效现象。本任务要
① **复现**（在提供的数据上找到对应帧）、② **归因到状态机内部动作**（不是"可能是噪声"这种猜测）、
③ **评估可解性**（滤波/判据/迟滞能不能救，代价是多少），
④ 给出**"能救到什么程度"的量化承诺**（例如"过充从 p90=18% 压到 5%，代价是 onset 稳定时间 +0.3 s"）。

## 2. T5-A 分支：过充 / 下冲

> **⚠️ 派发前必读**：`00_共享/接口冲突登记.md`。**C-4（κ 参数收益的两种相反结论）是本分支的最高优先待办** ——
> 第一轮说 κ 消融"最划算"（过充 7.06%→3.33% 且 `T_stable` 1.72→0.43 s），T4-B 说"κ 项零收益"。
> T5-A **必须**产出 `results/t5a_kappa_sweep.csv`（同一批事件、同一指标口径、含留一法），
> 给出 κ 工作点推荐与该点上的四联指标（过充 / `T_stable` / 1 s 误差 / 最大偏差），并解释两处差异来源。
> 同时注意 **C-1（`T_stable` 用 T1-A 冻结口径）**。

### 子问题

| # | 子问题 | 期望输出 |
|---|---|---|
| T5A-Q1 | **复现**：在 13 份录制 + 变载实录里，找出所有"基线识别后对抗快相 ⇒ 超出预期向上过充/向下过冲"的帧段。给事件清单（时间、幅度、持续） | `t5a_overcharge_events.csv`（每事件：`ds, t_on, 峰值偏差 ADC 与 %J, 超调/欠冲、持续时长、是否回调`） |
| T5A-Q2 | **归因**：把 v6 状态机内部量逐帧落盘（`Â`、滑行器输出、`g`、`γ`、`A`、`b`、状态码、事件类型），指出过充发生在**哪个内部动作**上（形状反演高估？滑行器速率上限？`τ_ho=5 s` 交接跳变？慢相模块提前起扣？） | 归因链（**每条带帧号与数值**）+ 内部量轨迹图 |
| T5A-Q3 | **v6 vs v6.1 对照**：同样的事件在 v6 / v6.1 上的超调各是多少？v6.1 的 `ROM_SCALE=1.06` 消掉了多少？剩下多少？ | 对照表（**这是判断"用户看到的是哪一版"的关键**） |
| T5A-Q4 | **滤波能不能救**：设计滤波候选（因果中值/Savitzky-Golay/一阶 IIR/卡尔曼/限幅+速率限制），扫描其参数，在"过充抑制"与"onset 稳定时间、台阶保真（`G`）"之间做 **Pareto** | `t5a_filter_pareto.csv` + Pareto 图（**已有 `r4_filter_pareto.csv/png` 是起点，必须扩展而非重做**） |
| T5A-Q5 | 滤波的**代价**：滤波在显示层做还是内部状态做？显示层滤波会不会把台阶边沿也磨掉（用户会看到"变钝"）？给量化代价 | 代价表（含 `G` 台阶捕获比的变化） |
| T5A-Q6 | 若滤波救不了，**非滤波手段**有哪些（如滑行器速率上限下调、交接时刻 `τ_ho` 调整、过充硬限幅、反向事件快速撤销）？各自代价 | 手段表 + 推荐组合 |
| T5A-Q7 | **"向上/向下"两种过充是否同源**？分上行过充与下行过冲独立统计，看是否同一机制 | 分类结论 |

### 方法要求

- 必须用**仪表化运行**（`a_common.make_traced` / `run_traced`）记录 `epoch / revoke / handoff / unload / gevent`，
  否则无法归因到内部动作。复制到 `scripts/t5_a_common.py` 并改 import。
- **过充定义要写死**：`OS% = max_t(Z(t) − Z_final)/J`，`t ∈ [t_on, t_on+30 s]`；
  `Z_final` = `t_on+60 s` 后中位（不足 60 s 的录制用后 1/3 段中位，需声明）。
  与 `08-v6.1` 的 `v61_overshoot.csv` 口径对齐，**并列出两口径差异**。
- 滤波候选**必须因果**（离线可以用非因果，但报告要标"该滤波器需要未来样本，上线需 r 帧延迟"）。

## 3. T5-B 分支：强扰动下的基线识别

### 子问题

| # | 子问题 | 期望输出 |
|---|---|---|
| T5B-Q1 | **复现**：在 `1w ADC ± 1000 ADC` 量级的场景下，v6 的基线识别在多少比例下失败？"失败"要有明确定义（如：`Â` 偏离真实最终电平 > 20%，或事件未被建立，或基线被错误重捕获） | `t5b_baseline_failure.csv` + 失败率 |
| T5B-Q2 | **失效机制**：把逐帧内部状态落盘，说明为什么"人手拍在负载上 ⇒ 找不到基线"。候选机制：检测器被拍击误触发 → 建立错误 epoch → 撤销/重捕获链 → 慢相模块把拍击当蠕变扣 → 基线被清零 | 机制链（带帧号）+ 状态机轨迹图 |
| T5B-Q3 | **扰动扫描**：白噪声 / 带限噪声 / 同相共模 / 拍击（幅值 10~100% 电平、时长 20~500 ms）四类扰动，扫幅值-频率，找 **v6 失效边界**（失效概率 50% 的位置） | `t5b_detector_roc.csv` + 失效边界图（已有 `a2_jitter_sweep.csv`/`a2b_jitter_ext.py` 是起点） |
| T5B-Q4 | **判据改进的可解性**：现有判据（短滞后电平差 + σ 门限）为什么被拍击骗？能否用"输入扰动 vs 电平约束"双重判据（如：拍击不产生持续电平、拍击通道空间模式与加载不同）区分？给出候选判据 + 误报/漏报率 | 判据候选表 + ROC/PR 曲线 |
| T5B-Q5 | **误触发率 vs 检测延迟的权衡**：提高门限能减少误触发，但会让真实 onset 检测变慢。给"误触发率 ↓ 与 onset 检测延迟 ↑"的 **Pareto**，并指出对 1~2 s 目标最优的工作点 | `t5b_detector_pareto.csv`（**这条直接喂给 T8 的路线裁决**） |
| T5B-Q6 | **"找不到基线"的保底行为**：当置信度不足时，算法应该做什么（保持上一基线不更新 / 退回 v5 免责 / 冻结并要求重新标定）？给 2~3 个保底策略并评估其副作用 | 保底策略表 + 副作用量化 |

### 方法要求

- **真实拍击数据优先**：变载实录里找真实"人手拍/扰动"段落；不够就注入（用 `t1_common.py` 的 `add_tap`）。
  注入的结论必须标"注入"，不得混入"实测"。
- **失效阈值必须给置信区间或样本量**，不要只说"大概 20%"。
- **空间信息要用起来**：本项目数据有 21/31 通道，拍击与真实加载的**通道空间模式**可能不同
  （拍击局部、加载相对全局）。这是既有工作没充分利用的一条线索，值得单列一个小节。
- 若发现 `1w ADC ±1000 ADC` 这种场景在现有数据里**没有直接对应录制**，
  必须明确写"无该场景实测数据，结论来自注入实验，需补采如下规格：……"。

## 5. 已知陷阱

1. **把 v6.1 已修的尖峰当成新问题重复分析** → 先看 08-v6.1，再决定做什么。
2. **只看输出、不看内部状态** → 过充是状态机动作造成的，不落内部量就只能猜。
3. **用非因果滤波给出"能救"的结论** → 上线需要未来样本，等于引入延迟，必须计入代价。
4. **用合成扰动代替实拍** → 可以，但必须标注，并说明真实扰动的空间相关性与合成模型差多少。
5. **忽略 `t_on` 定位误差** → 过充幅度对 `t_on` 敏感（滑行起点），要给 ±1 包敏感性。
6. **把"拍击"和"真实加载"混在一个失效统计里** → 两者误触发代价完全不同，分开统计。
