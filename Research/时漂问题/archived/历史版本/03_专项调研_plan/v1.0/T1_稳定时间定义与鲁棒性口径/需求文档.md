# T1 需求文档 —— 稳定时间的定义、测量与鲁棒性要求

| 项 | 值 |
|---|---|
| 任务 ID | **T1** |
| 回答用户诉求 | ①「稳定时间要求 1s-2s 左右，不能超过这个上限」+「处理算法需要鲁棒性更高」 |
| 依赖 | 无（**本任务是全项目口径基准，Phase 0 首发，必须最先交付**） |
| 席位 | **2 个 SubAgent 并行**（A：定义与实测；B：鲁棒性扰动扫描），产物合并到同一目录，报告分两节 |

---

## 1. 任务目标

把用户嘴里那句"**稳定时间是 1~2 s 左右，不能超过这个上限**"变成**可测、可复现、可判达标**的定义，
并在现有 13 份实机录制上把「v5.1（现役）/ v6 / v6.1 三条实现」的稳定时间**测出来**，
同时回答：**要让这个指标在真实工况（噪声、拍击、抖动、突变）下不超标，鲁棒性缺口有多大。**

本任务的产出是**全项目的度量地基**：T2~T8 都用 T1 冻结的口径，所以本任务**必须最早完成、最严格复核**。

| T1-Q2 | 在 13 份录制上，v5.1 / v6 / v6.1 的 `T_stable` 分布是多少？ | 每事件一行 + 分族/分工况汇总（中位、p10~p90、最差） |

| T1-Q4 | `T_stable` 与 `T_settle(ε)`（ε=2%/5%）两个口径的差距多大？用哪个当验收指标更合适？ | 两口径对照表 + 推荐 |

### T1-B（鲁棒性）

| # | 子问题 | 期望输出 |
|---|---|---|
| T1-Q6 | 加白噪声（总量 RMS = 1/2/5/10/20 ADC... 直到 50）时，`T_stable` 与超调如何退化？ | 噪声-指标曲线（**Pareto 图**）+ 拐点位置 |

## 3. 方法与实现要求

1. **口径**：严格按 `00_共享/指标字典与口径.md` §3；`T_stable` 的定义若你认为需要修订，
   在报告 §2 给出修订版 + 理由 + 对既有数字可比性的影响，**并明确"本任务冻结如下"**。
2. **事件集**：不要只用现成的 `v6_rise_times.csv`（只有 24 个事件）。用 `detect_events` + 人工核对建立
   **统一事件表**，至少覆盖：恒载 9 组的 onset（≥9 个）、负载内 restep（≥15 个）、变载实录的
   onset/restep/unload（≥10 个）。**事件表落 `results/t1_events.csv`，全项目复用**（列名对齐 §2.3）。
3. **算法运行**：用 `a_common.run_traced` 的仪表化方式跑 v5.1 / v6 / v6.1，
   **禁止修改算法原型**；`glm53_v6.py`、`glm53_v61.py`、`glm53_v51.py` 复制到本任务 `scripts/` 并改 import。
4. **扰动注入**：把 `13-v6-assessment/scripts/a_common.py` 的 `make_perturb / add_tap / add_step`
   复制为 `scripts/t1_common.py` 并**补充**：丢包、时序抖动、包聚合（把 2~4 帧时间戳改成同值）。
   这份 `t1_common.py` 是**全项目共享的注入器**，接口要在报告里写清楚（T5 会直接用）。
5. **真实数据优先**：所有噪声/扰动实验都基于**真实轨线**注入，不要用合成阶跃模型产生主结论；
   合成模型只能用来做"机制解释"的对照。
6. **两条真实工况必须分开报**：`processed_display` 域（恒载 9 组）与 ADC 域（变载实录 4 份），
   **不要合并成一个大平均**。ADC 域的量化台阶（1 ADC ≈ 多少 N）若能查到就换算，查不到就声明未换算。
7. **图**：至少 3 张——① `T1_01_settle_dist.png`（三条实现的 `T_stable` 分布，箱线或 ECDF）；
   ② `T1_02_noise_pareto.png`（噪声 vs `T_stable`/超调）；③ `T1_03_jitter_sensitivity.png`。

## 5. 已知陷阱（务必避开）

1. **用 `elapsed` 当时间轴** → 量化重复 38~72%，所有时间指标全废；一律用 `timestamp`。
2. **先做 τ=2 s 平滑再看形状** → 会把 0.5 s 稳定的现象"平滑"成 3 s，重蹈 07-v6 §2.1 的伪影。
3. **把变载实录的成批突发当成物理现象** → 帧到达是成包的（~40 ms 一包），事件起点有 ±1 包不确定度。
4. **拿 onset 的结论套 restep** → 两者 t90 差 6 倍（0.48 s vs 2.87 s），是本项目最贵的错误。
5. **只报中位数** → 用户要的是"不能超上限"，最差情况（p90/max）才是判据。
6. **扰动只加白噪声** → 同相共模与带限噪声对"电平门限类判据"的破坏完全不同，必须三类都测。
