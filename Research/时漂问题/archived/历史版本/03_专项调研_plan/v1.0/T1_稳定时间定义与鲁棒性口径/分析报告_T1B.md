## 1. 结论速览

1. **T1-Q6（逐字档位）白噪总量 RMS 1~50 ADC 区间内 v6 完全无退化**：ADC 域 2 份实录、70 次/档，
   `T_stable` 中位恒为 **0.555~0.560 s**、达标率（≤2 s）恒为 **0.75**、`OS%` 中位 4.83~5.75、
   漏检恒为 **0.29 个/次**（与零噪声档完全相同，零噪声档 = 0.29）。原因：50 ADC 仅为实录电平
   （≈2.1 万 ADC）的 **0.24%**，远低于 v6 的 `5%·电平` 门限（≈1 000 ADC）。
   → 这一区间**测不出任何鲁棒性问题**，鲁棒性缺口全在更高幅度（见下条）。
   （`t1b_summary_noise_adc.csv`，`n=70/档`，10 个种子 × 2 录制 × 3~7 个 onset）

2. **拐点/失守点**：显示域（7 个 clean onset，87 事件×种子/档）白噪相对幅度
   `r = RMS/保压电平` 的**噪声-指标曲线**为：
   `r ≤ 1%`：`T_stable` 中位 **0.53~0.55 s**、达标率 **71~74%**（与无噪档逐项相同）；
   `r = 2%`：`T_stable` 中位反降到 **0.39 s**、达标率升到 **91%**（**假象，见结论 3**）；
   `r = 5%`：达标率 **79%**、`OS%` 最坏 **11.3%**、偏差中位 3.36 显示单位；
   `r = 10%`：**崩塌**——`T_stable` 中位 **16.18 s**、达标率 **2/31=6%**；
   `r = 20%`：`T_stable` **不可测**（0/70）、`OS%` 中位 9.5%/最坏 24.0%。
   → **拐点 `r* ≈ 5%`，崩塌点 `r ≈ 10%`**（`t1b_knee.csv`、`figures/T1B_01_noise_pareto.png`）。

3. **"更稳"是假象：噪声先毁准确度，再毁稳定度**（第一轮未做，本报告关键新发现）：
   `r = 2%` 时显示出现**持续静偏**——21 组 (事件,种子) 的 |偏置| 中位 **2.26 显示单位 = 12.8% 电平**；
   机制已逐帧溯源：噪声把 onset 的**回溯真沿 `t0` 推迟 0.12~0.39 s**（个别运行直接漏掉 onset，
   改由 ~12 s 后的伪 epoch 接管）⇒ 形状反演 **Â 偏低 11.1%（中位 −1.77）**、**ΣA 偏低 1.70**
   ⇒ pin 模式下显示稳态 ≡ Â，于是"读数停了，但停在错的地方"。
   同期 `T_stable` 反而更小、达标率更高。→ **验收不能只看 `T_stable`，必须与偏差/超调同时看**
   （`t1b_noise_bias_probe.csv`、`_t1b_04b_bias.log`）。

4. **T1-Q7 三类扰动对照：带限（0.3~40 Hz）最狠，同相共模"另一种坏法"**：
   ADC 域同幅度下（`n=70/档`）：`A=2000 ADC` 漏检 **带限 1.96** > 同相 1.46 ≈ 白噪 1.44，
   `A=4000` 的 `OS%` 中位 **同相 23.2% > 带限 20.3% > 白噪 15.1%**；
   显示域 `r=5%` 时 `OS%` 最坏 **带限 31.3%** vs 白噪 11.3%、同相 11.1%。
   同相共模的**漏检与白噪相同**（它同时抬高所有通道，被总量判据当成整体电平抬升、不制造电平差），
   但它对**超调/偏差**的破坏最大 ⇒ "共模对电平门限类判据的破坏与白噪完全不同"这一预期
   **在偏差与最坏超调上成立、在漏检上不成立**。

5. **T1-Q8 时序抖动/丢包/事件起点：`T_stable` 全部不敏感（±0.03 s 量级），
   但最大显示偏差对 ±1 包就敏感**。显示域 v6：事件起点 ±1/±2 包 ⇒ `T_stable` **0.56/0.58 s**
   （基线 0.55 s，就是平移量本身）；包到达抖动 ±1/±2 包 ⇒ 0.54/0.55 s；单帧丢包 0.005~5% ⇒ 0.55 s；
   整包丢包 1~5% ⇒ 0.54~0.55 s；包聚合 k=3/6 ⇒ 0.51/0.48 s。达标率 71~83%（无系统性变化）。
   但 `maxdev`（对无扰动基线）：包抖动 ±1 包 **2.42**、±2 包 **4.25**、延迟档 3.75、
   **包聚合 k=3/k=6 = 9.67/9.91 显示单位（59%/61% 电平）**，而单帧/整包丢包 ≤0.07（0.4% 电平）。
   ADC 域同理：延迟/抖动/聚合的 `maxdev` 22 000~25 600 ADC（≈一个平台幅度），
   但**慢相偏差中位 ≈ 0**（0~52 ADC）⇒ 偏差是**边缘时刻的瞬态**、不是基线破坏。
   → **亚秒（<0.1 s）结论在 ±1 包（15.4 ms 指尖 / 39.9 ms 实录）下不可信；平台级与稳态结论稳健。**

6. **T1-Q9 拍击不破坏已建立的基线**：50/100/50 ms、峰值 10%/30%/50% 电平（显示域 7 事件 + ADC 域 3 事件，
   每格 10 种子）：**交接（handoff）次数全部 = 0**、撤销 = 1.00、`ΣA` 不变
   ⇒ **不需要重算 `T_stable`**。显示峰值偏差 = **1.06~1.87× 拍击幅度**（v6 自身的预判叠加），
   恢复 **0.24~0.25 s**（显示域，对照差分口径 0.3 s）/ **3.63 s**（ADC 域 30~50% 档）；
   净永久台阶 = **0.000**（ADC 域，与同段无拍击对照之差）/ **−0.13~−0.16 显示单位（0.8~1.0% 电平）**（显示域）。
   叠加白噪 r=2% 后结论不变（仍 0 交接、epoch 1.0~1.1）。

7. **T1-Q10 代价-收益矩阵：只有"驻留确认"是有效改造，且代价极小、但有漏检副作用**：
   `dwell 0.15 s`：clean onset `T_stable` **+0.00 s**（配对、快事件 0.50/0.54→0.50/0.54）、
   建事件延迟 0.04→**0.16 s**、拍击 30% 的 epoch **2.0→1.0**、白噪 2% 的 `maxdev` **2.94→2.08**；
   `dwell 0.40 s`：拍击 30%/50% 的 epoch **清零（0.0）**、`T_stable` +0.145 s（快事件）、
   建事件延迟 0.41 s。**新发现的代价**：驻留在 ADC 域强噪声（2000 ADC）下把**漏检从 3.5 抬到
   4.8（0.15 s）/5.7（0.25 s）个/录制**。
   **CAPF（用 5%·电平封顶 5σ_d）被独立复现为有害**：漏检 3.5→2.3 但**误触发 0.5→14.6 个/录制**、
   epoch 8→23.6（第一轮测到 13~59 个，量级一致）；
   **救援检测器（rescue 0.4 s）零收益**：实测触发 10.1 次/录制，漏检 3.5→3.5 不变；
   `rel 0.08/0.12`、`k 7/8`、`idle 0.25`、`revoke 0.80` 四个旋钮在本批数据上**完全不绑定**
   （四个场景逐项与原型相同）——它们只在更小台阶/更大噪声下才可能起作用。

### 2.2 指标（逐条对齐 `00_共享/指标字典与口径.md` §3；实现见 `scripts/t1_common.py`）

| 指标 | 实现 | 备注 |
|---|---|---|
| `T_stable_v1`（主） | 从 `t_on` 起首个 τ 使 `[t_on+τ, t_on+τ+30 s]` 内 `max|Z̄(t)−Z̄(t_on+τ)| ≤ 5%·|J|` | 字典定义；要求**完整 30 s 窗**，窗不可得 ⇒ `t_stable_ok=0`（**不可测，不是 0**） |
| `T_stable_v2` | 同 v1 + 窗末 10 s 净漂移 ≤ 2%·|J| | "不再同向移动"的严格化，两套并列 |
| `J` | `median(Z̄[t_on+4,+6]) − median(Z̄[t_on−2,t_on))` | 字典 §2.1；**用无扰动轨线算**，故 5% 带在各噪声档间可比 |
| `OS%`/`US%` | `max(Z̄−Z_final)/J`、`|min|/J`，窗 `[t_on,t_on+30]` | `Z_final` = `t_on+60~70 s` 中位；记录不足退回平台中位（标 `zfin_src=plateau`） |
| `T_settle(2%/5%)` | 首次进入并保持 `|Z̄−Z_final| ≤ ε·J` 到记录末 | O(n) 后缀实现 |
| `maxdev`/`slow_dev` | 相对**同一事件、同一臂、无扰动**基线的最大 / 慢相（后半段）中位偏差 | 配对口径，去掉臂间系统差；**maxdev 会被边缘时刻瞬态主导，必须与 slow_dev 同看** |
| 漏检/误触发 | epoch 与 T4-A 真值事件表 ±0.8 s 配对（ADC 域全长） | 与第一轮 `a2b/a7` 同法；`raw` 臂无检测器、不统计 |
| 通道 | **总通道 `Z = Σ_c`**（字典 §1 默认） | ⚠ 见 §2.4 |

### 2.3 扰动注入口径（`scripts/t1_common.py` = 全项目共享注入器）

- **幅度一律按"总量扰动的 RMS"标注**（字典 §5）：`kind=white` 每通道独立白噪；
  `band` = 0.3~40 Hz 带限；`common` = 通道间**完全同相**（按通道电平分摊，总量 RMS = A）。
  显示域用**相对幅度** `r = A/保压电平`，ADC 域用**绝对幅度** A（ADC）——两域无可换算标定（缺口 G1）。
- **时序类扰动在帧级时间戳上注入、之后再重采样**：`add_packet_jitter`（包到达 ±k 包；
  允许"同刻到达"⇒ 合并包：实录 k=1 合并 20.8%、k=2 合并 40.4%）、
  `add_dropout`（单帧/整包）、`add_packet_aggregate`（包聚合）；
  另设**事件起点不确定性** `shift_event_origin`（`t_on' = t_on ± k·T_pkt`，**只改指标对齐、不改数据**）。
- 拍击 `add_tap`：**50/100/50 ms**（余弦半波上升+保持+回落），峰值 = 10%/30%/50%·保压电平，
  注入在保压段 `t_on+25 s`（显示域）/ `t_on+20 s`（ADC 域，要求 `gap_next ≥ 25 s`）。
- **注入器自检 41 项全 PASS**（`t1b_injector_selftest.csv`）：白/带限/同相的总量 RMS 精确 = A、
  同相通道相关 = 1.000、带限带内能量 = 1.000、拍击峰值 = amp 且回落归零、抖动后时间轴非降且
  逐帧偏移 ≤ k·T_pkt + 0.01、丢包率复现、聚合唯一时间戳 = ⌈n/k⌉、指标在合成信号上复现设定值。

  ⇒ **ADC 域失守阈值 ≈ 2000 ADC（≈8% 电平），第一处漏检上升在 1000~2000 ADC**。
- `maxdev` 在 1~50 ADC 区间从 95 线性涨到 2 963 ADC，但**慢相偏差 ≈ 0**（≤20 ADC）
  ⇒ 是边缘时刻的瞬态差异 + 噪声透传，不是基线破坏（与 §3.4 时序扰动的结论同源）。

## 5. 未验证项与数据缺口

1. **跨域无法换算（最关键缺口 G1）**：13/13 录制 `has_raw_adc=false`、`force_conversion_active=false`、
   `calibration.params={}` ⇒ 显示域（N）与 ADC 域**无法给出换算系数**，本报告只能用相对口径 `r`
   把两域放在同一张曲线上。**需补采**：同一次按压同时记录 raw ADC 与 `processed_display`
   （`has_raw_adc=true` 的录制），才能把"1~50 ADC"直接映射到显示域。
2. **实录里没有"干净"的真实拍击样本**：37 个孤立双相扰动**全部**紧邻真实变载（最近 4.16 s），
   9 个干净候选全部来自恒载保压段。**需补采**：保压段中**单独**做一次人手拍击/揉压的实录，
   并在 `session.json`/日志里标注拍击时刻。
3. **`T_stable` 在实录（多事件）上大多不可测**：11 个 ADC onset 里只有 2~3 个满足"事件后 ≥30 s
   无其它事件"；ADC 域的"达标率"分母 <20，**只能定性**。需补采长保压（≥60 s）的变载实录。
4. **跨载荷量级（5N/10N/20N）缺失**（沿用 T4-A/T1-A）：噪声-幅度依赖性无法分层，
   无法回答"大载荷是否更抗噪"（第一轮 §2.4 的"电平越高越抗抖"只有 2 份录制支撑）。
5. **v5.1 / v6.1 只做了 3 个相对档的四臂对照**（`hold_armcomp` 组，5 个种子），未做全曲线；
   `raw` 臂的"达标率"没有意义（无补偿），报告里只作参照。
6. **救援检测器（rescue）是原型级近似实现**（未做 C++ 落地、未现场标定），其负结果只在本批数据成立；
   `rel/k/idle/revoke` 四个旋钮"未绑定"也只在本批数据的工况下成立。
7. **拍击撤销窗的安全余量未变**：本报告未做"更慢/更久拍击"（上升>80 ms 或保持>200 ms）的扫描，
   第一轮 §3.2 记录的"最晚撤销 0.39 s vs 窗口 0.40 s"余量仍然存在。
8. **包聚合实验只在"主机侧把 k 帧打成同值时间戳"的模型下做**，未模拟丢包重传/乱序重排缓冲；
   实录 k=8/16 的严重退化（`maxdev` ≈ 一个平台）说明该模型下的敏感性极高，但真实主机是否会
   聚合到 8~16 帧（=0.3~0.6 个包周期）未证实。
9. **未做 C++ 实测**：所有结论基于 Python 原型（`t1b_glm53_v6.py` 与原型的逐行复制件）；
   C++ `Push()` 多约 10 ms 滞后（第一轮已核对 13/13 常量一致），未在此复核。
