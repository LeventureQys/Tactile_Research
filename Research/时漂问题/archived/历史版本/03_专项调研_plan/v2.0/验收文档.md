## 4. 验收项列表

### A1. 编译测试（主程序）

- **目的**：改动后的主程序可编译。
- **前置条件**：前置条件 1~3。
- **操作步骤**：
  ```powershell
  cmake --build build-app --config Debug --target TactileSense -- /m:4
  ```
- **期望结果**：exit 0；输出中无 error；无本次改动引入的新 warning。
- **通过标准**：exit 0 且 `drift_v6_compensator.cpp` / `data_handler.cpp` 两个 TU 被重编。
- **失败标准**：任何 error；或未重编（说明改动未生效）。
- **证据要求**：完整命令 + 末尾 20 行输出 + exit code。

### A2. 编译测试（测试目标）

- **目的**：新增单元测试目标可编译并登记进 `data` 套件。
- **操作步骤**：
  ```powershell
  cmake --build build-tests-all --config Debug --target test_drift_v6_compensator -- /m:4
  ctest --test-dir build-tests-all -C Debug -N -R "test_drift_v6_compensator"
  ```
- **期望结果**：exit 0；`ctest -N` 列出 **≥13** 个用例（1B 的 6 个 + 3A 的 7 个）。
- **通过标准**：exit 0 且用例数 ≥13 且 `tests/suites.cmake` configure 无"未登记目标"提醒。
- **失败标准**：任一目标不存在 / 用例数 <13 / 有未登记提醒。
- **证据要求**：两条命令的输出。

### A3. 单元测试执行（含阳性对照）

- **目的**：四项修复的行为被测试真实锁定。
- **操作步骤**：
  ```powershell
  ctest --test-dir build-tests-all -C Debug -R "^test_drift_v6_compensator\." --output-on-failure
  ```
  阳性对照（**必做，逐个执行后改回默认值**）：
  1. 把 `Params::clamp_alpha` 默认改成 `0.0` → `ClampLimitsLeadOverRaw` **必须失败**；
  2. 把 `kValleyFrac` 默认改成 `0.0001` → `EventUnloadValleyExitFires` **必须失败**；
  3. 改回默认 → 全部通过。
- **期望结果**：默认参数下 **13/13 通过**；两次阳性对照**各自失败**。
- **通过标准**：默认全通过 **且** 两个阳性对照均失败。**只做前者不算通过**。
- **失败标准**：默认参数下有失败用例；或阳性对照不失败（说明断言恒真/失效）。
- **证据要求**：三次运行的输出 + 改动与回改的 `git diff` 片段。

### A4. 启动测试（本机）

- **目的**：应用可正常启动，v6 入口可触发，无崩溃/无异常日志。
- **前置条件**：`build-app\Debug\TactileSense.exe` 存在。
- **操作步骤**：
  1. 启动 exe；
  2. 打开菜单「设备 → 时漂/零漂补偿（v6 快速稳定）」开关一次；
  3. 观察主窗口与状态栏，运行 ≥30 s；
  4. 关闭。
- **期望结果**：主窗口正常显示；开关可点击且状态栏提示出现；无崩溃；无与改动相关的 `qCritical`/`spdlog::error`。
- **通过标准**：无崩溃 + 入口可触发 + 无相关 error 日志。
- **失败标准**：崩溃 / 入口不可用 / 出现与 `drift_v6` 相关的 error。
- **证据要求**：exe 启动时间、操作记录、日志片段（路径：exe 同目录日志或 Qt 输出）。
- **备注**：若无法本机启动，**必须**在完成报告写明阻塞原因，并把该阻塞追加到 `问题清单.md` 置顶区（按《Agent开发规范》§4）。

### A5. 功能完整性 · C 单侧限幅

- **目的**：显示超前量被限制在 `α·|原始|` 内。
- **操作步骤**：运行 `ctest` 用例 `CompensationNeverExceedsRaw`；并给出"限幅真实生效"的统计。
- **期望结果**：
  - 三段夹具全帧满足 `out_i ≤ raw_i + params().clamp_alpha·|raw_i| + 1e-6`；
  - **真实生效证据（口径已定）**：在 `seg_a_onset` / `seg_c_cycle` 上"限幅真实削掉的格数 > 0"、
    "取等帧数 > 0"（SubStage 2A 实测：seg_a 11721 格 / 838 帧取等；seg_c 1644 格 / 115 帧取等；
    全录制 276886 格 / 22438 帧取等，占 **66%** 帧）。
  - ⚠️ **不要用 `seg_b_handoff` 验限幅**：该夹具只有 39.0~50.0 s 的 221 帧，**冷启动重放时全部走直通出口**
    （补偿器需要 ≥ ~40 s 前置历史），限幅必然 0 次触发 —— 这是夹具的时间窗限制，不是实现缺陷。
  - ⚠️ **D 口径以"总量"为准**：设计文档 §3.3 的 `438 → 76 ADC` 是**21 通道求和后的总量口径**；
    逐通道口径的对应值是 6.27 → 2.32 ADC。两种口径都要给，**不得混报**。
- **通过标准**：不变量成立 + 限幅真实生效（取等帧 > 0）。
- **失败标准**：不变量被破坏；或限幅从未触发（说明没接上）。
- **证据要求**：ctest 输出 + 统计输出（含两种口径）。

### A6. 功能完整性 · F2/F3/F5

- **目的**：三条修复行为正确；默认配置不劣化。
- **前置条件**：**默认配置 = `legacy_fixes_enabled=false` + `clamp_alpha=0.005` + `g_neg_floor=-0.05`**
  （设计文档 §3.4 的自决修正）。F2/F3 的验证需**显式开启开关**。
- **操作步骤**：
  1. `ctest` 运行 `GNegFloorBoundsSlowResidual`、`NoLivelockOnLongHold`（默认配置）；
  2. `ctest` 运行 `EventUnloadValleyExitFires`、`ReanchorValleyZeroesResidual`（用例内部已开启开关）；
  3. 给出四个计数器的实测值（`params()`）。
- **期望结果**：
  - 默认配置：`n_valley_exit == 0`、`n_reanchor_idle == 0`（**锁住"默认关闭"语义**）；
  - 开关打开后（**须先喂一帧再 `SetParams`**，见设计文档 §4.1.1 C-5）：`n_valley_exit ≥ 1`、`n_reanchor_idle ≥ 1`；
  - 全程 `g ≥ g_neg_floor − 1e-9`；
  - **无活锁**：判据为"末帧状态与 `base` 臂一致"（**不是** `in_event()==false`——`seg_a`/`seg_c` 是"事件进行中"的切片，末帧本就落在事件内，见 §4.1.1 C-7），**并**另用一段"事件都会正常结束"的合成序列（开/关两配置）证明 `in_event()==false`。
- **通过标准**：上述全部满足。
- **失败标准**：默认配置下 F2/F3 被触发（说明开关未生效）；或开启后仍不触发；或 `g` 越界；或出现活锁。
- **证据要求**：ctest 输出 + 两次计数器数值（默认 / 开启）。

### A8. 定向回归（不劣化）

- **目的**：改动不破坏 plan v1.0 已验收的行为。
- **操作步骤**：
  ```powershell

  并对照 T9 案例：

  ```
  （T9 脚本读的是 T9 自己的数据集，只用于给出基线数字对照。）
- **期望结果**（口径见 `results/design_regress_summary.md` 与 `results/final_ab_verify.txt`）：
  - 新录制：`Δlead ≤ −3 pp`、`Δresid ≤ 0`、`offabs` 显著下降（对照 base 的 701 ADC）；
  - 既有 13 份录制：**`|Δresid| ≤ 0.01`** 且 `|ΔG| ≤ 0.01`；
    **已知例外（在阶段二设计期即已实测并接受）**：`变化负载/零负载-切换负载-零负载-再切换负载` 的
    `Δresid = +0.0073`、`ΔG = −0.010` —— 该数据集上 C 路把**超前量峰值 4.05% → 0.40%**、
    把另两处 **−21.6% / −35.1% 的欠充**一并修正，属"用一点平台平坦度换掉严重的瞬态偏差"的有意取舍；
    该例外对 `default`（C+F5）与 `legacy_on`（C+F2+F3+F5）**完全相同**，不由 F2/F3 引入；
  - T9 案例：**不得比现役更差**。口径与结果（`results/acc_t9_compare.txt`）：
    T9 录像在**新鲜回放**下几乎不产生补偿（偏移 0，与 T9 报告 §2.3 一致）；
    其现场失效来自"带状态进场"，故**必须在 seeded 通路（首帧后把 `min_ts` 预置为带外低值 1900，复现 never-idle）**上对比：
    `base seeded` 空载 `|off|` 中位 **70** / 最大 **468** / 末段 **+109** ADC；
    `default(C+F5) seeded` **69 / 178 / +61**；
    `legacy_on seeded` **69 / 178 / +61** ⇒ **最大偏差 −62%、末段 −44%，无劣化**。
    （现场实测登记为 −810 → +3070 ADC，属"带状态进场 + 未修版本"的更严重工况。）
- **通过标准**：上述三条全部满足（含上面已声明的例外）。
- **失败标准**：**其它**数据集的 `Δresid > +0.01` 或 `ΔG < −0.01`；或上述例外数据集的偏差**超过**已声明值。
- **证据要求**：`final_ab_verify.py` 与 `design_full_regress.py` 的完整输出（**必须包含每份数据集每一臂的一行**，不得只给汇总）。
- **必须写明未做全量回归的原因**（本项为"定向回归"，不做全量构建与全套件 CTest）。
