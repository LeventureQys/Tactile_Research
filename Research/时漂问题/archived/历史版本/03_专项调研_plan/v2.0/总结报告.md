## 1. 需求与结论（一句话）

**需求**（`需求文档.md`）：① 加上负载的"过充"能否优化；② 约 44 s 处基线被错误估计、此后越飘越远。

**结论**：
- ① **能**。落地**显示单侧限幅**（`显示 ≤ 原始 + 0.005·|原始|`）后，实测
  **加载沿后 0.3~1.2 s 的超前量中位 494 → 65 ADC**、**保压段"显示−原始"偏移 417 → 79 ADC（−81%）**、
  受载段滑窗极差比 **0.052 → 0.037**，且**14 份数据回归零劣化**（唯一例外已声明并接受）。
- ② **修好了量级，但根因是一条设计上就存在的链条**。逐帧证据锁定：44 s 处一次 `restep` 事件交接把
  无蠕变电平钉高（+7.8%），随后 **epoch 内的卸载被漏掉**（唯一卸载出口要求 `idle_now`，而本录制
  `idle_now` 在事件态内只真 1 帧、慢相态内真 0 帧），`Reanchor` 又按设计"保持扣除连续"继承错误扣除；
  偏移的**主导通路是慢相 `γ·A·g`**（恒载平台段占 100%），而 `g` 87.5% 的帧为负。本版用
  **`g` 的负向下界 + 回谷底归零**把这条通路的量级压住，并在 T9 的现场失效通路上实测
  **空载 |off| 最大 468 → 178 ADC（−62%）、末段 +109 → +61 ADC（−44%）**。

## 3. 改了什么（最终落定）

| 项 | 内容 | 默认 |
|---|---|---|
| **C** | 显示单侧限幅 `out_i ≤ 原始_i + 0.005·|原始_i|`（`ApplyOutputLimit`，接在 `Process` 的事件期与慢相两个出口、写回 `values_io` 之前） | **开** |
| **F5** | 慢相残差 `g_` 负向下界 `−0.05` + 回谷底归零 | **开** |
| **F2** | 事件期内**不依赖 `idle_now`** 的卸载出口（谷底判据 `valley_now_`） | **关**（`kLegacyFixesOn`） |
| **F3** | `Reanchor` 加"回到谷底即归零" | **关**（同上） |
| **P** | `DriftV6Compensator::Params`（14 字段）+ `params()/SetParams()`；协调器记忆式注入 | — |
| **修正** | `Reset()` 不再清 `params_`（原语义会让首帧 `ResetFor→Reset` 把注入参数静默抹掉、条目永久停留默认值） | — |
| **落盘** | 录制 manifest 增加 `clamp_alpha / valley_win_n / g_neg_floor / legacy_fixes_enabled`，`param_set = "plan-v2.0 C+F5"` | — |
| **UI 文案** | `menubar.cpp` 的 v6 注释与用户可见 tooltip 同步（补 C/F5 与 F2/F3 默认关闭说明） | — |
| **测试** | 新增 `tests/data/test_drift_v6_compensator.cpp`（**13 用例**，登记 `data` 套件）+ `tests/fixtures/drift_v6/`（三段夹具，约 1.1 MB） | — |

**为什么 F2/F3 默认关闭**（自决修正 Q11，证据见 `results/design_regress_summary.md`）：
14 份数据里 **12 份与"只加 C"逐位相同**、新录制也是逐位相同；**1 份方向不一致**
（消除 76.27 s 处 −9.19% 欠充的同时，在 233.56 s 处引入 +2.11% 过充、驻留 9.64 → 15.24 s）。
另有探针证明：100 Hz 默认参数下**谷底判据成立的那帧通常已满足 C4 空载带，F2/F3 的可用窗口只有约 0.15 s**
（`设计文档.md` §4.1.1 C-6）。⇒ 保留实现与开关，但**不让未证实行为进默认路径**。

## 5. 已知取舍与遗留（必须与结论同读）

| # | 内容 |
|---|---|
| 1 | **限幅接管了 v6 的主动超前能力**：加载后 0.3~1.2 s 的超前量由 494 → 65 ADC，"敢于超前显示以掩盖蠕变"的机制被限幅封顶。这是**有意的取舍**（用户诉求是"不要过充"），α 可运行期注入（备选 0.02 保留约 255 ADC 超前量）。 |
| 2 | **`seg_b_handoff` 夹具不适合量测**（冷启动 221 帧全走直通）；保压偏移须用总量口径，逐通道口径差约 50 倍。已写入夹具 README 与设计文档 C-8/C-9。 |
| 3 | **F2/F3 在本工况不产生可测收益**（结构上窗口仅约 0.15 s）。若将来放宽 `clamp_alpha` 或换工况，建议先在真机上开启 `kLegacyFixesOn` 做 A/B。 |
| 4 | **`legacy_fixes_enabled` 以 `int`（0/1）落盘**（`QJsonValue` 无 bool 构造）；若下游要 JSON 布尔语义需再改一行。 |
| 5 | **集成验证报告的 U1 未对齐**：C++ 单格最大削幅 217.8 ADC vs Python 审计 316 ADC、触发占比 68.95% vs 66%；两端口径差异未做实验区分（若要拿"削幅上限"当验收阈值，须先对齐口径）。 |
| 6 | **原计划的 `T_stable` 类绝对指标未做跨版本对表**：本录制的事件级到带时间受"显示偏移"支配，本版改用 `resid / lead / G / offabs` 四联口径，未与 plan v1.0 的 `T_stable_ch5` 直接横比。 |
| 7 | **增量构建的时间戳陷阱（实测踩到，必须记住）**：做阳性对照时"改默认值 → 构建 → 跑 → 改回"这一套，**用 `Move-Item` 还原文件会保留原时间戳**，导致 MSBuild 认为 `.obj` 比头文件新而**跳过重编**，于是跑的是旧目标文件（实测：还原后 `ClampDisabledIsPassThrough` 仍以"`kClampAlpha=0` 的旧二进制"失败）。处置：还原后 **touch 源文件**再构建。已按此复验：测试目标与主程序均重编 `drift_v6_compensator.cpp`，**13/13 通过**、启动测试复跑通过。 |
| 8 | `project_summary` 中仍有 **3 项 stale**（`module:device.connection` / `module:preset.painting` / 2 个 menu 缓存链），来源是**本次之前既有的** `wireless_host_service.h`、`painting_canvas_widget.cpp` 改动，与本次无关，**未处理**。 |
