## 1. 一句话目标与手段

**目标**：把「真实加载沿 → 显示稳定」从 v5 的 7.8 s（可见首扣）/ 14.5 s（扣到位）压到 **1~2 s 量级**。

**手段**：**不缩短等待，而是把快相算出来扣掉**——用离线标定的归一化加载形状 `f(τ)`，
在加载沿之后 0.2~0.8 s 内反演出「本次加载最终会到的电平」`Â`，把显示用速率受限的 smoothstep
滑行器滑到 `base_y + Â`，之后交给沿用 v5 的慢相蠕变模块。

**它与 v5 系列的根本差别（也是全部代价的来源）**：

| | v5 / v5.1（免责期） | **v6（形状约束反演）** |
|---|---|---|
| 快相 | **放任**：加载后 3 s 内不扣，等它走完 | **抵抗**：用形状先验预测未来电平并冻结显示 |
| 稳定时间 | 3.8 s 量级 | **0.5~1.8 s 量级**（口径决定） |
| 代价 | 慢 | **预测误差直接进显示** ⇒ 过充/欠报、对时序敏感、强扰动下失效 |

**稳定时间只能是中位承诺**：冻结口径（主通道 + 5 s 电平参考）下恒载 9 组中位 **1.80 s**、
达标率（≤2 s）**5/9**、最坏 13.16 s。

## 3. 输入 / 输出与口径前提

- **输入**：`values_io` = 该帧**逐通道显示域值**（力值/压强/ADC 三模式统一；本算法只看数值，不看单位）。
  `n_` 变化（通道数改变）自动 `ResetFor(n)`。
- **总量** `total = Σ v`（**跨通道求和**，算法的所有电平判据都建立在它之上）。
- **时间轴**：只用调用方给的 `timestamp_s`；`dt = clamp(ts − last_ts, 0, 0.1)`，
  **dt ≤ 0（同包重复时间戳）时不更新 EMA**也不累加谷底时长。检测/回溯一律走**帧环形缓冲**，不用包时间戳做微分。
- **抗毛刺**：检测与回溯使用**3 帧中值总量**（原始总量会出现 −8% 的单帧掉点，足以伪造一次「减重」）。
- ⚠️ **显示域前提（关键）**：算法的「空载/卸载」判据是**对 `total` 的绝对/半绝对比较**（见 §6.3），
  因此**隐含要求"空载读数接近 0"**。在**空载基线远大于负载增量**的工况（例如 ADC 显示域 + 装夹预载）下
  判据会失效 —— 见 §9.1。

## 4. 逐帧主流程（`Process`，源码 L295~L463）

```text
Process(ts, v):
  0. 预处理
     n 变化 → ResetFor(n)
     total = Σv ; y = 上一帧显示值(首帧 = v)
     dt = clamp(ts − last_ts, 0, 0.1)                    # dt≤0 不更新 EMA
     ts_smooth += (dt/0.30)·(total − ts_smooth)          # 总量平滑 EMA(τ=0.30 s)
     level_ref += (dt/10.0)·(ts_smooth − level_ref)      # 近期电平参考 EMA(τ=10 s)
     min_ts = min(min_ts, ts_smooth) ; max_ts = max(...) ; max_tot = max(max_tot, total)
     eps = 1e-6·(1+|max_tot|)
     UpdateValley(dt)                                    # ★plan-v2.0 新增(谷底判据, 见 §3.2)
     3 帧中值总量 → prev_med_total

  1. 检测器 D
     lv_now = mean(total, [ts−0.20, ts])
     lv_ref = mean(total, [ts−0.65, ts−0.35])
     d = lv_now − lv_ref
     σ_d = 1.4826·MAD(历史 d 分布, 样本 >40)
     thr_d = max(5.0·σ_d, 0.05·|lv_ref|, 0.01·max_tot)
     tail_gate = 0.10·|lv_ref|   (仅当 state≠Idle 且 τ_ep < 3.0 s)
     raw_hit = |d| > max(thr_d, tail_gate)
     hit = (raw_hit 连续 ≥3 帧) and armed
     armed 在 raw_hit 结束后连续 3 帧为假时重新置真

  2. 空载态/受载态判定
     lvl = max(level_ref, eps)
     idle_now = (ts_smooth < 0.10·lvl) or (ts_smooth < 1.5·min_ts + eps)   # ← 见 §6.3 / §9.1

  3. 建事件
     if hit and d > 0:
        if !ev.valid and (ts − last_ev_ts) > 0.30:            → 建事件
        elif ev.valid and τ_ep > 0.40:                        → 建事件(C5 复合)
        (Idle 态额外要求: (ts − idle_since) ≥ 0.50 且 d > max(thr_d, 0.10·max_tot))
        (刚处理完减重/卸载的 0.80 s 内静默: ts < ev_block_until ⇒ 不建)
        建事件前: t0/base ← Backdate(命中前 0.60 s 内定位真沿)
                  v0/y0 ← 事件前 [t0−0.30, t0−0.05] 的逐通道窗均值
        分类: C5 复合 → RestepReload ; (Idle 且 idle_pre) → Onset ; 其余 → Restep
     elif hit and d < 0 and state≠Idle and !ev.valid and (ts−last_ev_ts)>0.30:
        → 建减重事件 Decrease

  4. 事件期 → RunEvent（见 §5.1）
  5. 慢相态 → SlowStep（见 §6）
     若 idle_now 且 (ts − ev_end) > 0.30 → ToIdle()，本帧直通
  6. 否则直通: out = v
  7. ★plan-v2.0：事件期出口与慢相出口在写回 values_io 之前各施加一次 ApplyOutputLimit(v, &out)（见 §5.4）
```

### 5.1 事件期（`RunEvent`）—— 按执行顺序


### 5.2 逆模型 `InvEst`（形状约束反演）

```text
窗: [τ_ref=0.20, min(τ, τ_ref+0.60)]，需要 ≥5 个样本
Â_ls = Σ y·f(τ) / Σ f(τ)²                  # 电平域最小二乘(y = 事件内的实测增量)
Â    = min( max(Â_ls, inc) , κ·inc )       # 下界 = 已实测增量；上界 = 单侧上限 κ·inc
```

- `f(τ)` 是**13 份录制 onset 合并标定的 14 点形状 ROM**（线性插值，τ≥1 取 1）。
  **不可跨设备/跨加载方式搬用**（实测跨传感器差 15 个百分点、跨形态误差 56%）。
- **`κ` 是单侧上限，不是增益系数**：只有 `Â_ls > κ·inc` 时才起作用。
  onset 逐事件 `r_max` 落在 **1.207~2.925**（中位 1.2466）⇒ **κ ≥ 1.28 时对 22 个 onset 一个都不触发**
  （原值 1.30 实际等同"从未启用"）。当前 **κ_onset = 1.05**（几乎总是生效）、`κ_restep = 1.12`。
- **不用尾巴外推式**（`Â = y(τ_ref) + Σ(y−y_ref)f/Σf²`）：短窗被 `1/mean(f)` 放大（可达 ×25），
  实测把 14.2 的台阶算成 15.7。

### 5.3 交接（`Handoff`）

```text
ded_old = −share·c_applied                     # 当前逐通道扣除
A_new   = (y0 + share·max(Â,0))⁺               # ANCHOR_MODE = "pin"（钉住值, 非实测电平）
loaded_i = (A_i > 0.10·max A)
g       = median over loaded of ( ded_old_i / (γ_i·A_i) )   # 与当前扣除自洽(保持连续, 不归零)
trim_target_sum = base_y + (v.sum() − base)    # 仅 kTrimRate>0 时使用（默认关）
→ state = Slow ; ev_end = last_ts
```

**为什么 `A` 取"钉住值"而非"实测电平"**：`A←实测电平` 会让 `g_raw≈0` 而锚定 `g>0`，
于是 `g` 以 τ=3 s 衰减、显示朝 raw 爬 3~9 s，就是用户报告过的「先稳住又缓慢抬升」。

### 5.4 ★plan-v2.0 新增：C 路显示单侧限幅（默认生效）

```cpp
void DriftV6Compensator::ApplyOutputLimit(const Eigen::VectorXd& raw, Eigen::VectorXd* out) const;
// out_i = min(out_i, raw_i + params_.clamp_alpha·|raw_i|)      α 默认 0.005
```

- **只有两个出口施加**：`Process` 的**事件期出口**与**慢相出口**，均在 `prev_out_ = out` **之前**。
  直通出口不需要（`out == raw` 时不等式恒成立）。
- **不写任何内部状态**（与 `Capped` 同性质）；`clamp_alpha ≤ 0` / 尺寸不符 / `out == nullptr` 时静默跳过。
- **语义**：显示最多比**当前读数**高 `0.5%`。这是**硬不变量**：实测在 15 条实机录制、
  267,990 帧、约 700 万格点上**越界 0 格**（容差 0.01 ADC；更严的 1e-6 容差下"越界量"最大仅 0.005 ADC = CSV 精度）。

## 6. 慢相模块（`SlowStep`，沿用 v5 + F5）

### 6.1 每帧

```text
g_raw = median over loaded_i of ( (v_i − A_i) / A_i )      # 共识残差
g    += (dt/3.0)·(g_raw − g)                                # τ_g = 3 s
★plan-v2.0 F5：if (g < g_neg_floor(−0.05)) { g = −0.05; ++n_g_floor; }
              if (valley_now && valley_run ≥ 0.30 s && g < 0) { g = 0; ++n_g_valley_reset; }
若 g > 0.02:
    g2_acc  += dt·g²
    g_rel_i += dt·g·((v_i − A_i)/A_i)
    若 g2_acc > 1e-8:  γ_i = clamp(g_rel_i / g2_acc, 0.3, 2.0)   # 逐通道增益(过原点最小二乘)
out_i = v_i − Capped(v_i, clamp(γ_i·A_i·g, −0.5·A_i, 1.5·A_i))
```

`Capped(v, d)` 是"扣除量不超过当前读数"的逐通道封顶（**只封顶输出、不改内部状态**，显示不为负）。

**为什么需要 F5**：`g < 0` 时 `ded = γ·A·g < 0` ⇒ `out = v − ded = v + |ded|`，显示被**抬高**；
实测该录制慢相态 **87.5% 的帧 `g < 0`**、极值 −0.499。F5 把负向截到 −0.05，并在确认回到谷底时归零。

### 6.2 重锚（`Reanchor`，减重后）

```text
★plan-v2.0 F3（默认关闭）: if (legacy_fixes_enabled && valley_now && valley_run ≥ 0.20 s) { ++n_reanchor_idle; ToIdle(); return; }
vs = mean(v, [ts−0.25, ts])                    # 不能取瞬时帧(会有 −8% 单帧掉点)
ded_old = DeductionVector()                    # 用旧 A/g 算出的当前扣除
A_new = (vs − ded_old)⁺ ; loaded_i = (A_i > 0.10·max A)
g     = median( ded_old_i / (γ_i·A_new_i) )    # **保持扣除连续，不归零**
```

> ⚠️ 这条"保持连续"是有意设计（归零会让下降段变成 `g` 在重新填坑），但它同时意味着
> **任何已经错掉符号/量级的扣除都会被原样继承** ⇒ 与 §9.1 的 never-idle 缺陷叠加时会**锁定**错误偏移。

### 6.3 空载判定（全算法共用的 `idle_now`）

```cpp
lvl      = max(level_ref_, eps);                       // 近期电平参考 EMA(τ=10 s)
idle_now = (ts_smooth_ < 0.10 * lvl)                   // ① 相对电平：跌到近期电平的 10% 以下
        || (ts_smooth_ < 1.5  * min_ts_ + eps);        // ② 卸载：跌到"历史最小电平"的 1.5 倍以下
```

- ①只对「空载读数 ≈ 0」的器件成立；②的 `min_ts_` 是**补偿器全生命周期**的最小值
  （只在 `Reset()`/换设备/换值域签名时重新锚定）。
- `idle_now` 被三处使用：`Process` 建事件时的 `idle_pre` 分类、`RunEvent` 的 C4 卸载出口、
  `Process` 慢相态的 `ToIdle` 出口 —— **它是全算法唯一的"回到干净状态"入口**。
- ⚠️ **当空载基线远大于负载增量时两条判据同时退化**：要么恒真（受载也被判空载 ⇒ epoch 刚建即被杀、
  完全不补偿），要么恒假（永不认空载 ⇒ 状态机永不复位、扣除量残留并可能翻转符号）。见 §9.1。

### 6.4 ★plan-v2.0 新增：谷底判据 `UpdateValley`（供 F2/F3/F5 使用）

```text
每帧（在 ts_smooth 更新之后、任何状态判断之前）:
  把本帧 ts_smooth_ 写入长度 kValleyWinN(=4000 帧 ≈40 s @100 Hz) 的环形缓冲
  若 累计帧数 < kValleyWinN: valley_now_ = false; valley_run_ = 0; return   # 数据不足 ⇒ 保守不触发
  w_min / w_max = 窗内 ts_smooth_ 的最小 / 最大
  eps_v = 1e-6·(1 + |w_max|)
  valley_now_ = (ts_smooth_ < w_min + valley_frac(0.15)·(w_max − w_min + eps_v))
                && ((w_max − w_min) > valley_range_frac(0.05)·max(|w_max|, eps_v))
  valley_run_ = (valley_now_ && dt>0) ? (valley_run_ + dt) : (valley_now_ ? valley_run_ : 0)
```

- **语义**：「当前电平处于近 40 s 的谷底附近，**且**这 40 s 内确实发生过一次足够大的加载」。
- 这是**滚动窗相对判据，不依赖"空载读数≈0"**，与 `idle_now` 并存（**不替换**它）。
- 消费者：F2（事件内卸载出口）、F3（重锚归零）、F5（谷底归零 `g`）。
- ⚠️ **4000 帧暖机约束**：冷启动后 `valley_now_` 至少 4000 帧（≈40 s）才可能首次为真，
  而事件从建立到交接只有 `max(3.5, τ_g0+τ_glide) ≈ 4.3 s` ⇒ **冷启动后的首次事件内 F2 结构性不可达**。

## 8. 安全语义与不变式

1. **空载直通不归零**（与 v5.1 一致）：空载读数原样显示，不做自动归零。
2. **扣除量 ≤ 当前读数**（`Capped`）：只封顶输出值，不改内部状态；显示不为负，不会被阈值钳成硬 0。
3. **★显示超前量 ≤ α·读数**（`ApplyOutputLimit`，plan-v2.0）：硬不变量，实测 0 越界。
4. **未受载通道直通**：`loaded_i` 为假的通道不被慢相扣除。
5. **任何时刻估计不可靠都退化为直通**：`InvEst` 失败 / `τ < τ_ref` 时该帧直通，绝不塌显示。
6. **严格因果**：只用 `t ≤ now` 的数据；检测、回溯、反演、停滞判据、谷底判据全部因果。
7. **状态隔离**：协调器按目标 key 隔离；值域签名变化 / 开关切换 / 设备切换一律 `Reset`。
8. **回放旁路**：回放期间不生效。
9. **参数与状态分离**（plan-v2.0 修正）：`Reset()` **只重置补偿状态，不动运行期参数**
   （原实现会在 `Reset()` 里 `params_ = Params()`，导致"首帧之前注入的参数"被首帧的 `ResetFor→Reset` 静默抹掉）。

## 9. 已知边界与失效模式

### 9.1 ★空载判据在「大偏置 + 小增量」工况下结构性失效
空载总电平 12855~13800、受载仅高 15~23% 时，`idle_now` 两条判据同时退化 ⇒ 要么恒真（完全不补偿）、
要么恒假（永不复位、扣除残留并翻转符号 ⇒ 基线飞掉）。现场实测偏移 **−810 → +3070 ADC**（≈1 个完整负载）。
**v6 的 13 份验证录制空载基线全部 ≈ 0**，故属域外失效。修复方向 F1/F2/F3 见 `results/分析报告_C1.md`；
**本版未采用 T9 的 F1**（滚动窗替换 `idle_now`）——体检显示它在"长保压"工况漏报 93.6%。

### 9.2 长时偏移（慢相 `γ·A·g` 主导）
实测（新录制）：偏移全段时权中 **61.3% 来自慢相**，**恒载平台段 100% 来自慢相**；
`g` 在慢相态 **87.5% 的帧为负**。F5 把负向截到 −0.05 + 谷底归零，是本版对该通路的主要约束。

### 9.3 F2/F3 在默认参数下"结构性几乎不可达"
谷底判据成立的那一帧通常已满足 C4 空载带（`τ > 0.30`），而 F2 要求 `τ > 0.60`、
F3 要求 `valley_run_ ≥ 0.20 s` ⇒ 可用窗口仅约 **0.15 s**（见设计文档 §4.1.1 C-6）。
14 份数据实测触发 0~1 次、指标与"只加 C"逐位相同 ⇒ **默认关闭**，保留开关供未来放宽限幅或换工况时启用。

### 9.4 形状库必须先现场标定
形状 ROM 取自 13 份录制（砝码/硬压加载方式）。同一传感器内可复现（4.5~6.3 pt），
**跨传感器不通用（差 15 pt）**、**跨形态误差 56%** ⇒ 形状先验误差会直接进显示。
`κ` 的 `r_max` 阈值同样是本批录制的统计量、不是器件物理常数：**换夹具/加载方式/传感器须随之重标**。

### 9.5 ★随机震荡工况（2026-09-19 新发现的域外工况）
录制 `temp/算法数据&原始数据/各种奇怪工况/20260919_134056_single_device_f40a1b`（13160 帧 / 130.9 s）实测：

| 事实 | 数字 |
|---|---|
| 输入抖动 | 振荡段 std **2266 ADC**、峰峰 **~9069**（≈台阶 14672 的 **62%**），主频 ~4.2 Hz；全录 **23%** 的时间处于抖动 |
| 抖动空间形态 | **13 个通道同相**摆动（主频处 Δ相位 ≤ ±25°）⇒ **整片阵列一起起伏**，非单通道故障 |
| 安静段对照 | 108~118 s 输入 std 仅 **30 ADC** |
| **算法响应** | 显示偏移 std **686 ADC** ⇒ **抑制比 3.3×**（显示把 4.2 Hz 低通掉、只跟慢包络） |
| 基线偏差 | 振荡段偏移中位 **−1916 ADC**；**安静段仍偏 −666 ADC**（未被带坏，但也不是 0） |
| 限幅不变量 | 全程 **0 越界** |

**未采纳的优化尝试（均已离线验证并留痕）**：
1. **拉长检测器近窗**（0.20 → 0.35/0.50/0.65/0.80 s）：命中率**反向恶化** 13.8% → 16~21% ⇒ **否决**。
2. **包内去涨落**（同一 `elapsed` 的 1~4 帧先平均/取中位）：安静段偏差改善 −58%~−71%，但**在真实卸载沿上
   会把"一包内含满载与空载两个真实采样"抹成从未存在的中间电平**（实测 t=111.061 一个包含 17307 与 3495，
   抹成 10400）⇒ 算法误判为真实加载、显示偏移尖峰 **+6896 ADC**（自回落）⇒ 一致性与观感均被破坏 ⇒ **否决**。
3. **抖动时冻结锚定**（硬切换原型）：单帧跳变达 666~2884 ADC，全程偏移位移 ±4847 ⇒ **否决**（判据可分性不足）。

**未决与建议**：该工况的根治在**上游**——固件按采样时刻分别打时间戳（现在同一 `elapsed` 压 1~4 帧、
组内 `timestamp` 跨度中位仅 **0.01 ms**，算法拿不到"这几个值分别发生在什么时候"）。
若要继续优化，须按 plan v2.1 立项（四阶段），并把"抖动/跨沿判据的阈值与误判代价"提交用户裁决。

### 9.6 其他
| 边界 | 说明 |
|---|---|
| 采样率 | 3 帧持续判据与滑行器单帧限速都**按帧**计算；口径 ~100 Hz。低采样率（≤10 Hz）下 0.20 s 近窗只有 1~2 帧、滑行明显变慢 ⇒ 参数需重标 |
