## 3. 根因 A：交接锚定口径让重载后的 `A` 落到读数上

`Handoff()`（现役 v3.1）：

```cpp
A_new = y0 + share·max(Â, 0)        // “无蠕变电平” = 事件前显示 + 形状先验外推增量
```

这条式子隐含一个前提：**`Â`（形状先验外推出来的增量）里不含蠕变**。

对「首次加载」该前提近似成立（交接发生在 6.8 s，读数还在快相平台上）；
对「完全卸载后重载」不成立——交接发生在 3.5 s，此时实测增量已经含有本次加载的蠕变，
而 `Â` 的下界被 `InvEst` 钉在**实测增量**上（`a = max(a_ls, inc)`，`inc = hist.back().second`
即 τ≈1 s 处的实测增量），上限是 `κ·inc`（κ=1.05）。

于是 `Â ≈ 0.94~1.05 × 实测落定增量`，`A` 就落在读数电平附近：

| | 首次加载（3.30 s） | **重载（245.31 s）** |
|---|---|---|
| 交接后 `A_ho` | 12 068 | **17 048** |
| 交接当帧输入 | 12 645 | 17 007 |
| `g_raw = median((v_i−A_i)/A_i)` | **+0.45** | **≈0** |
| 后段 `ded` | +2232（E5 同负载） | **−85~+58** |

慢相的全部扣除都是 `g` / PCT 残差的函数：`A` 落在读数上 ⇒ `g_raw≈0`、PCT 残差≈0 ⇒
**补偿恒 0**，并且**永不恢复**：此后每次卸载-重载都从同一口径重新锚定，
而 `Reanchor`（部分卸载后的重锚）又用「沿用上一段扣除」把 ≈0 的扣除固化下来。

> 这条定因与 plan v3.2 的结论一致（本报告用交接帧对账把它量化到了 `A_ho` 这一层）。

## 4. 根因 B（本轮新发现）：plan v3.2 的 R1 在交接处把补偿自己抹掉了

plan v3.2 的 R1「重载蠕变接力」方向是对的（把已长出的蠕变从 `A` 里扣掉，
`seed = gain · r · inc_max`），但 **seed 被施加了三处，且符号不一致**：

| # | 位置 | 施加形式 | 符号 |
|---|---|---|---|
| ① | `RunEvent` 事件期输出 | `*out += (share/Σshare)·(−seed_used)` | 使显示**更低**（正确方向） |
| ② | `Handoff` 的 `ded_old` | `ded_old += (share/Σshare)·(−seed_used)` | **与 ① 相反** |
| ③ | `Handoff` 的 `pct_ded_` | `pct_ded_ −= (share/Σshare)·seed_used` | 又扣一次 |

而 `ded_old` 的语义是「事件期末帧**实际施加**的扣除」（它接着被用来反解 `g`、并被慢相继承）。
三处叠加后，交接当帧的扣除与事件期末帧**不相等**，差额约 `2~3×seed`。

**逐帧证据**（臂 = v3.2 等价配置 `--seed-gain 1.0`，`results/` 内的对照轨迹）：

| t | state | `A_sum` | `seed_used` | `ded` |
|---|---|---|---|---|
| 248.20 | Event | 1 607（未更新） | 2 359 | **+2 258** |
| 248.60 | Event | 1 607 | 2 364 | **+2 298** |
| **248.80** | **Slow（交接）** | **14 680** | 0 | **−81** |
| 249.00 | Slow | 14 680 | 0 | −81（被 C 限幅顶在 raw×1.005） |
| 250.00 | Slow | 14 680 | 0 | +875（PCT 从地板重新爬） |
| 251.80 | Slow | 14 680 | 0 | +2 199（≈3 s 后才爬回） |

⇒ 交接瞬间显示**向上跳约 2400 ADC**（被 C 限幅压成 `raw×1.005`），
再用约 3 s 慢慢滑回。这就是 plan v3.2 只测到「245 s 重载补偿 +1175（首次加载的 72%）」的真实原因：
**不是 gain 取 0.7 取小了，而是补偿在交接瞬间被自己抹掉、只有残值被窗口统计到**。

**本轮修法（R2.1）**：seed **只折进事件目标**一处（`target = base_y + Â − seed`），
其余两处全部删除。修后同一事件的轨迹：

| t | state | `A_sum` | `ded` |
|---|---|---|---|
| 248.20 | Event | 1 607 | +2 333 |
| 248.60 | **Slow（交接）** | **14 621** | **+2 807** |
| 249.40 | Slow | 14 621 | +2 813 |
| 249.80 | Slow | 14 621 | +2 830 |

**交接处严格连续**（2 333 → 2 807，无跳变），补偿一次到位。

## 7. 为什么「同一个负载应该显示同一个数」在物理上站得住

三条独立线索都指向「前段的显示电平（≈15.4 k）才是无蠕变电平」：

1. **读数对同一负载是可重复的**：8 次同负载平台的**原始读数**落在 17 032~17 784
   （跨度 752，含真实蠕变与历史效应），而**显示**在现役算法下跨度 2 559 —— 不一致是算法造成的，不是传感器造成的。
2. **卸载沿给出的蠕变量级**：240.11 s 完全卸载时读数由 17 406 回到 2 596，
   而录制起点的空载基线是 2 408~2 430（残余 +170，约 1.1% 电平）⇒ 卸载瞬间的恢复量很小，
   说明「加载时的读数里含 10%~15% 的蠕变」这一量级与前段 `ded/电平 ≈ 13.5%` 自洽。
3. **慢相蠕变的实测速率**：长保压 [70,232] s 内输入 +671、显示 +0（ded 由 2 011 长到 2 418），
   即算法确实把「读数还在爬」的那部分压住了；而重载后的 `ded ≈ 0` 段里读数继续爬 1 400 ADC 全进了显示。

> 需要注意的边界：本节是**同录制内的自洽性论证**，不是材料学标定。
> 严格的蠕变本构（弹性/蠕变比、恢复时间常数）需要单独的实验（阶跃加载 + 分级卸载 + 长时间保压）才能定。

## 8. 与 plan v3.4（**同期已落地产品**）的关系

本报告写作期间，另有会话把 **plan v3.4「卸载-重载蠕变记忆（creep-mem）」** 落地进
`src/domain/drift_v6/drift_v6_compensator.{h,cpp}`。它解决的是同一个问题，机制与 §4 的 R2.1 有明确呼应：

```cpp
// 事件期滑行目标（RunEvent）
const double target = ev_.base_y + ev_.a_hat - mem_eff.sum();
// 交接锚定（Handoff）
A_new = (ev_.y0 + share·Â - mem_eff).cwiseMax(0);
const Eigen::VectorXd ded_old = -(share * ev_.c_applied);   // ← 就是实际扣除，未再加第二遍
```

**两处施加、取值一致，`ded_old` 只由 `c_applied` 推出** —— 这正是 R2.1 的结论
（§4 根因 B 的教训）。因此：

- **v3.4 不含 v3.2 R1 的交接塌陷缺陷**（我用本桶口径重跑 `v34_runner.exe --mem 120` 复核过：
  245.31 s 补偿 −85 → **+1988**，交接处无跳变）；
- **v3.2 的 `src_v32/` 候选不该被回退使用**；
- v3.6 与 v3.4 是**并列的两种机制**（会话蠕变比 vs 快照记忆），不是前后版本。

| 判据（同负载组 E2~E9） | v3.1 | v3.4（落地） | v3.6（候选） |
|---|---|---|---|
| 显示电平极差 | 2 559 | **1 110** | 1 231 |
| 前 4 中位 / 后 4 中位 | 15 362 / 17 497 | 15 362 / 15 789 | 15 362 / 15 387 |
| 前后差 | −2 135 | −428 | **−26** |
| 245.31 s 重载的 ded | +18 | +1 988 | **+2 832** |
| G 中位 / 最差 | 1.002 / 0.937 | 0.946 / 0.760 | 0.946 / 0.778 |

⇒ §5 的「一致性差距」判据在两条修复臂上都成立；差异属机制细节（v3.4 的记忆按电平比折减 + 残差口径，
v3.6 的会话比是全局标量），需要真机数据裁决。
