# plan v3.6 · 问题清单与改动说明

> 本轮主题：**「同一负载 → 同一显示」的一致性**（用户报告「后续没有补偿的位置和前面有补偿的位置差别比较大」）。
> 定因链见 `分析报告_245s丢基线.md`。本轮**不改产品源码**，候选实现放在 `src_v36/`（生成物），
> 由 `scripts/make_v36_variant.py` 从 **plan v3.2 的已验收产物** `../v3.2/src_v32/` 叠加补丁得到。

---

## 1. 本轮改了什么（三条，全部在候选里已生效）

### R2.1 seed 只在一处施加 —— 修掉「交接塌陷」（**主修**）

**问题**：plan v3.2 的 R1 把 `seed` 同时施加在 ① `RunEvent` 的事件期输出、② `Handoff` 的 `ded_old`、
③ `Handoff` 的 `pct_ded_`，其中 ② 的符号与 ① 相反。而 `ded_old` 的语义是
「事件期末帧**实际施加**的扣除」，它随后被用来反解 `g_` 并被慢相继承 ⇒ 交接当帧二者不相等。

**实测**（`--seed-gain 1.0`，245.31 s 重载）：`ded` 由 248.60 s 的 **+2298** 跳到 248.80 s 的 **−81**，
显示被 C 限幅顶在 `raw×1.005` 上，再花约 3 s 由 PCT 慢慢爬回（250.0 s +875 / 251.8 s +2199）。

**改法**：

```cpp
// RunEvent：seed 折进目标电平（唯一施加点）
const double seed_now = std::max(ev_.seed_used, 0.0);
const double target   = ev_.base_y + ev_.a_hat - seed_now;
// 事件期输出不再单独 += (−seed)
// Handoff：ded_old = −(share·c_applied)  ← 就是实际扣除，不再加 seed
// Handoff：删除 pct_ded_ 的 seed 写入；SlowStep 里那段 seed 施加也删除（本就因 ev_ 已清空而是死代码）
```

**效果**：交接处严格连续（248.20 s +2333 → 248.60 s +2807），245.31 s 重载的补偿
由 v3.2 的 **+1175** 变为 **+2832**。

### R2.2 seed 的作用域（`v36_b`，默认 0 = 保持 v3.2 语义）

v3.2 只对「`Onset` 且从 `Idle` 起跳」的事件注入 seed（= 真正完全卸载后的重载），
对「短保压后的部分卸载 → 重载」（`Restep`）不注入。本轮把它做成开关：

- `v36_b = 0`（**默认**）：与 v3.2 同作用域。前 240 s 的行为**逐位不变**，副作用最小。
- `v36_b = 1`：所有加载事件（Onset/Restep/RestepReload）都注入。同负载一致性更好
  （前后差 −353 vs −26，见验收报告），但会改变**前段**行为、并在同族录制
  `archived/零基线-反复增减同一负载/…152749` 上把 ded 中位由 3334 抬到 4296、G 由 0.971 掉到 0.783。
  ⇒ **不建议默认开启**，留作「一致性优先」备选。

### R2.3 会话蠕变比 `r` 的记忆不被退化片段拖小（`v36_c` / `v36_d`）

- `r`（会话级 `ded/A`）是 R1 用来算 seed 的量。v3.2 用对称 EMA（τ=30 s）更新，
  当某个 episode 因为锚定失败而使 `ded/A` 变小时，`r` 会被拖小 ⇒ 下一次 seed 更小 ⇒ 更退化（自激下降）。
- 本轮：`v36_d > 0` 时，**下降用更慢的时间常数**（推荐 **400 s**），上升仍用 30 s。
  实测（`--seed-gain 1.0`，四次重载 E6~E9 的 ded）：

  | 臂 | E6 | E7 | E8 | E9 | 同负载组前后差(out) | `r` 末值 |
  |---|---|---|---|---|---|---|
  | 对称（`v36_d=0`） | 2 763 | 2 192 | 1 893 | 1 724 | −195 | 0.168 → **0.150** |
  | **`v36_d=400`** | 2 832 | 2 254 | 2 039 | 2 002 | **−26** | 0.168 → **0.178** |

  ⇒ 单侧记忆让 `r` 在整段多次重载中保持稳定（对称更新会缓降 11%），四次重载的补偿量抬高约 70~280 ADC。
  200 / 400 / 800 s 三档结果接近（前后差 −76 / −26 / −33），取中值 400 s。
- `v36_c`：空载期 `r` 的衰减时间常数；**默认 0 = 不衰减**（与 v3.2 的实际行为一致）。
  理由：本录制的空载间隙只有 3~7 s，粘弹性蠕变几乎不恢复；而「记忆被抹掉」会直接让后续重载失去一致锚定。
  若现场存在**长时间空载**（分钟级），应设 `v36_c = 60~120`。

## 2. 推荐参数（= `src_v36/` 的默认值 + 运行时注入值）

| 参数 | 采用值 | 说明 |
|---|---|---|
| `creep_seed_gain` | **1.0** | v3.2 取 0.7 是为了掩盖交接塌陷；修掉塌陷后 1.0 最优（物理口径：增量的蠕变 = r×增量） |
| `v36_b` | **0** | seed 作用域 = 从 Idle 起跳的 Onset（前段逐位不变） |
| `v36_c` | **0** | 空载期 `r` 不衰减（短时卸载恢复量有限） |
| `v36_d` | **400 s** | `r` 的下降时间常数（200/400/800 s 三档结果接近，取中） |

> 复现命令：`python v36_ab.py "v36:--seed-gain:1.0:--v36-d:400"`。
> `src_v36/` 里的 `kV36A..kV36D` 默认仍是占位 0，**实际取值由运行时注入**
> （与产品现状一致：产品链路只调用 `Process`，参数只在录制 manifest 里被读出——
> 若落地，应把上表写进 `Params` 的默认值）。

## 4. 与 plan v3.4（**已落地产品**）的关系

本轮进行到一半时，另有会话把 **plan v3.4「卸载-重载蠕变记忆（creep-mem）」** 落地进了
`src/domain/drift_v6/drift_v6_compensator.{h,cpp}`（`param_set = "plan-v3.4 creep-mem"`，16 字段），
它解决的是**同一个问题**。本轮的定位相应调整为：

1. **独立复核 v3.4**（用本桶自己的口径重跑 `v34_runner.exe --mem 0/120`）：
   同负载组极差 2559 → **1110**、家族 A（E2~E5）逐位相同、245.31 s 补偿 −85 → **+1988**、
   C 限幅 0 越界、`零负载-随机切换工况` 显示下移 ≈1250 —— **与 v3.4 的自报结论一致**（见验收报告 §4）。
2. **v3.4 不含 v3.2 R1 的交接塌陷**：它把记忆同时折进「事件滑行目标」与「交接锚定」两处且取值一致，
   正是本轮 R2.1 的纪律。⇒ **v3.2 的 R1 补丁不可回退使用**。
3. **v3.6 作为机制不同的备选**：在同一录制上前/后系统差更小（−26 vs −428）、
   对两条域外录制副作用更小（`零负载-随机切换` ded +506 vs +1247、G 不变 vs −0.069），
   但组内极差略大（1231 vs 1110）。
4. **禁止两条机制同时上**（叠加会重复扣减）。若要合并，以 v3.4 的记忆为主，
   把 R2.1 的「施加点唯一化」作为硬约束保留。

> 说明：本桶候选 `src_v36/` 的基线是 `plan/v3.2/src_v32/`（当时的最新候选），
> **不是**当前的 v3.4 产品源码。二者是**并列的两种机制**，不是前后版本关系。

## 5. 未关闭项 / 已知边界

| # | 事项 | 状态与建议 |
|---|---|---|
| 1 | **只在本条录制 + 数据根下 8 条做离线回放** | 未做真机 A/B、未做界面手测；`creep_seed_gain=1.0` 与 `v36_d=400` 只在本录制上扫过 |
| 2 | **E6（245.31 s 重载）仍比其它同负载平台低约 900 ADC** | 该时刻 `r=0.165`（被 219.5 s 那次部分卸载 episode 抬高），而稳态 `r≈0.135`。属「首次重载略过补偿」，量级 6% 电平；已在验收报告里如实报出 |
| 3 | **`零负载-随机切换工况`（域外）ded 中位 261 → 767** | 该录制本身就是 v6 的域外工况（零负载下随机切换）。G 未变（0.982），但补偿量被抬高；真机若观感变差，把 `creep_seed_gain` 降到 0.7/0.5 |
| 4 | **`v36_c`（空载衰减）在长空载工况下必须设非 0** | 默认 0 的隐含前提是「空载间隙 ≪ 蠕变恢复时间常数」；分钟级空载需要实测标定 |
| 5 | **`r` 的口径是"算法自证"的** | `r` 由 `ded/A` 得到，而 `A` 又由 `r` 决定 ⇒ 存在自洽不动点（本录制收敛到 `ded/A≈0.15`，与独立估计的蠕变比同量级，未发散）。物理上更严格的 `r` 需要独立的材料实验（阶跃 + 分级卸载）标定 |
| 6 | **未落产品代码** | 本轮只交付候选 `src_v36/`。**当前产品里已经落地的是 plan v3.4 的记忆机制**（见 §4），若要采用本轮的机制，需按 README §5 的说明叠加到 `src/domain/drift_v6/`，并同步 `01`/`02`/`MANIFEST`/`CHANGELOG`/`project_summary`；**不要与 v3.4 的记忆同时启用** |
| 7 | `零基线-反复增减同一负载/…152749`（同族录制） | G 0.971 → 0.892（ded 中位不变 3334 → 3363）；v3.4 在同录制上为 0.901。两臂同性质，需真机确认是「补偿正确」还是「过补偿」 |
| 8 | **v3.6 与 v3.4 未做机制级取舍的最终裁决** | 两者规模相当、各有胜负（v3.4 组内极差更好、v3.6 前后系统差与域外副作用更好）。建议以已落地的 v3.4 为主线，v3.6 作为交叉验证备选；最终取舍需真机数据 |
