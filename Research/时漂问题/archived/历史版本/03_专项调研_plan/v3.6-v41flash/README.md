# plan v3.6 · 一致性修复（针对 `零基线-反复增减同一负载` 的「丢基线」）

> 本轮主题：**让「同一个负载」在全录制范围内显示同一个电平**。
> 用户报告：「245 s 之后的数据，按理说其形状应该类似 15 s 之后的数据，……导致丢失了基线」，
> 并指出「后续没有补偿的位置和前面有补偿的位置差别比较大」。
>
> **结论一句话**：现象成立且比 245 s 一处更广（240 s 之后的**每一次**加载都拿不到补偿）；
> 根因两条——① 交接锚定口径，② **plan v3.2 的 R1 补丁自身的「交接塌陷」缺陷**。
> 本轮修好后同一负载的显示电平前后差 **−2135 → −26 ADC**，且前 240 s 逐位不变。
>
> ⚠️ **重要**：在我做这一轮的同时，另有会话把 **plan v3.4「卸载-重载蠕变记忆（creep-mem）」**
> 落地进了产品源码，它解决的正是同一个问题，并且**没有犯 v3.2 的交接塌陷错误**
> （记忆同时折进「事件目标」与「交接锚定」，两处一致）。因此本桶的定位是：
> **独立复核 v3.4 ＋ 给出同口径的第三方判据 ＋ 提供一条机制不同的等价候选**。详见 §5。
>
> 交付形态：`src_v36/` 候选源码（由 `scripts/make_v36_variant.py` 生成，**产品 `src/` 一行未动**）
> + 离线回放 A/B + 跨数据集核查 + 效果图。
> **未做真机 A/B、未改产品代码、未写单元测试**（按项目规范）。

## 3. 三条结论

1. **现象**：240.11 s 完全卸载之后**每一次**加载的补偿都≈0（E6 +18、E7 +58、E8 −85、E9 −22），
   此前为 +1156~+2258 ⇒ 后 66 s 算法实质没有输出。同一负载的显示电平前后差 **2135 ADC（12% 电平）**。
2. **定因两条**：
   - **根因 A（交接锚定口径）**：`Handoff` 的 `A_new = y0 + share·Â` 隐含「`Â` 不含蠕变」，
     而 `InvEst` 把 `Â` 的下界钉在实测增量上 ⇒ 完全卸载后重载时 `A` 落到读数电平上，
     `g_raw≈0`、PCT 残差≈0 ⇒ 补偿恒 0 且沿链条复现。
     **交接帧对账证明「阶跃被正确拿到」**（`Â`/`inc_max` 与外部实测落定增量只差 1.1%）——
     用户猜的「没有正确拿到阶跃」不成立，是**拿到之后用错了**。
   - **根因 B（plan v3.2 的 R1 缺陷，本轮新发现）**：R1 的 `seed` 同时施加在
     ① `RunEvent` 输出、② `Handoff` 的 `ded_old`、③ `Handoff` 的 `pct_ded_` 三处，
     ② 的符号与 ① 相反，而 `ded_old` 的语义是「事件期末帧**实际施加**的扣除」⇒
     **每次带 seed 的交接都把扣除量打成负值**（248.60 s `ded`=+2298 → 248.80 s `ded`=−81，
     显示被 C 限幅顶在 `raw×1.005` 后花约 3 s 爬回）。这才是 v3.2 只测到「72% 补偿」的真实原因。
3. **修法（R2.1/R2.2/R2.3）**：seed 只折进事件目标一处（交接自然连续）；
   seed 作用域做成开关（默认与 v3.2 同，前段逐位不变）；会话蠕变比 `r` 改单侧记忆。
   **结果**：同负载组前后差 −2135 → **−26**，极差 2559 → 1231；前 240 s 与 3 条无关录制逐位不变；
   C 限幅仍 0 越界；长保压平坦度不变。

## 5. 与 plan v3.2 / v3.4 的关系

| | plan v3.2 | **plan v3.4（已落地产品）** | plan v3.6（本轮） |
|---|---|---|---|
| 机制 | 会话级蠕变**比** `r` × 实测增量，事件期单独加 seed | **蠕变记忆快照**：Decrease 当帧记下总扣除向量，重载时按电平比 `s` 与 `e^(−Δt/120 s)` 折减，**以残差口径**补齐 | 同 v3.2 的机制族（`r`×增量），但**修掉交接施加方式**，并让 `r` 单侧记忆 |
| 施加点 | 三处（**含符号错误**） | **两处且一致**：事件滑行目标 `target = base_y + Â − mem` 与交接锚定 `A = y0 + share·Â − mem` | **一处**：seed 折进 `target`，锚定与扣除自然一致 |
| 245 s 补偿 | +559~+1175（塌陷后残值） | +1 988 | +2 832 |
| 同负载组极差 | 2 558 | **1 110** | 1 231 |
| 前后差 | −1 456 | −428 | **−26** |
| 跨数据集副作用（8 条） | 见 v3.2 报告 | 6 条有变化（`零负载-随机切换` ded 中位 261 → **1 508**、G 0.982 → 0.913；`从零基线开始…反复加减` −68 → +11） | 5 条有变化（同一条 ded 261 → **767**、G **不变**；`从零基线开始…反复加减` **逐位不变**） |
| 状态 | 候选 | **已落地 + 已增量构建**（另有会话完成） | 候选（未落地） |

**本轮对 v3.4 的独立复核**（我用自己的口径重跑了 `v34_runner.exe --mem 0/120`）：

- `--mem 0` 与 plan v3.1 在 8 条录制上**逐位相同** ⇒ 我的 v31 臂与 v3.4 的 OFF 臂是同一个东西，口径可比；
- `--mem 120` 复现了 v3.4 报告的方向与量级：目标录制同负载组极差 2559 → 1110、
  家族 A（E2~E5）**逐位不变**、C 限幅 0 越界、长保压 pk-pk 不变；
- 也**独立确认了它的副作用**：`零负载-随机切换工况` 显示整体下移（ded 中位 261 → 1508，
  v3.4 报告写「下移 ~1200」，一致）；`各种奇怪工况` ded 中位 19 → 239；`f9740b` −68 → +11。

**结论与建议**：

1. 用户的原始问题**已由 v3.4 解决**（若尚未跑真机，请直接按 `../v3.4/问题清单.md` §5 做真机 A/B）。
2. v3.4 的实现**没有** v3.2 R1 的交接塌陷问题——它把记忆同时折进「事件目标」与「交接锚定」，
   这正是本轮 §2 根因 B 的教训。**v3.2 的 R1 补丁不能回退使用。**
3. v3.6 可作为**交叉验证 / 备选**：机制不同（会话比 vs 快照记忆），在同一录制上前后差更小（−26 vs −428）
   且对两条域外录制的副作用更小（`零负载-随机切换` ded +506 vs +1 247、G 不变 vs −0.069）；
   代价是同负载组极差略大（1 231 vs 1 110）。
4. **建议不要两条机制同时上**（叠加会重复扣减）；若要合并，应以 v3.4 的记忆为主，
   把 R2.1（施加点唯一化）的纪律作为硬约束保留。
