## 2. 定因链（源码级）

### 定因 A：交接把"无蠕变电平"锚在 `y0 + Â`，而 `Â` 是**含蠕变**的实测增量外推 ⇒ 重载时 A 落到读数上，`g_raw ≈ 0`、扣除恒 0

- `Handoff()`：`.cpp:801-802`
  `Eigen::VectorXd A_new = (ev_.y0 + share * std::max(ev_.a_hat, 0.0)).cwiseMax(0.0);`
- `InvEst()`：`.cpp:264-268`
  `const double inc = hist.back().second;` → `a = std::max(a, inc);` → `*a_out = std::min(a, kappa * inc);`
  即 `Â` 的**下界 = τ≈1 s 处的实测增量**，上界 = `κ·inc`（onset `kKappaOnset = 1.05`，`.h:156`）。
- 后果（`plan/v3.6-v41flash/分析报告_245s丢基线.md` §3）：

| | 首次加载（3.30 s） | **重载（245.31 s）** |
|---|---|---|
| 交接后 `A_ho` | 12 068 | **17 048** |
| 交接当帧输入 | 12 645 | 17 007 |
| `g_raw = median((v_i − A_i)/A_i)`（`.cpp:917`） | **+0.45** | **≈0** |
| 后段 ded | +2 232（E5 同负载） | **−85 ~ +58** |

- 这条是**自我延续**的：慢相扣除全部是 `g`（`.cpp:948-953`）与 PCT 残差（`.cpp:958-979`）的函数；`A` 落在读数上 ⇒ `g_raw ≈ 0`、`pct` 残差 ≈ 0 ⇒ 补偿恒 0；此后每次卸载-重载都从同一口径重新锚定，而 `Reanchor`（`.cpp:867`：`A_new = (vs - ded_tot).cwiseMax(0.0)`）又用"沿用上一段扣除"把 ≈0 的扣除固化。

### 定因 B：整片卸载走 `Decrease → Reanchor → ToIdle` 会**清空全部慢相状态**，血统被剪断

- `RunEvent` 的 Decrease 分支 `.cpp:625-650`：沉降窗（`kDecreaseSettleS = 0.30`，`.h:178`，从**检测时刻** `ev_.t_det` 起算，`.cpp:630`）内保持上一段扣除，之后 `ev_ = EventCtx(); state_ = State::Slow; Reanchor(ts, v); ev_block_until_ = ts + kUnloadBlockS;`（`.cpp:643-647`）。
- `ToIdle()`：`.cpp:884-894` —— 清 `loaded_`、`pct_elig_`、`pct_ded_`、`g_`。
- 触发路径有二：事件内 C4 出口 `.cpp:610-614`（`tau > kUnloadFastS(0.30)` 且 `idle_now`）与 Slow 态出口 `.cpp:487-490`（`idle_now && ts - ev_end_ > 0.30`）。
- `plan/v3.4/问题清单.md` §2 的现场轨迹：240.08 s 确认 Decrease（此时输入已塌到 1841）→ 240.42 s Reanchor → **240.86 s ToIdle**（清空 `pct_ded_/A_/g_/掩码`）；244.3~245.9 s 重载作为**全新 Onset** ⇒ 整段受载历史（239 s）累积的 ~2 000 ADC 蠕变补偿被遗忘。
- 对比：15 s 一族的"形状好"是因为它走 **Restep/RestepReload**，靠 `y0/c0` 继承保持扣除连续（`NewEvent` 的 `ev_.c0 = ev_.base_y - base`，`.cpp:523`；`.cpp:718` 的 `c_target = ev_.c0*(1-w) + (target-total)*w`）。**机制没坏，坏的是整片卸载后没有等价的记忆**。

### 定因 C（现场 v3.0 专有）：交接瞬间补偿被"自己抹掉"，再用约 3 s 爬回——而统计窗口只看到爬回前的空档

`plan/v3.6-v41flash/分析报告_245s丢基线.md` §4，臂 = v3.2 等价配置（`--seed-gain 1.0`）逐帧证据：

| t | state | `A_sum` | `seed_used` | ded |
|---|---|---|---|---|
| 248.20 | Event | 1 607 | 2 359 | **+2 258** |
| 248.60 | Event | 1 607 | 2 364 | **+2 298** |
| **248.80** | **Slow（交接）** | **14 680** | 0 | **−81** |
| 249.00 | Slow | 14 680 | 0 | −81（被 C 限幅顶住） |
| 250.00 | Slow | 14 680 | 0 | +875（PCT 从地板重爬） |
| 251.80 | Slow | 14 680 | 0 | +2 199（≈3 s 后才爬回） |

机制：seed 被施加在三处（`RunEvent` 事件期输出、`Handoff` 的 `ded_old`、`Handoff` 的 `pct_ded_`），其中 `ded_old` 那处**符号相反**；而 `ded_old` 的语义是"事件期末帧**实际施加**的扣除"（它随后被用来反解 `g_`：`.cpp:826-831`，并被慢相继承）⇒ 交接当帧扣除与事件期末帧不相等，差约 2~3×seed。
**这条属于 v3.2 候选臂的缺陷，但它解释了「为什么只测到 245 s 重载补偿 +1175（首次加载的 72%）」——那不是 gain 取小了，而是补偿在交接瞬间被自己抹掉、只有残值被窗口统计到。**

> 当前源码 v3.4 里没有 `seed`，改成了 `CreepMemory`（`.cpp:772-791`）在 `Handoff` 里以**同一残差口径**下移 `A_new`（`.cpp:805-810`），
> 因此该条在 v3.4 上不再以同样形态出现；**但"交接点扣除连续性是唯一不能出错的约束"这一点仍然成立**（`plan/v3.6-v41flash/问题清单.md` §1）。

### 定因 D（当前源码 v3.4 仍有）：记忆快照抓到的是"已被侵蚀 12% 的扣除"，且单调不缩水把它锁死

- 快照点 `.cpp:451-467`，取 `DeductionVector()`（`.cpp:756-765`，rank-1 + PCT）。
- `kFreezeSlowOnHit`（`.h:255`，用于 `.cpp:380`、`.cpp:919`、`.cpp:961`）只挡**确认之后**的侵蚀；确认之前 `g_`（EMA τ=3 s，`.h:195`、`.cpp:923`）已经掉了一截。
- 实测：`plan/v3.4/results/v34_replay_mem_on.txt` 第 13 行（239.05 s，沿前）= `ded 2295`；第 16 行（240.08 s，检测当帧快照）= `ded 2030` ⇒ **一次侵蚀 −265 ADC / −12%**。
- 单调不缩水 `.cpp:454-459`（`mem_ded_ = cap.cwiseMax(mem_ded_ * decay)`）本意是防逐代缩水，但它同时保证**偏小的 cap 不被纠正**；`mem_valid_` 仅在 `.cpp:465-466` 的 `|mem_ded_|.sum() <= eps` 时失效 ⇒ 偏小值一路带下去。
- 另有采样侧问题：`mem_lv_` 取 `lv_ref`（`.cpp:452`），而 `lv_ref` 来自参考窗 `[t−0.65, t−0.35]`（`.cpp:353-354`）——在多级台阶卸载（本工况 239.1~240.6 s、四级 ~1.5 s）时它落在**塌落中间电平**上，于是 `CreepMemory` 的缩放 `s = clamp(lv_now / mem_lv_, 0, 1)`（`.cpp:780`）被打错折，而**外部完全看不出**。

### 定因 E（结构风险，未在本录像触发但必须记）：`ToIdle` 与 Decrease 快照存在顺序竞争

- Decrease 事件只在 `else if (hit && d < 0 && state_ != State::Idle && !ev_.valid)`（`.cpp:431`）建立，快照在 `.cpp:451`；而 `ToIdle()` 可由 C4 出口（`.cpp:610-614`）或 Slow 出口（`.cpp:487-490`）在**同一帧更早**执行。
- 检测需 `|d| > max(thr_d, tail_gate)`（`.cpp:369-377`）+ 3 帧确认（`.cpp:384`）；慢速/渐进卸载时确认可能**晚于** C4 出口。
- 一旦 `ToIdle()` 先跑：`ev_` 被清、`loaded_/pct_elig_` 归零、`pct_ded_` 清零（`.cpp:884-890`），本帧再也进不了 `.cpp:431` ⇒ **`mem_ded_` 不更新**，下一次 Onset 的 `ev_.use_mem`（`.cpp:529-530`）为假 ⇒ **直接退回 plan-v3.1 的"全新 Onset、零记忆"**（差 ~2 000 ADC 的最坏形态）。

## 4. 基线结论（一句话）

**基线没有被"算错"，是被"剪断"了**：15 s 一族之所以有扣除，是因为它继承了 2.4 s 起就一直压着的 load1 的累计蠕变（ded 从 1 073 → 1 565 → 2 017 → 2 265 逐代增长，属**正确行为**）；245.27 s 的重载从 Idle 出发，锚点只由形状反演给出（`A ≈ y0 + Â`，`.cpp:801`），没有这条血统，且交接后 `g_raw ≈ 0` ⇒ 扣除 ≈ 0。用户看到的"基线丢失"= **同负载两族显示的约 2 135 ADC 差**（v3.0/v3.1 口径）。
