## 1. 候选 plan-v3.6 改了什么（三条）

来源：`temp/v4.1flash/plan/v3.6-v41flash/问题清单.md` §1。

### R2.1（主修）seed 只在一处施加 —— 修掉「交接塌陷」

**问题**：`plan-v3.2` 的 R1 把 `seed` 同时施加在
① `RunEvent` 事件期输出、② `Handoff` 的 `ded_old`、③ `Handoff` 的 `pct_ded_`，其中 ② 的符号与 ① **相反**。
而 `ded_old` 的语义是"事件期末帧**实际施加**的扣除"（它随后被用来反解 `g_` 并被慢相继承）
⇒ 交接当帧扣除与事件期末帧不相等，差约 **2~3×seed**。

逐帧证据（`plan/v3.6-v41flash/分析报告_245s丢基线.md` §4）：`ded` 由 248.60 s 的 **+2 298** 跳到 248.80 s 的 **−81**，显示被 C 限幅顶在 `raw×1.005`，约 3 s 后由 PCT 爬回 +2 199。

**改法**（对应当前源码的同位代码）：

```cpp
// RunEvent：seed 折进目标电平（唯一施加点）
const double seed_now = std::max(ev_.seed_used, 0.0);
const double target   = ev_.base_y + ev_.a_hat - seed_now;
// 事件期输出不再单独 += (−seed)
// Handoff：ded_old = −(share·c_applied)   ← 就是实际扣除，不再加 seed
// Handoff：删除 pct_ded_ 的 seed 写入
```

**效果**：交接处严格连续（248.20 s +2 333 → 248.60 s +2 807），245.31 s 重载补偿由 v3.2 的 **+1 175** 变为 **+2 832**。

### R2.2 seed 的作用域（`v36_b`，默认 0 = 与 v3.2 同作用域）

只对「`Onset` 且从 `Idle` 起跳」的事件注入 seed；对「短保压后部分卸载 → 重载」（`Restep`）不注入。
`v36_b = 1` 使同负载一致性更好（前后差 −353 vs −26），但会改变前段行为、并在同族录制上把 ded 中位由 3 334 抬到 4 296、G 由 0.971 掉到 0.783 ⇒ **不建议默认开启**。

### R2.3 会话蠕变比 `r` 的记忆不被退化片段拖小（`v36_c` / `v36_d`）

- `r`（会话级 `ded/A`）是 R1 用来算 seed 的量。v3.2 用对称 EMA（τ=30 s）更新，某个 episode 锚定失败会把 `r` 拖小 ⇒ 下一次 seed 更小 ⇒ **自激下降**。
- `v36_d > 0`：下降用更慢的时间常数（推荐 **400 s**），上升仍用 30 s。实测不加时 `r` 由 0.17 掉到 0.08。
- `v36_c`：空载期 `r` 的衰减时间常数，**默认 0 = 不衰减**（本录制空载间隙只有 3~7 s，粘弹性蠕变几乎不恢复）。

### 推荐参数（= 候选的运行时注入值）

| 参数 | 采用值 | 说明 |
|---|---|---|
| `creep_seed_gain` | **1.0** | v3.2 取 0.7 是为了掩盖交接塌陷；修掉塌陷后 1.0 最优 |
| `v36_b` | **0** | seed 作用域 = 从 Idle 起跳的 Onset（前段逐位不变） |
| `v36_c` | **0** | 空载期 `r` 不衰减 |
| `v36_d` | **400 s** | `r` 的下降时间常数（200/400/800 三档接近，取中） |

> `src_v36/` 里的 `kV36A..kV36D` 默认仍是占位 0，**实际取值由运行时注入**；若落地，应写进 `Params` 的默认值并同步 `data_handler.cpp` 的 `param_set` / 字段落盘。

## 2. 与当前源码 v3.4 的机制关系（不要误以为 v3.6 是"v3.4 的下一版"）

| 维度 | v3.4（现役源码） | v3.6（候选） |
|---|---|---|
| 恢复重载补偿的手段 | `CreepMemory()`（`.cpp:772-791`）向量补齐：`mem_ded_ · s · e^(−Δt/τ_mem)`（`kMemTauS = 120`，`.h:269`；`kMemMaxFrac = 0.5`，`.h:270），在事件滑行目标（`.cpp:697-702`）与交接锚定（`.cpp:805-810`）**两处**下移 | `seed = gain · r · inc_max` 标量补齐，**只折进事件期目标一处** |
| 施加点数 | 2 处（目标 + 锚定）。两处用同一残差口径，实测交接后 `A = 15234 / ded = 2009` 连续，**未见塌陷形态** | 修掉 v3.2 的 3 处施加（其中一处反号） |
| 记忆载体 | 逐通道向量（可处理"哪条通道在蠕变"，与 PCT 的空间分布一致） | 单个会话标量 `r`（不能区分通道） |
| 已知残留缺陷 | 快照抓到的是"已被侵蚀 ~12% 的扣除"（定因 D）；`ToIdle` 与快照存在顺序竞争（定因 E） | 未在本轮评估这两条 |

**结论**：v3.6 的证据链（前后差 −2 135 → −26）建立在 **v3.1/v3.2 血统**上；
v3.4 已经用另一条机制（向量记忆）拿到"残余 ~600 ADC / 显示极差 2 516 → 1 018"。
⇒ 若要让 v3.6 的收益落到产品，**必须先决定是"移植 seed 到 v3.4"还是"回退到 v3.1 血统再叠 v3.6"**，二者不能直接相加。
