**算法语义**（PCT = Per-Channel Tracking）：

```text
每帧（仅慢相态 SlowStep）：
  ① rank-1 扣除不变：ded_rank1_k = clamp(γ_k·A_k·g, −0.5·A_k, 1.5·A_k)   （loaded_ 通道）
  ② PCT 慢环（dt>0 才积分；**输出施加与 dt 无关**）：
        resid_k = (v_k − A_k) − ded_rank1_k − pct_k
        pct_k  += (dt/τ)·resid_k ,  τ = 10 s ,  pct_k ∈ [−0.5·A_k, 4.0·A_k]
        作用通道：A_k > 2%·maxA（比 loaded_ 的 10% 宽）
  ③ out_k = v_k − Capped(v_k, ded_rank1_k + pct_k)
```

- 目标：让每个通道的显示收敛到 `A_k`（交接时刻钉住的无蠕变电平），即"恒定负载 ⇒ 显示不飘"。
- `pct_hi_frac = 4.0` 是实测选定的：末帧逐通道快照显示残余漏扣集中在
  **蠕变超过 2×A_k 的通道**（ch1 creep 160 / A=45、ch2 creep 133 / A=31），放到 4.0 正好放开；
  4.0 → 8.0 无进一步收益，且 2.0 → 4.0 在其余 17 条录制上**逐位相同**。
- **`pct_tau_s = 0` 时整段不执行 ⇒ 逐位回到 `plan-v2.0 C+F5` 行为**（可一行回退）。

## 4. 已知代价与未关闭项

| # | 内容 |
|---|---|
| **C1** | **右拇指指尖/数据3 轻微反向**（保压偏离 0.0371→0.0402，+8%）。该录制输入偏离 0.1858、算法补偿量本身就很小，属低信噪场景。若需消除，可把 `pct_elig_frac` 由 0.02 提到 0.05 试。 |
| **C2** | **振荡工况中性但未解决**。`各种奇怪工况/f40a1b` 的根治在上游（同一 `elapsed` 压 1~4 帧、组内 `timestamp` 跨度中位 0.01 ms，算法拿不到"这几个值分别发生在什么时候"），与 plan v2.0 §9.5 的结论一致，本轮未投入。 |
| **C3** | **"冻结显示"是 PCT 的机制性代价**：PCT 会把显示拉向交接时刻的电平。若现场加载后存在**真实的缓慢加载**（如持续加压），PCT 会把它当作蠕变吸收掉一部分。判据上它与蠕变不可分，只能靠检测器/事件重锚（已在链路里）。**建议真机 A/B 时专门做一次"慢加载"工况。** |
| **C4** | **回归锁单测未加**（按 `AGENTS.md` 禁止构建 `test_*` 目标）。方案见 `问题清单.md` N2。 |
| **C5** | **未做真机/界面手测**（按规范交用户）。 |
| **C6** | 指标重定义：本轮引入**"保压偏离"**（保压期内显示相对"加载后落定电平"的偏离 / 台阶）作为决定性口径，因为"末段−首段漂移"会被"先冲高再回落"的驼峰骗过（实测 `--loaded-frac 0.05` 即为此例）。**与 plan v2.0 的 `resid/lead/G/offabs` 四联口径不可直接横比。** |
