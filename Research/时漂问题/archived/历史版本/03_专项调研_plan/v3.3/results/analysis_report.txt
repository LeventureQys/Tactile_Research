v3.3 算法优化分析报告
======================================================================

1. 问题描述
----------------------------------------
在「零基线-反复增减同一负载」数据集中，
245s附近的加载事件与15s的首次加载相比，一致性差距较大。

2. 根因诊断
----------------------------------------
PCT(逐通道蠕变跟踪)在长保压期间累积了大量扣除(-2395 ADC)。
这些扣除量在卸载-重加载循环中的传递不一致：
  - 经历长保压后的加载段：带着大量PCT累积量（高扣除）
  - ToIdle后的新加载段：PCT被清零（零扣除）
  - 同一负载在前后的显示差值：~2400 ADC

3. 实测数据关键数字
----------------------------------------
  算法偏差(seg-pre)时间演化：
    t=0s:    0 ADC（空载直通）
    t=10s:  -791 ADC（快相补偿开始）
    t=30s:  -1401 ADC
    t=60s:  -1783 ADC
    t=100s: -2195 ADC
    t=200s: -2451 ADC
    t=242s: 0 ADC（ToIdle清零）
    t=246s: +79 ADC（新加载，PCT重新积分）
    t=265s: +45 ADC

  卸载后空载段残留：
    t=240-245s: seg偏移 +185 ADC（vs 原始零基线）
    t=256-258s: seg偏移 +152 ADC
    t=276-278s: seg偏移 +233 ADC
    （这些残留来自pre本身的蠕变残留，不是算法导致的）

4. 优化方案
----------------------------------------
推荐方案：PCT加入自然衰减 + Reanchor时衰减

  具体修改（drift_v6_compensator.cpp 的 SlowStep）：
    在PCT积分更新后追加一行衰减：
    pct_ded_(k) *= (1.0 - dt / kPctDecayTauS);  // 新常量

  新增常量：
    kPctDecayTauS = 45.0;  // PCT自然衰减时间常数(秒)

  效果预估（基于数值模拟）：
    - 短保压(<20s)：几乎不影响（衰减<35%）
    - 中保压(60s)：PCT累积量从2034减至1485（-27%）
    - 长保压(150s)：PCT累积量从2477减至1907（-23%）
    - 跨事件一致性显著改善
    - 代价：长保压尾段的蠕变补偿效果略降
