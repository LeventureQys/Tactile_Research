# K12 v2 零上下文迁移指南

**状态：离线研究候选，不是已定版的产品算法。** 本文档面向从零实现者，完整给出输入输出、K9底座、K12 v2事件账本、默认参数、边界行为和复验方法；实现不要求接收者拥有本研究仓库、Python插件或数据解析工具。文末路径仅用于原作者交叉核对，不参与算法运行。

## 1. 算法要解决什么

输入是触觉阵列每帧各测点的**算法输入阶段ADC显示值**，不是原始整数ADC，也不是映射后的力值。K9使用逐通道零点、快态`x_fast`、慢态`x_slow`估算并扣除蠕变，但在慢态可以积分的情况下，分布在多个通道的微小真实荷载变化可能逐渐被吸收。K12 v2在K9外围增加一个**总值检测、逐通道记账**的事件层：

```text
输入向量 v_i ─→ 因果小变化检测 ─→ 逐通道账本 L_i ─→ v_i−L_i ─→ 原样K9 ─→ +L_i ─→ 输出 z_i
```

大加载后抑制小事件检测，候选事件须持续确认；检测层只改变K9的**输入背景**，不改K9的参数公式。K12**没有替换K9**。关闭账本时输出等于所采用的K9实现。

已经验证的只是受控输入中100ADC小阶跃的保护能力，**未证明**真实10g操作全部可识别、恒载漂移达标或算法可以直接写入设备。

## 2. 运行契约

### 2.1 输入与输出

- `v_i`: 每帧长度固定为`M`的`float64`数组；只含有效测点，通道顺序在整个会话内固定。K12和K9必须使用完全相同的顺序和数值域。
- `t_i`: 对应秒制时间轴；正常要求严格递增。时间原点任意，但一次运行内不可重置。录制回放可用`frame_index/observed_fps`，真实产品应使用采集时间戳。不同时间轴可能导致不同结果。
- `p9`: 下表列出的K9参数，必须记录且同一A/B实验保持不变。
- `p12`: 账本参数，详见第3节。
- 输出`z_i`长度为`M`，总ADC为`Σ_k z_i[k]`。可选诊断：累计账本`L_i`、事件时间/方向/各通道增量/实际确认阈值、抑制窗和冷却窗状态。

**状态实例一设备一会话**。设备、布局、通道数、输入单位或K9参数变化时，新建整套K9和K12状态；不同设备不得共享状态。启动帧保留原始输入语义。函数应接受空序列的明确处理（返回空结果），不要访问`v_0`。

### 2.2 一帧更新顺序

原型按两遍回放：先把整个输入计算成`b_i=v_i−L_i`与账本序列，再对`b_i`逐帧执行K9，最后`z_i=K9(b)_i+L_i`。**这并非需要未来数据的非因果算法**：两层状态均只依赖到当前帧，可在产品中做成单遍流式管线，严格保持“更新账本→产生背景→K9处理背景→加回当前账本”的顺序。不能先让K9处理`v_i`再补账本。

## 3. K12 v2 默认参数与状态

| 参数 | 默认 | 单位 | 当前实现语义 |
|---|---:|---|---|
| `enabled` | true | — | false时直接运行K9，不更新账本 |
| `window_s` | 0.25 | s | 最近原始帧的**矩形算术均值**窗口，不是中值滤波 |
| `separation_s` | 0.50 | s | 当前短窗均值与历史短窗均值间隔；允许近似5% |
| `threshold_total_adc` | 45 | 总ADC | 小事件总值变化绝对阈值 |
| `noise_multiplier` | 4 | — | 动态阈值乘数 |
| `drift_tau_s` | 8 | s | 慢趋势斜率的一阶低通时间常数 |
| `confirm_s` | 0.35 | s | 初次越阈后的**再确认等待**；不要求每一帧连续越阈 |
| `large_step_adc` | 2000 | 总ADC/帧 | 当前帧与上一有效帧的总值跳变门限 |
| `large_freeze_s` | 8 | s | 大跳变后抑制微小事件检测 |
| `refractory_s` | 2 | s | 确认事件后禁止再次启动新事件的时间 |

实验中均为ADC域数值；切到力值域前必须重新标定所有ADC阈值。时间常数应为正；`window_s/separation_s`须覆盖多个实际采样帧。确认时间设零时，应明确测试立即触发行为。参数没有按采样率乘以固定帧数，而是按时间戳组织窗口。

每设备K12状态：

- `recent`: `(时间戳, 原始向量副本)`队列，保存`[t−window_s,t]`窗口；
- `history`: `(时间戳, recent均值副本)`队列，保留约`separation_s`历史；
- `ledger[M]`: 已确认真实变化的逐通道累计值，初始零；**可正可负**；
- `drift[M]`: 短窗均值的慢趋势斜率估计，初始零；
- `previous_mean[M]`、`previous_input[M]`、`previous_t`；
- `blocked_until`（大加载屏蔽终点）、`refractory_until`（小事件冷却终点）；
- `pending`: 可空元组`(开始确认时刻, 锚点时间, 锚点短窗均值, 方向, 当时斜率副本)`。

额外诊断`guard_i = t_i < refractory_until`，`large_guard_i = t_i < blocked_until`。这里的`guard`只是**冷却窗标志**，不是“本帧存在真实10g真值”或“某通道补偿被完全冻结”。

### 3.1 完整逐帧伪代码

以下伪代码按原型语义写；`vector`操作逐通道执行，`sum`对所有有效测点求和。`deque.pop_left()`必须保留一条足够早的history记录用于插值近邻选取。

```text
state: recent=[], history=[], ledger=zeros(M), drift=zeros(M), pending=null
       previous_mean=null, previous_t=t0, previous_input=copy(v0)
       blocked_until=t0, refractory_until=t0

for each (t,v):
    dt = max(0, min(t−previous_t, 0.1))    # 当前K12代码计算dt但不用它限制均值窗口
    if any channel of v is NaN or infinite:
        background = v−ledger
        offset = copy(ledger)
        output = K9.process(t, background)+offset
        # 仅跳过K12本帧检测状态更新，不跳过K9处理；
        # previous_t/input/mean、检测队列与K12定时状态均保持原值
        continue

    if abs(sum(v−previous_input)) >= large_step_adc:
        ledger=0; drift=0; recent.clear(); history.clear()
        previous_mean=null; pending=null
        blocked_until=t+large_freeze_s
        # 冷却截止时间不重置，K9状态也不重置

    recent.push((t,copy(v)))
    while recent.front.time < t−window_s: recent.pop_left()
    mean = arithmetic_mean(recent.vectors)
    history.push((t,copy(mean)))
    while size(history)>1 and history[1].time <= t−separation_s:
        history.pop_left()
    ready = history非空且(t−history.front.time)>=0.95*separation_s

    if t < blocked_until:
        large_guard=1                     # 仍更新recent/history，但暂停识别
    else if ready:
        span = t−history.front.time
        innovation = mean−history.front.mean−drift*span
        noise = population_std([sum(frame) for frame in recent]) / sqrt(size(recent))
        threshold = max(threshold_total_adc, noise_multiplier*noise)
        event_size = sum(innovation)

        if pending exists:
            (started, anchor_t, anchor, direction, slope_before) = pending
            candidate = mean−anchor−slope_before*(t−anchor_t)
            if t−started >= confirm_s:
                size = sum(candidate)
                if size*direction >= threshold:
                    ledger += candidate               # 累计逐通道增量，不仅是总值
                    refractory_until=t+refractory_s
                    history.clear(); history.push((t,copy(mean)))
                    emit event(t,size,threshold,copy(candidate))
                pending=null                          # 未过阈也结束本次候选
        else if t>=refractory_until and abs(event_size)>=threshold:
            pending=(t, history.front.time, copy(history.front.mean),
                     sign(event_size), copy(drift))
        else if t>=refractory_until and previous_mean!=null and dt>0:
            slope=(mean−previous_mean)/dt
            drift += (1−exp(−dt/drift_tau_s))*(slope−drift)

    guard = (t < refractory_until)
    background = v−ledger
    offset = copy(ledger)
    previous_mean=copy(mean); previous_t=t; previous_input=copy(v)
    output = K9.process(t, background)+offset
```

特别注意：`pending`在`blocked_until`期间**不更新**；大跳变会将其清空。`drift`只有在未屏蔽、历史窗口就绪、无pending且已退出冷却窗时更新。确认仅比较结束时的`size*direction`与当帧`threshold`，不要求候选整段逐帧越阈。对于**总值不变但空间重排**的真实接触事件，本版无法识别。

### 3.2 对大跳变与异常时间的真实语义

- 大跳变仅按`abs(sum(v−previous_input))`判断，两个反向通道若互相抵消则不会触发；该分支清K12账本和检测参考，**没有清K9状态**。这会影响输出连续性，迁移前须专门验证。
- 原型没有拒绝非单调时间：窗口按`timestamp`比较，但不会排序；上游必须保证递增。对于NaN帧，K12状态跳过更新，K9仍收到包含NaN的`background`；K9按自身NaN规则处理。
- 初始大加载如果分多帧、每帧总变化均小于2000 ADC，可能不触发屏蔽。反之一次大的真实快速荷载事件会清空账本。
- `ledger`无硬幅度上限；不能把本版理解为“永久准确识别真实荷载”的保证，须监控误检后的累计偏差。

## 4. 必须保留的K9底座

要复现K12 v2，迁移方应实现如下K9或提供同样输入输出语义的K9内核。只复制事件层接入其他滤波器会产生**不同算法**。K9状态每设备每通道：`zero, y_max, y_floor, x_fast, x_slow, v_lp, v_fast_lp, t_edge, load_dwell, ramp_dwell, applied`；全局：`total_baseline,total_noise,last_ts,first_frame`。

### 4.1 K9参数（右拇指指腹本批录制的实际值）

| 参数 | 值 | 参数 | 值 |
|---|---:|---|---:|
| r_fast | 0.03 | tau_c_fast_s | 2 |
| tau_r_fast_s | 0.1 | r_slow_max | 0.1 |
| tau_r_slow_s | 150 | tau_slope_s | 1 |
| slope_gate_frac | 0.05 | slope_cap_frac | 0.02 |
| tau_zero_s | 8 | idle_frac | 0.05 |
| y_max_tau_s | 600 | edge_slope_thres | 60 ADC/s |
| edge_refract_s | 2 | edge_boost_s | 2 |
| tau_c_fast_boost_s | 2 | soft_unfreeze_s | 2 |
| hold_eps | 2 ADC/s | hold_tau_s | 0.5 |
| slow_confirm_s | 3 | y_floor_tau_s | 300 |
| tau_r_slow_idle_s | 0.2 | bypass_release_frac | 1.15 |
| bypass_engage_frac | 1.25 | bypass_noise_sigma | 3 |
| bypass_base_tau_s | 10 | ramp_slope_min | 0.5 ADC/s |
| ramp_full_s | 4 | | |

时间参数单位为秒，比例参数无量纲；`slope_gate_frac`及`slope_cap_frac`用于计算`ADC/s`速率门和积分速率。不同硬件、力值域或新标定不能直接复用这些数。`param_set`只是记录标识，不参与计算。`r_slow_max=0.3`曾作为**独立调参对照**，不是K12 v2默认值，也未完成联合验收。

### 4.2 K9每帧流程（实现级伪代码）

初始化首帧：`zero=v0; v_lp=v0; v_fast_lp=v0; y_floor=v0; y_max=0; x_fast=x_slow=applied=load_dwell=ramp_dwell=0; t_edge=1e6; total_baseline=sum(v0); total_noise=0; last_ts=t0`，原样输出首帧。后续每帧先设置`dt=max(0,min(t−last_ts,0.1))`并无条件将`last_ts=t`；非有限值行使`dt=0`，非有限通道在K9状态数值计算中当零，输出该通道仍保留NaN。

1. 旁路判据：`total=sum(v)`；`release=max(1.15*total_baseline,total_baseline+3*total_noise)`，`engage=max(1.25*total_baseline,total_baseline+4*total_noise)`。若`total<engage`，先用`alpha=min(dt/10,1)`向total更新baseline，再以**更新后的baseline**计算`abs(total−baseline)`更新noise；`total_noise>=0`。注意release/engage由**更新前**基线计算。`bypass_frame=(total<release)`。
2. 逐通道零点：`y0=v−zero`；`y_floor=min_follow(y0)`：下降瞬时跟随，上升`+=dt/300*(y0−y_floor)`；`y_max=max(y_max*exp(-dt/600),max(y0,0))`。`span=max(y_max−y_floor,1)`；`idle=(y0−y_floor)<0.05*span`；idle则`load_dwell=0`并`zero+=dt/8*(v−zero)`，否则`load_dwell+=dt`。再算`y=v−zero`。
3. 斜率与快态：`slope=(v−v_lp)/1`，使用更新前`v_lp`；`e_now=max(y−x_fast−x_slow,0)`。`t_edge+=dt`；若`slope>60`且`t_edge>max(edge_refract_s,edge_boost_s)`，置`t_edge=0`。`ramp_on=(0.5<slope<=60)`，持续则`ramp_dwell+=dt`，否则清零；若`abs(slope)>60`则`load_dwell=0`。在`t_edge<edge_boost_s`期间用`tau_c_fast_boost_s`，否则用`tau_c_fast_s`；若`ramp_full_s>0`，令`w=min(ramp_dwell/ramp_full_s,1)`，`tc1=tc1*(1-w)+tau_c_fast_boost_s*w`。若`e_now>0`：`dx1_rate=(r_fast*e_now−x_fast)/tc1`；否则`dx1_rate=−x_fast/tau_r_fast_s`。`x_fast=max(x_fast+dt*dx1_rate,0)`；再更新`v_lp+=dt/tau_slope_s*(v−v_lp)`。
4. 慢态：`e=max(y−x_fast−x_slow,0)`，`base=max(e,1)`，`cap=slope_cap_frac*base`；重新计算`idle_k=(y−y_floor)<idle_frac*max(y_max−y_floor,1)`。仅当`e>0 && load_dwell>=slow_confirm_s && (1−exp(-t_edge/soft_unfreeze_s))>0.5 && abs(slope)<slope_gate_frac*base`时，`x_slow+=dt*clamp(slope−dx1_rate,−cap,+cap)`。仅`e>0`时钳位`x_slow=clamp(x_slow,0,r_slow_max*base)`。若`e<=0 || idle_k`，按`tau_r_slow_idle_s`（idle且其大于0）否则`tau_r_slow_s`泄放`x_slow=max(x_slow−dt*x_slow/tau,0)`。
5. K6施加补偿：若`hold_eps>0`，`slope_a=(v−v_fast_lp)/hold_tau_s`，更新`v_fast_lp`；`desired=x_fast+x_slow`，`up=applied+dt*max(slope_a+hold_eps,0)`，`down=applied+dt*(slope_a−hold_eps)`；`desired>applied`时`candidate=min(desired,up)`，否则`candidate=max(desired,down)`；`e>0`时`applied=clamp(candidate,0,max(desired,0))`，否则`applied=desired`。
6. 旁路输出：若`bypass_frame`，置`applied=x_fast+x_slow`并**原样输出v**；否则若`hold_eps>0`输出`v−applied`，否则输出`v−x_fast−x_slow`。旁路帧仍须执行前述状态更新，不能提前跳出。

上述伪代码对应本批录制全部正时间常数；若要开放更大参数范围，须补齐K9实现中的零分母保护、`hold_eps<=0`等边界。K9在额外工作区仅保证与录制结果**接近**，不是逐位相等；迁移方应以独立基准回放验证自己的具体平台实现。

## 5. 移植步骤

1. 将K9底座与K12账本写成两个**独立可重置**状态对象，接口分别为`K9.process(t,vector)->vector`和`Ledger.update(t,vector)->(background,offset,diagnostic)`。
2. K12以全通道总值触发，但记录及回填逐通道`candidate`向量；不可把45总ADC阈值错误应用到每一单通道。
3. 使用时间戳维护两个deque；平均值、总体标准差（`ddof=0`）、噪声除以`sqrt(N)`以及`history[1].time`修剪条件须保持原型定义。优化为滑动和时应保证浮点误差在回放容差内。
4. `pending`记录触发时的锚点、方向与趋势**副本**；确认时以该锚点重新估算完整变化量，避免越阈瞬间只记下一半幅度。
5. 在代码启动时记录K9/K12全部参数及版本；参数变化或设备重连时重置两层状态。生产实现应显式限制账本幅度、处理持久化和异常帧，但这些限制将改变现有实验算法，需新一轮验证。
6. 先运行第6节受控用例，随后才用带操作时刻标签的真实数据评估10g检出率和漂移；不要把图中的未标注波动直接宣称为10g。

## 6. 最小验收集及已得结果

### 6.1 关闭账本等价

对同一输入和时间轴，`enabled=false`返回K9结果。受控例逐位相等；迁移方至少对空载、加载、长保压、部分卸载和含非有限帧做同样检查。

### 6.2 已知真值的增载、持载与撤载

生成6000帧、100Hz、57通道：每通道初始8ADC，在`t>=2s`各通道加500ADC；实验臂在`30<=t<45s`额外加100ADC总值，对照臂不加。分别把这100ADC集中在一通道，或平均给57通道。用实验输出减对照输出得到净阶跃响应。参考结果：

| 分布 | K9在40~44s持载响应 | K12 v2持载响应 | K12 v2在52~58s撤载残余 |
|---|---:|---:|---:|
| 1通道加100ADC | 94.59896 | 101.40220 | -0.04616 |
| 57通道各加100/57ADC | 0.000576 | 95.07518 | -1.05872 |

按总ADC中位统计。事件时间约30.48s和45.47s；确认延迟属于本算法代价。可按移植语言浮点实现选定容差，而不能把上表当作真实10g标定。

### 6.3 因果与负对照

取上述输入前3500帧单独运行，结果应与全6000帧输出的前3500帧逐位一致（如需跨平台，可规定有限浮点容差）。另以`t>=15s`后每通道匀速`0.1 ADC/s`的无小荷载序列做负对照；本原型未确认事件。**只证明该速率及该无噪声输入下未误触发**，不保证温度非线性漂移或共模噪声下不误判。

### 6.4 真实数据边界

六份ADC录制中，K12 v2使用原录制K9参数，指定窗口净变化分别有改善也有恶化：设备1两份10g/恒载测试约`+496,+608,+490 ADC`；设备2约`+117,+1036,+193 ADC`。这些记录缺荷载增减的时间真值，因此只称为**窗口净变化**，不是纯时漂，也不是10g保留率。真实恒载记录仍出现候选触发。`r_slow_max=0.3`是独立对照而非K12的隐含设置或迁移推荐参数。

## 7. 已知限制与不得推断的结论

- 总值门不能检测总和几乎不变的空间重排，也不能区分真实共模施力与电子共模扰动；多事件在冷却时间内被合并或遗漏。
- 矩形窗口噪声估计是`std(sum(recent))/sqrt(N)`，对相关噪声及非平稳蠕变未做校准。K12的事件是**候选事件**，不是附有真实荷载标签的事件。
- 清账本不等于重置K9状态；大加载之后的输出连续性需单独检查。误确认事件在`ledger`中累积，当前无自动审计、硬边界或回滚机制。
- Python原型采用离线存储完整中间矩阵后调用K9；在线迁移在数学上可流式，但还未实现逐帧在线与原型的跨语言逐帧对拍。
- 输入时间乱序、NaN/Inf、空流、设备断开重启与参数热更新，必须由上游契约约束或由新实现显式处理并新增回归。不能假装文中实验已经覆盖。
- 当前版本**不能承诺**长期漂移低于300ADC、真实10g检出率或可下发设备。力值映射也不在算法内：1000ADC/N仅是用户提供的误差量级估计，不替代局部映射表。
