# K9 缓坡前馈 — 嵌入式迁移说明

> 2026-09-21。基准代码：`src/domain/drift_v6/creep_observer.{h,cpp}`（菜单「v3.4 观测器」档，
> 数据层 param_set = `plan-v4 observer-k9`，见 `src/data/data_handler.cpp`）。
> 本文以该 C++ 实现为唯一权威口径；`K9缓坡前馈.md` 为研究背景。

## 0. 版本核对结论（迁移基准确认）

- K9 **已合入 v3.4 算法模块本体**，不是独立文件：菜单 v3.4 档的唯一实现是
  `CreepObserverCompensator`（`src/domain/drift_v6/creep_observer.h/.cpp`）。
- K9 在该模块中的落点：
  - 参数：`ramp_slope_min = 0.5`（ADC/s）、`ramp_full_s = 4.0`（s），见 `creep_observer.h` Params；
  - 状态：每通道 `ramp_dwell_`（1 个标量），头文件与 `Reset()`/`ResetFor()`/首帧初始化均已同步；
  - 逻辑：`creep_observer.cpp` 主循环内 `ramp_on` 判定 + `tc1` 线性混合。
- 数据层标识：`data_handler.cpp` 中 v3.4 档 `param_set = "plan-v4 observer-k9"`，
  即**当前 v3.4 档已是含 K9 的最终版本**。嵌入式迁移以这份代码为准，无需再叠加补丁。
- 行为结论（研究档案）：K9 相对 K7 在既有 10 会话数据上零行为差异，属安全冗余；
  真正的增量场景（斜率 20~60 ADC/s 的陡缓坡）待补录验证。嵌入式实现照抄即可，
  不需要调参分支。

## 1. 迁移范围

K9 不能脱离 v3.4 观测器单独运行——它修改的是快态收敛时间常数 `tc1` 的取值路径。
因此迁移单元是**整个 v3.4 观测器逐通道流水线**，K9 是其中一处 ~6 行的增量。
下文伪代码给出完整逐帧流程，K9 段以 `【K9】` 标注。

## 2. 状态与参数（嵌入式侧清单）

### 2.1 每通道状态（11 个标量 + 全局 2 个）

| 状态 | 类型建议 | 初值 | 来源 |
|---|---|---|---|
| `x_fast` | F32/Q15 | 0 | 快态（plan-v3.4） |
| `x_slow` | F32/Q15 | 0 | 慢态（plan-v3.4） |
| `v_lp` | F32 | 首帧 v | 慢漂移速率低通（τ_slope） |
| `zero` | F32 | 首帧 v | 零点跟踪 |
| `y_max` | F32 | 0 | 量程包络 |
| `t_edge` | F32 | 1e6 | 距上次上升沿时长（H3） |
| `applied` | F32 | 0 | 已施加补偿（K6 预留池） |
| `v_fast_lp` | F32 | 首帧 v | 预留池快速低通（K6） |
| `y_floor` | F32 | 首帧 v | 去趋势基线（K7） |
| `load_dwell` | F32 | 0 | 连续受载确认（K7） |
| `ramp_dwell` | F32 | 0 | **【K9】缓坡持续计时** |

全局：`total_baseline`、`total_noise`（K7 旁路），`first_frame`、`last_ts`。

### 2.2 参数（ Defaults 直接照抄 creep_observer.h::Params ）

```
r_fast=0.10         tau_c_fast_s=12      tau_r_fast_s=2       r_slow_max=0.35
tau_r_slow_s=150    tau_slope_s=1        slope_gate_frac=0.05 slope_cap_frac=0.01
tau_zero_s=8        idle_frac=0.05       y_max_tau_s=600
edge_slope_thres=60 edge_refract_s=2     edge_boost_s=2       tau_c_fast_boost_s=2
soft_unfreeze_s=4   hold_eps=2           hold_tau_s=0.5       slow_confirm_s=10
y_floor_tau_s=300   tau_r_slow_idle_s=8  bypass_release_frac=1.15
bypass_engage_frac=1.25  bypass_noise_sigma=3  bypass_base_tau_s=10
ramp_slope_min=0.5  ramp_full_s=4.0      ← 【K9】
```

建议嵌入式侧全部编译期常量（或一次性下发的只读结构体），RAM 中不占空间。

## 3. 伪代码（逐帧，与 creep_observer.cpp 一一对应）

```
procedure PROCESS_FRAME(ts, v[n])            # v 为原始 ADC 向量，就地扣除
    dt = clamp(ts - last_ts, 0, 0.1); last_ts = ts
    if dt <= 0: return

    # ── K7 全局旁路（总值门限，迟滞两门限）──
    total = Σ v[k]
    α = min(dt / bypass_base_tau_s, 1)
    release = max(1.15·total_baseline, total_baseline + 3σ·total_noise)
    engage  = max(1.25·total_baseline, total_baseline + 4σ·total_noise)
    if total < engage:
        total_baseline += α·(total - total_baseline)
        total_noise    += α·(|total - total_baseline| - total_noise)
    bypass = (total < release)

    for k in 0..n-1:
        # ── 零点跟踪 + 去趋势空载门（K7）──
        y0 = v[k] - zero[k]
        y_floor[k] = (y0 < y_floor[k]) ? y0
                     : y_floor[k] + (dt/y_floor_tau_s)·(y0 - y_floor[k])
        y_max[k]  = max(y_max[k]·exp(-dt/y_max_tau_s), max(y0, 0))
        span  = max(y_max[k] - y_floor[k], 1)
        idle  = (y0 - y_floor[k]) < idle_frac·span
        load_dwell[k] = idle ? 0 : load_dwell[k] + dt
        if idle: zero[k] += (dt/tau_zero_s)·(v[k] - zero[k])
        y = v[k] - zero[k]

        # ── 低通导数（用更新前的 v_lp）──
        slope = (v[k] - v_lp[k]) / tau_slope_s

        # ── 沿检测（H3）──
        t_edge[k] += dt
        if slope > edge_slope_thres AND t_edge[k] > max(edge_refract_s, edge_boost_s):
            t_edge[k] = 0

        # ──【K9】缓坡前馈 ──────────────────────────
        ramp_on = (ramp_slope_min < slope ≤ edge_slope_thres)
        ramp_dwell[k] = ramp_on ? ramp_dwell[k] + dt : 0
        # ─────────────────────────────────────────────

        if |slope| > edge_slope_thres: load_dwell[k] = 0   # K7

        # ── 快态收敛 τ 选择：沿后前馈（H3）+ 缓坡混合【K9】──
        tc1 = (t_edge[k] < edge_boost_s) ? tau_c_fast_boost_s : tau_c_fast_s
        w   = min(ramp_dwell[k] / ramp_full_s, 1)          # 【K9】
        tc1 = tc1·(1-w) + tau_c_fast_boost_s·w             # 【K9】

        # ── 快态 x1 ──
        e_now = max(y - x_fast[k] - x_slow[k], 0)          # 帧首统一算
        dx1_rate = (e_now > 0) ? (r_fast·e_now - x_fast[k]) / tc1
                                : -x_fast[k] / tau_r_fast_s
        x_fast[k] = max(x_fast[k] + dx1_rate·dt, 0)
        v_lp[k]  += (dt/tau_slope_s)·(v[k] - v_lp[k])

        # ── 慢态 x2（软冻结 H3 + 受载确认 K7 + 空载快泄放 K7）──
        e = max(y - x_fast[k] - x_slow[k], 0)
        idle_k = (y - y_floor[k]) < idle_frac·span
        if e > 0:
            base  = max(e, 1)
            cap   = slope_cap_frac·base
            soft_ok  = t_edge[k] > soft_unfreeze_s·ln2      # ≡ 1-exp(-t/w)>0.5
            dwell_ok = load_dwell[k] >= slow_confirm_s
            if dwell_ok AND soft_ok AND |slope| < slope_gate_frac·base:
                x_slow[k] += dt·clamp(slope - dx1_rate, -cap, cap)
            x_slow[k] = clamp(x_slow[k], 0, r_slow_max·base)
        if e <= 0 OR idle_k:
            τ = idle_k ? tau_r_slow_idle_s : tau_r_slow_s
            x_slow[k] -= (dt/τ)·x_slow[k];  floor at 0

        # ── K6 预留池：applied 增速受快速导数限幅 ──
        slope_a  = (v[k] - v_fast_lp[k]) / hold_tau_s
        v_fast_lp[k] += (dt/hold_tau_s)·(v[k] - v_fast_lp[k])
        d_des = x_fast[k] + x_slow[k]
        a_up  = applied[k] + dt·max(slope_a + hold_eps, 0)
        a_dn  = applied[k] + dt·(slope_a - hold_eps)
        a = (d_des > applied[k]) ? min(d_des, a_up) : max(d_des, a_dn)
        applied[k] = (e > 0) ? clamp(a, 0, max(d_des,0)) : d_des

    if bypass:
        applied = x_fast + x_slow        # 空载直通
        return                             # 显示不扣
    v[k] -= applied[k]                    # 显示 = v − x1 − x2（经预留池）
```

**K9 最小增量**（若载体模块已迁移到 K7 版本，只需追加）：

```
状态:  ramp_dwell[k] (F32, 初值 0)
帧内:  ramp_on  = (0.5 < slope ≤ 60)
       ramp_dwell[k] = ramp_on ? ramp_dwell[k] + dt : 0
       w  = min(ramp_dwell[k] / 4.0, 1)
       tc1 = tc1·(1-w) + 2.0·w
复位:  缓坡斜率跌回 0 / 越沿（slope>60）时 ramp_dwell 自动清零，无额外路径
```

## 4. 开销说明

### 4.1 内存（RAM）

- **K9 净增**：每通道 1 个 F32（`ramp_dwell`）+ 2 个参数（建议常量，0 RAM）。
  32 通道传感器 = **净增 128 B**。
- 载体模块（v3.4 全量，K9 版）：每通道 11 × F32 = 44 B/通道 + 全局 ~12 B。
  常见规模：16 通道 ≈ 716 B；32 通道 ≈ 1 420 B；64 通道 ≈ 2 828 B。
  无动态分配、无查找表、无历史环形缓冲——状态量固定，便于静态分配。

### 4.2 计算（每通道每帧）

| 段 | 加/乘 | 除 |超越函数| 备注 |
|---|---|---|---|---|
| 旁路 + 零点 + 包络 | ~15 | 4 | 1×exp（帧级，可查表）| `exp(-dt/600)` 每帧 1 次 |
| 斜率 + 沿 + dwell | ~6 | 1 | — | |
| **【K9】段** | **~4** | **1** | **—** | 2 比较 + 1 累加 + 1 混合 |
| 快态 | ~8 | 1 | — | |
| 慢态 | ~15 | 2 | 1×exp | **可化为 `t_edge > w·ln2` 比较，免 exp**（见 §5.2）|
| 预留池 | ~12 | 1 | — | |
| 合计 | **~60 FLOP** | **~10 除** | **1 exp/帧 + 1 可消除** | 无 sin/cos/开方 |

按 100 Hz 帧率、32 通道：≈ 3.2×10⁵ FLOP/s。
带 FPU 的 Cortex-M4F/M7 单核占用 **< 0.5%**；无 FPU 的 M3 用软件浮点约
3~5 MHz 等效主频，仍属空闲级负载。所有 `1/τ·dt` 均为常量可预计算，
除法可全部移到初始化，帧内只剩乘加。

### 4.3 时序/接口

- 输入：`timestamp_s`（秒，单调）+ 逐通道 ADC 原始值；帧间隔自适应（dt 就地积分），
  **不要求固定采样率**，但 dt > 0.1 s 会被钳到 0.1 s（丢帧保护）。
- 输出：原址覆盖（显示值 = 输入 − applied）。
- 通道数变化或 signature（显示值域签名）变化 → 全状态重置；
  嵌入式侧对应"传感器配置变更时调用 Reset()"。

## 5. 嵌入式落地建议

### 5.1 数值表示
- 有 FPU：直接 F32，与 C++（F64）参数同值即可；ADC 域 0–4095、
  x1/x2 上限 ~0.45·e，F32 尾数完全够。
- 定点：建议 Q16.16（int32）；`tc1` 混合与 τ 都在 ADC 尺度下工作良好。
  `ramp_dwell` 为时间量（0–4 s），Q8.8 即可。

### 5.2 免 exp 的两处
- `soft_ok = 1 - exp(-t_edge/soft_unfreeze_s) > 0.5` ⟺ `t_edge > soft_unfreeze_s × ln2`
  （= 2.77 s），一次比较替代一次 exp。
- 帧级 `y_decay = exp(-dt/y_max_tau_s)`：dt 恒定时是常量；变帧率用 8 项
  泰勒或 32 项查表，误差 < 1 LSB(ADC)。

### 5.3 并发与原子性
模块单线程逐帧调用，无内部锁；多设备（多 key）各自独立实例，天然可分核。

### 5.4 验收口径
1. 与 C++ 版逐位对拍：同一段录制 CSV 回放，显示值序列差应在 F32 舍入
   （|Δ| < 1e-3 ADC）内；
2. K9 专项：构造 slope ∈ (0.5, 60] ADC/s 的斜坡激励，确认 ramp_dwell 累积、
   tc1 渐变、slope 归零/越沿时 ramp_dwell 清零；
3. 回归：现有 10 会话数据下 K9 与 K7 输出零差异（研究档案结论，作不变量）。
