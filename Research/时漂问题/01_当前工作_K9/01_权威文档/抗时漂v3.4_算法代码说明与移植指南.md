## 3. 输入输出契约（移植替换点）

### 3.1 接口

```cpp
void CreepObserverCompensator::Process(double timestamp_s, Eigen::VectorXd& values_io);
void CreepObserverCompensator::Reset();
void SetParams(const Params&);   const Params& params() const;
```

- **输入**：`timestamp_s` 是**秒**为单位的单调时间戳；`values_io` 是**本帧 n 通道显示值**，函数内**原地覆盖为补偿后显示值**（无返回值）。
- **输出**：`values_io`。**不做正值钳位、不取整、不归零** —— 这些属于下游显示管线（§10.2-10）。
- **调用频率**：每帧一次、单线程、无锁。**不要求固定帧率**（§9.3）。
- **状态所有权**：全部在实例内（无静态量、无全局量）；一个实例对应一个"目标"（一台设备/一个传感器）。**注意**：当前 C++ 实现的 `Process()` 每帧会构造 3 个动态向量（`y`/`slope`/`e_now`），**不是零分配**——移植侧必须改为定长数组/预分配缓冲（§10.3-13）。

### 3.2 上位机里的挂载点（决定移植侧"放在哪一级"）

数据链路上的**唯一正确位置**是：

```
原始帧 → 零点偏移(整数) → [单位换算/标定换算] → ★补偿（此处） → 阈值过滤 → 2D/3D 显示、录制
```

三条必须一起搬的接线语义（源码事实）：

| 语义 | 源码位置 | 原因 |
|---|---|---|
| 放在**单位换算之后、阈值过滤之前** | `data_handler.cpp` 串口路径 `HandleDecodedFrame`（canonical 帧与算法前副本抓取之后、补偿块 `:825-834`、`ProcessingPipeline::ApplyThreshold` `:860` 之前）；typed 路径 `ProcessTypedFrame` 同构（`:1669` canonical → `:1708` 换算 → `:1748-1757` 补偿 → `:1772` 阈值） | 算法全部判据是**相对量**（乘 e），ADC 域/力值域都成立，但**一帧序列中途不许换域**；阈值过滤会破坏读数连续性（把负值钳成 0），必须排在其后 |
| **业务 canonical 帧与原始 ADC 流不受补偿影响** | 两条路径都在补偿之前发出 canonical 帧；原始 ADC 是更上游的快照（`:721-725`） | 假电芯判定、录像 raw 流、业务记录必须拿到"未补偿"的值；只有**显示**被补偿 |
| **录制主文件的角色随路径而异** | 串口单设备路径 `main_stream_role = "algorithm_result"`（`:1120-1121`，主 CSV 即算法结果）；typed/多设备路径 `= "canonical_business"`（`:1195-1196`），算法结果另写 `device_NNN_algo_segM.csv` | 回放时按 `session.json` 的角色字段分辨主 CSV 是"算法后"还是"算法前"；算法前另有 `device_NNN_pre_segM.csv`（§14.1） |

> 移植到嵌入式时，对应的位置是"标定换算后、发送/显示前"，与上位机的相对顺序完全一致。若把算法放在原始 ADC 上而下游又做换算，所有门限都会失真。

### 3.3 显示值域签名（`signature`）：什么时候必须换一个"新实例"

上位机给每个目标配一个**签名串**，签名变化 → 协调器对该目标做 `Reset()`（等效全新启动）：

```cpp
// data_handler.cpp BuildDisplayValueSignature()
"mode | reported_pressure | reported_force | display_pressure | display_force | ZeroOffset | HasForceCalibration | extra"
```

即：**显示模式**（ADC/压强/力值）、**单位设置**、**软件零偏 `ZeroOffset`**、**是否装载标定表**、以及路径附加段（串口路径 `cal|raw`；typed 路径 `dom<值域>|<canonical 域>|<单位>`）任一变化都会重置。

移植侧等价物：**显示域描述符**（模式/单位/零偏/标定态）——它一变就重置算法；**软件调零（写入零偏）因此天然等价于算法重启**（§7.3 的启动语义由此而来）。

## 4. 算法原理（够用来推理，不展开研究史）

### 4.1 模型与信号流

把传感器 + 夹具当成线性粘弹性体，逐通道维护两个非弹性状态，并先从读数里扣掉一个逐通道演化的零点：

```
y = v − z          # 去零点后的负载响应
e = max(y − x1 − x2, 0)   # 弹性响应估计（同时充当"受载门"）
显示 = v − a       # a = 实际施加的补偿；a ≤ x1 + x2，空载 a = x1 + x2
```

- **x1 快态**（位置式）：受载时朝 `r1·e` 以 `τc1` 收敛，空载时按 `τr1` 衰减但**不清零**——吸收加载后数秒~数十秒的快相爬升；
- **x2 慢态**（速率式）：受载时把"实测慢漂移速率"积分进状态（速率上限 ±`cmax·e`），空载按 `τr2` 恢复——吸收分钟级慢蠕变。**不朝固定幅度收敛**，因为辨识表明蠕变幅度因工况差 3 倍（0~0.34），固定幅度必在一边过扣一边欠扣；
- **z 零点**：只在近零带内以 `τ0` 向读数靠拢（受载时冻结），实现"空载直通 + 慢速再校准"；
- **受载门是估计出来的**：卸载后 y 塌回近零带、而 x 还在，于是 `e = 0`，状态自动转入恢复分支——**没有任何"受载/空载"阈值状态机**。

**为什么"显示 = 弹性响应"就是想要的真值**：恒载下 x1 收敛、x2 积分掉全部实测慢漂移 ⇒ 显示被钉在弹性电平；重载时读数的快相落点 = 弹性电平 + 残余非弹性，显示自动扣掉后者 ⇒ **跨卸载的连续性来自状态本来连续**，不需要事件账本（这正是上一代"丢基线"被修好的原因）。

### 4.2 沿后/缓坡机制（H3 + K6 + K9，当前版的核心增量）

实测"阶跃后约 2 s 见峰、随后回落过大"的纯过补偿成分，75~85% 来自 x2 在沿后过速积分。算法内建五个机制（前四个由逐通道计时驱动，第五个在显示侧）：

| 机制 | 参数 | 做什么 | 解决什么 |
|---|---|---|---|
| **上升沿检测** | `edge_slope_thres=60` ADC/s、`edge_refract_s=2` s | 低通导数超阈且距上次触发 > max(不应期, 前馈窗) 时记一次触发，`t_edge=0` | 只驱动后面两个开关，**不是事件账本**（不清零、不写状态） |
| **沿后前馈** | `edge_boost_s=2` s、`tau_c_fast_boost_s=2` s | `t_edge<2 s` 内 τc1 临时取 2 s | 首次大台阶快相早段欠扣 |
| **缓坡前馈（K9）** | `ramp_slope_min=0.5`、`ramp_full_s=4` s | 斜率落在缓坡带 (0.5, 60] ADC/s 内累积 `ramp_dwell`，按权重 `w=min(ramp_dwell/4,1)` 把 τc1 **线性过渡**到 2 s | 缓坡加载（不过沿阈）与快上冲到达**同一收敛速度**；如实记录：现有 10 会话上 K9 与 K7 逐帧零差异（安全冗余） |
| **沿后软冻结** | `soft_unfreeze_s=4` s | x2 积分门额外要求 `1−exp(−t_edge/4)>0.5`（≈离沿 2.8 s） | 沿后斜率被台阶瞬态抬高时不许进 x2 |
| **补偿预留池（K6）** | `hold_eps=2` ADC/s、`hold_tau_s=0.5` s | 显示不直接减 x1+x2，而减受限的 `a`：受载期 `a` 增速 ≤ 输入**快速**导数 + 2 ADC/s；空载 `a=x1+x2` | 保证显示"只升不降"地被填平：快相期间偏高一点，慢相随输入爬升逐步归位 |

> **限额必须用 τ=0.5 s 的快速导数**（`hold_tau_s`）：若换用 `tau_slope`（1 s）的低通导数，它在减速段高估输入爬升率，约束会形同虚设。

### 4.3 全局总值旁路 + 去趋势空载门（K7 轮加入，**在 K9 里生效**；旧移植文档缺失的部分，最容易漏）

K7 修的是"反复 4~6 s 加卸载 ×25 循环"里算法输出逐循环变小（空载塌向 0）。四个机制叠加，**全部在 `Process()` 里，移植必须一起搬**：

1. **全局总值旁路**：维护 `total_baseline`（空载期跟踪总值基线，**上下双向漂移都能跟**）与 `total_noise`（|total−baseline| 的慢速均值）；`total < release` 时**整帧直通**（不施加补偿）。注意两个门限的分工：**是否直通只由 `release` 决定**（`creep_observer.cpp:92`），`engage` 只用来门控"是否继续跟踪基线/噪声"（`:87`）；因 `release < engage`，正常工况表现为"超过 engage 才恢复算法"，但写代码时不要用 engage 当直通判据：
   ```
   release = max(1.15·baseline, baseline + 3σ)      // 低于此：直通
   engage  = max(1.25·baseline, baseline + 4σ)      // 高于此：恢复
   ```
2. **旁路帧不可整帧 return**：直通帧**仍要跑逐通道状态演化**（零点跟踪、快慢态泄放、dwell 清零），否则 `load_dwell` 只进不出、确认门跨循环失效，空载塌陷换姿势复发（源码注释原文）。实现上是：逐通道循环照跑，最后 `if (bypass_frame) { applied = x_fast + x_slow; return; }`（即"状态更新、但不施加"）。
3. **去趋势空载门限**：`y_floor` 逐通道跟踪 `y0` 的慢速最小值（**下行瞬时跟随、上行按 `y_floor_tau_s=300` 慢跟**），判据从 `y0 < idle_frac·y_max` 改为
   ```
   idle = (y0 − y_floor) < idle_frac · max(y_max − y_floor, 1)
   ```
   旧判据要求基线 < 5%·包络，而实测基线≈7%·包络 ⇒ 空载判定整场失效（这是"空载零点塌陷换姿势复发"的根因③）。**移植时不要退回旧判据。**
4. **慢态门控两件**：① 受载确认 `slow_confirm_s=10` s（`load_dwell` 连续受载计时，**任一快变（升或降）`|slope|>沿阈`都清零重计**，防递减台阶跨挡累积骗过确认门）；② 空载期快泄放 `tau_r_slow_idle_s=8` s（原 τr2=150 s 且被 `e>0` 锁死 ⇒ 只进不出的逐循环棘轮）。

实测（10 会话离线复放）：回撤工况 growth +3.40 → **+0.24** ADC、空载偏置 −2.36 → −0.05；代价是保压前 10 s+确认期内 x2 不积分 ⇒ **系统性少扣约 10~15%**，长保压补偿起效推迟约 13 s。

- **凡是要区分工况的地方都是相对量**（乘 e）⇒ 读数按比例放大，行为逐帧不变，不需要负载分类；
- **参数值夹在两把尺子之间**：如 `slope_gate_frac` 大于最快真实蠕变率（约 0.8%·e/s）、小于台阶表观峰值（约 100%·e/s）；`ramp_slope_min` 同理夹在"蠕变速率"与"沿阈值"之间。

## 6. 逐帧流程（与 `creep_observer.cpp::Process()` 一一对应）

符号：`v[k]` 本帧读数（就地覆盖）、`dt` 帧间隔、其余同 §5。`clamp(a,lo,hi)`/`max`/`min` 为普通标量运算。

```
PROCESS(ts, v[n])                          # v 就地覆盖
  n = len(v); if n ≤ 0: return
  if n ≠ n_:  ResetFor(n)                  # 通道数变化 = 全状态重置（§7.1）

  ── 首帧 ──────────────────────────────────────────────
  if first_frame:
     first_frame = false;  last_ts = ts
     zero = v                       # 零点取首帧读数 ⇒ 定义了"算法当前认为的零点"
     y_max = 0;  v_lp = v;  v_fast_lp = v;  y_floor = v
     x_fast = x_slow = applied = load_dwell = ramp_dwell = 0
     t_edge = 1e6
     total_baseline = Σv;  total_noise = 0
     v −= applied                   # = v（直通）
     return

  ── 时间步 ────────────────────────────────────────────
  dt = ts − last_ts;  last_ts = ts
  dt = (dt > 0) ? min(dt, 0.1) : 0          # 回退/重复 → 0；卡顿 → 截到 0.1 s

  ── K7 全局总值旁路（dt>0 才更新统计）────────────────
  bypass = false
  if dt > 0 and isfinite(Σv):
     total = Σv
     α = min(dt / bypass_base_tau_s, 1)
     release = max(bypass_release_frac·total_baseline, total_baseline + bypass_noise_sigma·total_noise)
     engage  = max(bypass_engage_frac ·total_baseline, total_baseline + (bypass_noise_sigma+1)·total_noise)
     if total < engage:                       # engage 只门控"是否继续跟踪基线/噪声"
        total_baseline += α·(total − total_baseline)
        total_noise    += α·(|total − total_baseline| − total_noise);  total_noise = max(total_noise, 0)
     bypass = (total < release)               # ★ 直通判据只用 release，不用 engage

  if dt > 0:
     y_decay = exp(−dt / y_max_tau_s)         # ★ 整帧唯一必留的超越函数（帧级，循环外）
     逐通道 k（★ 下列顺序不可调换）:
       ── ① 去趋势空载门 + 包络 + 零点跟踪（K7/v3）──
       y0 = v[k] − zero[k]
       y_floor[k] = (y0 < y_floor[k]) ? y0 : y_floor[k] + (dt/y_floor_tau_s)·(y0 − y_floor[k])
       y_max[k]   = max(y_max[k]·y_decay, max(y0, 0))
       span = max(y_max[k] − y_floor[k], 1)        # ★ 下限 1 不可省
       idle = (y0 − y_floor[k]) < idle_frac·span
       load_dwell[k] = idle ? 0 : load_dwell[k] + dt
       if idle: zero[k] += (dt/tau_zero_s)·(v[k] − zero[k])      # 受载时冻结

       y[k] = v[k] − zero[k]
       ── ② 低通导数（用更新前的 v_lp，解析式）──
       slope[k] = (v[k] − v_lp[k]) / tau_slope_s
       ── ③ 沿检测（H3）──
       t_edge[k] += dt
       if slope[k] > edge_slope_thres and t_edge[k] > max(edge_refract_s, edge_boost_s):
          t_edge[k] = 0
       ── ④ 缓坡前馈计时（K9）──
       ramp_on = (ramp_slope_min < slope[k] ≤ edge_slope_thres)
       ramp_dwell[k] = ramp_on ? ramp_dwell[k] + dt : 0
       ── ⑤ K7 任一快变都重计受载确认窗 ──
       if |slope[k]| > edge_slope_thres: load_dwell[k] = 0
       ── ⑥ 快态收敛 τ（沿后前馈 → 缓坡线性混合）──
       tc1 = (edge_boost_s > 0 and t_edge[k] < edge_boost_s) ? tau_c_fast_boost_s
                                                             : tau_c_fast_s
       if ramp_full_s > 0:
          w = min(ramp_dwell[k]/ramp_full_s, 1)
          tc1 = tc1·(1−w) + tau_c_fast_boost_s·w
     帧首统一算一次（★ 用更新前的 x1 / x2 / 本帧 y）:
       e_now[k] = max(y[k] − x_fast[k] − x_slow[k], 0)
     逐通道 k:
       ── ⑦ 快态 x1 ──
       dx1_rate = (e_now[k] > 0) ? (r_fast·e_now[k] − x_fast[k]) / tc1
                                 : −x_fast[k] / tau_r_fast_s     # ★ 斜率口径：用更新前 x1
       x_fast[k] = max(x_fast[k] + dx1_rate·dt, 0)                # ★ 下限 0 必须保留
       v_lp[k]  += (dt/tau_slope_s)·(v[k] − v_lp[k])              # ★ 更新放在斜率之后
       ── ⑧ 慢态 x2（软冻结 H3 + 受载确认 K7 + 空载快泄放 K7）──
       e   = max(y[k] − x_fast[k] − x_slow[k], 0)                 # ★ 此处 x1 已是本帧更新后
       idle_k = (y[k] − y_floor[k]) < idle_frac·max(y_max[k] − y_floor[k], 1)
       if e > 0:
          base = max(e, 1)                                        # ★ 下限 1
          cap  = slope_cap_frac·base
          soft_ok  = (1 − exp(−t_edge[k]/soft_unfreeze_s)) > 0.5   # ≡ t_edge > w·ln2
          dwell_ok = load_dwell[k] ≥ slow_confirm_s
          if dwell_ok and soft_ok and |slope[k]| < slope_gate_frac·base:
             x_slow[k] += dt · clamp(slope[k] − dx1_rate, −cap, +cap)   # ★ 减的是快态斜率
          x_slow[k] = clamp(x_slow[k], 0, r_slow_max·base)
       if e ≤ 0 or idle_k:
          τ = (idle_k and tau_r_slow_idle_s > 0) ? tau_r_slow_idle_s : tau_r_slow_s
          x_slow[k] = max(x_slow[k] − (dt/τ)·x_slow[k], 0)
       ── ⑨ K6 预留池：a 的增速受限 ──
       if hold_eps > 0:
          slope_a = (v[k] − v_fast_lp[k]) / hold_tau_s
          v_fast_lp[k] += (dt/hold_tau_s)·(v[k] − v_fast_lp[k])
          d_des = x_fast[k] + x_slow[k]
          a_up = applied[k] + dt·max(slope_a + hold_eps, 0)
          a_dn = applied[k] + dt·(slope_a − hold_eps)
          a = (d_des > applied[k]) ? min(d_des, a_up) : max(d_des, a_dn)
          applied[k] = (e > 0) ? clamp(a, 0, max(d_des, 0)) : d_des
                                                  # ★ 空载直写 d_des（保证空载显示≈读数）

  ── 输出（dt=0 的帧也执行）──────────────────────────
  if bypass:
     applied = x_fast + x_slow                    # ★ 状态已更新，只是不施加
     return
  if hold_eps > 0: v −= applied
  else:            v −= x_fast;  v −= x_slow
  # 不做正值钳位、不取整、不归零
```

**与 `creep_observer.cpp` 的行号对照**（便于逐行走查）：首帧 50~67；dt 与旁路 69~94；逐通道 96~201；`e_now` 帧首统一算 124；x1 与 v_lp 147~152；x2 156~181；预留池 185~199；旁路输出 202~205；正常输出 206~211。

## 7. 重置语义、启动语义与首帧

### 7.1 重置触发表（移植侧必须实现同一张表）

| 触发事件 | 上位机落点 | 移植侧对应 | 效果 |
|---|---|---|---|
| 通道数变化 | `if (n_ != n) ResetFor(n)` 在 `Process` 内 | 阵列/掩码配置变更 | 全部状态 = 首帧 |
| 值域签名变化 | `CreepObserverCoordinator::Process` 比对 `signature` | 显示域描述符（模式/单位/零偏/标定态）变更 | 该目标 `Reset()` |
| 算法开关切换（off→on，或跨算法切档） | `CreepObserverCoordinator::SetEnabled(on)` → 变化即 `ResetAll()` | 功能使能位 | 全部目标清空 |
| 设备切换 / 设备类型变更 | `DataHandler::SetDeviceType` → `drift_v34_comp_.ResetAll()` | 传感器重连/更换 | 全部目标清空 |
| 软件调零 | `ZeroOffset` 进入签名 ⇒ 签名变化 | 零偏写入 | **等效算法重启**（§7.3） |
| 回放播放 | `!playback_active_` 作为调用前置条件 | —（嵌入式无此概念） | 回放期间**完全不跑**算法（不推进状态） |

### 7.2 首帧做了什么（三条语义）

1. `zero = 首帧读数` ⇒ **首帧定义了"算法当前认为的零点"**，启动语义全由此而来；
2. `v_lp / v_fast_lp / y_floor = 首帧读数` ⇒ 避免起步瞬间的**虚假斜率**（否则首帧会看到巨大导数）；
3. `total_baseline = 首帧总值`、`total_noise = 0` ⇒ 旁路从"当前工况就是空载基线"起步；`t_edge = 1e6` ⇒ 首帧不算"刚过沿"。
   首帧**不做任何补偿**（`applied = 0`，输出 = 输入）。

### 7.3 启动方式与现场行为（写进使用说明）

| 启动方式 | 行为 |
|---|---|
| 空载启动 | 理想：零点 = 真空点，一切正常 |
| **带载启动 + 调零（推荐）** | 调零后读数≈0 → 落进近零带 → 零点约 8 s 内重锚；软件零偏变化还会直接触发算法重置。**操作规范：装好负载 → 调零 → 开算法**（或算法常开，每次调零自动重置） |
| 带载启动 不调零 | **安全但不补偿**：零点锚在带载读数上 ⇒ `e≈0`、显示逐位跟随输入（随蠕变上爬）；后续负载**增量**正常补偿；第一次卸载后零点自动重锚，完全恢复 |

两个注意点：① **调零 = 重定义参考**，不同调零周期之间的显示值不可直接横比（差一个调零偏置，任何调零系统的固有性质）；② 调零瞬间的读数跳变被 x2 沿门（`|slope|>5%·e/s` 不积分）挡住，不会被当成蠕变吸收。

## 8. 多目标与线程模型

### 8.1 `CreepObserverCoordinator`（多设备/多传感器场景）

```cpp
Process(key, signature, ts, v)   // key = 目标标识（target_id）；signature = 显示值域签名
  if (!enabled_) return;                       // 关着就完全不跑（连状态都不推进）
  is_new = targets_.find(key) == end;
  Entry& e = targets_[key];
  if (is_new || e.signature != signature) { e.comp.Reset(); e.comp.SetParams(params_); e.signature = signature; }
  e.comp.Process(ts, v);
SetEnabled(on)  { if (enabled_ != on) { enabled_ = on; ResetAll(); } }   // 开关切换 = 全部清空
ResetAll()      { targets_.clear(); }
```

- 上位机在**串口单设备**路径用固定 key `"__serial_single__"`（无 target_id 时），**typed（无线/多设备）**路径用 `frame.target_id`；
- 协调器内部是 `std::map<std::string, Entry>`，**每目标一份独立状态**；单设备嵌入式场景可整体退化为"一个实例 + §7.1 的触发表"；
- 注意 `ResetAll()` 是 `clear()`（惰性重建）⇒ 重置后**参数会丢**，所以协调器在重建条目时重新 `SetParams(params_)` 补回（移植侧别只清状态不补参数）。

### 8.2 线程模型（嵌入选型参考）

上位机 `DataHandler` 被 `moveToThread(data_thread_)` 到**独立数据线程**（`application_controller.cpp:431-433`），补偿在数据线程内随帧执行；开关从 GUI 线程用 **`Qt::QueuedConnection`** 投递（`SetDriftV6CompensationEnabled` 等），因此**补偿器状态不存在被并发读写的窗口**。（注意限定：`DataHandler` 上的 `SetPlaybackActive` 等标志由未迁移线程的 `LivePlaybackCoordinator` 直接调用，属跨线程读写，与补偿器状态无关。）

移植建议：
- 单线程逐帧调用，**算法内不要加锁**（加了反而引入优先级反转）；
- 若必须跨核，按"一台设备一个实例、帧数据拷贝进队列"划分，**绝不共享实例**；
- 开关/重置属于**低频控制面**，用消息投递到算法所在线程执行，不要在算法线程外直接改状态。

### 8.3 上位机的六路互斥（移植时的接线参照）

`ApplicationController::ApplyCompensationAlgorithm` 是**唯一开关点**：先向数据层投递**四个 false**（drift / creep / v6(mem=false) / v6(mem=true)），再打开选中项。数据层 `SetDriftV6CompensationEnabled(on, creep_mem)` 用一个布尔区分 v6 档与 v3.4 档：

```cpp
if (creep_mem) { v6 档参数里 mem_tau_s = 0; v6 关; v34 开 }   // creep_mem=true ⇒ v3.4 观测器
else           { v34 关;  v6 参数 mem_tau_s = 0; v6 开 }       // false       ⇒ v6 档
```

**移植只有一套算法时，这段互斥逻辑可以整段丢掉**，但要保留"关闭 = 清空状态"这一条语义（否则再次打开会带着上次的残留状态，现场表现为"刚打开就显示偏低"）。

## 9. 数值、时间与算力

### 9.1 精度

- 上位机全部状态与参数为 **double**；C++ ↔ Python 原型逐帧对拍 **max|Δ| = 5e-5 ADC**（`v34_parity_check.py`；输入 CSV 只有 1 位小数，对拍容差 0.5 ADC）。
- **float32 移植的唯一风险点**是 `slope = (v − v_lp)/τ` 在大读数、小差值下的有效位数：当前 ADC 量级约 2×10⁴、实测每帧 `v − v_lp` 为个位数 ADC，float32 绝对分辨率约 2×10⁻³ ADC ⇒ 仍有约三个数量级余量。
- 若目标域量程更大或蠕变更慢，**先把这一处保留 double**（或 int64 定点），其余状态（x1/x2/zero/y_max）对精度不敏感。
- **不建议早期定点化**：公式含 6 个以上不同 τ 与运行时 clamp，定点带来的收益远抵不过验证成本；真要定点，建议 **Q16.16（int32）**、时间量（`ramp_dwell`/`t_edge`/`load_dwell`）用 Q8.8。

### 9.2 时间基

- 算法**按秒计时**，全部 τ 以秒为单位；MCU 用 tick 计数时换成浮点秒即可。
- 帧率不敏感：所有判据都是相对量与时间常数，帧率变化只改变离散化误差。
- **dt 截断必须保留**：
  ```cpp
  dt = (dt > 0) ? min(dt, 0.1) : 0;
  ```
  - `dt ≤ 0`（重复/回退时间戳）⇒ **跳过全部状态积分，但仍执行输出扣除**（显示照常减去当前 `applied`）；
  - `dt > 0.1`（卡顿/丢帧补发）⇒ 截到 0.1 s。**不截断的后果**：一次 2 s 的 dt 会把 2 s 的积分一次算完，沿门也拦不住（x2 一步吃掉大量台阶增量）。
- 上位机录制 CSV 的 `elapsed` 列约 70% 帧重复、真实帧率约 100.5 Hz（见 `plan/v4/README.md` §5）：**离线复算脚本**要按均匀时间轴重建；但**在线算法本身不需要**——`dt=0` 的帧只施加输出，状态不会因为重复时间戳而畸变。

### 9.3 资源预算（解析估算，非真机剖析）

| 口径 | 数值 | 说明 |
|---|---|---|
| 每通道每帧运算 | 约 60~80 次标量乘加/比较 | 空载分支更少（无沿门/速率限幅/x2 积分）；无 sin/cos/开方/除法（τ 全为常数、预计算倒数）；**复杂度 O(1)**，与录制时长、已积累帧数无关 |
| 超越函数 | 帧级 **1 次 `exp`**（`y_decay`，循环外）；**另有受载通道各 1 次 `exp`**（`soft_ok = 1−exp(−t_edge/soft_unfreeze_s)>0.5`，`creep_observer.cpp:162-163`）——可化为 `t_edge > soft_unfreeze_s·ln2` 比较（=2.77 s）消除，见 §9.4 | 变帧率时 `y_decay` 可用 8 项泰勒或 32 项查表，误差 < 1 LSB |
| 内存 | 每通道 **11 × sizeof(标量)**（F32 44 B/通道）；全局 5 项标量约 29 B（双精度）+ 每实例 `Params` 216 B（27×8，编译期常量则 0） | 21 通道 ≈ 0.9 KB；32 通道 ≈ 1.4 KB；64 通道 ≈ 2.8 KB。**常数内存、无环形缓冲**（对比上一代约 2 MB/目标）；但**上位机实现每帧有 3 次临时向量分配**，移植时必须消除 |
| 吞吐参考 | 21 通道 @100 Hz ≈ 1.2×10⁵ FLOP/s；32 目标×64 通道 @100 Hz ≈ 1.1×10⁷ FLOP/s | 带 FPU 的 Cortex-M4F/M7 单核占用 **<0.5%**；无 FPU 的 M3 软件浮点亦属空闲级 |
| 时序余量 | 21 通道单帧 ≈ 1.2 µs（按 10⁹ 次运算/秒保守口径） | 距 100 Hz 的 10 ms 帧预算有 4 个数量级余量 |

> 参考：`plan/v4/k9/嵌入式迁移说明.md` §4 给出更细的逐段计数（含"K9 净增 128 B@32 通道"）。

### 9.4 免 exp / 降开销的具体手法

1. `soft_ok = 1−exp(−t_edge/soft_unfreeze_s) > 0.5` ⟺ **`t_edge > soft_unfreeze_s × ln2`**（一次比较替代一次 exp）；
2. `y_decay = exp(−dt/y_max_tau_s)`：dt 恒定时是常量；变帧率用泰勒/查表；
3. 所有 `dt/τ` 改为 `dt × (1/τ)`（τ 为编译期常量，倒数预计算）⇒ **帧内真实除法为 0**；
4. 逐通道循环内不要出现函数指针/虚调用（上位机版本是纯成员内联循环）。

## 10. 移植注意点清单（★ 踩坑排序，全部来自实测失效）

### 10.1 顺序与口径（对拍最容易对不上的 6 处）

1. **`dx1_rate` 用更新前的 x1 与帧首算出的 `e_now`**：先算斜率、后更新 x1。写成"先更新 x1 再算斜率"会让 x1 的系统性偏快，逐帧差会累积到可见。
2. **x2 积分里减的是 `dx1_rate`**（快态已认领的速率），不是 `slope` 本身；漏掉 ⇒ 同一份快相爬升被两个状态各记一次（该算例 90 s 处多计约 2% 载荷）。
3. **x2 用的 `e` 必须用本帧更新后的 x1 重算**（源码里 `e_now` 与 `e` 是两个量）。
4. **`v_lp_` 的更新在斜率计算之后**（斜率用更新前的 `v_lp_`）；顺序反了等价于把低通滞后缩短一拍。
5. **门限/钳位里的 `max(·, 1)` 下限**共 3 处（`span`、`base`、`idle_k` 的 span）——漏掉后冷启动（`y_max=0`）时判据不可用，症状是"零点永不跟踪"，而且**不报错**。
6. **沿的 `refract` 取 `max(edge_refract_s, edge_boost_s)`**，不是直接用 `edge_refract_s`。

### 10.2 语义类（不报错、只表现为"换姿势就复发"）

7. **旁路帧不能整帧 return**：旁路帧必须照常跑逐通道状态演化（零点跟踪、x1/x2 泄放、`load_dwell` 清零），只把 `applied` 写成 `x_fast+x_slow` 后返回。整帧 return ⇒ `load_dwell` 只进不出、确认门失效 ⇒ 空载塌陷换姿势复发。（K7 轮的关键实现教训，源码注释有原文；该机制在 K9 里生效。）
8. **空载时 `applied = d_des`**（不是 limit 后的 `a`）：保证"空载显示≈原始读数"的语义。写成 `a` 会让空载残差被一直扣着。
9. **`slow_confirm_s` 不可缩到 5 s**：4~6 s 保载工况下 5 s 刚好够门槛 ⇒ 短保载被当慢漂移吸收，逐循环棘轮复发（growth +0.70）；**`tau_c_fast_s` 不可减小**（快态吸走更多真实响应）。
10. **不做正值钳位、不取整、不归零**：输出是"显示值"，正值钳位属于下游阈值过滤（上位机 `ApplyThreshold` 把 `<阈值` 一律置 0）。在算法里顺手加钳位 ⇒ 内部状态与显示不一致，卸载段会出现假的"贴 0"平台。
11. **`dt≤0` 的帧仍要执行输出扣除**（旁路判定也不更新基线/噪声），只是不积分。
12. **`t_edge` 初值必须是"很大的数"（1e6）**，不能是 0：否则首帧被当成"刚过沿"，前馈与软冻结都会误开。

### 10.3 移植工程类

13. **Eigen 可以整段去掉**：算法本体只用到 `+= / -= / cwiseMax / sum / size / operator()`，另有 `Zero/Constant` 用于初始化；**关键是 `Process()` 内每帧新建的 3 个临时向量（`y`/`slope`/`e_now`）必须改成定长数组或成员缓冲**（这是"嵌入式零分配"唯一的必改项）。
14. **首帧与 `ResetFor(n)` 的分工**（§5.1 注）：`ResetFor` 只构造一部分状态，其余由首帧分支赋值，两条路径都要覆盖到。
15. **通道数=0 直接返回**（同一次连接里 layout/mask 可能瞬时空）。
16. **别把 27 个参数硬编码进公式常数**：至少留一个可注入结构（未来重标才不用重编固件）；建议编译期常量 + 只读"参数集版本"标识。
17. **协调器 `ResetAll()` 后要补回参数**（§8.1）。
18. **开关/签名/设备切换的重置语义要成套实现**（§7.1），否则症状是"换个显示模式显示突然不对"。
19. **源码注释有几处是历史口径，别被误导**：`creep_observer.h` 里 `idle_frac` 的行注释仍写 `近零带：y < 5%·y_max 视为空载`（K7 已改为去趋势判据）、文件头注释里 `tau_r_fast_s` 的默认值仍写 6 s（实际 2 s）、`x2` 的"空载以 τr2 恢复"未提到空载快泄放 τ=8 s。**以 `.cpp` 实际代码与本文 §6/§7 为准**。

## 12. 已知限制与代价（如实，随版本标注）

| 限制 | 机制来源 | 现场含义 |
|---|---|---|
| **慢态会吸收真实的缓慢加载** | x2 是速率式，`≤1%·e/s` 且连续的真实加压会被当蠕变积掉（`slope_cap_frac`） | "恒载钉平"与"缓慢加载保真"是同一把尺子的两面，只能调权衡；现场若是持续缓慢加压，需明确评估（或与 K7 基线对比开关效果） |
| **受载态小台阶落位为秒~十秒级**（7.5~15 s） | 无事件重锚快捷路径；剩余限制是**输入自身后沿蠕变**（斜坡顶后 10 s 输入仍爬升中位 8.5%·台阶） | 首次大台阶 2.0~2.6 s、重载 1.3~1.6 s 是好的；小台阶"1 s 内完全钉平"在单帧信息下不可达 |
| **快相期间显示略偏高** | 预留池把"会往下拉"的补偿暂存（K6 取向性偏差） | 随后数十秒缓慢归位；这是"绝不回落"换来的 |
| **卸载后有一段低于原始零点的过渡** | 零点再校准（τ0=8 s）+ 非弹性状态恢复 | 语义自洽（"恢复中的非弹性估计"），但比空载直通慢一步 |
| **带载启用不调零 ⇒ 不补偿** | 零点锚在带载读数上，`e≈0` | 安全侧设计；需补偿请先调零，**必须写进使用说明** |
| **保压前 10 s+确认期少扣约 10~15%** | `slow_confirm_s=10` s | 长保压补偿起效推迟约 13 s；<30 s 保压可见欠扣，超长保压影响可忽略 |
| **频繁切换工况的平台 std 上升** | 速率跟踪有惯性（R1 33→81、R6 28→69） | 是平台内波动、不是落点错误（一致性判据照样合格）；在意时可下调 `slope_cap_frac`，代价是慢漂移跟踪变慢 |
| **2e35b8 类工况棘轮未根除** | 递减台阶 + 短循环（~10 s/循环）下慢态仍有累积（growth +512） | K7 已知局限，需按其真实加载序列针对性设计（怀疑需按"加载段结构"重置 x2） |
| **参数全局固定** | 跨会话辨识表明参数（尤其慢相量级）不稳定 | 选择"全局默认 + 换设备重标"，不做启动期在线辨识 |

## 13. 现场操作规范（随固件/软件一起交付）

1. **推荐流程**：装好负载 → **调零** → 开启补偿（或算法常开、每次调零后自动重置）；
2. 采集前确认"补偿算法"选择正确（上位机：调试 → 补偿算法选择...；固件：使能位 + 参数集版本），并**记录参数集**；
3. 需要"卸载-重载后保持一致"的反复增减工况，选本算法；需要"加载沿后极快稳定"的工况，另选 v6 档；
4. 归零/换传感器/改显示域之后，算法会重启，**前 8 s 内的零点仍在重锚**，不要在这段时间做读数判断；
5. 若观察到"刚打开就显示偏低"，检查是不是**关闭时没清状态**（§10.3-18）。

### 14.3 术语

| 术语 | 含义 |
|---|---|
| 快态 / x1 | 加载后数秒~数十秒的快相非弹性分量（位置式，朝 `r_fast·e` 收敛） |
| 慢态 / x2 | 分钟级慢蠕变分量（速率式，积分实测慢漂移速率） |
| 弹性估计 / e | `max(y − x1 − x2, 0)`，同时充当受载门 |
| 预留池 / applied | "会把显示往下拉"但暂不施加的补偿量（K6） |
| 沿（edge） | 低通导数超过 60 ADC/s 的快速加载/卸载瞬间 |
| 旁路（bypass） | 总值低于空载门限时整帧直通（状态仍演化，只是不施加补偿，K7） |
| param_set | 参数集标识，随录制落盘，用于把结论与"跑的是哪一版参数"绑定 |
