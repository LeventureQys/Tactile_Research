## 0. 这份文档解决什么

移植 K11 的失败方式几乎都不是"算错了某个公式"，而是**顺序错了**或**口径错了**：

- 把 `dt` 与 `raw_dt` 混用 → 断流检测永久失效；
- 把总量斜率当成每通道斜率 → 阈值差 n 倍（52/57/71 倍），门控要么永不触发、要么永远触发；
- 把门控接到错误的接点 → 加载期的载荷被零点吞掉（这正是 K11 要防的缺陷）；
- 把"冻结增长"实现成"清零" → 卸载瞬间跳变，比不做更糟。

所以本文的主体不是公式，而是**唯一合法执行顺序**（§3）、**口径定义**（§5）、**接点位置**（§5.8）
与**陷阱清单**（§8）。照 §3 的顺序与 §5 的口径实现，逐帧等价是可判定的（§9）。

## 1. 算法定位与边界

### 1.1 三档关系

| 档位 | 构成 | 界面入口 | 落盘 id |
|---|---|---|---|
| v3.4 观测器 | 内核（27 参数） | 有 | `drift_v34_creep_observer` |
| K10 观测器 | v3.4 + 瞬态防护层（`guard_enable=1`） | 无（数据层保留，仅回归） | `drift_k10_creep_observer` |
| K11 v1 观测器 | K10 + 慢态进入门控（`k11_enable=1`） | 有 | `drift_k11_creep_observer` |

三档**同一个内核**，差别只有两层可选叠加。`param_set` 字符串随录制落盘：
`plan-v4 observer-k9 [+ K10 transient guard] [+ K11v1 plateau gate] [+ floor-rise-gate]`。

**硬约束**：`k11_enable=1` 必须以 `guard_enable=1` 为底座（`DataHandler::SetCreepObserverK11Enabled`
在开启时强制把 guard 置 1）。单独开 k11 而不开 guard 是界面上不存在的组合，移植时不得提供该组合。

### 1.2 K11 v1 改了什么

只改 **`x_slow` 的进入条件** 与 **`zero` 的更新条件**，加一组可观测的诊断量。四件事：

1. **时间质量**：`dt≤0`（重复/回退时间戳）与 `dt>k11_max_gap_s`（断流）的帧不许跨过去积分；
2. **事件状态机**：`INIT → RISING → MOTION_HOLD → PLATEAU_CANDIDATE → STABLE_PLATEAU`，另有 `UNLOAD` / `UNCERTAIN`；
3. **平台确认**：短窗与长窗斜率同时回到平台带并持续 `k11_plateau_confirm_s`（带超时兜底）；
4. **空间共模置信度**：共模占比不足时**延长**确认，不单独否决。

### 1.3 K11 v1 明确不动的东西（移植时一个字都别改）

- `x_fast` 的微分方程、`r_fast`、`tau_c_fast_s`、`tau_r_fast_s`、沿检测与缓坡前馈；
- `x_slow` 的**幅度上限**（`r_slow_max·base`）、**速率上限**（`slope_cap_frac·base`）、钳位顺序；
- `applied` 预留池的增速限制与空载直通语义；
- `zero` / `y_max` / `y_floor` / `load_dwell` 的既有更新方程（K11 只增加"是否允许执行"的门）；
- K7 全局总值旁路、K10 瞬态防护层的阈值与分支；
- 输出语义：`z = v − applied`（`hold_eps>0` 时）或 `z = v − x_fast − x_slow`。

**冻结的是"增长"，不是"已有值"**：任何状态下都不得把 `x_slow` 归零或重钳位；
卸载/空载仍走既有泄放分支（`tau_r_slow_idle_s` / `tau_r_slow_s`）。

## 2. 移植目标契约（算法侧接口）

源实现的最小接口面（`creep_observer.h`）：

```text
class CreepObserverCompensator {
    struct Params { ... 43 项，见 §6 ... };
    void Process(double timestamp_s, Vector& values_io);   // 就地改写：输入原始 ADC，输出补偿后读数
    void Reset();                                          // 全状态清零（含 K11 状态机）
    void SetParams(const Params&);
    // K11 诊断（只读）
    int    k11_state();            // 0=Init 1=Rising 2=MotionHold 3=PlateauCandidate 4=StablePlateau 5=Unload 6=Uncertain
    bool   k11_allow_slow();       // 本帧是否允许 x_slow 增长（关闭态恒 true）
    double k11_short_slope();      // ADC/s（总量口径）
    double k11_long_slope();       // ADC/s（总量口径）
    double k11_common_mode_ratio();// |median(Δ)| / median(|Δ|)
    double k11_spatial_energy();   // median(|Δ − median(Δ)|)
    int    k11_time_quality();     // 0=valid 1=repeated/backward 2=long_gap
};
```

多目标协调器（`CreepObserverCoordinator`）的语义必须一并移植：

- 按 `key` 隔离状态，每个 key 一份完整状态；
- `signature`（显示值域签名）变化 → 该 key `Reset()`；
- `SetEnabled(true/false)` 翻转 → **全部** `ResetAll()`；
- 通道数 `n` 变化 → `ResetFor(n)`（等价于 `Reset()` 后按新 n 建零状态）。

**状态编号 0~6 不可改**：诊断、录制落盘、上位机界面都按这套编号解读。

## 3. 逐帧执行顺序（唯一合法顺序）

源实现：`Process()` 第 86–343 行。`values_io` 是就地输入输出，**全程使用原始 ADC**，
直到函数末尾才扣补偿。

### 3.1 首帧（`first_frame_`，第 92–126 行）

```text
first_frame_ = false; last_ts_ = ts
zero_        = v
y_max_       = 0
v_lp_        = v
v_fast_lp_   = v
y_floor_     = v                     // 若 guard_floor_recover_s > 0 则改为 v − zero_ (= 0)
```

### 3.2 每帧九步

```text
S1  时间与步长
    raw_dt = ts − last_ts_ ; last_ts_ = ts
    dt     = (raw_dt > 0) ? min(raw_dt, 0.1) : 0
    ※ 0.1 s 夹断只用于数值积分，判据一律用 raw_dt

S2  K7 全局总值旁路判定（第 133–154 行；下文 baseline = total_baseline，noise = total_noise）
    total = Σv ; alpha = min(dt/bypass_base_tau_s, 1)
    release = max(bypass_release_frac·baseline, baseline + bypass_noise_sigma·noise)
    engage  = max(bypass_engage_frac ·baseline, baseline + (bypass_noise_sigma+1)·noise)
    ※ 两个门限都用**本帧更新前**的 baseline/noise 计算
    if total < engage:  baseline += alpha·(total − baseline)
                        noise    += alpha·(|total − baseline| − noise)   ← 用刚更新的 baseline
                        noise     = max(noise, 0)
    bypass_frame = (total < release)
    ※ baseline/noise 只在 total < engage 时跟踪；受载期冻结

S3  时间质量标记（第 156–161 行，只有 k11 档才置位）
    if k11_enable≠0 and dt ≤ 0: time_quality = 1 ; allow_slow = false
    ※ 该帧此后不进 S4（dt=0），但标记必须留下

S4  K11 门控（仅 dt > 0，第 163–170 行）
    allow_slow = true                      // 先复位，再由门控覆盖
    if k11_enable≠0: UpdateK11Gate(v, raw_dt, dt)     // 见 §5

S5  逐通道零点 / 包络 / 基线（第 176–234 行）
    y0 = v − zero
    ① y_floor 下行：guard 开时需持续 guard_floor_confirm_s，或深度 > guard_floor_deep 立即跟随；
       回抬锚开启时在"从非下探转入下探"那一帧记 anchor = y_floor（旧值）
       in_drop = 本帧是否发生下行（仅 guard_floor_recover_s > 0 时影响 ③ 的回抬分支）
    ② y_max = max(y_max·exp(−dt/y_max_tau_s), max(y0,0))
    ③ y_floor 上行：floor_rise_idle_only=1 时仅在本帧判空载时抬升，即
       (y0 − y_floor) < idle_frac·max(y_max − y_floor, 1) 成立才执行 y_floor += (dt/y_floor_tau_s)·(y0 − y_floor)；
       受载期冻结（此判据用**抬升前**的 y_floor，与 ④ 的 idle 判据不是同一个值）
    ④ span = max(y_max − y_floor, 1) ; idle = (y0 − y_floor) < idle_frac·span
    ⑤ load_dwell = idle ? 0 : load_dwell + dt
    ⑥ k11_zero_ok = (k11_enable=0) || (time_quality=0 && allow_slow)     ← K11 接点①
    ⑦ if idle && k11_zero_ok: zero += (dt/tau_zero_s)·(v − zero)

S6  快态与低通（第 235–271 行）
    y     = v − zero
    slope(k) = (v − v_lp)/tau_slope_s          ← 用**更新前**的 v_lp（与 §5.2 的 K11 双窗口径不同，别统一）
    e_now = max(y − x_fast − x_slow, 0)        ← 用**更新前**的 x_fast / x_slow
    每通道：
      t_edge += dt
      fire = slope > edge_slope_thres && t_edge > max(edge_refract_s, edge_boost_s) ; if fire: t_edge = 0
      ramp_dwell = (ramp_slope_min < slope ≤ edge_slope_thres) ? ramp_dwell+dt : 0
      if |slope| > edge_slope_thres: load_dwell = 0
      tc1 = (edge_boost_s > 0 && t_edge < edge_boost_s) ? tau_c_fast_boost_s : tau_c_fast_s
      if ramp_full_s > 0: w = min(ramp_dwell/ramp_full_s,1) ; tc1 = tc1·(1−w) + tau_c_fast_boost_s·w
      dx1_rate = (e_now>0) ? (r_fast·e_now − x_fast)/tc1 : −x_fast/tau_r_fast_s
      x_fast = max(x_fast + dx1_rate·dt, 0)
      v_lp  += (dt/tau_slope_s)·(v − v_lp)     ← 更新发生在 slope 取用之后

S7  慢态积分（第 272–294 行）

    span_k = max(y_max − y_floor, 1) ; idle_k = (y − y_floor) < idle_frac·span_k
    if e > 0:
      base = max(e,1) ; cap = slope_cap_frac·base
      soft_ok  = 1 − exp(−t_edge/soft_unfreeze_s) > 0.5
      dwell_ok = load_dwell ≥ slow_confirm_s
      if dwell_ok && soft_ok && allow_slow && |slope| < slope_gate_frac·base:      ← K11 接点②
          x_slow += dt·clamp(slope − dx1_rate, −cap, cap)
      x_slow = min(x_slow, r_slow_max·base) ; x_slow = max(x_slow, 0)

S8  泄放（第 295–312 行）
    if e ≤ 0 || idle_k:
      tau_r2 = (guard 开) ? (idle_k && idle_elapsed ≥ guard_idle_confirm_s && tau_r_slow_idle_s>0
                            ? tau_r_slow_idle_s : tau_r_slow_s)
                          : (idle_k && tau_r_slow_idle_s>0 ? tau_r_slow_idle_s : tau_r_slow_s)
      x_slow −= (dt/tau_r2)·x_slow ; x_slow = max(x_slow, 0)

S9  预留池与输出（第 313–342 行，K11 不介入）
    if hold_eps > 0:
      slope_a = (v − v_fast_lp)/hold_tau_s

      d_des = x_fast + x_slow
      a_up  = applied + dt·max(slope_a + hold_eps, 0)
      a_dn  = applied + dt·(slope_a − hold_eps)

      if e > 0: a = clamp(a, 0, max(d_des, 0)) else: a = d_des
```

### 3.3 顺序不能换的三个反例

| 调换 | 后果 |
|---|---|
| 把 S4 挪到 S2 之前 | `load_scale` 会用上一帧的 `total_baseline_`，受载第一帧的阈值偏小，加载被判 RISING 早一帧；关闭态虽不受影响，但 k11 档逐帧不等价 |
| 把 S4 挪到 S5 之后 | 零点先用旧 `allow_slow` 更新一帧，加载帧的读数被写进 `zero`（正是缺陷入口） |
| 把 S3 的标记挪到 S4 内 | `dt=0` 帧根本不进 S4，标记永久丢失，诊断上看不出断点 |

## 5. K11 门控完整规格

源实现：`UpdateK11Gate(v, raw_dt, dt)`，第 350–492 行。**只读输入与既有状态，不改写
`zero / x_fast / x_slow / applied`**——这条纪律必须保留，否则门控会变成第二个补偿器。

### 5.1 载荷尺度 `load_scale`

```text
load_scale = max( max(total − total_baseline, 0.5·|total|), 1 )
```

- 优先用「当前总量 − 空载基线」= 真实载荷；
- 兜底 `0.5·|total|`：**首帧即受载**时 `total_baseline` 已被初始化成载荷电平，
  `total − baseline ≈ 0`，若没有兜底 `load_scale→1`，阈值塌到 `0.05 ADC/s`，
  任何噪声都被判 rising，慢态永久冻结。这是"门控把补偿全冻死"最现实的失效路径。
- 单位：**全通道总 ADC**，不是每通道。`rise_thr`、`plat_thr`、`slope` 全部是总量口径。

### 5.2 双窗斜率（**先更新低通，再取斜率**）

```text
tau_s = max(k11_short_window_s, 1e-3) ; tau_l = max(k11_long_window_s, 1e-3)
a_s = min(dt/tau_s, 1)                 ; a_l = min(dt/tau_l, 1)
short_lp += a_s·(total − short_lp)
long_lp  += a_l·(total − long_lp)
short_slope = (total − short_lp)/tau_s
long_slope  = (total − long_lp )/tau_l
```

这是"一阶低通解析导数"口径，等价于 `dv/dt ≈ (x − lp)/τ`。

**与 S6 的 `slope(k)` 口径不同**：S6 用更新前的 `v_lp`，这里用更新后的 `short_lp`。
两处都照抄，不要"统一"——统一会让所有锚点漂移。

### 5.3 空间共模置信度

```text
if size(v_short_lp) == n:
    Δ[k]    = v[k] − v_short_lp[k]           // 更新前的参考
    common  = median(Δ)
    resid[k]= |Δ[k] − common| ; spatial_energy = median(resid)
    abs_med = median(|Δ[k]|)
    common_mode_ratio = (abs_med > 1e-9) ? |common|/abs_med : 0
    v_short_lp[k] += a_s·(v[k] − v_short_lp[k])
else:                                        // 仅 Reset 后首帧可能触发；实际被首帧 return 挡掉
    v_short_lp = v ; common_mode_ratio = 1 ; spatial_energy = 0
```

三条必须照抄的性质：

1. **用中位数不用均值**：单点尖峰不能主导空间结论；
2. **`abs_med ≤ 1e-9` → ratio = 0**（不是 1）。全通道零变化时共模置信度为 0，
   于是 `spatial_ok=false`，平台确认只能靠超时兜底（默认 3 s × 2 = 6 s 才放行）。
   改成"无变化视为高置信"会改变空载起步的行为与诊断量。
3. 偶数 n 的中位数取中间两数均值；n=57 时 `mid = 28`，取 `nth_element` 后索引 28（0 基）的元素。

`spatial_energy` 只作诊断，不参与任何判定（源实现无 `k11_spatial_energy_max` 判定分支）。

### 5.4 时间质量

```text
raw_dt ≤ 0            → quality = 1   （重复/回退时间戳）
raw_dt > k11_max_gap_s → quality = 2   （断流）
否则                   → quality = 0
```

判据用 **raw_dt**；若用夹断后的 `dt`（≤0.1 s），一秒级断流永远看不出来。

### 5.5 三个布尔判据

```text
rise_thr = k11_rise_slope_frac    · load_scale
plat_thr = k11_plateau_slope_frac · load_scale
rising  = short_slope >  rise_thr
falling = short_slope < −rise_thr
plateau = |short_slope| ≤ plat_thr && |long_slope| ≤ plat_thr
time_ok = (quality == 0)
spatial_ok = (common_mode_ratio ≥ k11_common_mode_ratio_min)
```

`plat_thr = rise_thr/2` 形成**滞回带**；`rising` 与 `plateau` 的边界分开是刻意的，
合并成一个阈值会让状态在边界附近逐帧抖动。

### 5.6 状态机（严格按源码优先级）

`enter(s)`：仅当目标状态 ≠ 当前状态时赋值并令 `k11_state_elapsed = 0`。
`k11_state_elapsed += dt` 在 switch **之前**统一执行；`k11_plateau_elapsed` 由各分支显式管理。

| 当前状态 | 判定顺序（命中即 break） | 目标 |
|---|---|---|
| INIT | `!time_ok` | UNCERTAIN |
| | `rising` | RISING |
| | `falling` | UNLOAD |
| | 否则 | PLATEAU_CANDIDATE，`plateau_elapsed=0` |
| RISING | `!time_ok` | UNCERTAIN |
| | `falling` | UNLOAD |
| | `plateau` | MOTION_HOLD |
| MOTION_HOLD | `!time_ok` | UNCERTAIN |
| | `rising` | RISING |
| | `falling` | UNLOAD |
| | `state_elapsed ≥ k11_motion_hold_s` | PLATEAU_CANDIDATE，`plateau_elapsed=0` |
| PLATEAU_CANDIDATE | `!time_ok` | UNCERTAIN |
| | `rising` | RISING，`plateau_elapsed=0` |
| | `falling` | UNLOAD，`plateau_elapsed=0` |
| | `!plateau` | 停留，`plateau_elapsed=0` |
| | `plateau` | `plateau_elapsed += dt`，然后见下式 |
| STABLE_PLATEAU | `!time_ok` | UNCERTAIN |
| | `rising` | RISING |
| | `falling` | UNLOAD |
| | `!plateau` | PLATEAU_CANDIDATE，`plateau_elapsed=0` |
| UNLOAD | `!time_ok` | UNCERTAIN |
| | `rising` | RISING |
| | `plateau` | PLATEAU_CANDIDATE，`plateau_elapsed=0` |
| UNCERTAIN | `!time_ok` | 停留 |
| | `rising` | RISING |
| | `falling` | UNLOAD |
| | 否则 | PLATEAU_CANDIDATE，`plateau_elapsed=0` |

候选期放行：

```text
need = max(k11_plateau_confirm_s, 0)
hard = need · max(k11_plateau_timeout_frac, 1)
if (plateau_elapsed ≥ need && spatial_ok) || plateau_elapsed ≥ hard → STABLE_PLATEAU
```

三条易错点：

1. 进入 PLATEAU_CANDIDATE 的那一帧 `plateau_elapsed` 被显式清 0，**当帧不累加**，
   所以确认实际耗时是 `need + 一帧`；
2. `MOTION_HOLD` 的退出条件用的是"进入后再累加 dt"的值，进入帧不算；
3. 超时兜底只在"斜率已满足平台"时生效（它在 `plateau` 分支内），不放宽平台判定本身。

### 5.7 放行规则

```text
k11_allow_slow = (k11_state == STABLE_PLATEAU)
```

只放行 STABLE_PLATEAU。RISING / MOTION_HOLD / PLATEAU_CANDIDATE / UNLOAD / UNCERTAIN
一律冻结**增长**：不清零、不跳变、不阻断泄放。

### 5.8 三个接点（缺一不可）

| 接点 | 位置 | 表达式 | 缺失后果 |
|---|---|---|---|
| ① 零点门 | S5 ⑥ | `k11_zero_ok = (k11_enable=0) \|\| (quality=0 && allow_slow)` | 加载/断流期的读数被写进 `zero`，载荷被慢慢吞进基线 → 补偿归零、显示阶梯上飘 |
| ② 慢态增长门 | S7 | `dwell_ok && soft_ok && allow_slow && \|slope\| < slope_gate_frac·base` | 门控完全不起作用（等于 K10） |
| ③ 时间质量标记 | S3 | `quality=1; allow_slow=false`（仅 `dt≤0`） | 断点不可观测；`dt=0` 帧看起来与正常帧无差别 |

注意接点①的完整语义：K11 档下 `zero` 只能在 **idle 且 STABLE_PLATEAU 且时间有效** 时更新。
这条比设计稿的"降权或冻结"更硬，是源码口径。

## 7. 数值与实现约束

1. **全程 double**。总量是 57 通道求和（~3e4 ADC），`short_slope` 峰值达 ~5.5e4 ADC/s，
   单精度可算但逐帧等价不可达（相对误差 1e-7 在阈值比较处会翻状态）。
2. **每帧开销**：3 次 `nth_element`（空间中位数）+ 3 次一阶低通 + O(n) 循环。
   n ≤ 71，100 Hz × 多目标可忽略。MCU 上可用"三路快速选择"或对 n ≤ 71 直接插入排序。
3. **定点不建议**：阈值链路是相对比例的乘法（`frac·load_scale`），且斜率动态范围
   1e-4 ~ 5e4（约 29 bit），定点需要 ≥ 24 bit 小数位并重标全部锚点。
4. **平台相关浮点**：本文锚点由 MSVC 2022 `/O2`（默认 `/fp:precise`）产生。
   换编译器/换 FMA 收缩策略，末位可能差 ~1e-12 相对量；状态与门限判定不受影响，
   但"逐位一致"只在同编译参数下成立（见 §9 容差）。
5. **时间戳**：只接受单调递增的秒（double）。首帧时间戳任意；`dt` 的上限夹断 0.1 s 是内核口径，
   不允许为了"补偿断流"把它调大。

## 8. 移植陷阱（每条都配"错了会怎样"）

1. **`raw_dt` 与 `dt` 混用** → 断流检测失效：夹断后 `dt ≤ 0.1`，`> k11_max_gap_s` 永不成立。
   反向错误同样致命：**断流帧不许整帧跳过**。参照实现仍用夹断后的 `dt=0.1` 推进一次数值积分
   （`zero`/`x_fast`/`x_slow`/`applied` 都动），只是门控把状态推进到 UNCERTAIN 并停掉 `x_slow` 增长。
   整帧跳过会让恢复后的轨迹与参照实现偏离，且状态机没走到 UNCERTAIN。
2. **统一两处低通口径** → 所有锚点漂移，逐帧等价不可判定。
3. **按每通道实现总量斜率** → 阈值差 n 倍（57 倍），门控要么永不触发（慢态冻结、补偿死），
   要么永远触发（等于 K10）。
4. **省掉 `load_scale` 的 `0.5·|total|` 兜底** → 首帧即受载时阈值塌到 0.05 ADC/s，永久 RISING。
5. **把 `abs_med ≤ 1e-9` 时 ratio 写成 1** → 空载起步立刻 STABLE（真值要等 6 s 超时），诊断口径不同。
6. **合并 `state_elapsed` 与 `plateau_elapsed` 的清零时机** → 确认时长少一帧或跨状态残留。
7. **把 `allow_slow = true` 的复位放错位置** → 复位必须在 `dt>0` 分支的入口、紧接门控调用的前一行；
   而门控在关闭态**一次都不被调用**。写成"总是调用门控、关闭态返回 true"会破坏关闭态的逐位一致。
8. **在 `bypass_frame` 时跳过门控** → 旁路是输出直通，不是门控停摆。长空载后第一次加载会带着
   陈旧平台证据，进入 STABLE 的时刻提前。
9. **把冻结实现成清零或钳位** → 卸载瞬间 `x_slow` 跳变，显示上出现"台阶"。
10. **漏掉接点①（零点门）** → 这正是 K11 要防的缺陷入口：加载期 `zero` 吞掉载荷、`e≡0`、
    `x_slow` 泄放、显示逐通道阶梯上飘。
11. **改 `applied` 限速**（K6）→ `slope_a = (v − v_fast_lp)/hold_tau_s`；
    `a_up = applied + dt·max(slope_a+hold_eps, 0)`，`a_dn = applied + dt·(slope_a−hold_eps)`；
    `a = d_des > applied ? min(d_des, a_up) : max(d_des, a_dn)`；`e>0` 时再 `clamp(a, 0, max(d_des,0))`，
    `e≤0` 时 `a = d_des`。顺序错会让预留池反向放行。
12. **通道数/signature 变化不 Reset** → K11 带着上一段的平台证据，进入 STABLE 早一个事件。
13. **状态编号重排** → 落盘诊断与界面解读全部错位。
14. **给 K11 提供"单独开 k11 不开 guard"的组合** → 产生界面上不存在的档位，回归对照失去意义。

## 10. 已知失效模式与红线

1. **`k11_rise_slope_frac = 1e-3`（设计稿原值）会冻死补偿**：实测蠕变 1.6e-2 /s 持续高于阈值，
   状态永久 RISING，慢态冻结 **66 s**。这不是"调参"，是默认值错误。
2. **空间置信度做成硬门 → 死锁**：某些传感器空间形态长期不达标时永久停在候选期，补偿整段失效。
   源码的解法是超时兜底（`k11_plateau_timeout_frac`），且只在平台已满足时生效。
3. **10g 级小阶跃未被覆盖**：约 `7e-3 /s` < `5e-2 /s`，仍走平台分支，慢态是否吸收取决于
   `slope_gate_frac` 与受载确认，不是本门控能解决的（需求文档 §3.3 的后续目标）。
4. **部分卸载无独立模型**：`UNLOAD` 只冻结增长，交回既有泄放路径。
5. **跨传感器参数分档未做**：门控参数全局一套；幅度/速率类由既有 8 项现场参数承担。
6. **红线**：不得为了"让补偿跟上"而放宽 `allow_slow`；不得在门控里改写补偿状态；
   不得把 K11 变回"慢于某时间常数的上行一律按蠕变扣除"（那是已弃用的 v3.5 `hold_lock` 语义，
   对真实慢速加载过于强硬）。

## 附 A 三档切换与宿主接线（移植到上位机时照抄）

```text
切 v3.4 ：① SetCreepObserverK11Enabled(false)  → k11_enable=0（无条件先关）
          ② SetCreepObserverGuardEnabled(false) → guard_enable=0
切 K10  ：① SetCreepObserverK11Enabled(false)  → k11_enable=0
          ② SetCreepObserverGuardEnabled(true)  → guard_enable=1（界面无入口，仅数据层回归）
切 K11  ：① SetCreepObserverGuardEnabled(true)  → guard_enable=1（先落底座）
          ② SetCreepObserverK11Enabled(true)   → k11_enable=1（数据层在此强制 guard=1）
```

- 每次都先把 `k11_enable` 关掉再按档设 guard：否则从 K11 档切到 v3.4/K10 会残留
  `k11_enable=1`（界面上不存在的组合，数据层却仍按门控冻结慢态）；
- K11 档两步顺序是刻意的：先 guard 后 k11，日志里能看出档位是怎么叠上去的；
- 开关取值真的变化时才 `ResetAll()`（未变则直接返回，不打断正在跑的观测器）；
- `CurrentDisplayAlgorithm()` 按 `k11_enable` / `guard_enable` 反推 id 与 label（§1.1 表）；
- **设备侧无 K11**：固件只有 v3.4 观测器（无 K10 防护层、无门控）。「参数...」对话框下发的
  是设备侧 v3.4 的 8 项现场参数，与 K11 的 10 项门控参数互不相干。若移植目标是固件，
  需要一并扩展寄存器映射（现有 `tau_c_fast_s`/`slope_cap_frac`/`r_slow_max` = 寄存器 206/207/208）。
