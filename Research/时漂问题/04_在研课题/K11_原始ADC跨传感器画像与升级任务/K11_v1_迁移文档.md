# K11 v1 迁移文档

> 文档状态：设计与迁移规范，尚未进入产品源码
>
> 版本：K11 v1
>
> 日期：2026-10-20
>
> 适用基线：K10 瞬态防护版；K10 继承 K9/v3.4 双态蠕变观测器

## 1. 迁移结论

K11 v1 采用 **K10 增量迁移**，不另起一套观测器，不直接恢复旧 K11/v3.5 的 `hold_lock` 实验代码。

迁移目标是：

- 保留 K9/K10 已有的 `zero`、`x_fast`、`x_slow`、`applied` 和空载恢复机制；
- 在慢态积分之前增加输入质量、变化保护和平台确认；
- 让加载、卸载、异常时间和空间证据不足时的行为可观测、可回退；
- 默认关闭 K11 v1 时，与当前 K10 保持逐帧等价；
- 不把缺少操作标签的原始曲线直接解释为恒载或 10g 真值。

K11 v1 的定位是“慢态进入条件升级”，不是完成全部时漂需求的最终版本。

## 2. 当前基线与迁移范围

### 2.1 K9/K10 当前计算链

```text
输入逐通道 ADC v[k]
    -> zero[k]
    -> y[k] = v[k] - zero[k]
    -> x_fast[k]
    -> x_slow[k]
    -> applied[k]
    -> 输出 z[k] = v[k] - applied[k]
```

K10 当前已经包含：

- 快态 `x_fast`；
- 慢态 `x_slow`；
- 上升沿与缓坡前馈；
- `slow_confirm_s` 受载确认；
- `soft_unfreeze_s` 沿后软解冻；
- K6 `applied` 预留池；
- K7 去趋势空载门和慢态快速泄放；
- K10 瞬态防护层。

对应的现役参考实现位于：

```text
Research/时漂问题/01_当前工作_K9/00_基线_K9源码/creep_observer.h
Research/时漂问题/01_当前工作_K9/00_基线_K9源码/creep_observer.cpp
Research/时漂问题/03_K10_算法迁移包_20261014/creep_observer_portable.h
```

本目录中的 K11 v1 文件只描述迁移方案，不代表产品源码已经完成修改。

### 2.2 不在本次迁移中修改的内容

K11 v1 暂不修改：

- `x_fast` 的基本微分模型；
- `x_slow` 的幅度上限和速率上限公式；
- `applied` 的预留池增速限制；
- 既有空载旁路的输入输出语义；
- ADC 到力值映射；
- 通道布局和通道顺序；
- 产品 UI 中的现有 K9/K10 参数语义；
- 旧 K11/v3.5 的 `track_base_frac`、`hold_lock_tau_s`、`hold_lock_freeze_s`。

旧 K11/v3.5 的核心规则是“慢于指定时间常数的上行一律按蠕变处理”。这条规则对慢速真实荷载变化过于强硬，先不直接迁移。

## 3. K11 v1 的核心机制

### 3.1 原有慢态机制

K10 的慢态路径可抽象为：

```text
e > 0
且连续受载时间达到 slow_confirm_s
且沿后软解冻完成
且 abs(slope) 小于 slope_gate_frac * base
    -> 允许 x_slow 积分
```

### 3.2 K11 v1 新机制

K11 v1 改为：

```text
输入时间有效
且不存在长时间间隔
且没有处于变化保护期
且状态为 STABLE_PLATEAU
且短窗、长窗斜率均满足平台条件
且空间共模置信度足够
且原有 K10 慢态条件全部满足
    -> 允许 x_slow 积分
否则
    -> 不增加 x_slow；保留已有状态，按卸载/空载规则恢复
```

关键原则：

- 变化期间冻结慢态增长，不直接清零已有补偿；
- 变化结束后先进入平台候选，再进入稳定平台；
- 时间异常期间不让慢态积分跨越异常间隔；
- 空间特征只作为置信度，不独立宣判“时漂”或“真实荷载”；
- K11 v1 默认关闭时不改变 K10 行为。

## 4. 状态机设计

### 4.1 状态定义

```text
INIT
RISING
MOTION_HOLD
PLATEAU_CANDIDATE
STABLE_PLATEAU
UNLOAD
UNCERTAIN
```

| 状态 | 进入条件 | x_slow | zero | 说明 |
|---|---|---|---|---|
| `INIT` | 首帧、重置、通道签名变化 | 冻结 | 初始化或受限更新 | 建立时间和窗口，不判定物理事件 |
| `RISING` | 短窗上升、缓坡持续或上升沿 | 冻结增长 | 降权或冻结 | 保护加载过程 |
| `MOTION_HOLD` | 上升结束或方向刚变化 | 冻结增长 | 降权或冻结 | 保持新平台，避免立即吸收 |
| `PLATEAU_CANDIDATE` | 斜率降低但确认不足 | 冻结增长 | 受限 | 等待短窗、长窗一致 |
| `STABLE_PLATEAU` | 连续满足平台确认 | 允许积分 | 仅按原有空载门 | 允许慢态跟踪 |
| `UNLOAD` | 持续下降或明显卸载 | 冻结增长 | 冻结或受限 | 由恢复逻辑撤销旧补偿 |
| `UNCERTAIN` | 长间隔、时间异常、证据冲突 | 冻结增长 | 冻结 | 等待重新满足确认条件 |

### 4.2 推荐状态转移

```text
INIT -> RISING                 检测到持续上升或缓坡
INIT -> PLATEAU_CANDIDATE      无明显变化但已有有效平台证据

RISING -> MOTION_HOLD          上升停止或方向转折
RISING -> UNLOAD               持续下降
RISING -> UNCERTAIN            时间质量失效

MOTION_HOLD -> PLATEAU_CANDIDATE 保护时间结束且斜率降低
MOTION_HOLD -> RISING             再次上升
MOTION_HOLD -> UNLOAD             持续下降
MOTION_HOLD -> UNCERTAIN          时间质量失效

PLATEAU_CANDIDATE -> STABLE_PLATEAU  平台确认完成
PLATEAU_CANDIDATE -> RISING          再次上升
PLATEAU_CANDIDATE -> UNLOAD          持续下降
PLATEAU_CANDIDATE -> UNCERTAIN       证据不足或时间失效

STABLE_PLATEAU -> RISING            新增上升变化
STABLE_PLATEAU -> UNLOAD            持续下降
STABLE_PLATEAU -> UNCERTAIN         时间异常或空间证据冲突

UNLOAD -> PLATEAU_CANDIDATE          新平台候选
UNLOAD -> INIT                        明确全卸载并完成状态重置
UNLOAD -> UNCERTAIN                  时间或输入质量失效

UNCERTAIN -> RISING                  重新检测到上升
UNCERTAIN -> UNLOAD                  重新检测到下降
UNCERTAIN -> PLATEAU_CANDIDATE       连续获得有效稳定窗口
```

状态切换必须使用当前帧和历史窗口，不能使用未来帧或完整事件的终点信息。

## 5. 时间质量层

### 5.1 输入规则

```cpp
dt = timestamp_s - last_ts;
```

处理规则：

- `dt <= 0`：不推进计时器、慢态积分和零点；记录 `REPEATED_TIME` 或 `BACKWARD_TIME`；
- `0 < dt <= max_gap_s`：允许正常推进；
- `dt > max_gap_s`：标记 `LONG_GAP`，进入 `UNCERTAIN`，冻结慢态和零点；
- 长间隔后的第一段有效数据重新建立斜率参考，不直接使用跨间隔差值；
- `dt` 仍可按 K10 规则限制快态数值积分步长，但“截断 dt”不能替代质量标记。

### 5.2 斜率估计

K11 v1 不使用单个相邻帧作为慢态判定依据。至少维护：

```text
short_slope：短窗稳健斜率
long_slope：长窗稳健斜率
slope_variance：窗口内斜率离散度
```

推荐初始窗口：

```text
short_window_s = 0.20~0.50
long_window_s  = 1.0~3.0
```

实际窗口必须根据采样频率、帧交替结构和时间戳质量复核。对于新增原始记录中观察到的交替帧现象，优先使用固定时间桶中值或成对聚合后的信号计算判定量；输出流不因此强制重采样。

## 6. 平台确认与慢态门控

### 6.1 平台候选条件

```text
abs(short_slope) <= plateau_short_slope
abs(long_slope)  <= plateau_long_slope
slope_variance   <= plateau_variance_limit
最近没有方向反转
时间质量有效
```

平台候选期间：

- `x_slow` 不增加；
- 已有 `x_slow` 不因候选状态直接清零；
- 不更新受载状态为“已稳定”；
- 继续收集空间和时间诊断量。

### 6.2 进入稳定平台

连续满足 `plateau_confirm_s` 后进入 `STABLE_PLATEAU`。建议起始扫描范围：

```text
plateau_confirm_s = 2~4 s
motion_hold_s     = 1~3 s
```

这些值只是设计起点，不能在没有带标签数据时直接写入产品默认值。

### 6.3 慢态积分条件

```cpp
allow_slow_integral =
    k11_enabled &&
    state == STABLE_PLATEAU &&
    time_quality == VALID &&
    e > 0 &&
    load_dwell >= slow_confirm_s &&
    soft_unfreeze_ok &&
    abs(slope) < slope_gate_frac * base &&
    common_mode_confidence_ok;
```

如果 `allow_slow_integral=false`：

- 保持 `x_slow` 当前值；
- 不把变化量倒写入永久荷载账本；
- 下降和空载仍可按照既有 K10 恢复逻辑处理；
- 进入 `RISING`、`MOTION_HOLD`、`UNLOAD` 或 `UNCERTAIN` 时，慢态只暂停增长，不强制置零。

## 7. 空间置信度

### 7.1 计算量

在判定窗口内计算逐通道变化 `delta[k]`：

```text
common_mode   = median(delta[k])
residual[k]   = delta[k] - common_mode
spatial_energy = median(abs(residual[k]))
active_count   = count(abs(delta[k]) > channel_noise_band[k])
positive_ratio = count(delta[k] > band) / active_count
negative_ratio = count(delta[k] < -band) / active_count
```

### 7.2 v1 使用方式

空间特征只决定“是否允许慢态继续积分”：

- 多数通道同向、变化连续、空间残差较小：置信度提高；
- 少数通道局部集中或正负变化同时明显：置信度降低；
- 置信度不足时进入 `PLATEAU_CANDIDATE` 或 `UNCERTAIN`；
- 不因一次局部变化直接把全局状态判为真实荷载；
- 不使用跨 52、57、71 通道阵列共用的绝对 ADC 阈值。

## 9. 代码迁移步骤

### 阶段 A：建立 K11 v1 兼容层

1. 在 `Params` 增加 K11 v1 参数，默认 `k11_enable=0`。
2. 增加状态枚举、时间质量枚举和诊断字段。
3. 增加短窗/长窗历史缓冲区或固定容量环形缓存。
4. 增加 `Reset()` 时的状态、缓存、诊断量清理。
5. 通道数量或通道签名变化时完整重置 K11 状态。

### 阶段 B：接入时间质量层

1. 保留 K10 的 `dt` 上限保护。
2. 在上限保护前记录原始 `dt` 状态。
3. 异常间隔不参与慢态积分和零点跟踪。
4. 长间隔后的首个有效窗口标为“重新建窗”。
5. 输出诊断：`dt_raw`、`dt_used`、`time_quality`。

### 阶段 C：接入平台状态机

1. 先计算短窗、长窗斜率和方向反转。
2. 依据状态机更新 `k11_state`。
3. 仅在 `STABLE_PLATEAU` 放行 K10 的慢态积分条件。
4. 状态切换采用迟滞，进入和退出阈值分开。
5. 发生 `RISING`、`UNLOAD`、`UNCERTAIN` 时冻结慢态增长。

### 阶段 D：接入空间置信度

1. 在判定窗口上计算共模和空间残差。
2. 将空间结果写入诊断量。
3. 第一轮只作为慢态积分附加门，不改变输出空间布局。
4. 对 52、57、71 通道分别做阈值标定。

### 阶段 E：兼容验证

必须验证：

- `k11_enable=0` 时 K11 与 K10 逐帧一致；
- 输入时间戳重复时，K11 不增加慢态积分；
- 长间隔后不出现补偿跳变；
- 通道数变化触发状态重置；
- 参数热切换的状态行为明确；
- 输出通道顺序、时间戳和长度不变。

## 11. 离线验收矩阵

每份数据至少运行三种配置：

```text
A. K10 基线
B. K11 v1，新增门控开启
C. K11 v1，k11_enable=0
```

C 必须与 A 逐帧一致。B 至少报告：

### 恒载

- 恒载段首尾总 ADC 漂移；
- 恒载段最大偏移；
- 末段斜率；
- 10 分钟、20 分钟、30 分钟分段结果；
- 各通道漂移分布；
- 状态切换次数。

### 10g 或小变化

- 每次增加检测率；
- 每次移除检测率；
- 增量/减量幅度保留率；
- 快速和慢速两种操作速度的差异；
- 事件后平台保持时间；
- 逐轮幅度是否衰减。

### 卸载

- 部分卸载后的平台误差；
- 全卸载后的恢复时间；
- 旧 `x_slow` 释放是否产生跳变；
- 再加载时是否出现逐轮累积。

### 鲁棒性

- 重复时间戳误触发率；
- 长间隔前后补偿差；
- 交替帧结构下的状态切换率；
- 轻拍后的恢复时间；
- 输入异常对长期状态的影响。

## 12. 数据采集要求

K11 v1 设计至少需要以下带标签原始数据：

1. 右拇指两台设备各 3 次约 8.9N 恒载，包含加载、保持、卸载和恢复准确时间；
2. 右拇指两台设备各至少 2 份 10g 增减记录，每份不少于 10 个循环；
3. 10g 的快速变化和慢速变化各 5 个循环；
4. 20%~80% 部分卸载以及全卸载记录；
5. 空载起始、已有负载起始、首帧已受载三类初始化条件；
6. 稳定平台轻拍和短扰动记录；
7. 原始 `timestamp`、`elapsed`、连续 `frame_index`、通道布局和设备真实序列号；
8. 同步事件表，不能只依赖文件名或目录名。

推荐记录结构：

```text
session.json
raw/device_001_raw_seg000.csv
events.csv
operator_notes.md
calibration.json
```

`events.csv` 至少包含：

```text
session_id,event_id,event_type,start_timestamp,end_timestamp,
load_delta_g,load_delta_N,hold_s,position,quality,note
```

## 14. 放行条件

K11 v1 具备进入产品候选验证的条件，需要同时满足：

```text
k11_enable=0 时与 K10 逐帧一致
且时间异常不会改变长期状态
且恒载漂移相对 K10 有可重复改善
且快速 10g 增减不被吞掉
且慢速 10g 增减有明确的保留率结果
且部分卸载后的平台可解释、可恢复
且不同传感器的参数差异有记录
且诊断量足以定位误触发和误积分
```

如果只改善恒载漂移，却损失 10g 变化保留率，则 K11 v1 不放行。

如果只有少数记录改善，或改善依赖未标注的自动窗口，则结论只能标为“探索结果”，不能进入产品参数表。

## 15. 当前明确结论

- K11 v1 应从 K10 迁移，不应从旧 K11/v3.5 原样恢复。
- 改动重点是慢态积分门和状态管理，不是重写快态补偿。
- 参数数量增加有限，但状态和诊断逻辑增加明显。
- `hold_lock` 可以作为后续实验策略，不能作为 v1 的唯一核心机制。
