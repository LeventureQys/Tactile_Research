# K11 v1 设计边界与采集需求（2026-10-20）

## 1. K11 的基线来源

K11 v1 不是脱离现有观测器重写，也不是从 K9/K10 两套代码并行发展。

本设计以当前 K10/K9 观测器为基线：

```text
K9：zero + x_fast + x_slow + K6 applied + K7 空载/确认 + K9 缓坡前馈
K10：K9 基础上增加 transient guard，主要保护 y_floor 下探和空载确认
K11 v1：K10 基础上增加输入质量、事件状态、平台确认和有限慢态门控
```

当前产品源码仍是 K9/K10 观测器口径；已有 hold_lock/track_base_frac 的 K11/v3.5 只存在于旧离线原型与文档，不在当前产品源码中。K11 v1 先不把旧 hold_lock 原样搬回产品。

## 2. K11 v1 的目标

K11 v1 只解决一个明确问题：

> 让慢态补偿只在“输入时间有效、变化已结束、平台证据足够、空间形态更像共模慢漂”的条件下工作；其他时间保持原有 K10 行为或冻结慢态。

它不在 v1 阶段承诺完成：

- 8.9N 恒载验收；
- 10g 逐次检测验收；
- 完整部分卸载模型；
- 自动识别真实物理荷载；
- 跨传感器统一参数。

这些是 v1 的验证对象和后续版本目标，不是未采集数据上的预先结论。

## 3. 改动机制

### 3.1 维持 K10 的三条状态通路

以下结构保持不变：

```text
输入 v
  -> zero
  -> y = v - zero
  -> x_fast：快态补偿
  -> x_slow：慢态补偿
  -> applied：K6 预留池限制
  -> 输出 z = v - applied
```

K11 v1 不改动 x_fast 的基本微分形式，也不改动 K6 applied 的增速限制；不先动已经在 K9/K10 中验证过的快态与显示交接机制。

### 3.2 新增输入质量层

每帧计算：

```text
dt = timestamp - last_timestamp
```

按以下规则处理：

- `dt <= 0`：不推进时间状态，不推进 x_slow、zero、dwell；保留诊断标记；
- `0 < dt <= max_gap_s`：正常推进；
- `dt > max_gap_s`：进入 `UNCERTAIN`，冻结慢态积分和 zero 更新，快态按受限 dt 恢复；
- 连续出现重复/交替打包结构时，斜率不再使用单个相邻帧，而使用短窗稳健斜率；
- 对交替帧优先采用两帧聚合或固定时间桶中值，避免把帧间反相结构当成真实沿。

推荐 v1 初始值：

```text
max_gap_s = 0.25
slope_window_s = 0.20~0.50
```

`max_gap_s` 和 `slope_window_s` 在不同采集器上需要根据原始 timestamp 统计定版。

### 3.3 新增事件状态

每个传感器目标维护一个全局事件状态，逐通道保留原有 x_fast/x_slow：

```text
INIT
RISING
MOTION_HOLD
PLATEAU_CANDIDATE
STABLE_PLATEAU
UNLOAD
UNCERTAIN
```

状态含义：

- `INIT`：首帧或状态重置后，只建立 zero、时间基准和窗口；
- `RISING`：检测到持续上升或缓坡，冻结 x_slow，zero 降权；
- `MOTION_HOLD`：变化刚结束，继续保护新平台，禁止立即吸收；
- `PLATEAU_CANDIDATE`：斜率已降低，但还没有通过平台确认；
- `STABLE_PLATEAU`：平台稳定且时间质量有效，允许 x_slow 慢速积分；
- `UNLOAD`：检测到持续下降，冻结 x_slow，使用既有恢复路径；
- `UNCERTAIN`：长间隔、时间异常、强烈方向反转或空间证据冲突，冻结 x_slow 和 zero。

状态转移只使用当前帧和历史窗口，不使用未来帧。

### 3.4 慢态积分门改造

K10 现有逻辑大致是：

```text
受载确认 + 沿后软解冻 + 斜率门通过 -> x_slow 积分
```

K11 v1 改成：

```text
输入质量有效
AND state == STABLE_PLATEAU
AND short_slope 与 long_slope 同向且低于平台阈值
AND 最近没有方向反转
AND 空间共模置信度达到门限
AND e > 0
-> 才允许 x_slow 积分
```

以下状态一律不增加 x_slow：

```text
INIT、RISING、MOTION_HOLD、PLATEAU_CANDIDATE、UNLOAD、UNCERTAIN
```

已有 `r_slow_max`、`slope_cap_frac` 仍保留，用于限制幅度和速率；K11 v1 只是收紧它们的生效条件，不把它们替换掉。

### 3.5 平台确认逻辑

平台候选需要连续满足：

```text
abs(short_slope) <= plateau_slope_threshold
abs(long_slope)  <= plateau_slope_threshold_long
方向反转次数 <= flip_limit
时间质量有效
```

建议：

```text
plateau_confirm_s = 2~4 s
motion_hold_s = 1~3 s
```

平台确认期间只保护输入，不进行慢态积分。确认成功后再进入 `STABLE_PLATEAU`。

### 3.6 空间置信度逻辑

在短窗内计算每通道变化：

```text
common_mode = median(delta_channel)
spatial_energy = median(abs(delta_channel - common_mode))
common_mode_ratio = abs(common_mode) / (median(abs(delta_channel)) + eps)
```

v1 只把空间特征作为慢态积分的置信度门，不做绝对事件分类：

- 多数通道同向、共模占比高：允许进入平台候选；
- 少数通道集中变化、正负方向混合明显：延迟或阻止慢态积分；
- 空间证据不足：进入 `UNCERTAIN` 或维持 `PLATEAU_CANDIDATE`。

不能用跨阵列绝对 ADC 阈值；空间阈值需要按通道数和部位标定。

## 4. 参数改动规模

### 4.1 不改动的主参数

v1 继续使用：

```text
r_fast
tau_c_fast_s
tau_r_fast_s
r_slow_max
tau_r_slow_s
slope_cap_frac
slope_gate_frac
tau_zero_s
tau_slope_s
edge_slope_thres
edge_refract_s
edge_boost_s
tau_c_fast_boost_s
soft_unfreeze_s
hold_eps
hold_tau_s
slow_confirm_s
tau_r_slow_idle_s
```

因此，v1 不是大幅重调全部参数，也不先改变快态模型。

### 4.2 新增参数

建议新增 8 个配置项，其中 6 个用于行为，2 个用于时间质量：

```text
k11_enable                  // 总开关，默认 0，确保回退 K10
k11_plateau_confirm_s      // 平台确认时间，建议 2~4 s
k11_motion_hold_s          // 变化结束后的保护时间，建议 1~3 s
k11_plateau_slope_frac     // 平台短窗斜率门
k11_common_mode_ratio_min  // 共模置信度下限
k11_spatial_energy_max     // 空间残差上限
k11_max_gap_s              // 最大可用时间间隔，建议 0.25 s
k11_slope_window_s         // 稳健斜率窗口，建议 0.20~0.50 s
```

内部状态增加：

```text
k11_state
k11_state_elapsed
k11_motion_elapsed
k11_plateau_elapsed
k11_short_slope
k11_long_slope
k11_common_mode_ratio
k11_spatial_energy
k11_time_quality
```

状态数组不需要永久账本，不增加无限增长状态。所有计时器都要有上限或在状态退出时清零。

### 4.3 参数变化大小的判断

从代码规模看，v1 属于“中等结构改动、小范围参数扩展”：

- 原有 27 项 K9/K10 参数继续保留；
- 新增约 8 项 K11 参数；
- 每个目标增加状态和诊断量；
- 不重写 x_fast/x_slow 的核心方程；
- 不把旧 K11 hold_lock 直接叠加到当前 K10；
- 默认关闭时应与当前 K10 逐帧一致。

真正较大的变化在慢态进入条件，不在参数数值本身。

## 5. 为什么不先使用旧 hold_lock

旧 K11/v3.5 的核心语义是：

```text
慢于 hold_lock_tau_s 的上行一律作为蠕变扣除
```

它适合“装好负载后调零并长期盯住”的场景，但不能单独覆盖：

- 缓慢真实荷载变化；
- 10g 增减；
- 部分卸载；
- 交替帧和异常 timestamp；
- 空间局部变化。

因此 v1 先使用“平台确认后才积分”的机制。待有标签数据证明某类场景确实需要更强的锁定，再把 hold_lock 作为可选策略放到 `STABLE_PLATEAU` 内部，而不是作为全局硬规则。

## 6. 需要采集的数据

### A. 必采：时间和原始流

每次记录必须保留：

- 原始 `raw_adc` 独立流；
- 逐帧 `timestamp`；
- `elapsed`；
- 连续 `frame_index`；
- 通道数和通道布局掩码；
- 设备真实序列号；
- 采集器版本、固件版本、算法开关状态；
- 记录开始的绝对时间；
- 不要只保留算法输出流。

原始文件头需要明确：

```text
数据阶段=raw_adc
算法施加=none
阈值已施加=false
```

### B. 必采：右拇指 8.9N 恒载

至少 4 次，最好 6 次：

1. 空载 30 s；
2. 放置约 8.9N 砝码，记录放置准确时刻；
3. 保持至少 20 min，最好 30~60 min；
4. 移除砝码，记录移除准确时刻；
5. 空载恢复至少 5 min；
6. 每次记录独立设备序列号和传感器安装信息。

每次必须记录：

```text
t_load_start
t_load_end
t_unload_start
t_unload_end
砝码实际质量或力值
保持时长
按压位置
是否重新调零
```

### C. 必采：右拇指 10g 反复增减

至少 3 次完整记录，每次至少 10 个循环：

```text
已有稳定负载平台
增加 10g
保持 5~10 s
移除 10g
保持 5~10 s
重复
```

每次增加、移除都记录：

```text
t_add_start
t_add_end
t_remove_start
t_remove_end
实际质量
保持时长
操作是否有滑动/抖动
```

不要只给“10g测试”文件名；必须有逐次事件表。

### D. 必采：慢速真实变化对照

这是检验 K11 是否会吞掉慢变化的关键数据：

- 在已有稳定负载上，缓慢增加 10g，持续 2~5 s 完成；
- 保持 10 s；
- 缓慢移除 10g，持续 2~5 s 完成；
- 重复至少 5 次。

还需要一组更慢的版本：

- 增加 10g，持续 10~20 s；
- 保持 20 s；
- 移除 10g，持续 10~20 s。

这组数据直接检验 `hold_lock` 或平台门是否把真实慢变化当成时漂。

### E. 必采：部分卸载与全卸载

每个设备至少 3 次：

1. 建立 8.9N 平台；
2. 卸载约 20%；保持 10 s；
3. 再卸载约 30%；保持 10 s；
4. 全部卸载；空载保持 5 min；
5. 再加载同一砝码。

记录每次卸载比例和准确时刻。该数据用于验证旧 x_slow 是否正确释放，不能只用“是否空载”判定。

### F. 必采：起始条件对照

同一传感器至少三类：

- 真空载开始后加载；
- 已有负载开始后再次加载；
- 首帧已经受载的记录。

每类至少 3 次。这样才能区分首帧状态初始化、快态响应和慢态补偿，不把首秒误当空载基线。

### G. 必采：扰动和时间质量

至少采集：

- 稳定平台上的轻拍；
- 稳定平台上的短压后释放；
- 人为短暂停顿；
- 包聚合或重复时间戳的真实记录；
- 允许的话保留原始通信包或采集器日志。

每次标注扰动开始和结束时刻。不要只在导出后重采样，否则无法验证 K11 的时间质量层。

### H. 跨传感器最小集合

对以下三类各采一套完整 A~G：

- 右拇指指腹，57 通道；
- 右手掌，71 通道；
- 四指指腹，52 通道。

每类至少包含：3 次恒载、3 次 10g/小阶跃、3 次部分卸载、3 次全卸载。这样才能决定哪些是结构逻辑，哪些只是传感器参数。

## 7. 采集文件组织

建议每次实验目录包含：

```text
session.json
raw/device_001_raw_seg000.csv
events.csv
operator_notes.md
calibration.json
```

`events.csv` 至少包含：

```text
session_id,event_id,event_type,start_timestamp,end_timestamp,
load_delta_g,load_delta_N,hold_s,position,quality,note
```

`event_type` 使用：

```text
idle
load
hold
add_10g
remove_10g
partial_unload
full_unload
tap
```

## 8. K11 v1 的验收输出

拿到上述数据后，K11 v1 需要在同一批输入上对照：

```text
K10 baseline
K11 v1 with new gate
K11 v1 with gate disabled
```

至少报告：

- 恒载首尾 ADC 漂移；
- 恒载末段斜率；
- 10g 增加检测率；
- 10g 移除检测率；
- 增减幅度保留率；
- 慢速 10g 的保留率；
- 部分卸载后的新平台误差；
- 全卸载恢复时间；
- 异常时间段误触发率；
- 状态切换次数；
- K10 与 K11 的逐帧最大差异。

K11 v1 的通过条件不是“漂移越小越好”，而是：

```text
恒载漂移明显改善
且 10g 快速/慢速增减不被吞掉
且部分卸载能够建立新平台
且异常 timestamp 不改变长期状态
且默认关闭时与 K10 逐帧一致
```
