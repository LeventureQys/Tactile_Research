# 在线双态蠕变观测器（K9）算法迁移文档

**文档版本**：1.0 ｜ **算法版本**：portable-1.0
**读者**：需要把该算法移植到其它上位机软件或嵌入式固件的工程师。
**前置要求**：无。本文档自包含，不需要阅读任何其它文档或历史记录。

## 1. 这是什么算法

一个**在线、因果、逐帧、逐通道**的传感器时漂补偿器。用途：触觉/压力传感器阵列在恒定载荷下会持续蠕变漂移，本算法在显示侧把蠕变补偿掉，同时对真实载荷变化保持保真。

- **输入**：每帧的通道原始读数值（ADC 或已换算的显示值）+ 时间戳。
- **输出**：同样长度的补偿后显示值（**就地改写**输入数组）。
- **特性**：单通道状态独立；跨帧连续；无事件分类、无记忆账本；不使用未来帧；无动态内存；O(n) 每帧。

### 1.1 接口契约（必须遵守）

| 项 | 约定 |
|---|---|
| 调用频率 | 每次采样调用一次；不要求固定采样率 |
| 时间戳 | 单调递增，单位**秒**（double）。内部按 `dt = min(dt, 0.1)` 截断，`dt <= 0` 视为 0 |
| 通道数 | 创建时固定；通道数变化必须重建实例 |
| 数据布局 | 一维连续数组，长度 = 通道数；就地修改 |
| 首帧 | 不补偿，返回原值，但完成状态初始化 |
| 线程模型 | 单个实例**非线程安全**；多目标各自持有一个实例 |
| 状态重置 | 参数变更、通道签名变化、开关切换都必须重置实例 |

所有平台都从这一份派生，**不要**再各自维护算法副本：

## 3. 逐帧规范

以下为完整状态机。任何新实现只要逐帧复现本规范，就与本权威实现等价。

### 3.1 状态量

**逐通道（每个通道各一份，共 13 个数组）**

| 名称 | 含义 | 初值 |
|---|---|---|
| `zero` | 零点 | 首帧输入值 |
| `y_max` | 量程包络（慢衰减峰值） | 0 |
| `v_lp` | 低通值（供 slope 估计） | 首帧输入值 |
| `v_fast_lp` | 预留池快速低通 | 首帧输入值 |
| `y_floor` | 去趋势基线包络（慢速最小值跟踪） | 首帧输入值 |
| `t_edge` | 距上次上升沿的时长 | `1e6`（视为早已离沿） |
| `x_fast` | 快态补偿量 | 0 |
| `x_slow` | 慢态补偿量 | 0 |
| `applied` | 实际施加的补偿（预留池） | 0 |
| `load_dwell` | 连续受载计时 | 0 |
| `ramp_dwell` | 缓坡计时 | 0 |
| `below_elapsed` | 防护：`y_floor` 跌破计时 | 0 |
| `idle_elapsed` | 防护：idle 持续计时 | 0 |

**全局标量**：`total_baseline`（空载总值基线，初值 = 首帧总值）、`total_noise`（初值 0）、`last_ts`、`first_frame`。

### 3.2 逐帧流程

```
process(timestamp_s, v[]):            # v 为长度 n 的数组，就地改写

  ── 首帧 ──
  if first_frame:
      first_frame = false; last_ts = timestamp_s
      zero = v; y_max = 0; v_lp = v; v_fast_lp = v; y_floor = v
      load_dwell = 0; ramp_dwell = 0; t_edge = 1e6
      x_fast = 0; x_slow = 0; applied = 0
      below_elapsed = 0; idle_elapsed = 0
      total_baseline = sum(v); total_noise = 0
      return                       # 首帧不补偿

  dt = timestamp_s - last_ts
  last_ts = timestamp_s
  dt = (dt > 0) ? min(dt, 0.1) : 0     # ★ 必须截断

  ── ① 全局空载旁路判定（用原始 v）──
  bypass = false
  if dt > 0:
      total = sum(v)
      if isfinite(total):
          alpha   = min(dt / bypass_base_tau_s, 1)
          release = max(bypass_release_frac * total_baseline,
                        total_baseline + bypass_noise_sigma * total_noise)
          engage  = max(bypass_engage_frac  * total_baseline,
                        total_baseline + (bypass_noise_sigma + 1) * total_noise)
          if total < engage:
              total_baseline += alpha * (total - total_baseline)
              total_noise    += alpha * (|total - total_baseline| - total_noise)
              total_noise     = max(total_noise, 0)
          bypass = (total < release)

  if dt > 0:
      y_decay = exp(-dt / y_max_tau_s)
      refract = max(edge_refract_s, edge_boost_s)

      ── ② 零点跟踪 + 去趋势空载门（逐通道）──
      for k in 0..n-1:
          y0 = v[k] - zero[k]

          if y0 < y_floor[k]:                     # 下行
              y_floor[k] = y0                     # ★ 瞬时跟随（见第 9.4 节）
          else:                                   # 上行：慢速爬升
              y_floor[k] += (dt / y_floor_tau_s) * (y0 - y_floor[k])

          y_max[k] = max(y_max[k] * y_decay, max(y0, 0))
          span = max(y_max[k] - y_floor[k], 1)    # ★ 下限 1
          idle = (y0 - y_floor[k]) < idle_frac * span
          load_dwell[k] = idle ? 0 : load_dwell[k] + dt
          if idle: zero[k] += (dt / tau_zero_s) * (v[k] - zero[k])

      ── ③ 逐通道状态推进 ──
      for k in 0..n-1:
          y     = v[k] - zero[k]
          slope = (v[k] - v_lp[k]) / tau_slope_s

          # 沿检测：先累加时间，再判触发
          t_edge[k] += dt
          if slope > edge_slope_thres and t_edge[k] > refract:
              t_edge[k] = 0

          # 缓坡计时
          ramp_on = (slope > ramp_slope_min) and (slope <= edge_slope_thres)
          ramp_dwell[k] = ramp_on ? ramp_dwell[k] + dt : 0

          # 任一快变（升或降）重计受载确认窗
          if |slope| > edge_slope_thres: load_dwell[k] = 0

          # 快态收敛常数：沿后前馈 → 缓坡线性混合
          tc1 = (edge_boost_s > 0 and t_edge[k] < edge_boost_s)
                    ? tau_c_fast_boost_s : tau_c_fast_s
          if ramp_full_s > 0:
              w = min(ramp_dwell[k] / ramp_full_s, 1)
              tc1 = tc1 * (1 - w) + tau_c_fast_boost_s * w

          # 快态 x_fast（e 用★更新前★的 x_fast）
          e_now = max(y - x_fast[k] - x_slow[k], 0)
          dx1_rate = (e_now > 0)
                        ? (r_fast * e_now - x_fast[k]) / tc1
                        : -x_fast[k] / tau_r_fast_s
          x_fast[k] = max(x_fast[k] + dx1_rate * dt, 0)
          v_lp[k]  += (dt / tau_slope_s) * (v[k] - v_lp[k])

          # 慢态 x_slow（e 用★更新后★的 x_fast 重算）
          e = max(y - x_fast[k] - x_slow[k], 0)
          span_k = max(y_max[k] - y_floor[k], 1)
          idle_k = (y - y_floor[k]) < idle_frac * span_k

          if e > 0:
              base = max(e, 1)                    # ★ 下限 1
              cap  = slope_cap_frac * base
              soft_ok  = (1 - exp(-t_edge[k] / soft_unfreeze_s)) > 0.5
              dwell_ok = load_dwell[k] >= slow_confirm_s
              if dwell_ok and soft_ok and |slope| < slope_gate_frac * base:
                  dx2 = clamp(slope - dx1_rate, -cap, cap)
                  x_slow[k] += dt * dx2
              x_slow[k] = clamp(x_slow[k], 0, r_slow_max * base)   # 上限=该值

          # 泄放（e<=0 或空载）
          if e <= 0 or idle_k:
              tau_r2 = (idle_k and tau_r_slow_idle_s > 0)
                          ? tau_r_slow_idle_s : tau_r_slow_s
              x_slow[k] -= (dt / tau_r2) * x_slow[k]
              x_slow[k] = max(x_slow[k], 0)

          # K6 预留池
          if hold_eps > 0:
              slope_a = (v[k] - v_fast_lp[k]) / hold_tau_s
              v_fast_lp[k] += (dt / hold_tau_s) * (v[k] - v_fast_lp[k])
              d_des = x_fast[k] + x_slow[k]
              a_up  = applied[k] + dt * max(slope_a + hold_eps, 0)
              a_dn  = applied[k] + dt * (slope_a - hold_eps)
              a = (d_des > applied[k]) ? min(d_des, a_up) : max(d_des, a_dn)
              a = (e > 0) ? clamp(a, 0, max(d_des, 0)) : d_des
              applied[k] = a

  ── ④ 输出 ──
  if bypass:
      applied = x_fast + x_slow       # 仅清空预留池，★显示不扣★
      return                          # v 保持原值
  if hold_eps > 0:
      for k: v[k] -= applied[k]
  else:
      for k: v[k] -= (x_fast[k] + x_slow[k])
```

### 3.3 执行顺序硬约束

以下顺序**不可调换**，调换即产生数值差异：

1. 旁路判定必须在零点/包络更新**之前**，且用**原始** `v`。
2. `y_floor`/`y_max`/`zero` 更新在 `slope` 计算之前。
3. `t_edge += dt` 在触发判定之前。
4. `x_fast` 更新用**更新前**的 `x_fast` 计算 `e_now`；`x_slow` 用**更新后**的 `x_fast` 重算 `e`。
5. `v_lp` 更新紧随 `x_fast` 之后（同一帧内 `slope` 仍用旧 `v_lp`）。
6. 预留池 `applied` 在所有其它状态之后更新。
7. 旁路帧仍要完整跑完状态更新，只是最后不改写 `v`。

## 4. 参数表

单位：时间为秒；斜率为 ADC/s；比值为无量纲。**全部参数都是 ADC 域标定值**，若输入已是力值域必须重新标定（尤其 `edge_slope_thres`、`slope_gate_frac`、`slope_cap_frac`、`idle_frac`）。

| 参数 | 语义 | 工作树默认 | plan-v4 observer-k9 |
|---|---|---:|---:|
| `r_fast` | 快态幅度比，终值 = `r_fast·e` | 0.01 | **0.03** |
| `tau_c_fast_s` | 快态受载收敛 τ | 40.0 | **2.0** |
| `tau_r_fast_s` | 快态空载恢复 τ | 6.0 | **0.1** |
| `r_slow_max` | 慢态幅度上限系数：`x_slow ≤ 该值·max(e,1)` | 0.2 | **0.1** |
| `tau_r_slow_s` | 慢态常规泄放 τ | 150.0 | 150.0 |
| `slope_cap_frac` | 慢态积分速率上限：`|dx2| ≤ 该值·max(e,1)` | 0.05 | **0.02** |
| `slope_gate_frac` | 慢态积分斜率门：`|slope| < 该值·max(e,1)` | 0.05 | 0.05 |
| `tau_zero_s` | 零点跟踪 τ（仅近零带） | 8.0 | 8.0 |
| `idle_frac` | 近零带比例（去趋势口径） | 0.05 | 0.05 |
| `y_max_tau_s` | 量程包络衰减 τ | 600.0 | 600.0 |
| `tau_slope_s` | 低通导数 τ | 1.0 | 1.0 |
| `edge_slope_thres` | 上升沿判定阈值 | 60.0 | 60.0 |
| `edge_refract_s` | 沿触发最小间隔 | 2.0 | 2.0 |
| `edge_boost_s` | 沿后前馈窗 | 2.0 | 2.0 |
| `tau_c_fast_boost_s` | 前馈窗内快态 τ | 2.0 | 2.0 |
| `soft_unfreeze_s` | 沿后慢态软冻结窗 | 8.0 | **2.0** |
| `hold_eps` | 预留池限额余量；≤0 关闭预留池 | 2.0 | 2.0 |
| `hold_tau_s` | 限额用快速低通 τ | 0.5 | 0.5 |
| `slow_confirm_s` | 慢态积分需连续受载时长 | 5.0 | **3.0** |
| `y_floor_tau_s` | 基线包络爬升 τ | 300.0 | 300.0 |
| `tau_r_slow_idle_s` | 空载快泄放 τ；≤0 回落 `tau_r_slow_s` | 0.5 | **0.2** |
| `bypass_release_frac` | 直通释放比 | 1.15 | 1.15 |
| `bypass_engage_frac` | 直通恢复比 | 1.25 | 1.25 |
| `bypass_noise_sigma` | 门限噪声带宽（σ） | 3.0 | 3.0 |
| `bypass_base_tau_s` | 空载总值基线跟踪 τ | 10.0 | 10.0 |
| `ramp_slope_min` | 缓坡斜率下限 | 0.5 | 0.5 |
| `ramp_full_s` | 缓坡满窗时长；≤0 关闭缓坡层 | 4.0 | 4.0 |
| `guard_enable` | 瞬态防护开关（0/1） | 0 | 0 |
| `guard_floor_confirm_s` | `y_floor` 下行需持续确认时长 | 0.5 | 0.5 |
| `guard_idle_confirm_s` | 快速泄放需 idle 持续确认时长 | 0.3 | 0.3 |
| `guard_floor_deep` | 深跌破该值立即跟随 | 200.0 | 200.0 |
| `floor_rise_idle_only` | `y_floor` 抬升门（0=原行为；1=仅空载时抬升）。**长恒载缺陷的修复项，建议置 1**，见 §9.5 | 0 | 0（建议 1） |

**两套参数集的选择**：
- `plan-v4 observer-k9` 是设备录制实际下发的现场参数，**迁移时优先使用它**（`preset = 1`）。
- 工作树默认值是代码内建默认，与现场参数不同，仅作为缺省兜底。

## 5. 内存与实时性

**内存**：`16 × n × sizeof(double)` 字节（n = 通道数）。

| 通道数 | double 实现 | float32 实现 | 定点 Q24.8（int32） |
|---:|---:|---:|---:|
| 32 | 4096 B | 2048 B | 2048 B |
| 57 | 7296 B | 3648 B | 3648 B |
| 128 | 16384 B | 8192 B | 8192 B |

分配方式：调用方提供连续缓冲（静态数组、内存池或栈均可），`dv6_init` 内部按 16 段切分，**算法自身不调用 malloc**。

**实时性**：每帧 O(n) 次算术 + 4 次 `exp()`/帧（与 n 无关：`y_decay`、`soft_ok` 每通道一次，实际是每通道一次 `exp`，共 1 + n 次）。若 MCU 无 FPU，建议：
- 用 `float32` + 查表/近似 `exp`；
- 或把 `exp(-dt/τ)` 用一阶近似 `1 - dt/τ`（dt ≤ 0.1s，τ ≥ 0.1s 时误差可接受，但**会引入数值差异，必须用黄金向量复核**）。

**状态跨帧连续**：没有事件分类与历史账本，卸载后状态按时间常数自然衰减，不需要额外的复位逻辑。

```c
#define N_CH 57
static double g_state[N_CH * 16];      /* 需要 dv6_buffer_bytes(N_CH) 字节 */
static dv6_observer g_obs;

void comp_init(void) {
    dv6_params p;
    dv6_params_plan_v4_observer_k9(&p);
    p.r_slow_max = 0.6;            /* 现场标定值，按需覆盖 */

```


### 6.2 移植检查清单

1. **浮点**：确认目标有 `double`（软浮点也可，但注意耗时）或改用 `float`。
2. **`exp()`**：确认链接了数学库；裸机上需自带实现。
3. **`isfinite`**：权威实现用 `total == total` 判非 NaN，不依赖 `isfinite`。
4. **字节序 / 对齐**：缓冲区必须按 `double` 对齐。
5. **中断安全**：`dv6_process` 不可重入；在中断里调用时需保证每帧只调用一次。
6. **时间戳来源**：任何单调递增的秒计数都可以（不需要绝对时间）。

### 6.3 定点化注意事项

若必须定点（Q 格式）：

| 量 | 量级 | 建议 |
|---|---|---|
| ADC 通道值 / `zero` / `x_fast` / `x_slow` / `applied` | 0 ~ 50000 | Q 格式整数部分 ≥ 18 bit |
| 比值参数（`r_fast`、`idle_frac`…） | 0 ~ 1 | Q16 足够 |
| 时间常数 | 0.1 ~ 600 s | Q16 |
| `slope`、`dx1_rate`、`dx2` | 可达数千 | 需 24 bit 以上，注意中间量溢出 |

**定点化是唯一允许引入数值差异的场合**，但必须满足第 7 节的容差标准，否则不得替换权威实现。

## 8. 已知陷阱（务必阅读）

以下每一条都曾造成过实际数值偏差或现场问题。

### 8.1 `dt` 必须截断到 0.1 s

`dt = min(dt, 0.1)`；`dt <= 0` 取 0。遗漏会导致长时间停帧后用超大 `dt` 一次性推进状态，输出跳变。

### 8.2 首帧不补偿

首帧只做初始化，返回原值。若首帧也扣补偿，前若干帧会整体偏移。

### 8.3 旁路帧要"跑状态但不扣显示"

`bypass` 为真时：**仍需完整执行状态更新**（否则 `load_dwell` 只进不清、确认门失效），但 `applied` 要置为 `x_fast + x_slow`（清空预留池），并且 **不改写 `v`**。

### 8.4 `y_floor` 下行瞬时跟随是已知风险点

原实现：

```c
if (y0 < y_floor) y_floor = y0;      /* 瞬时跟随 */
```

后果：**一次短促的向下抖动（几十毫秒、几十 ADC）会把 `y_floor` 永久拉到谷底**。由于 `y_floor` 只能以 `y_floor_tau_s = 300 s` 的时间常数爬回，期间 `span = y_max − y_floor` 变大、idle 判据被系统性放宽，进而触发 `x_slow` 的**空载快速泄放**（`tau_r_slow_idle_s`，默认 0.2~0.5 s），把慢态补偿量永久扣掉一部分。

实测后果：一次 0.3 秒、最深约 105 ADC 的下探，让三个相关通道的补偿量永久减少 27.6 / 19.8 / 15.2 ADC（合计约 62 ADC），补偿后基线永久抬高约 54 ADC 且长时间不回归；而算法输入与原始数据完全没有这个偏移。

若现场存在此类瞬态，请启用第 9 节的防护层。

> **注意：`y_floor` 的抬升分支比下行分支更危险。** 下行是「一次抖动污染基线」，
> 上行是「慢速把载荷本身吸收进基线」，见 §9.5。长恒载（>20 min）场景必须读那一节。

### 8.5 `e_now` 与 `e` 用的是不同版本的 `x_fast`

- `e_now`（驱动 `x_fast`）用**更新前**的 `x_fast`；
- `e`（驱动 `x_slow` 与预留池）用**更新后**的 `x_fast`。

混用会造成慢态过积分，表现为阶跃后过冲回落。

### 8.6 三处 `max(e, 1)` 下限不可省

`base = max(e, 1)` 出现在 `slope_cap_frac`、`slope_gate_frac`、`r_slow_max` 的生效条件里。去掉会在 `e → 0` 时产生数值爆炸。

### 8.7 `refract = max(edge_refract_s, edge_boost_s)`

沿检测用的是二者较大值，不是 `edge_refract_s` 单独。

### 8.8 `hold_eps <= 0` 是另一条输出路径

`hold_eps <= 0` 时：跳过整个预留池更新，输出改为 `v -= x_fast + x_slow`。两条路径的数值不同，不要假设等价。

### 8.9 通道数变化必须重建实例

`ResetFor(n)` 会清零全部状态。运行中动态改变通道数会导致状态错位。

### 8.10 NaN / 非有限值

权威 C 实现只对总值做 NaN 判定（`total == total`），不做逐通道 NaN 处理。若输入可能含 NaN/Inf，请在调用前自行清洗：**含非有限值的帧应跳过（`dt` 视为 0）或整帧替换为上一有效帧**，不要让 NaN 进入状态。

### 8.11 FFI 结构体必须逐字段对齐，编译选项必须对得上

两条都是**静默失败**，不会报错：

1. **`dv6_params` 布局失配**。`floor_rise_idle_only` 是 `int`，加在结构体末尾，`sizeof` 从 248 → 256 字节。
   若 FFI 侧（C#、Python ctypes、Delphi…）仍按旧布局传，C 侧会多读 4 字节缓冲区外的内容当参数。
   对策：调用前比对 `dv6_portable_params_bytes()` 与本地结构体字节数（`verify_portable.py` /
   `guard_parity.py` 已内置该校验）。C# 用 `Marshal.SizeOf`，Python 用 `ctypes.sizeof`。
2. **源文件是 UTF-8 无 BOM，编译必须带 `/utf-8`（GCC 为 `-finput-charset=UTF-8`）**。
   MSVC 默认按系统代码页（936/GBK）解析，会出 C4819 警告并误读中文注释；上位机工程
   `CMakeLists.txt` 已全局 `add_compile_options("/utf-8")`，本包的 `build_dll.bat` 也必须一致。

另外要注意**这份算法对 ulp 级差异是病态的**：`idle`/`edge`/`slope_gate` 一串阈值判决 + `x_slow`
正反馈，会把 1e-16 的浮点差异在数百帧内放大成可见电平差。所以：

- 逐帧 `0.0` 只能要求**同一份源码、同一编译单元、同一编译选项**（本包 DLL 与产品 `creep_observer.cpp`
  实测 287374 帧 × 57 通道差 0.0）；
- 换了编译器/优化级别/精度（float32、定点）后，请按 §7.2 的容差判定，不要用逐帧 0 差当验收；
- 统计指标（漂移、10g 保留率、台阶数）比逐帧差更能反映移植是否等价。

## 9. 可选瞬态防护层

`guard_enable = 1` 时启用，**默认关闭**。关闭时与原实现逐帧一致（实测差 0.0）。

### 9.1 改动的两处

**改动 1：`y_floor` 下行跟随需持续确认**

```
if y0 < y_floor:
    if (y_floor - y0) > guard_floor_deep:          # 深度跌破（真实卸载）
        y_floor = y0                               #   立即跟随，不引入延迟
    elif 持续跌破 >= guard_floor_confirm_s:         # 持续下移
        y_floor = y0                               #   确认后跟随
    else:                                          # 短促浅跌破（扰动）
        y_floor 保持不变                            #   不跟随
```

**改动 2：快速泄放需 idle 持续确认**

```
if e <= 0 or idle_k:
    idle_elapsed = idle_k ? idle_elapsed + dt : 0
    fast_ok = idle_k and idle_elapsed >= guard_idle_confirm_s
    tau = (fast_ok and tau_r_slow_idle_s > 0) ? tau_r_slow_idle_s : tau_r_slow_s
    x_slow -= (dt / tau) * x_slow
```

其余逻辑（快态、慢态积分、预留池、旁路、零点、斜率门控）**完全不变**。

### 9.2 实测效果

| 验收项 | 关闭防护 | 开启防护 |
|---|---:|---:|
| 短促下探造成的永久偏移 | +23.99 ADC | **−0.05 ADC** |
| 注入事件的长期稳态差 | — | **0.0 ADC** |
| 真实持续加载的长期漂移 | −30.13 | −30.11 |
| 真实 90% 卸载的长期漂移 | −23169.29 | −23169.28 |
| 六份录制漂移指标变化 | — | ≤ 4.81 ADC（0.7%） |
| 小阶跃（100 ADC）保留率 | 0.3569 | 0.3568 |

### 9.3 代价

1. 真实大卸载在确认窗（0.5 s）内与原实现有瞬时差异，长期稳态为 0；若对卸载边沿要求严格，调低 `guard_floor_deep`。
2. 空载检测与零点跟踪触发时机最多滞后 `guard_floor_confirm_s`。
3. 快速泄放最多滞后 `guard_idle_confirm_s`。
4. **参数需现场标定**：`guard_floor_deep = 200 ADC/通道`、`guard_idle_confirm_s = 0.3 s` 只在部分录制上验证；现场噪声更大或真实卸载更慢时可能把真实卸载误判为扰动。

### 9.4 小幅度卸载不会被拒绝（实测）

判据不是"幅度阈值"，而是"偏离是否持续"：真实卸载后输入停在新电平，`below = (y0 < y_floor)`
持续成立，因此 `guard_floor_confirm_s` 到期后 `y_floor` 照样跟随。`guard_floor_deep` 仅是加速通道。

每通道减 X ADC、0.2 s 内完成并保持，比较关闭/开启防护的输出差：

| 每通道卸载 ADC | 0~1 s 最大差 | 1~5 s | 30~90 s 稳态差 |
|---:|---:|---:|---:|
| 20 | 0.0 | 0.0 | **0.0** |
| 50 | 9.1 | 0.05 | **0.0** |
| 150 | 16.6 | 0.08 | **0.0** |
| 400 | 17.3 | 0.08 | **0.0** |

无卸载对照两臂最大差 0.0。即：**小卸载不会被卡住**，代价仅为卸载后最初 1 秒内最多约 17 ADC 的
瞬时差异，5 秒内收敛。

被拒绝的只有一种形态：**跌破后在确认窗内回到原电平**（V 形）。连续小幅卸载（每 0.3 s 降一点）
因 `below` 持续成立、计时连续累积，不受影响。

## 9.5 可选硬化 1.1：`y_floor` 抬升门（`floor_rise_idle_only`）

### 9.5.1 没有被防护层覆盖的那一半

§9 的防护层管的是 `y_floor` 的**下行**与 `x_slow` 的**快速泄放**。
`y_floor` 的**抬升**分支（`y_floor += dt/300·(y0 − y_floor)`）在 portable-1.0 里是**无条件**的，
没有任何门控，它自己就能把算法搞垮：

恒载段 `y0` 恒定 ⇒ `y_floor` 以 `y_floor_tau_s = 300 s` 指数追平 `y0`，把**载荷本身**吸收进基线。
26 min（≈5τ）后 `(y0 − y_floor)` 从 48 ADC 掉到 7 ADC（噪声量级），而
`idle` 判据是 `(y0 − y_floor) < idle_frac·span`，`span` 同步收缩到 20 ADC ⇒ 门限只有 1.0 ADC。
单通道噪声 p2p 约 18 ADC，**任何一次噪声下沿都会击穿**：

```c
/* 触发帧（真实录制，cell6, t=1599.977s） */
pre = 1201, zero = 38.1, y0 = 1160.5, y_floor = 1162.3, span = 20.5
y0 − y_floor = −1.8 < 0.05·20.5 = 1.0    → idle = true
```

一帧 idle 的代价（21 ms）：

- `x_slow -= (dt/0.2)·x_slow` ⇒ 一次扣掉 **10.5%**（216.66 → 198.73）；
- `zero += (dt/8)·(v − zero)` ⇒ zero 上移，`y0` 下降，下一帧更容易再中。

随后进入不可逆正反馈：`zero` 以 τ=8 s 追平 `v`（t=1620 s 时 zero=994.8，t=1680 s 时 zero=1212＝pre 电平），
`y0 ≡ 0`、`e ≡ 0`、`x_slow → 0`、`applied → 0`，**补偿永久归零，显示回到原始电平**。
各通道按自己的噪声尾部在不同时刻失守，总力曲线因此呈**阶梯状上飘**。

2026-10-19 拇指指腹 48 min 恒载实录：输入只漂 +314 ADC，输出漂 +3494 ADC（11 倍）；
同数据上 K10 防护层（`guard_enable=1`）**也崩**，末态 applied 仅 3.4 ADC，比 K9 更彻底。

### 9.5.2 改动

```c
/* 原：无论受载与否都抬升 */
if (y0 >= y_floor) y_floor += (dt / y_floor_tau_s) * (y0 - y_floor);

/* 新（floor_rise_idle_only = 1）：仅在本帧被判为空载时抬升，受载期冻结 */
if (!floor_down) {
    int allow_rise = 1;
    if (p->floor_rise_idle_only) {
        const double span0 = DV6_MAX(o->y_max[k] - o->y_floor[k], 1.0);
        allow_rise = (y0 - o->y_floor[k]) < p->idle_frac * span0;
    }
    if (allow_rise) y_floor += (dt / p->y_floor_tau_s) * (y0 - y_floor);
}
```

- 新增状态量：**0 个**。新增参数：1 个（`int`）。
- `y_max` 的计算被前移到 `y_floor` 更新之前（只依赖 `y0`，不改变任何数值）。
- `floor_rise_idle_only = 0` 时 `allow_rise` 恒为 1，**与原实现逐帧一致**（新旧 DLL 实测差 0.0）。
- 与 §9 防护层**正交**，可任意组合。

### 9.5.4 已知边界

1. 抬升门只堵入口，`zero` 跟踪本身仍无载荷保护；若将来有别的路径让 idle 误判，同样的崩塌会重演。

3. 空载段（`y0 ≈ y_floor`）仍可抬升，行为与 portable-1.0 一致。
4. 缺陷时间常数 300 s ⇒ **20 min 以下的录制无法复现**，验证长恒载必须 ≥30 min。
5. 本包 `dv6_params_default()` 与 `dv6_params_plan_v4_observer_k9()` 都保持 **0**（库级向后兼容，
   黄金向量不变）；**产品侧 `Params` 默认值是 1**（修复态），需要"零配置即修复"的移植请自行把默认置 1。

完整报告与复现脚本：`../05_阶梯上飘诊断_20261019/`。

## 9.6 可选硬化 1.2：下探回抬锚（`guard_floor_recover_s`）

### 9.6.1 抬升门留下的另一半问题

§9.5 的抬升门堵住了"把载荷吸进基线"，同时也堵住了自愈：**`y_floor` 被真实下探拉低之后就永不回抬**。
48 min 实录实测（`gate=1`）：

| 档位 | `y_floor` 末值 | `y_floor` 最小值 | 说明 |
|---|---:|---:|---|
| guard=0（v3.4 档） | −758.9 | −758.9 | 末值 = 最小值 ⇒ 停在最低点 |
| guard=1（K10 档） | −654.2 | −654.4 | 同上 |

后果：`span = y_max − y_floor` 长期偏大 ⇒ `idle` 判据变钝 ⇒ 空载期 `zero` 跟踪随之失效
（空载电平若高于被钉住的 `y_floor`，`(y0 − y_floor)` 永远大于 `idle_frac·span`，`zero` 不再更新）。

### 9.6.2 改动

新增每通道状态「锚 + 是否在下探中」，在 ① 段生效：

```c
/* 下探起点记锚：只在"从非下探转入下探"那一帧更新，阶梯式连续下探不会把锚拽下去 */
if (recover_s > 0 && in_drop == 0) floor_anchor = y_floor;

/* 抬升分支里：受载期仍冻结，但若 y0 已回到锚以上（那次下探不是真实卸载），
   以 recover_s 为 τ 回抬到锚——注意回抬目标是锚，不是 y0，所以不会重新吸载荷 */
else if (recover_s > 0 && y0 > floor_anchor && floor_anchor > y_floor)
    y_floor += (dt / recover_s) * (floor_anchor - y_floor);
```

- 新增状态：每通道 2 个（`floor_anchor`、`in_drop`），`dv6_buffer_bytes` 由 16n 变 **18n** doubles。
- 新增参数：1 个（`double guard_floor_recover_s`），**默认 0 = 关闭**。
- 开启时**同时**把首帧 `y_floor` 由 `v` 改为 `y0`（= 0）：否则首帧那次"伪下探"会把锚记成
  整个载荷电平，之后 `y0` 一高过它就会把载荷重新抬进基线。关闭时首帧保持原值，逐帧一致。

### 9.6.3 实测

| 档位 | `recover_s` | 恒载漂移 | `y_floor` 末值 | 产品 ↔ 本包逐帧差 |
|---|---:|---:|---:|---|
| gate=1 guard=0 | 0 | −74.4 | −758.9 | **0.0** |
| gate=1 guard=0 | 30 | −74.4 | −602.1 | **0.0** |
| gate=1 guard=1 | 0 | −78.3 | −654.2 | **0.0** |
| gate=1 guard=1 | 30 | −81.7 | **−249.4** | **0.0** |

即：开启后 `y_floor` 从 −666 回抬到 −249，而漂移、p2p、`applied` 全部不变（不破坏主修复）。

### 9.6.4 为什么默认仍然关闭

**收益尚未被证实。** 本批数据是全程受载，没有"卸载 → 空载 → 再加载"段，因此无法证明
"回抬后 zero 跟踪恢复"确实带来收益。按 §13 数据缺口与 §14 判定原则，这属于
"候选结构、待验证"，不能写成已完成验收。

要定档需要补一份录制：**长恒载（≥30 min）→ 全卸载 → 空载保持（≥10 min）→ 再加载**，
并在其上比较 `recover_s = 0 / 30 / 60` 的空载漂移、再加载落位时间与 10g 保留率。

## 11. 附录：快速上手

```bash
# 1) 生成 DLL（上位机 FFI 需要）
build_dll.bat

# 2) 验证等价性并生成黄金向量
python verify_portable.py
#    期望：max_abs_diff = 0.0, equivalent = true

# 3) 嵌入式：把 creep_observer_portable.h 加入工程
#    #define DV6_IMPLEMENTATION  +  #include  → dv6_init / dv6_process
```

最小可用代码（任意 C99 环境）：

```c
#define DV6_IMPLEMENTATION
#include "creep_observer_portable.h"

static double state[57 * 16];
static dv6_observer obs;

int main(void) {
    dv6_params p;
    dv6_params_plan_v4_observer_k9(&p);          /* 现场参数集 */
    dv6_init(&obs, 57, &p, state, sizeof(state));

    double frame[57] = {0};
    double ts = 0.0;
    for (;;) {
        /* 读取一帧到 frame，ts 累加（秒） */
        dv6_process(&obs, ts, frame);            /* frame 就地变为补偿后显示值 */
        /* 使用 frame 显示 / 上报 */
    }
}
```
