# 瞬态下探污染基线的分析与抑制（左拇指 r_slow_max=0.6）

日期：2026-10-14 ｜ 数据：`Research/时漂问题/data/左拇指指腹 r_slow_max=0.6/测试1-2026-10-14_10-18-40`
结论位置：`02_K10_瞬态防护_20261014`（原 `01_当前工作_K9/07_瞬态扰动基线污染_20261014`，2026-10-14 整理后提升为顶层 K10）

## 一、现象确认

194.5 秒前出现一次下探，**补偿后输出基线被永久抬高约 54~60 ADC，而原始数据与算法输入都没有这个偏移**。

| 时刻 | raw 总值 | pre（算法输入） | seg（补偿后） |
|---|---:|---:|---:|
| 194.0s | 43883.5 | 43883.5 | 42649.0 |
| **194.5s** | 43871.0 | 43871.0 | **42698.8**（同段最低 42271） |
| 195.0s | 43879.0 | 43879.0 | 42708.5 |
| 200.0s | 43896.0 | 43896.0 | 42714.7 |

`pre` 与 `raw` 逐段中值完全相同，说明震荡**不是输入信号本身**，而是补偿器内部状态被改写的产物。按 1000 ADC≈1N 粗折算，这 60 ADC 相当于约 0.06 N 的长期基线误差。

同类事件在录制的其他位置也有：214.88s 有一次深 221 ADC 的下探，同样伴随补偿量永久变化。

## 二、通道级归因

用固件自身的 `applied = pre − seg`（实际扣除量）比较事件前后：

- 补偿量总减少 **−61.6 ADC**
- 下探最深的 3 个通道，正是补偿减少最多的 3 个通道：

| 通道 | 下探幅度 | 补偿量变化 |
|---|---:|---:|
| ch13 | −105.2 | **−27.6** |
| ch25 | −41.8 | **−19.8** |
| ch8 | −36.0 | **−15.2** |

三者合计 −62.6 ADC，与总减少量 −61.6 ADC 吻合。扣减比例 22%~47%，与 `tau_r_slow_idle_s = 0.2 s` 的指数泄放在 0.05~0.1 秒内的理论值一致。

**即：下探没有改变输入，却永久扣掉了这些通道的慢态补偿量。**

## 三、机制定位（代码路径）

在 C++ 权威实现 `src/domain/drift_v6/creep_observer.cpp` 中，存在一条会被瞬态触发的链路：

```
104-105  y_floor_(k) = y0        // 下行“瞬时跟随”：只要 y0 < y_floor 就直接拉低
111-113  idle = (y0 - y_floor) < idle_frac·span
         load_dwell = 0          // 受载确认计时被清零
         zero += ...             // 零点被更新
174-180  if (e <= 0 || idle_k) x_slow -= (dt/tau_r_slow_idle_s)·x_slow   // 0.2s 快泄放
```

下探帧里 `y_floor` 被瞬时拉到谷底，于是 `y0 − y_floor = 0`，**必然被判为 idle**，进而触发按 0.2 秒时间常数的快速泄放。这一设计本意是"空载快速泄放"（卸载后让补偿回落），但它对**短促下探**没有分辨能力。

附加效应：被拉低的 `y_floor` 只能以 `y_floor_tau_s = 300 s` 的速度爬回，期间 `span = y_max − y_floor` 变大，idle 判据被系统性放宽，因此基线抬升后长期不回归。这解释了为什么该偏移能保持几百秒。

## 四、必须说明的验证边界

**用同一份 `pre` 从零重放，复现不出固件的这个偏移。**

| 指标 | 固件 seg | 工具箱 K9 重放 |
|---|---:|---:|
| 194.5s 事件前后变化 | **+54.16 ADC** | −2.54 ADC |
| 事件前绝对电平 | 42649 | 40956（差 1693 ADC） |

1693 ADC 的绝对差说明：**固件录制当时的内部状态，与从 t=0 干净重放的状态并不相同**（可能是录制前已有运行历史，或固件版本细节差异）。

因此机制归因的强度排序是：

1. **通道级证据强**：下探通道与补偿减少通道一一对应，比例符合泄放时间常数（第二节）；
2. **代码路径确定**：三处代码逻辑必然被浅下探触发（第三节）；
3. **重放状态不可复现**：不能用重放直接证明"就是这一条链路"，这属于未闭环部分；
4. 结论表述应为"最可能机制"，而非"已逐帧证明"。

## 五、受控测试床：链路可以复现

要复现该链路，关键条件是让 `y_floor` 已经爬到接近工作电平。用固件 `pre` 长时重放到 1000 s（`y_floor` 已接近工作电平）后，注入固件实测的同一段下探波形：

| 场景 | 事件后输出偏移 |
|---|---:|
| 无注入（对照） | −0.71 ADC |
| 注入下探，无防护 | **+23.29 ADC** |
| 注入下探，防护开启 | **−0.75 ADC** |

**测试床复现了"下探 → 永久基线偏移"的完整链路，并且防护能将其阻断。**

## 六、能不能滤掉：两种方案与实测

### 方案A：输入侧瞬态抑制（不推荐）

思路是在数据进入算法前识别并抹平异常段。实测两种判据都不理想：

| 判据 | 对注入下探的阻断 | 对真实加载/卸载的代价 |
|---|---:|---:|
| 短窗偏离 + 短段替换 | 残留 +7.5 ADC（仅阻断 69%） | 持续加载产生 **264 ADC** 输出差异 |
| 长窗偏离 + 恢复性判据 | 残留 +7.8 ADC | 持续加载/卸载 **264 ADC** 差异 |

原因是边沿本身就像一次瞬态偏移，输入侧无法区分"下探后恢复"与"阶跃后保持"，总要牺牲一边。

### 方案B：算法内两处持续确认（推荐）

直接在污染链路的两个点上加"持续确认"，其余逻辑完全不动：

```
① y_floor 下行跟随需要持续确认
   if (y0 < y_floor):
       if (深度 > floor_deep_adc=200)  y_floor = y0            // 真实卸载：立即跟随，不延迟
       elif (持续 > floor_confirm_s=0.5s) y_floor = y0          // 持续下移：确认后跟随
       else 保持 y_floor 不变                                    // 短促扰动：不跟随
② 快速泄放需要 idle 持续确认
   瞬时 idle  → 用 tau_r_slow_s (150s，几乎不泄放)
   持续 idle 0.3s → 才启用 tau_r_slow_idle_s (0.2s 快泄放)
```

实现在 `guarded_k9.py`，可用开关关闭。实测结果：

| 验收项 | 结果 |
|---|---|
| 关闭防护 vs 工具箱实现 | **逐帧最大差 0.0**（完全等价） |
| 注入下探的永久偏移 | 无防护 +23.99 → 有防护 **−0.05 ADC** |
| 注入下探的长期稳态差 | **0.0 ADC** |
| 真实持续加载（+2000 ADC/20s） | 稳态差 **0.0**，长期漂移 −30.13 → −30.11 |
| 真实 90% 卸载 | 稳态差 **0.0**，长期漂移 −23169.29 → −23169.28 |
| 无注入对照 | 稳态差 **0.0** |

完整录制回归（`exp13_regression.py`）：

| 录制 | 无防护漂移 | 有防护漂移 | 漂移差 | 每60s中值差(最大) |
|---|---:|---:|---:|---:|
| 左拇指0.6/测试1 | −40493.9 | −40493.91 | **−0.01** | 0.014 |
| 右拇指0.6/测试1 | −44.69 | −44.65 | **+0.04** | 0.24 |

代价只有真实大卸载瞬间的短暂差异（峰值约 630~1630 ADC 的瞬时偏离，出现在 0.5 秒确认窗内），**长期稳态为零**。若对卸载瞬态也要求零代价，可把 `floor_deep_adc` 调低（让更深的下探立即跟随），但会削弱对较深扰动的防护，两者需按现场噪声标定。

（说明：本节 `applied_shift` 字段用的是事件前后各 20 s 的宽窗，混入真实漂移，只可用于横向比较事件数量，不可当作单次事件的净污染量；单次事件的净量以第二节通道级归因为准。）

## 七之二、改动清单与副作用实测

### 改了什么（仅两处，均在 `guarded_k9.py`）

**改动1：`y_floor` 下行跟随加持续确认**（对应 cpp 104-105 行）

```python
# 原实现
if (y0 < y_floor):  y_floor = y0

# 改后
if (y0 < y_floor):
    if (y_floor - y0 > floor_deep_adc):      y_floor = y0      # 深度跌破：立即跟随
    elif (持续跌破 > floor_confirm_s):        y_floor = y0      # 持续下移：确认后跟随
    else:                                     y_floor 不变       # 短促浅跌破：不跟随
```

**改动2：快速泄放加 idle 持续确认**（对应 cpp 174-180 行）

```python
# 原实现
if (e <= 0 || idle_k):  x_slow -= (dt / tau_r_slow_idle_s) * x_slow    # 0.2s 快泄放

# 改后
if (e <= 0 || idle_k):
    tau = (idle_k 持续 > idle_confirm_s) ? tau_r_slow_idle_s : tau_r_slow_s
    x_slow -= (dt / tau) * x_slow
```

**没有改动**的部分：快态 `x_fast`、慢态积分 `dx2`、K6 预留池、K7 旁路、零点更新规则、`slope` 门控、缓坡前馈、卸载泄放 `tau_r_slow_s`。新增参数 `floor_confirm_s=0.5s`、`idle_confirm_s=0.3s`、`floor_deep_adc=200`，可开关，默认关闭时与原实现**逐帧差 0.0**。

### 对原有指标的实测影响（右拇指指腹六份录制）

|---|---:|---:|---:|---:|---:|
| 设备1/测试1 | 711.12 | 706.31 | −4.81 | 0.715 | 5.22 |
| 设备1/测试2 | 547.57 | 547.05 | −0.52 | 0.841 | 1.01 |
| 设备1/10g | 575.09 | 574.80 | −0.29 | 0.432 | 0.49 |
| 设备2/测试1 | 993.33 | 993.13 | −0.20 | 0.288 | 0.50 |
| 设备2/测试2 | 96.20 | 96.11 | −0.09 | 0.017 | 0.12 |

漂移指标最大变化 −4.81 ADC（相对 711 ADC 为 0.7%），其余均小于 1 ADC；每 60 秒稳态差最大 0.84 ADC。

### 对小增量保护的影响

在同一份真实背景（设备1测试2）注入总 100 ADC 分散阶跃、2.5 秒上升、保持 15 秒后撤载：

| 指标 | 原实现 | 防护后 |
|---|---:|---:|
| 持载末 5 秒保留率 | 0.3569 | **0.3568** |
| 撤载后残差 ADC | +7.77 | +7.51 |

**小增量保护能力没有变化**（差 0.0001），说明防护不干扰原有的慢态积分与小信号行为。

### 有代价的地方

1. **真实大卸载的瞬态**：确认窗（0.5 秒）内与原实现有差异，峰值瞬时偏离约 630~1630 ADC，长期稳态为 0。若现场对卸载边沿要求严格，可调低 `floor_deep_adc` 让更深的下探立即跟随。
2. **`y_floor` 迟跟随**：空载检测与零点跟踪的触发时机会略滞后（最多 `floor_confirm_s`），影响的是空载期基线回归速度，实测 60 秒尺度差异 ≤0.84 ADC。
3. **快速泄放延迟 0.3 秒**：真实卸载后的补偿回落比原来晚最多 0.3 秒，稳态无差异。
4. **参数未跨工况标定**：`floor_deep_adc=200` 与 `idle_confirm_s=0.3` 只在右拇指/左拇指这两批录制上验证，未覆盖不同载荷量级、温度与接触姿态；现场噪声更大时应重新标定，否则可能把真实卸载误判为扰动。

## 七之三、小幅度真实卸载验证（澄清"阈值"含义）

一个合理的疑问：防护里的 `guard_floor_deep = 200 ADC/通道` 是不是等于"给下探设了阈值，
小幅卸载会被拒绝"？

**判据实际不是幅度阈值，而是"偏离是否持续"**：

```
below = (y0 < y_floor)                       # 输入是否跌破基线包络
若 below 持续成立 → below_elapsed 累积 → 达 guard_floor_confirm_s 后 y_floor 照样跟随
guard_floor_deep 只是"加速通道"：幅度超过它就不必等确认
```

真实卸载会让输入**停在新电平**，`below` 持续成立 ⇒ 0.5 s 后必然跟随。
只有"跌破后回到原电平"（V 形）才被拒绝——而那正是要滤掉的瞬态形态。

### 实测（长时恒载让 `y_floor` 爬到接近工作电平后施加卸载）

每通道减 `X` ADC、0.2 s 内完成、保持到记录结束；比较关闭/开启防护的输出差：

| 每通道卸载 ADC | 总卸载 ADC | 卸载后 0~1 s 最大差 | 1~5 s | 5~30 s | 30~90 s 稳态差 | 两臂卸载响应 |
|---:|---:|---:|---:|---:|---:|---:|
| 20 | 1040 | 0.0 | 0.0 | 0.0 | **0.0** | 一致（−925.2 / −925.2） |
| 50 | 2600 | 9.1 | 0.05 | 0.0 | **0.0** | 一致（−1253.1 / −1253.1） |
| 150 | 7800 | 16.6 | 0.08 | 0.0 | **0.0** | 一致（−6453.0 / −6453.0） |
| 400 | 20800 | 17.3 | 0.08 | 0.0 | **0.0** | 一致（−19452.7 / −19452.7） |

无卸载对照：两臂最大差 **0.0**。

**结论**：小幅度真实卸载**不会被卡住**，两臂装卸响应完全一致；防护只影响卸载后最初 1 秒
（最大约 17 ADC 的瞬时差异，来源于 0.5 s 确认窗），5 秒内收敛，长期稳态差为 0。

注：20 ADC/通道那一档差异为 0，是因为幅度太小、根本没跌破 `y_floor`（`below` 不成立），
防护完全不介入——这也说明防护对"未跌破基线包络"的卸载没有任何影响。

### 仍然存在的真实边界（必须知道）

1. **卸载后 0.5 s 内又压回去**：若操作是"卸一点 → 立刻回压 → 停在原电平"，形态与扰动相同，
   `y_floor` 不会跟随。但此时新电平并未真正建立，`y_floor` 保持原值在语义上是合理的。
2. **卸载瞬间的前 1 秒**：最大约 17 ADC 的瞬时差异（确认窗效应）。若现场对卸载边沿要求严格，
   调低 `guard_floor_deep` 可让更深的下探立即跟随。
3. **连续小幅卸载**（每 0.3 s 降一点）不受影响：`below` 持续成立，计时连续累积，0.5 s 后跟随。

## 八、建议

1. **短期**：把方案B的两处持续确认作为可开关选项加入固件，先用本条录制回放确认 194.5 s 的抬升是否消失。由于固件当前状态无法离线复现，这一步必须在固件侧做实测对照。
2. **参数起点**：`floor_confirm_s = 0.5 s`、`idle_confirm_s = 0.3 s`、`floor_deep_adc = 200 ADC/通道`。需按现场噪声与真实卸载速度重新标定，避免把真实卸载拖慢。
3. **不建议**采用输入侧抹平方案：它对真实边沿的损伤大于收益。
4. 若无法改算法，退而求其次可在数据后处理阶段做**恢复性判据**的段替换，但必须接受对真实快速卸载的边沿损失。

## 九、未验证项

- 固件实测：本防护的数值全部来自离线重放，固件侧未验证；
- 机制逐帧闭环：因固件状态与干净重放差 1693 ADC，未做到逐帧复现，机制归因属"代码路径 + 通道证据 + 测试床"三重支持；
- 参数泛化：`floor_deep_adc` / `idle_confirm_s` 只在两条录制上标定，未覆盖不同载荷量级、温度、接触姿态；
- 真实 10g 逐次验收：仍缺同步操作标签。
