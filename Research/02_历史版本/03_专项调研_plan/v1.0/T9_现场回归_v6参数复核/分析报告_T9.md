# T9 现场回归复核 · 「恒定负载反复加减 → 基线飞掉」分析报告

> **数据**：`temp/算法数据&原始数据/恒定负载下反复加减同一个负载/20260919_092417_single_device_602c03`
> （单设备 21 通道，6296 帧 / 62.65 s，`display_mode = adc`，`force_conversion_active = false`）
> **算法**：`drift_v6_fast_settle`，参数集 `plan-v1.0 A1+A4+A5a`（κ_onset 1.05 / κ_restep 1.12 /
> ho_min 3.5 s / revoke_hold_n 3）—— 即本次刚落地的参数版本。
> **结论**：**基线偏移确实严重（最大 ±3070 ADC ≈ ±1 个完整负载），但成因不是本次参数改动，
> 而是 v6 的「空载/卸载判据」在【大偏置 + 小增量】工况下结构性失效。**
> 日期：2026-09-19 · 全部结论可复算（`scripts/t9a`~`t9g`，产物在 `results/`）。

## 0. 一页结论

| # | 结论 | 证据 |
|---|---|---|

| **6** | **两条代码级后果**（读完代码可直接确认）：① `RunEvent` 里唯一的卸载出口 `if (tau > 0.3s && idle_now) ToIdle()`（`drift_v6_compensator.cpp:493`）需要 `idle_now` ⇒ **epoch 内发生的卸载被完全忽略**；② `Process` 里建减重事件的条件是 `hit && d < 0 && state_ != Idle && **!ev_.valid**`（同文件 `:362`）⇒ **epoch 进行中不建减重事件**。于是「加载 → 卸载」序列在 epoch 未结束时，卸载**无人处理**，epoch 照常跑到 `tau ≥ max(kHoMinS, τ_g0+τ_glide)` 交接，把 `A_` 钉在**受载电平**上 | `drift_v6_compensator.cpp:493 / :362` |

**一句话**：**不是参数调坏了，是 v6 在这台传感器/这个显示域的「空载」根本不可识别** ——
判据要么把受载当空载（⇒ 完全不补偿），要么从不认空载（⇒ 状态机永不复位、扣除量残留并翻转符号，
显示停在"加载时的读数"上）。本录制落在后者。

### 1.3 扣除量的形状（`t9e_deduction.csv`）

|---|---|---|---|---|

## 2. 根因（代码级）

### 2.1 判据本身在本工况下无法工作

```cpp
// drift_v6_compensator.cpp:317-319（Process）
const double lvl = std::max(level_ref_, eps);
const bool idle_now = (ts_smooth_ < kIdleFrac * lvl) ||                       // 0.10·level_ref
                      (ts_smooth_ < kUnloadMinRatio * min_ts_ + eps);          // 1.5·min_ts
```

本机实测（本录制）：空载总电平 **12855~13800**，受载 **15400~15800**（+15~23%）；
`min_ts_` = **补偿器全生命周期**的最小电平（只在 `Reset()`/换设备/换值域签名时重新锚定）。

| 情形 | ① 10%·level_ref | ② 1.5·min_ts | `idle_now` | 后果 |
|---|---|---|---|---|
| `min_ts_` ≈ 空载电平（本录制之外，如算法在装夹后才开） | 假（需 < ~1400） | **真（连受载时也真）** | **恒真** | 受载时也被判"空载" ⇒ `RunEvent` 的卸载出口立刻 `ToIdle`，**epoch 刚建就被杀 ⇒ 完全不补偿**（离线回放实测偏移 ≈ 0） |
| `min_ts_` ≪ 空载电平（本录制：算法先开、之后才装夹/加载） | 假 | **假（需 < 1.5·min_ts ≈ 3000~9000）** | **恒假** | **永不认空载** ⇒ 状态机永不复位、扣除量永久残留、符号可翻转（**本录制**） |

**两条判据对一个「空载基线远大于负载增量」的传感器同时失效** —— 不存在任何一个 `min_ts_` 取值让它们
能区分空载/受载。这是**结构性**的，不是调参能解决的。

### 2.2 never-idle 的三条连锁后果

1. **epoch 进行中发生的卸载被丢弃**（`Process`）：
   ```cpp
   } else if (hit && d < 0 && state_ != State::Idle && !ev_.valid) {   // ← 要求 !ev_.valid
   ```
   而 `RunEvent` 内唯一的卸载出口需要 `idle_now`：
   ```cpp
   if (tau > kUnloadFastS && idle_now) { ToIdle(); *out = v; return true; }
   ```
   ⇒ 本录制 43.83 s 的卸载正好落在 41.0 s 那个 epoch 内（tau ≈ 2.8 s < 3.5 s 交接），**没人处理**。
2. **epoch 照常跑到交接，把 `A_` 钉在受载电平**：`Handoff` 里 `A_new = y0 + share·Â`（`ANCHOR_MODE="pin"`）。
   于是"无蠕变电平"被固定成**受载**电平。
3. **慢相模块把错误固化并反过来把显示抬上去**：`SlowStep` 里
   `g_raw = median((v − A_)/A_)`；传感器已回到空载而 `A_` 在受载电平 ⇒ 残差 ≈ **−12%** ⇒ `g_`（τ=3 s EMA）
   趋负 ⇒ `ded = γ·A·g < 0` ⇒ `out = v − ded = v + |ded|` ⇒ **显示被抬到空载 + Â ≈ 受载电平**。
   前半段的 −800 是同一机制的反号（`A_` 被钉在电平**以下**）。
4. **永不归零**：`Reanchor` 明确选择"g 与当前扣除自洽、不能归零"，所以每次减重/重锚都把错误的
   `g` 原样继承；唯一的清零出口 `ToIdle()` 又要 `idle_now` ⇒ **锁定**。

### 2.3 离线回放验证（`t9g_seed.py`）

| 变体 | 建 epoch 数 | 末态 | 末段偏移 | 现场实测偏移 |
|---|---|---|---|---|
| 新鲜状态（不预置 `min_ts`） | 2 | idle | **0** | −810 / +1956 |
| `min_ts` 预置低值（= never-idle） | **19** | **slow** | 由负转正（+166 → +352） | 同向、幅度更大 |

- **新鲜状态几乎不产生补偿**（偏移逐平台 0 ADC）⇒ **本录制不可能用"从零开始"复现**，
  印证了第 0 帧已在扣除 ⇒ 补偿器状态是**录制之前**带进来的。
- **预置低 `min_ts` 后**：每次加载都建 epoch、末态停在 `slow`、`g` 转负、偏移由负转正 —— **与现场同向同机理**
  （幅度较小，因为回放中后续减重事件把 `A_` 又拉回空载电平；现场的一次交接把 `A_` 永久钉在了受载电平）。
- **两套参数都复现该机理**（回放中 `seed1900_old` 的偏移 +352/+436 反而**大于**新参数 +166/+274）。
  ⇒ 参数只决定偏移的**符号与量级**，不决定**是否发生**。

### 2.4 与本次参数改动的关系（逐条）

| 改动 | 是否触及病因 | 本录制的实际作用 |
|---|---|---|
| **A1 `κ_onset` 1.05** | 否 | `Â = min(max(a_ls, inc), κ·inc)` ⇒ κ 只**截上界**；1.05 比 1.30 钉得更低 ⇒ **减轻**本失效模式的偏移量级 |
| **A4 `kHoMinS` 3.5 s** | 否 | 本录制事件 t0≈41.0 s ⇒ 3.5 s 与 5.0 s 的交接时刻（44.5 / 46.0 s）**都晚于 43.83 s 的卸载** ⇒ 结局相同 |
| **A5a `kRevokeHoldN` 3** | 否 | 本段数据回放 **revoke 次数 = 0**（新/旧参数一致）⇒ 无差别 |

⇒ **本次改动不是成因**；但**它也无法修复**这个失效。

### 2.5 为什么 13 份录制没暴露（关键对照）

| 数据集 | 显示域 | 空载基线 | 负载增量 | 增量/基线 |
|---|---|---|---|---|
| 右/左拇指、四指指尖 9 份（v6 全部验证来源） | `force` | **0.0~0.5** | 16~20 | **40~266** |
| 变化负载 4 份实录 | `adc` | **28** | 25900 | **925** |
| **本录制** | **`adc`** | **12855~13800** | **+2000~3000** | **0.16** |

⇒ v6 的「空载 = 接近 0 的那种状态」假设，**只在空载基线 ≈ 0 的域里成立**；
本录制是「装夹预载把基线抬到 4~7 倍于负载增量」的**反向工况**，属**域外失效**，
与 T1~T8 里 restep 的 `T_stable` 结构性失效属同一类问题（"指标/判据在信噪比不足的工况下没有定义"）。

## 3. 处置建议

### 3.1 立刻可用（不改代码）

1. **不要在「ADC 显示域 + 装夹预载」下用 v6**。v6 的空载判据要求"空载读数 ≈ 小值"。
   可行做法：切到**力值/压强域并先做零偏（去皮）**，让空载读数落到接近 0；或换用 v5.1 / 三档免责期 /
   变点感知对数蠕变（它们没有"必须识别空载"的强依赖）。
2. **每次启用算法前，先让传感器处于空载**（先空载再点开关，再装夹/加载）：这样 `min_ts_` 锚在空载电平，
   退化成"恒判空载"⇒ 至少不会飞（代价是**几乎不补偿**，等于关闭算法）。
   ⚠️ 这与 3.2 的根因是同一件事的两面：**本工况下 v6 只有"不补偿"和"错补偿"两种结果。**

### 3.2 真正的修复（状态机改动，需授权）

| 编号 | 改动 | 说明 |
|---|---|---|
| **F1** | **空载判据改为"滚动窗相对判据"** | 用**滑动窗**（如近 20~30 s）的 `w_min/w_max` 代替全生命周期的 `min_ts_` 与绝对 `10%·level_ref`：`idle = ts_smooth < w_min + 0.10·(w_max − w_min)`，并要求 `w_max − w_min` 足够大。零基线与大偏置两种工况都成立。 |
| **F2** | **补上"epoch 内卸载"处理** | 在 `RunEvent` 内增加 `d < 0`（或 `ts_smooth` 回到滚动窗谷底附近）的卸载出口，不再只依赖 `idle_now`；同时把 `Process` 建减重事件的条件从 `!ev_.valid` 放宽为"先结束当前 epoch 再建减重事件"。 |
| **F3** | **给 `Reanchor` 一个"回到谷底就归零"的口子** | 当重锚时读数已回到滚动窗谷底附近（真的卸载了），不再"保持扣除连续"，直接 `ToIdle`（否则错误扣除被永久继承）。 |
| **F4**（可选） | **`min_ts`/`level_ref` 加时间常数或窗口** | 让历史最小电平只反映"近期"而非全生命周期，避免长期锁定。 |

**离线可先验证**：本录制的 `pre` 流是完整的算法输入，可直接回放做 F1~F3 的 A/B（含"改坏必非零"的
阳性对照），**不需要重新录制**。

### 3.3 顺带修的两处交付缺陷

1. `device_001_pre_seg0.csv` 表头缺 21 个通道名（数据行有 24 列）——`pre` 流的表头生成没有复用主表头；
   影响：任何按列名读 pre 的离线脚本都会失败（本次分析被迫按位置回退）。
2. 同一会话内 `display_force_unit` 不一致（pre 写 `mN`、main 写 `N`）。
