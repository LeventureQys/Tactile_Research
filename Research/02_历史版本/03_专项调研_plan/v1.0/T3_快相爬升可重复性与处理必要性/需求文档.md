# T3 需求文档 —— 快相爬升的可重复性判别与「是否必须处理快相」的路线裁决

| 项 | 值 |
|---|---|
| 任务 ID | **T3** |
| 回答用户诉求 | ③「我需要你评估一下这个快相爬升是否是稳定的」+「1~2 s 稳定，快相肯定必须处理，我不确定对不对，你可以反驳我」 |
| 依赖 | T1（事件表/口径）、T2（`t2_shape_profile.csv` 形状剖面） |
| 席位 | **2 个 SubAgent**（A：可重复性统计；B：路线 ROI 与反事实实验）。**B 必须独立于 A 的判断**，可以得出相反结论 |
| 模型 | deepseek / deepseek-v4-flash |
| 预期耗时 | 40~70 min |

---

## 1. 任务目标

用户提出两个希望被检验的假设：

> **H1（形状稳定假设）**：快相爬升的形状"总是差不多稳定的"，所以可以把它当作已知形状用掉。
> **H2（必须处理假设）**：要在 1~2 s 内稳定基线，快相爬升**必须**被处理。

本任务要**量化地支持或推翻**这两个假设，并给出**路线裁决**：
`放任（等它走完，v5 方式）` / `抵抗（形状约束反演算掉，v6 方式）` / `第三条路（如有）`，
每条路线的**代价-收益**都用可复现的数字表达。

**用户明确说"你可以反驳我"**，所以本任务的结论允许且鼓励与用户直觉相反——
但**必须带反例**，不许空谈。

## 2. 必须回答的子问题

### T3-A（可重复性统计）

| # | 子问题 | 期望输出 |
|---|---|---|
| T3-Q1 | 归一化快相形状 `f(τ)` 在**同类事件内**（如全部 onset）有多稳定？`CV`/`p10~p90` 在 τ 网格上各是多少？ | `t3_shape_spread.csv` + 变异带图 |
| T3-Q2 | 形状参数化后（如单 τ、双 τ、幂律指数），参数本身的 `CV` 是多少？哪个参数最稳？ | 参数 CV 表 + **推荐"可依赖的 1~2 个参数"** |
| T3-Q3 | 形状稳定性受什么影响？按**族**（右/左拇指、四指）、按**载荷量级**、按**批次**分层，稳定性是否随之变差？ | 分层稳定性表（说清 n） |
| T3-Q4 | **形状库的泛化能力**：留一法 / 跨录制训练-测试时，用"别人的形状"反演本事件的最终电平，误差多大？ | LOO 与跨录制误差表 + **乐观性折扣**（既有工作用测试集自身标定，是**乐观上界**，必须给悲观数） |
| T3-Q5 | 形状的**时不变性**：同一录制内早/中/晚期的加载形状是否一致（会不会随温漂/加载历史变）？ | 时间分层对照 |

### T3-B（路线裁决，**必须三态**：支持 / 反驳 / 有条件支持**）

| # | 子问题 | 期望输出 |
|---|---|---|
| T3-Q6 | 若**不处理快相**（v5 免责期），在 13 份录制上 `T_stable` 的分布是多少？能不能进 2 s？ | 分布表 + 与 1~2 s 上限的距离 |
| T3-Q7 | 若**处理快相**（v6 形状反演），`T_stable` 是多少？代价（最大偏差/epoch 数/过充）是多少？ | 代价-收益对表（**用 T1 的指标**） |
| T3-Q8 | 反事实：把快相**部分处理**（如只扣到 0.5 s、只对 onset 生效）会怎样？扫一遍"处理强度"维度 | **ROI 曲线**：处理强度 vs `T_stable` vs 最大偏差，找拐点 |
| T3-Q9 | 第三条路是否存在？例如：① 只对 onset 做反演、restep 走 v5 免责；② 用更长的滑行器把过充摊平；③ 双层（显示层平滑 + 内部快速基线）。给至少 2 个候选并做**数值可行性估计** | 候选方案表 + 每个方案的预期指标（可基于已有原型参数扫描，不需要新算法实现） |
| T3-Q10 | **H1/H2 三态裁决**：逐条给出「支持 / 反驳 / 有条件支持」+ 一句话理由 + 支撑数字 | 裁决表（**这是本任务的主交付结论**） |

## 3. 方法与实现要求

> **⚠️ 派发前必读**：`00_共享/接口冲突登记.md`。其中 **C-1（`T_stable` 口径）** 与 **C-2（形状 τ 网格）**
> 直接影响本任务：本任务的 `T_stable` 必须用 **T1-A 冻结的口径**（若 T1-A 已交付）并复算一次；
> 形状骨架必须用 **T2 的 `results/t2_shape_profile.csv`** 为主网格（可用更密网格补充但要标明主网格）。

1. **形状必须有统一口径**：直接用 T2 的 `t2_shape_profile.csv`（若 T2 未就绪，用 §3.3 的 τ 网格自建，交付后回对）。
2. **重复性优先报 `p10~p90` 与 `CV`**，n 小（<20）时不要只报 std。
3. **乐观性折扣（硬性要求）**：既有 v6 的形状 ROM 用**测试集自身**标定，因此 07-v6 的
   "0.2 s 估到 ±7%" 是**乐观上界**。你必须给出**留一法/跨录制**版本的数字，并在结论里
   **以悲观数为主**、乐观数作为上界同时列出。
4. **反事实实验的做法**：用既有原型 `glm53_v6.py` / `glm53_v51.py` 的参数扫描，
   **不要新写算法**（本轮不做算法开发）。参数包括 v6 的 `ROM_SCALE`、滑行器速率上限、
   形状库版本（v6 vs v6.1 的 `ROM_SCALE=1.06`）、以及"只对 onset 生效"的开关（若原型无此开关，
   用事件过滤模拟：只让 onset 事件进事件分支）。
5. **ROI 曲线必须给拐点**：说明"再加大处理强度，收益已经不值得代价"的位置。
6. **图**：至少 4 张——① `T3_01_shape_spread.png`（形状变异带，onset/restep 分面）；
   ② `T3_02_loo_error.png`（留一 vs 自身标定误差分布）；③ `T3_03_route_roi.png`（处理强度 ROI）；
   ④ `T3_04_verdict.png`（三态裁决一览）。

## 5. 已知陷阱

1. **用自身标定的形状库证明形状稳定** → 循环论证。必须留一/跨录制。
2. **把 onset 和 restep 混在一起算稳定性** → 两者形状族不同（一个是输入阶跃，一个是输入斜坡），
   混算会得到"极不稳定"的假结论。**必须分开算，然后才谈"是否同一个形状族"**。
3. **把"形状稳定"当成"形状正确"** → 形状稳定但 ROM 比现场慢 6% 时，反演会系统性高估
   （08-v6.1 已实证：onset 中位 +3.2%、最大 +10.9%）。稳定性与准确性是两件事，**分开报**。
4. **用处理强度扫描时忘了对齐其他参数** → 扫 `ROM_SCALE` 时形状库必须是同一版，否则结论无效。
5. **忽略 `t_on` 定位误差** → 反演对 `t_on` 极敏感（形状在 0.2 s 内变化最快）；事件起点 ±1 包
   的影响必须算进误差预算。
