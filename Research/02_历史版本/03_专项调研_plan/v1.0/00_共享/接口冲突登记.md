## C-4 · κ 参数的收益存在两种相反结论（**用户决策级**）

| 项 | 内容 |
|---|---|
| 第一轮结论 | changelog 记：κ 消融 `κ_onset` 1.30→1.10 使过充中位 **7.06%→3.33%**，且 `T_stable` **1.72→0.43 s**、1 s 误差 **+1.97%→+0.88%**（三项同向变好，被称为"最划算"的改进） |
| T4-B 结论 | "**κ 项本身零收益**"：`M0_now`(κ=1.30) 与 `M2_correctA`(κ=1.12) 在 35 个事件上输出**完全相同** |
| 根因 | **两者不是同一个实验**：T4-B 比的是"分支是否正确 vs 不变更 κ 值"，两组 κ 值不在同一对拍上；第一轮扫的是 κ 本身 |
| **MainAgent 已定位的机制（2026-09-19，读原型代码得到）** | v6 原型里 **κ 不是增益系数，而是"单侧上限（cap）"**：`KAPPA_ONSET, KAPPA_RESTEP = 1.30, 1.12`（`glm53_v6.py` line 63），在 `_inv_est` 里以 `min(A, kappa * inc)` 生效（line 237，`inc` = 当前已实测增量），调用处 `kappa = KAPPA_ONSET if kind == "onset" else KAPPA_RESTEP`（line 460-461）。⇒ **只有当反演值超过 `κ·inc` 时 κ 才起作用**。<br>**这解释了表面矛盾**：T4-B 的 κ 1.30 vs 1.12 输出完全相同 ⇒ 说明**在其 35 个事件上该上限根本没被触发**，"κ 无收益"只在"未触发区间"成立；第一轮的 κ 1.30→1.10 则**跨过了触发阈值**（封顶生效 ⇒ 压掉过充，且实测 `T_stable` 反而变好），两者**不矛盾**。<br>⇒ **C-4 的裁决关键量是"上限触发率"**，T5-A 必须对每个 κ 给出该列 |
| **处置** | **T5-A 负责做一次统一的 κ 扫描**：κ_onset 取 `[1.30,1.25,1.20,1.15,1.10,1.05,1.00,0.95]`（跨过触发阈值）、restep 按比例；**每档必须给"`Â` 被截断的事件占比（触发率）"** + 四联指标（过充/`T_stable`/1 s 误差/最大偏差）+ **留一泛化**；并**逐字解释 T4-B 为何测到零差**（用触发率）。这是本轮调研性价比最高的一个待办 —— 若不解决，"要不要动形状库/κ"的开发建议就是悬空的 |
| 交付要求 | T5-A 必须新增 `results/t5a_kappa_sweep.csv`（含 `kappa, trigger_rate, OS_med, OS_max, T_stable, err_1s, MD, loo_*` 列），并在报告 §④ 单列一小节裁决 C-4 |
| 补丁口径 | T4-B 已把形状库改成可插拔（`G_TAU/G_G` 类属性，见其 `scripts/t4b_glm53_v6.py` 文件头）；**T5-A 应复用该接口**以保持两席位实验口径一致；无论自写或复用，**都必须给"补丁不改变默认行为"的 A/B 零差证明** |
