## 1. 任务目标

用户不理解的是"**卸载后的时漂**"。这件事在物理上有三个不同的问题，必须**先分开**：

| 问题 | 物理含义 | 用户可见现象 |
|---|---|---|
| **P1 卸载瞬态** | 卸载沿本身的响应（可能有自己的快相/慢相，方向为负） | 退载后读数不是一步到位，而是慢慢往下走 |
| **P2 蠕变回复** | 加载期累积的蠕变在卸载后**是否回复**、多久回复、回复多少 | 退载后基线"回不到原来"，长时间还在漂 |
| **P3 零基线漂移** | 卸载后绝对零点是否回得去（传感器本身的零点漂移 + 算法的零点处理） | 反复加压/退载后，零点的读数越来越高/越来越低 |

**P3 是用户"最不理解"的部分，也是 T7 的核心交付。**

## 2. 必须回答的子问题

### T7-A（全卸载）

| # | 子问题 | 期望输出 |
|---|---|---|
| T7-Q1 | 卸载事件的**时间特征**：`t50/t80/t90/t95`、是否有自己的"快相/慢相"、持续多久 | `t7_unload_events.csv`（每事件一行，与加载表**列名对齐**便于对照） |
| T7-Q2 | 卸载后读数是否**回到零**？回不到的话，残余偏移是多少（绝对 ADC + 相对原载荷 %）？随时间怎么变？ | `t7_frozen_offset.csv` + 残余偏移-时间曲线 |
| T7-Q3 | **蠕变是否回复**：加载期累积的慢相补偿量在卸载后是否被正确撤销？还是被冻结/被当成新蠕变？ | 补偿量轨迹（内部 `A/g/γ/b`）与原始读数并排 |
| T7-Q4 | 卸载段的时漂是**单调回零**、**过冲回零（回到零以下）**、还是**不回来**？分录制给出类型 | 类型分类表（含比例） |
| T7-Q5 | 卸载后再加载（第二/第三轮）时，**第一轮的残余是否影响第二轮**？给"轮次偏差" | 多轮偏差表 |

### T7-B（部分卸载）

| # | 子问题 | 期望输出 |
|---|---|---|
| T7-Q6 | 部分卸载（减少 20%~80%）的时间特征与全卸载有何不同？**卸载幅度是否决定回复速度**？ | `t7_partial_shape.csv` + 幅度-回复关系 |
| T7-Q7 | 部分卸载后**基线正确性**：算法认为的新基线 vs 真实新电平，偏差多大？会不会把"卸载"当成"加压方向的事件"处理？ | 基线偏差表 + 反向事件误判率 |
| T7-Q8 | **对称性检验**：加载与卸载在同一 `|J|` 下，时间常数是否对称？（物理上粘弹性蠕变往往不对称，这条能验证机制） | 对称性表（`t90_load` vs `t90_unload` 之比） |
| T7-Q9 | **零基线漂移 P3 的规律**：多轮加卸载后，零点读数随轮次的漂移量；是否与累计加载时长/累计载荷相关？ | `t7_zero_drift.csv` + 轮次/累计量相关分析 |
| T7-Q10 | **对算法的建议**：卸载段应该怎么处理才不产生"冻结偏差/单帧跳变"？
（既有工作曾发现切换负载时单帧跳变 7561 ADC，见 `Document/ChangingLog` 2026-10-26 条目） | 建议表 + 每条建议的预期收益/风险 |

## 3. 方法与实现要求

> **⚠️ 派发前必读**：`00_共享/接口冲突登记.md`。**C-5 直接点名本任务**：T4-A 用「同录制同带载状态下
> 卸载 0.2 s 完成 100.3%」作为「差别在输入不在传感器」的机制证据（E2），**该论证依赖"正负方向响应对称"**。
> 你的对称性结论（T7-Q8）**优先级更高**：若你发现明显不对称，必须在本报告 §④ 显式回应 T4-A 的这条假设
> （其结论方向不受影响，因为 E1/E3/E4 不依赖对称性，但证据强度要下调），T8 会据此调整评级。
> 另注意 **C-1（`T_stable` 用 T1-A 冻结口径）**。

1. **卸载事件定义（写死）**：`unload` = 减少量 ≥ 80% 当前电平；`partial unload` = 20%~80%；
   两者都要求"事件前后各 2 s 稳定"（用 `Z̄` 判稳）。
2. **方向对称处理**：把 `J` 与所有时间指标按"卸载取负"统一，或明确规定**用 `|J|`**，
   但必须**在报告里写清楚**，否则读者会误把符号差异当机制差异。
3. **必须用真实卸载段**：变载实录里有真实的"加压→退载"（`中途切换-最终目标-13ffca` 是重点，
   用户明确说"提供的数据里有这样的数据"）。
   **注入实验只做补充**（用于补足样本量与扫幅度），且必须标注"注入"。
4. **零基线（P3）的证据要慎重**：零点漂移可能来自**传感器**（物理）或**算法**（补偿残留）。
   必须用"原始读数不含补偿"与"补偿后读数"**两条线**分别看，才能区分。
   这是本任务最容易出错的地方。
5. **与算法解耦**：先做**纯数据规律**（原始读数上的卸载时漂），再叠加算法看耦合。
   报告的 §A 应为纯数据规律，§B 才是算法视角。
6. **图**：至少 4 张——① `T7_01_unload_profile.png`（卸载归一化轮廓 + 分位数）；
   ② `T7_02_residual_offset.png`（卸载后残余偏移随时间）；
   ③ `T7_03_asymmetry.png`（加载 vs 卸载时间常数对称性）；
   ④ `T7_04_zero_drift.png`（多轮零点漂移）。

## 5. 已知陷阱

1. **把"卸载后慢慢往下走"全归因于蠕变回复** → 也可能是算法在继续扣慢相（起扣未撤销），
   必须看内部量。
2. **用补偿后数据研究物理规律** → 算法已经改了读数，物理规律要用**原始读数**看。
3. **把单帧跳变当成"真实读数跳变"** → 既有工作已证实存在"补偿场整体清零 ⇒ 单帧跳 7561 ADC"，
   这是算法产物，不是传感器现象。
4. **忽略卸载段的包结构** → 变载实录 ~40 ms 一包，卸载沿的时间定位误差 ±1 包，
   而卸载瞬态可能就发生在 1~2 包内，结论必须给敏感性。
5. **样本太少就下定论** → 卸载事件数量可能只有个位数，必须报 n 并明确"仅作定性参考"。
6. **混淆"回不到零"与"回零慢"** → 前者是残余偏移（稳态），后者是时间常数，两个指标分开报。
