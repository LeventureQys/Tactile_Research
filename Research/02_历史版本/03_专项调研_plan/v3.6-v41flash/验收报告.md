# plan v3.6 · 验收报告

> 目标：**「同一负载 → 同一显示」的一致性**（用户：「后续没有补偿的位置和前面有补偿的位置差别比较大」）。
> 结论一句话：**达成——同负载组的显示电平前后差由 −2135 ADC 降到 −26 ADC（极差 2559 → 1231），
> 前 240 s 与 3 条无关录制逐位不变，C 限幅硬不变量保持 0 越界。
> 同期另有会话把 plan v3.4（creep-mem）落地产品，本报告用同一口径对它做了独立复核：它也把问题解决了
> （极差 → 1110、前后差 → −428），两者规模相当、各有胜负。**

- 数据：`temp/算法数据&原始数据/working/零基线-反复增减同一负载/20260919_160854_single_device_7b3977`
  （311.8 s、21 通道、31 306 帧）
- 口径：**总量 Σch（ADC）**；`ded = 算法输入(pre) − 显示`
- 「同负载组 E2~E9」= 「同一次装配 + 全部砝码」这个**同一负载**在录制中出现的 8 次平台
  （E1 的载荷只有 13 328，属更小的首次加载，单列不参与比较）
- 四臂：**v31**（plan v3.1，产品历史版）/ **v32**（plan v3.2 R1，`--seed-gain 0.7`）/
  **v34**（**plan v3.4 creep-mem，当前产品源码**，`--mem 120`）/ **v36**（本轮候选，`--seed-gain 1.0 --v36-d 400`）
- 全为离线回放；回放与现场显示的中位 |Δ| = **20.9 ADC**（v31 臂，与 plan v3.1 记录的 22 ADC 同口径）；
  `v34 --mem 0` 在全部 8 条录制上与 `v31` **逐位相同** ⇒ 两臂口径可比
- 原始输出：`results/v36_final_table.txt`（总表）、`results/v36_ab.txt`、`results/v36_crosscheck.txt`

## 3. 跨数据集核查（`results/v36_crosscheck.txt`，数据根下全部 8 条）

判据：没有「完全卸载 → 重载」的录制应当**逐位不变**。

| 数据集 | 帧数 | v3.4 差异帧 / max\|Δ\| | v3.6 差异帧 / max\|Δ\| | ded 中位 v3.1 → v3.4 → v3.6 | G v3.1 → v3.4 → v3.6 |
|---|---|---|---|---|---|
| archived/恒定负载下反复加减同一个负载 | 6 296 | **0** / 0 | **0** / 0 | 0 → 0 → 0 | 1.000 → 1.000 → 1.000 |
| archived/持续恒定负载 | 70 156 | **0** / 0 | **0** / 0 | 1180 → 1180 → 1180 | 1.006 → 1.006 → 1.006 |
| archived/从零基线开始-恒定负载-反复加减 | 33 908 | 27 027 / 463 | **0** / 0 | −68 → **+11** → −68 | 1.006 → 0.991 → **1.006** |

| archived/零基线-反复增减同一负载（同族） | 34 460 | 28 259 / 3 597 | 4 200 / 5 059 | 3334 → 3365 → 3363 | 0.971 → 0.901 → 0.892 |
| archived/零负载-随机切换工况（域外） | 8 080 | 5 728 / 2 026 | 1 586 / 865 | 261 → **1508** → 767 | 0.982 → 0.913 → **0.982** |
| working/零基线-剧烈变化负载情况 | 6 836 | 1 616 / 682 | 2 419 / 1 001 | 0 → 11 → 25 | 0.970 → 0.960 → 0.959 |
| **working/零基线-反复增减同一负载（目标）** | 31 306 | 5 918 / 2 122 | 5 918 / 2 858 | 2183 → 2183 → 2205 | 0.996 → 0.937 → 0.937 |

读法：

- 两条「无真实卸载-重载」的录制对两臂都**逐位不变**；`从零基线开始…反复加减` 对 v3.6 **逐位不变**
  （它的卸载是分级塌落、未回到 Idle，v3.6 的 seed 作用域不含这种事件），对 v3.4 有 27 027 帧变化
  （ded 中位 −68 → +11，方向同为「补回补偿」）；
- 目标录制的中位 ded 两臂都几乎不变（2183 → 2183 / 2205）⇒ **中位行为未改动，只改了丢基线那一小段**；
- **两臂共同的代价集中在两条域外录制**：`零负载-随机切换工况`（v3.4 ded 261 → 1508、G −0.069；
  v3.6 ded 261 → 767、G 不变）与 `各种奇怪工况`（v3.4 ded 19 → 239；v3.6 → 34）。
  ⇒ 这一族工况必须真机复核，两臂都需要（v3.4 可调 `mem_tau_s`，v3.6 可调 `creep_seed_gain`）。

## 4. 对已落地的 plan v3.4 的独立复核

我用自己的探针（`v36_ab.py` / `v36_crosscheck.py` / `v36_compare_final.py`）重跑了
`plan/v3.4/scripts/build/v34_runner.exe`，得到以下独立结论：

| 复核项 | 结果 | 与 v3.4 自报的一致性 |
|---|---|---|
| `--mem 0` 是否等于 plan v3.1 | 8 条录制**逐位相同** | —（口径对齐的前提） |
| 目标录制同负载组极差 | 2559 → **1110**（−57%） | v3.4 报「2516 → 1018（−60%）」，**一致** |
| 家族 A（E2~E5）是否零扰动 | **逐位相同** | 一致 |

| C 限幅不变量 | **0 越界** | 一致 |

| `零负载-随机切换工况` 副作用 | ded 中位 261 → **1508**（≈下移 1250） | v3.4 报「显示整体下移 ~1200」，**一致** |

## 5. 验收结论

| 项 | 结果 |
|---|---|
| 245.31 s 重载后是否恢复补偿 | **是**（v31 +18 → v3.6 +2 832；v3.4 +1 988） |
| 同一负载的显示电平是否一致（E2~E9） | **是**（前后差 −2135 → **−26**（v3.6）/ **−428**（v3.4）；极差 2559 → 1231 / **1110**） |
| 是否影响首次加载 / 前 240 s / 无关录制 | **否**（前 240 s 三臂逐位相同；「持续恒定负载」「恒定负载下反复加减」两臂逐位相同） |
| C 限幅硬不变量 | **保持**（0 越界） |
| 长保压平坦度 | **不变**（pk-pk 2 700） |
| 代价 | G 中位 1.002 → 0.946（两臂相同）；G 最差 0.760（v3.4）/ 0.778（v3.6） |
| 验证范围 | 8 条录制离线回放；**未做真机 A/B、未写单元测试** |

**建议下一步**：

1. **真机 A/B 以 v3.4 为主线**（它已落地，改动面已被其自身回归覆盖）：
   确认「卸载-重载后显示与前面加载段一致」、`param_set = plan-v3.4 creep-mem`。
2. **把 v3.6 当交叉验证/备选**：若现场发现 v3.4 在域外工况（零负载随机切换）下移过多，
   可对比 v3.6（同工况下移约为其 40%，且 G 不变）。**两条机制不要同时上。**
3. **硬约束记账**：任何「在事件期对显示做固定扣减」的机制，其扣减量必须**同时**体现在
   事件滑行目标与交接锚定上（v3.2 的塌陷就是只加了一处、且 `ded_old` 处符号还写反）。
4. **回归锁（需用户授权）**：合成「加载 → 长保压 → 整片卸载 → 重载」序列，
   断言重载后的显示与卸载前保持段一致（|Δ| ≤ 阈值），并断言关闭开关时逐位回到 plan-v3.1。
