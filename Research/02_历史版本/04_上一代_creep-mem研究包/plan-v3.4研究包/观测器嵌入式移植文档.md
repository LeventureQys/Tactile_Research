# 在线双态蠕变观测器 · 嵌入式移植文档

> 移植对象：`src/domain/drift_v6/creep_observer.{h,cpp}`（observer-v3，零点跟踪 + 快态模型 + 慢漂移跟踪）。
> 事实来源：产品源码逐行核对 + `temp/v4.1flash/plan/v3.4/算法说明_v3.4观测器.md` + `results/v34_observer_v3_eval.txt`。

## 1. 移植前的认知对齐

这个算法与常见"滤波器移植"有三个本质差异，先讲清楚，后面的取舍才有依据：

1. **它是逐通道独立的状态观测器，不是滤波器组**。五个状态量之间没有任何跨通道运算（无中位、无共识、无矩阵乘），整帧就是同一套标量公式对每个通道各跑一遍。这意味着移植工作是一次"把一个 10 行标量循环写对"，没有数据流复杂性，但**顺序与限幅位置必须逐字复刻**——对拍时最容易出的差异全在这些细节上（§6.2）。
2. **它是显示层算法，不是采集层算法**。输入是"单位换算之后、阈值过滤之前"的显示值向量（主机侧口径），输出就地覆盖。放在 MCU 上对应的位置是"标定换算后、发送/显示前"。放错位置（如放在原始 ADC 上但下游又做换算）会让所有相对判据失真——算法里全部门限都是相对量，理论上对 ADC 域与力值域都适用，但**域不能在一帧序列中途变**。
3. **它没有事件、没有清零，但有一组明确的重置语义**。移植最容易丢的就是这组语义：什么时候必须整体重置（§4.3）。丢了它不会立刻报错，只会表现为"换个模式显示突然不对"。

## 2. 移植的最小接口

单目标（单设备）场景下，协调器（按 key/签名隔离多目标）不需要移植，需要的是补偿器本体：

```
每帧调用一次：
  输入  timestamp_s   帧时间戳（秒，单调递增；重复或回退见 §5.2）
        values[n]     n 通道显示值（浮点，就地覆盖为补偿后显示值）
  输出  无（values 即输出）
```

参数为 11 个标量（§3），实例常驻状态为：

| 状态量 | 每通道个数 | 说明 |
|---|:--:|---|
| `zero` | 1 | 零点（近零带内慢速跟踪，受载冻结） |
| `y_max` | 1 | 负载响应峰值包络（慢衰减，近零带判据用） |
| `x_fast` | 1 | 快态非弹性估计 |
| `x_slow` | 1 | 慢态非弹性估计 |
| `v_lp` | 1 | 慢漂移速率估计的低通量 |
| 标量杂项 | — | 通道数、首帧标志、上帧时间戳 |

内存账：**每通道 5 个浮点 + 每实例 3 个标量**。21 通道、float32 下约 430 B；double 下约 850 B。对比上一代 v6 档约 2 MB/目标的环形缓冲，这个量级可以直接放 RAM，不需要堆。**稳态零动态分配**（主机侧唯一一次分配发生在通道数首次确定时；MCU 移植应改为编译期定长数组）。

## 3. 参数表（11 个，全局固定）

| 参数 | 值 | 含义 |
|---|:--:|---|
| r_fast | 0.12 | 快态幅度比（快相终值 = r_fast·e） |
| tau_c_fast_s | 8 s | 快态受载收敛 τ |
| tau_r_fast_s | 6 s | 快态空载恢复 τ |
| r_slow_max | 0.35 | 慢态上限（相对弹性电平） |
| tau_r_slow_s | 150 s | 慢态空载恢复 τ |
| tau_slope_s | 3 s | 慢漂移速率估计的低通 τ |
| slope_gate_frac | 0.02 | 沿门：\|dv/dt\| > 2%·e/s 不积分 |
| slope_cap_frac | 0.01 | 慢态积分速率上限（1%·e/s） |
| tau_zero_s | 8 s | 零点跟踪 τ（仅近零带内） |
| idle_frac | 0.05 | 近零带宽：y < 5%·y_max |
| y_max_tau_s | 600 s | 峰值包络衰减 τ |

定标依据与"为什么慢态幅度不设固定值"见算法说明 §3；换传感器/夹具需重标 r/τ（上位机侧规律辨识脚本可复用）。**移植时不要为了省一个参数把某个 τ 硬编码进公式常数**——11 个全部走可配置结构，将来重标才不用重编固件。

## 4. 逐帧流程（按执行顺序，顺序不可调换）

### 4.1 首帧

零点、低通量取首帧输入；包络清零；两个非弹性状态为零。首帧输出 = 输入（减去零状态）。**这一帧定义了"算法当前认为的零点"**，启动语义全由此而来（§4.4）。

### 4.2 时间步

```
dt = timestamp − last_ts
dt = (dt > 0) ? min(dt, 0.1) : 0      // 回退/重复 → 0；卡顿 → 截到 0.1 s
```

dt = 0 时**跳过全部状态积分，但仍执行输出扣除**（显示照常减去当前状态）。这是主机侧对时间戳异常的容错语义，MCU 上如果帧率严格固定且不丢帧，可以简化为常数 dt；但只要存在丢帧后补发或时间戳抖动，就必须保留截断——一次 2 s 的 dt 若不截断，慢态会把 2 s 的积分一次算完，沿门也拦不住。

### 4.3 主体（每通道）

按以下顺序，每一步的限幅位置都要保留：

1. **包络与零点**：y = v − zero；y_max ← max(y_max·exp(−dt/600 s), y, 0)；若 y < 0.05·max(y_max, 1)，则 zero 以 τ=8 s 向 v 靠拢（受载时不碰 zero）。注意 idle 判据里的 max(y_max, 1) 下限——它保证冷启动（y_max 尚为 0）时判据可用。
2. **快态**：e = max(y − x1 − x2, 0)；斜率取（用**更新前**的 x1）：e>0 时 (r_fast·e − x1)/8 s，否则 −x1/6 s；x1 ← max(x1 + dt·斜率, 0)。x1 的下限 0 必须保留。
3. **慢态**：slope = (v − v_lp)/3 s，随后更新 v_lp（解析式低通导数，**不引入显式差分**）；重算 e = max(y − x1 − x2, 0)（此处的 x1 已是本帧更新后的值）；
   - e > 0：base = max(e, 1)；**仅当** |slope| < 0.02·base 时积分 x2 += dt·clamp(slope − 快态斜率, ±0.01·base)；随后把 x2 夹到 [0, 0.35·base]；
   - e = 0：x2 ← max(x2·(1 − dt/150 s), 0)。
4. **输出**：显示 = v − x1 − x2。**不做正值钳位、不做取整、不做归零**——这些属于下游显示管线，移植时不要顺手加。

三处最容易被"优化"掉的细节，对拍差异的常见来源：

- 快态斜率用**更新前**的 x1 与第一步的 e（先算斜率、后更新 x1）；
- 慢态积分的是 slope **减去快态斜率**，不是 slope 本身；
- 慢态的两个限幅（沿门判断、±cap 夹取）与范围钳位 [0, 0.35·base] 是四次独立操作，顺序是"先判断沿门→夹取→加→范围钳位"。

### 4.4 重置语义（必须整体移植）

以下任一事件发生，**全部状态回到首帧**（含零点、包络、低通量、非弹性状态）：

| 触发 | 嵌入式对应 |
|---|---|
| 通道数变化 | 阵列配置变更 |
| 值域签名变化 | 显示域切换（ADC/标定值切换等，对应寄存器 0x000D 一类的输出模式位） |
| 算法开关切换（off→on） | 功能使能位 |
| 软件调零 | 零偏写入——主机侧它会直接触发算法全新启动 |

其中"软件调零 = 算法重启"这一条必须写进两边的一致理解：调零后算法把当前读数（含当前载荷）当新零点，带载调零后该负载的蠕变正常补偿（这正是推荐操作规范：装好负载 → 调零 → 开算法）；反过来，**带载启动不调零 = 安全直通但不补偿**，直到第一次卸载或调零。不要在 MCU 侧把调零做成"只改显示偏移、算法状态不动"——那会制造主机侧没有的失配路径。

### 4.5 完整伪码（与产品源码逐行对应）

以下伪码与 `src/domain/drift_v6/creep_observer.cpp` 的 `CreepObserverCompensator::Process()` 一致，是 §4.1~§4.3 的展开形式。逐通道状态为 `zero/x1/x2/v_lp/y_max`，参数名见 §3。`max(a,b)`/`min(a,b)`/`|a|`/`clamp(a,lo,hi)` 均为普通标量运算。

```
过程 CreepObserverProcess(timestamp, v[n])          # v 就地覆盖为输出显示值
  若 n <= 0: 返回
  若 通道数 n 变化: 全部状态重置并按 n 重新分配        # 见 §4.3/§4.4 重置语义

  # ── 首帧：零点/低通/包络取首帧输入，非弹性状态为零 ──
  若 首帧:
    首帧 ← 假;  last_ts ← timestamp
    对每通道 k:  zero[k] ← v[k];  y_max[k] ← 0;  v_lp[k] ← v[k]
                                              # x1[k]、x2[k] 保持 0
    对每通道 k:  v[k] ← v[k] − x1[k] − x2[k]   # = v[k]，直通
    返回

  # ── 时间步：回退/重复 → 0；卡顿 → 截到 0.1 s（§4.2）──
  dt ← timestamp − last_ts;  last_ts ← timestamp
  dt ← (dt > 0) ? min(dt, 0.1) : 0

  若 dt > 0:
    y_decay ← exp(−dt / y_max_tau)               # 帧级一次，通道循环外（= 参数 y_max_tau_s）

    # ── 第 1 步：包络与零点跟踪（逐通道）──
    对每通道 k:
      y0 ← v[k] − zero[k]
      y_max[k] ← max(y_max[k] · y_decay, max(y0, 0))
      idle ← y0 < idle_frac · max(y_max[k], 1)   # 下限 1 不可省（§6.2-3）
      若 idle:                                    # 受载时冻结 zero
        zero[k] ← zero[k] + (dt / tau_zero) · (v[k] − zero[k])

    # ── 第 2 步：快态 x1（固定模型，作用在 y 上）──
    对每通道 k:  y[k] ← v[k] − zero[k]            # 用第 1 步更新后的 zero
    对每通道 k:
      e_now[k] ← max(y[k] − x1[k] − x2[k], 0)
      dx1_rate[k] ← (e_now[k] > 0)
          ? (r_fast · e_now[k] − x1[k]) / tau_c_fast   # 受载：向 r_fast·e 收敛
          : −x1[k] / tau_r_fast                        # 空载：恢复
      x1[k] ← max(x1[k] + dt · dx1_rate[k], 0)    # 下限 0 必须保留

    # ── 第 3 步：慢态 x2（低通导数跟踪，扣除快态份额）──
    对每通道 k:
      slope ← (v[k] − v_lp[k]) / tau_slope        # 解析低通导数
      v_lp[k] ← v_lp[k] + (dt / tau_slope) · (v[k] − v_lp[k])
      e ← max(y[k] − x1[k] − x2[k], 0)            # 此处 x1 已是本帧更新后
      若 e > 0:
        base ← max(e, 1)
        cap ← slope_cap_frac · base
        若 |slope| < slope_gate_frac · base:      # 沿/快变不积分
          x2[k] ← x2[k] + dt · clamp(slope − dx1_rate[k], −cap, cap)
                                              # ^ 积分 slope 减快态斜率
        x2[k] ← clamp(x2[k], 0, r_slow_max · base)  # 范围钳位
      否则:
        x2[k] ← x2[k] − (dt / tau_r_slow) · x2[k]
        x2[k] ← max(x2[k], 0)

  # ── 第 4 步：输出（dt=0 时也执行，§6.2-4）──
  对每通道 k:  v[k] ← v[k] − x1[k] − x2[k]
  # 不做正值钳位、不取整、不归零
```

配套的协调层伪码（单设备 MCU 场景可退化为"一个实例 + 重置触发表"，§7）：

```
过程 CoordinatorProcess(key, signature, timestamp, v[n])
  若 未使能: 返回
  若 key 不存在 或 该 key 的 signature 与本次不同:
    重置该 key 的补偿器（等同首帧）;  记录新 signature
  调用 CreepObserverProcess(timestamp, v[n])

过程 SetEnabled(on)        # 开关切换 = 全部目标整体重置（§4.4）
  若 enabled ≠ on:  enabled ← on;  清空全部目标状态
```


## 5. 数值与算力

### 5.1 算力〔推断，按公式估算〕

每通道每帧约 25~35 次浮点乘加、1 次取绝对值、若干次比较；整帧唯一的超越函数是包络衰减 exp(−dt/600 s)，**每帧一次（帧级标量），不在通道循环内**。21 通道、100 Hz 下约 7 万 flops/s 量级，对任何带 FPU 的 MCU 都不构成负载；无 FPU 平台上，可将 exp 替换为 1/(1 + dt/τ) 或每帧查表（该量只进峰值包络的慢衰减，误差容忍度高），τ 的除法可预计算倒数。

### 5.2 精度

主机侧全部状态与参数为 double。float32 移植的主要风险点只有一个：`slope = (v − v_lp)/τ` 在大读数、小差值下的有效位数。当前 ADC 量级（~2×10⁴）与实测漂移速率（每帧 v − v_lp 约为个位数 ADC）下，float32 的绝对分辨率（~2×10⁻³ ADC @ 2×10⁴）仍有约三个数量级余量〔推断，按 IEEE 754 单精度分辨率估算〕。若目标平台的量程更大或蠕变更慢，先把这一处保留 double，其余状态（x1、x2、zero、y_max）对精度不敏感。**不建议定点化**：公式含除以 τ 的六个不同时间常数与运行时 clamp，定点带来的省电远抵不过验证成本。

### 5.3 时间戳

算法按秒计时，全部 τ 以秒为单位。MCU 用 tick 计数时，换算保留浮点秒即可；host 侧原型时间戳来自录制文件、约 15 ms/帧（65 Hz），但算法不依赖特定帧率——所有判据都是相对量与时间常数，帧率变化只改变离散化误差。重复/回退时间戳的处理见 §4.2。

## 6. 验证与验收

### 6.1 对拍资产

已有三份逐帧一致的实现链：Python 原型（`v34_observer_core3.py`）↔ 主机 C++（PARITY OK，max|Δ|=5×10⁻⁵ ADC）。移植验收应复用同一方法：

1. 取若干真实录制（覆盖：全程空载、恒载长保压、反复增减、变化负载）的 pre 流 CSV 作为输入；
2. 同一输入分别喂主机实现与 MCU 移植，逐帧比对；
3. 验收阈值建议按精度方案定：double 移植沿用 5×10⁻⁵ ADC；float32 移植应先在主机上用 float32 跑一遍同数据，拿到"精度损失基线"，再要求 MCU 与 float32 基线的差异在噪声级。

### 6.2 最容易对不上的点（按历史踩坑排序）

1. 快态斜率的 x1 时序（更新前 vs 更新后）；
2. 慢态积分量的"减快态斜率"遗漏；
3. idle 判据里 max(y_max, 1) 的下限（漏掉后冷启动永远判不进近零带，零点永不跟踪——症状是 v2 的空载下沉，且不会报错）；
4. dt=0 帧仍需执行输出扣除；
5. 范围钳位 [0, 0.35·max(e,1)] 里的 base 同样带 max(e,1) 下限。

### 6.3 行为级验收断言（对拍之外）

- 空载录制：显示与输入均值差应在数十 ADC 内（参考实测 −20 ADC），不得出现持续单向下沉；
- 恒载录制 346 s：显示漂移应在 ±150 ADC 内（参考实测 −108，输入自身 +1010）；
- 反复增减：各保压段落点偏差在 ±10%·台阶内（参考实测 −257~+1178 ADC，判据 ±1500）；
- 带载启动不调零：显示逐位≈输入（安全直通）；
- 调零后：算法行为等同重启，零点在 ~8 s 内重锚。

以上参考值全部来自 21 通道 ADC 域录制回放，目标平台传感器/夹具不同时数值会变，但"空载不下沉、恒载钉平、直通安全"三条性质必须成立。

## 7. 主机侧不需要带过去的东西

- 协调器的多目标 key/签名 map：单设备 MCU 场景替换为一个实例 + §4.4 的重置触发表；
- Eigen 向量：五个状态改为定长数组；
- 录制落盘（参数集标识 11 字段）：建议保留等价物——在固件里留一个版本/参数集只读寄存器或命令，否则现场排查"这台设备参数是哪套"会变成盲区。

## 8. 已知边界（移植后依然存在，与平台无关）

- 慢态会吸收 ≤1%·e/s 且连续的真实缓慢加载（"恒载钉平"的另一面，由 slope_cap 限幅决定）；
- 受载态小台阶稳定时间 7.5~15 s（无快相前馈；下一轮方向是沿后形状先验直接置 x1，预计 2~4 s，届时移植侧只需改 x1 初始化一处）；
- 卸载后到零点再校准完成前（τ0=8 s 量级），显示有一段低于原始零点的过渡；
- 参数为全局默认，换传感器建议重标 r_fast 与各 τ。
