|---|---|---|

只冻结「蠕变补偿」这一件事。这样免责期结束时不需要任何状态迁移。

## 2. `drift_compensator.h`

### 2.1 参数常量（追加到现有参数区的末尾，`kAWindowEndS` 之后）

```cpp
    // ── v4: 快相免责期（加载瞬间的确定性快速爬升不做补偿）──
    // 依据: 9 组实测数据显示加载后 0~1s 为机械加载、1~4s 为接触建立(4s 完成 92%)、
    //       4s 后进入慢相蠕变; 快相归一化形状 9 组逐点标准差 <= 0.026 (高度可复现)。
    static constexpr double kFastPhaseS   = 5.0;  // 免责期长度(首次 onset 后, 秒)
    static constexpr double kExemptAWinS  = 1.5;  // 幅度采集窗长度, 紧贴免责期末端
```

> `kExemptAWinS` 使幅度窗落在 **[3.5, 5.0] s**。
> **不要沿用 v3 的 `kAWindowStartS..kAWindowEndS`（1~3 s）** ——
> 该窗口整段落在免责期内会被跳过，导致 `A_` 永远捕获不到、补偿恒为 0（原型阶段的真实踩坑）。

### 2.2 成员变量（追加到 v3 切换连续性状态区之后）

```cpp
    // v4: 免责期状态
    bool fast_done_ = false;      // 本次负载段的免责期是否已结束
    Eigen::VectorXd exempt_acc_;  // 免责期末段幅度采集滑窗(Σ Z)
    int exempt_frames_ = 0;
```

> 注意 `Eigen::VectorXd exempt_acc_;` **不要**写成带 `= Eigen::VectorXd::Zero(n)` 的
> 类内初始化 —— `n` 不是常量，类内初始化无法编译（必须放到 `ResetFor(n)` 里）。

> **为什么另开 `exempt_acc_` 而不是复用 `a_acc_`**：
> `a_acc_` 同时承担「v3 的 A 窗累加器」与「v4 的采集累加器」会造成语义冲突 ——
> 原型阶段正是复用 `a_acc_` 又在免责期内把它清零，才导致收尾时 `a_frames_ == 0`、
> `A_` 拿不到值。分开命名后这条路径不会互相污染。

## 3. `drift_compensator.cpp`

### 3.0 本骨架的代码已实测可编译

本文档 2.x / 3.x 节的 C++ 片段由 `../cpp_snippet_check/extract_check.py` **从本文件原样抽取**，
拼成最小 harness 后用 MSVC（VS Build Tools 18，`/std:c++17 /EHsc /O2`，Eigen 5.0.0）编译并运行：

```text
cl exit = 0（仅 Eigen 自身的 C4819 代码页警告）
run 输出:
  免责期末段采集帧数 = 150
  fast_done=1  a_captured=1  A_max=1.339600  n_loaded=5/6
  自检: A非零=1  loaded>0=1  fast_done=1  采集窗非空=1
  run exit = 0
```

`A_max = 1.3396` 与合成输入在 0.8~1.4 s 窗口的均值相符；第 6 个弱受载通道（0.05 vs 1.4）
被 `kLoadedFrac` 正确排除（5/6）。

**抽取-编译过程抓到并已修正两个真实缺陷**（保留在此，避免重犯）：

1. `Eigen::VectorXd exempt_acc_;` 原写成 `= Eigen::VectorXd::Zero(n)` 的类内初始化 ——
   `n` 不是常量，**无法编译**；必须移到 `ResetFor(n)` 里（§2.2 已加注）。
2. 收尾赋值原写成 `A_ = (frames>0) ? (acc/frames) : (v-b_);` ——
   Eigen 的 `?:` 两个分支表达式类型不同（商表达式 vs 差表达式），**无法隐式转换，编译不过**；
   已改为先赋兜底值再覆盖（§3.4）。

### 3.1 `Reset()`

```cpp
    fast_done_ = false;
    exempt_acc_.resize(0);
    exempt_frames_ = 0;
```

### 3.2 `ResetFor(int n)`

```cpp
    exempt_acc_ = Eigen::VectorXd::Zero(n);
```

### 3.3 `BeginLoad(double ts)`

在函数末尾追加（保持原有语句不动）：

```cpp
    // v4: 每次进入负载段(首次 onset 或 restep 中途变载)都重新起免责期
    fast_done_ = false;
    exempt_acc_.setZero(n_);
    exempt_frames_ = 0;
```

> 注意这里对 **restep** 也复用同一个 `BeginLoad()`。实测表明这是必要的：
> 中途变载同样伴随一次快相，v3 在检测滞后期会用变载前的旧幅度继续扣，
> 造成变载后 2~4 s 内欠报 35%；v4 冻结补偿后该欠报降到 21.6%（整阵口径 8/8 事件不劣化）。

### 3.4 `Process(double ts, Eigen::VectorXd& v)` —— 插入位置

**插入点**：在 v3 的 `in_load_` 状态迁移块（`if (!in_load_) { ... } else if (u > kUnloadFastS && idle) { ... }`）
**之后**、`Eigen::VectorXd Z = v - b_;` **之前**。

理由：这样 `in_load_` 的迁移（含 restep 调用 `BeginLoad()`）已经完成，
`hold_comp_` 也已由 v3 的 pending 分支准备好；v4 只负责「覆盖输出」与「收尾赋值」，
不参与状态判定。

```cpp
    // ── v4: 快相免责期(首次 onset 与负载内变载都生效) ──────────────────
    // 免责期内不扣蠕变, 输出直通(只扣零漂基线 b_); 免责期结束当帧捕获幅度 A_
    // 并清零 g/γ, 让慢相蠕变的 epoch 从快相末开始计。
    if (in_load_ && !fast_done_) {
        const double ux = ts - onset_ts_;
        if (ux < kFastPhaseS) {
            // 冻结蠕变状态: 不积分 g/γ、不累积蠕变、不使用 v3 的 A 窗
            a_captured_ = false;
            A_.setZero();
            a_acc_.setZero();
            a_frames_ = 0;
            g_ = 0.0;
            g2_acc_ = 0.0;
            g_rel_acc_.setZero();
            gamma_.setOnes();

            // 幅度采集: 仅紧贴免责期末端的窗口 [kFastPhaseS-kExemptAWinS, kFastPhaseS]
            if (ux >= kFastPhaseS - kExemptAWinS) {
                exempt_acc_ += v - b_;
                ++exempt_frames_;
            }

            v = v - b_;                 // 直通(仅扣零漂基线), 不做蠕变扣除
            return;
        }

        // ── 免责期结束当帧: 收尾 ──
        // 注意: 这里不能写成 A_ = (frames>0) ? (acc/frames) : (v-b_);
        // Eigen 的 ?: 两个分支表达式类型不同 (商表达式 vs 差表达式), 无法隐式转换, 编译不过。
        // 必须先赋值再按需覆盖。
        A_ = v - b_;                    // 兜底: 采集窗为空时用当帧 Z
        if (exempt_frames_ > 0)
            A_ = exempt_acc_ / static_cast<double>(exempt_frames_);
        const double amax = A_.maxCoeff();
        if (amax > 1e-9) {
            for (int i = 0; i < n_; ++i)
                loaded_[i] = A_(i) > kLoadedFrac * amax ? 1 : 0;
        } else {
            std::fill(loaded_.begin(), loaded_.end(), 0);
        }
        a_captured_ = true;
        g_ = 0.0;
        g2_acc_ = 0.0;
        g_rel_acc_.setZero();
        gamma_.setOnes();
        exempt_acc_.setZero();
        exempt_frames_ = 0;
        fast_done_ = true;
        // 不 return: 当帧继续走 v3 的蠕变补偿逻辑
    }
```

> **`rate limiting` 说明**：这里没有 `return` 丢失事件检测的风险 ——
> v3 的状态机与 `b_` 基线跟踪都在**本分支之前**已经跑完，
> 本分支只决定「这一帧的输出是不是直通」以及「收尾时怎么给 A_」。

## 4. 自检断言（必须加，不必等测试就能发现问题）

原型阶段的教训：A 窗被免责期跳过 → `A_=0` → `loaded_` 全 0 → **补偿恒为 0**。
症状是「变化负载上增益恰好 1.000、恒载上时漂与原始完全相同」，
看起来像「没有副作用」，实际算法没在工作。因此加三条断言：

```cpp
    // 自检 1: 免责期结束后 A_ 必须非零
    // 自检 2: loaded_ 中为真的通道数 > 0
    // 自检 3: g_ 应随慢相单调增长(非恒 0)
    // 建议以 debug 断言或日志形式实现, 例:
    if (fast_done_ && a_captured_) {
        const double amax = A_.maxCoeff();
        const int n_loaded = static_cast<int>(
            std::count(loaded_.begin(), loaded_.end(), static_cast<char>(1)));
        // 首次进入时检查一次, 避免每帧开销
        // if (amax <= 1e-9 || n_loaded == 0) { spdlog::warn("[drift v4] A 捕获失败: amax={:.3g}, loaded={}", amax, n_loaded); }
    }
```

## 5. 验收口径（建议同时补进单测/离线回归）

现有「负载段末 10% − 首 10%」口径**区分不出本改造的收益**，需补三项：

| 指标 | 定义 | v3 | v4(5 s) | 目标 |
|---|---|:--:|:--:|:--:|
| `时漂残余_慢相段` | onset+5 s 起，末 10% − 首 10%，/ 幅度 | 1.49% | **0.95%** | < 1.1% |
| `非线性残差` | 慢相段残差去线性后 RMS / 幅度 | 1.29% | **1.17%** | < 1.2% |
| `变载最坏欠报` | 变载窗内 `max\|显示−原始\|` / 本次跳变 | 9.6% | **5.9%** | < 7% |
| `事件跳变超额` | 负载段内(不含卸载沿)单帧 `\|Δ显示−Δ原始\|` | 0.03 | 0.03 | 不劣于 v3 |
| `阶跃保真` | onset+0.5~2.5 s 幅度 / 原始同窗 | 1.00 | 1.00 | 不劣于 v3 |

离线回归可直接复用 `temp/v4.1flash/scripts/ac_final5.py` 的口径（见该脚本 `metrics()` 的注释）。

## 6. 参数调优建议

| 参数 | 默认 | 调整依据 |
|---|:--:|---|
| `kFastPhaseS` | 5.0 s | 实测快相 4 s 完成 92%、5 s 基本结束。改 3 s ⇒ 全段指标更好看但慢相段变差（1.74%）；改 8 s ⇒ 两头都变差（全段 3.54%、慢相 1.59%） |
| `kExemptAWinS` | 1.5 s | 只影响 `A_` 的估计噪声；窗口取免责期末段是为了让 A 代表「接触已建立的弹性幅度」 |

两个参数都由右拇指 / 左拇指 / 四指三处指尖数据联合标定。
**若换传感器型号或改采样率，应重新确认 `kFastPhaseS`**（快相时长是器件+安装的物理属性）。

## 7. 未验证项（落地前建议补做）

1. **跨载荷量级**：现有数据每处指尖只覆盖相近载荷量级，未证明快相形状在 5N / 10N / 20N 间一致；
2. **短保压**：加载保持 <5 s 的工况下免责期会被卸载打断，需确认行为可接受；
3. **多档反复变载**：数据仅有一档中途加重，缺少「5N→10N→15N→5N」这类连续多档录制；
4. **带原始 ADC 的录制**：本批为 `processed_display`（量化刻度 0.001、无负值），
   若要评估负漂或更细的噪声结构，需补 `has_raw_adc=true` 的数据。
