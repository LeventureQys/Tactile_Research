# 算法说明：卸载门控自动归零 + 混合蠕变补偿（推荐方案）

> 版本：2026-09-16 · GLM53 分析产出 · 参考实现：`scripts/b_compare.py`（算法块 7/8 与公共基座）、计时脚本 `scripts/e_timing.py`
> 验证数据：右拇指指尖（9×7/31ch）、左拇指指尖（9×7/31ch）、四指指尖（8×5/21ch）各 3 组，空载-恒载(107~147s)-空载
> 全部组件**严格因果**：任意时刻输出只依赖当前与历史采样

---

## 1. 算法定位与实测效果

两级结构：**① 卸载门控自动归零**（解决零漂）+ **② 混合蠕变补偿**（解决时漂）。

数学模型：`Y_i(t) = X_i(t) − b_i(t) − γ_i · A_i · g(t)`

| 传感器 | 原始时漂 | 补偿后（主通道） | 补偿后（受载中位） | 阶跃保真 | 噪声比 | 零漂残余 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| 右拇指指尖 | 38.6% | **4.8%** | **0.9%** | 1.02 | 0.60 | 0.6% |
| 左拇指指尖（弱蠕变） | 5.8% | **0.9%** | **0.6%** | 1.01 | 0.75 | 0.0% |
| 四指指尖（8×5） | 15.5% | **1.1%** | **0.9%** | 1.02 | 0.55 | 0.2% |

参数对三种传感器零重调通用；弱蠕变场景无过补偿（数据驱动自适应）。

## 2. 算法流程（伪代码，逐帧执行）

```
状态: b[m]      各通道基线（初始 = 首帧值，假设首帧空载）
      ts,min,max 总量平滑值及其历史极值（初始 = 首帧总和）
      A[m], loaded[m], gamma[m](=1), g=0, g2=0, grel[m](=0)
参数: τ_b=2s, τ_g=3s, τ_s=0.3s, γ∈[0.3,2.0], creep∈[−0.5A, 1.5A]
      通道入选阈 0.10·A_max

每帧 (X[m], dt):
  # ── ① 卸载门控自动归零 ──
  total = Σ X_i
  ts    += dt/τ_s · (total − ts)          # 总量平滑（EMA τ=0.3s）
  min = min(min, ts);  max = max(max, ts)  # 历史极值（因果累积）
  unloaded = (ts < 1.5·min) 或 (ts < 0.15·max)
  if unloaded:
      b += dt/τ_b · (X − b)               # 空载：基线快速跟踪（τ=2s）
  Z = X − b                                # 自动归零后信号

  # ── ② 混合蠕变补偿（仅在负载状态） ──
  if 加载后 1~3s（历史窗）:
      A = mean(Z[1s..3s])                  # 各通道负载幅度估计（一次性）
      loaded = (A > 0.10·A_max)
  if 处于负载段:
      rel_i = (Z_i − A_i) / A_i            # 受载通道归一化残差
      g_raw = median(rel, loaded)          # 阵列共识蠕变形状
      g    += dt/τ_g · (g_raw − g)         # 平滑（τ=3s）
      if g > 0.02:                          # g 有效后更新增益
          g2   += dt · g²
          grel += dt · g · rel              # 仅受载通道
          gamma = clip(grel/g2, 0.3, 2.0)   # 逐通道增益（过原点增量LS）
      creep = clip(gamma·A·g, −0.5A, 1.5A)  # 安全限幅
      Y = Z − creep
  else:
      Y = Z
```

**设计要点**：
- 卸载检测双判据缺一不可——单用 `ts<1.5·min` 会被卸载瞬态的负向过冲毒化历史最小值，导致归零永不触发；
- 蠕变场模型 `γ_i·A_i·g(t)`：g(t) 是数据驱动形状（免 τ 假设），γ_i 修正个体通道偏差；
- g² 加权使 γ 估计早期自动低权重 → 冷启动天然渐进，无补偿跳变。

## 3. 参数表（默认值）

| 参数 | 默认值 | 作用 | 敏感度 |
|---|---|---|---|
| τ_b | 2 s | 空载基线跟踪速度 | 低（1~5s 均可，95%重置≈3τ） |
| τ_s | 0.3 s | 总量平滑（事件检测） | 低 |
| τ_g | 3 s | g(t) 平滑 | 中（1~5s；过小噪声传入 g，过大追踪慢） |
| γ 限幅 | [0.3, 2.0] | 逐通道增益安全界 | 低 |
| creep 限幅 | [−0.5A, 1.5A] | 补偿量安全界 | 低 |
| 通道入选阈 | 0.10·A_max | 受载通道判定 | 中（弱受载边缘通道残余来源，可收紧至 0.15） |
| g 启用阈 | 0.02 | γ 更新门槛 | 低 |

## 5. 算力需求

**逐帧操作计数（m=31 通道，k=23 受载）**：

| 组件 | 操作数/帧 |
|---|---|
| 总量求和 + 平滑 + 极值/判定 | ~40 |
| 门控基线 EMA（空载态）+ Z 计算 | ~125 |
| rel 计算（k 通道 sub+div） | ~46 |
| **median(k=23)** | ~110（比较） |
| g 平滑 + g2/grel 累积 | ~55 |
| γ 除法+限幅、creep 计算+限幅、Y 输出 | ~230 |
| **合计（负载态）** | **≈ 500–650 op/帧**（空载态 ≈ 200） |

**实测与平台估算（100 Hz 帧率）**：

| 平台 | 每帧耗时 | CPU 占用（100Hz） | 依据 |
|---|---|---|---|
| Python/numpy 原型 | **15–16 µs**（实测，`results/compute_cost.txt`） | ~0.16% 单核 | 含 numpy 逐调用开销，为上界 |
| 桌面 x86 C++（TactileSense 宿主） | **~0.3–1 µs**（估算） | **<0.01%** | 500–650 标量 op + 一次小数组 median |
| Cortex-M4 @168MHz（有 FPU） | ~10–20 µs（估算） | **~0.1–0.2%** | 含 ~46 次硬件除法（~14 周期/次） |
| Cortex-M0 @48MHz（软浮点） | ~300–500 µs（估算） | ~3–5% | 无 FPU 时建议定点化（Q16.16） |

> 唯一"重"的操作是每帧一次 k 元素 median；k≤32 时用插入排序/nth_element 均为微秒级。无三角函数、无矩阵运算、无动态内存分配。

## 7. 部署注意事项与已知局限

1. **初始化假设**：首帧空载（b=X[0]）。若上电即受载，首次基线错误——建议上电做 2s 空载确认；
2. **负载中途变化**：A_i 失效需重估（检测到新 onset 后重置 A/g/γ/grel）；
3. **单点/稀疏受载（受载通道 <3）**：median 共识不可靠，建议降级为逐通道在线对数蠕变模型（`b_compare.py` 算法 5）；
4. **暖机期**（加载后 ~15s）：补偿从 0 渐进到 90%，期间蠕变部分残留；根治需出厂蠕变先验冷启动；
5. **弱受载边缘通道**（A 接近入选阈）：残余可达 20–46%，改进方向为按 A 加权 γ / 收紧阈值；
6. **原理性边界**：与真实"缓慢增大/减小的力"在数学上不可分——补偿会跟随缓变分量（本方案通过 γ≤2.0 与 creep 限幅约束最坏情况；若工况包含 >10s 尺度的真实缓变力，需慎用或缩短 g 追踪带宽）；
7. 数据若存在 0 削波（processed_display），真实负向零漂被掩盖，标定/验证请用带偏置或 raw ADC 数据。
