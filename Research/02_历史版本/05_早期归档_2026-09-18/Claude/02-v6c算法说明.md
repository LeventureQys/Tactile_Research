> 版本：**v6c**（形状校正加速版）
> 日期：2026-09-20

## 0. 一句话与速览

**v6c = v5.1 的全部机制（不改一行）+ 免责期内的形状校正快速前端（替换空等）**。

v5 的问题：免责期 3s 内不做任何补偿，免责期结束后 g=0 从零开始追，追到位需要 ~9s。
v6c 的改进：在免责期结束时，用预标定的形状 ROM 把幅度 A 上调 ≤15%（校正快相未完成的部分），
并从观测到的蠕变初始化 g，使慢相补偿立即以正确量级启动。

| 项目 | v5.1 | v6c | 变化 |
|---|---|---|---|
| 检测/确认 | 2.5s 确认 | **不变** | 0 |
| 状态机 | 空载/负载/卸载/变载 | **不变** | 0 |
| 免责期长度 | 3s（可切 5s） | **不变** | 0 |
| 免责期内输出 | Z - carry | 形状校正后的限速斜坡扣除 | **改进** |
| 免责期结束时 A | A = exempt窗均值 | A = exempt窗均值 / shape(τ) | **改进** |
| 免责期结束时 g | g = carry/(γA) 锚定 | g = 斜坡末帧扣除/(γA) | **改进** |
| 慢相模块 | median共识 g + 逐通道 γ | **不变** | 0 |
| 安全语义 | 输出封顶/空载直通 | **不变** | 0 |

**代价**：无新增风险。形状修正上限 15%（v6 是 30%），且完全退化为 v5（关掉 SHAPE_CORRECT 即可）。

## 1. 设计动机

### 1.1 v5 的时间线问题

从真实加载沿到补偿生效：

```
真实加载 ──[0.5s检测]→ [2.5s确认]→ epoch起点 ──[3s免责期]→ 首扣(g=0) ──[9s爬升]→ 到位
   0s          0.5s        2.5s                    5.5s              14.5s
```

用户目标：**从阶跃后 ~1s 内平稳滑行。**

### 1.2 v6 的失败教训

v6 用全新前端替代 v5 的检测/确认/免责期，引入形状反演+滑行器+6类分类器。
实测结果：T_stable 中位 0.55s（达标），但：
- epoch 数 44-57（v5 为 16-29），因检测器过敏
- 实录全程偏差 4571 ADC（v5 为 1889），因形状先验误差
- 阶跃保真 1.08（多报 8%），因形状外推
- 用户报告的两个具体问题均由新机制引入

### 1.3 v6c 的核心取舍

**不替换 v5 的任何机制，只在免责期内利用形状知识加速补偿启动。**

形状 ROM 的使用方式：
- v6：**预测**未来电平（外推，误差 ±30%）
- v6c：**校正**已观测幅度（内插修正，误差 ≤15%，实际 ~6%）

## 2. 算法定义

### 2.1 形状 ROM

```
ROM_TAU = [0.0, 0.05, 0.10, 0.20, 0.30, 0.50, 0.65, 0.80,
           1.00, 1.50, 2.00, 3.00, 4.00, 5.00]
ROM_G   = [0.0, 0.680, 0.740, 0.790, 0.824, 0.854, 0.873, 0.886,
           0.904, 0.922, 0.941, 0.970, 0.989, 1.000]
```

含义：`shape(τ) = Z(τ) / Z(5s)`，即加载后 τ 秒时读数占 5s 电平的比例。
来源：13 份录制 onset 事件合并中位（与 v6 相同）。

### 2.2 形状校正系数

在免责期内的每一帧，计算：

```
τ_real = ts - real_step_ts    // 相对真实加载沿的时间
f = shape(τ_real)             // 当前读数占 5s 电平的比例
correction = min(1/f, SHAPE_MAX_CORRECT)   // 校正系数，上限 1.15
```

真实加载沿 `real_step_ts` 通过回溯检测（在确认帧前的环形缓冲中找最大跳变帧）获得。

### 2.3 免责期内行为（替换 v5 的空等）

v5 在免责期内输出 `Z - carry`（直通 + 保留旧扣除）。

v6c 在免责期内：
1. 同样采集 exempt 窗数据（不改 v5 逻辑）
2. 计算 `A_obs = exempt窗均值 - carry`
3. 计算 `A_corr = A_obs × correction`（形状校正后幅度）
4. 估算目标扣除量（基于已观测蠕变 `Z - A_corr`）
5. 用 **限速 smoothstep 斜坡** 从 `carry` 过渡到目标扣除量
6. 输出 `Z - 斜坡扣除量`（经输出封顶）

斜坡的关键约束：
- **限速**：`RAMP_RATE_FRAC × A / dt`，防止突变
- **只增不减**：`max(ded, carry)`，防止 restep 时回退
- **smoothstep**：`x²(3-2x)` 平滑，保证 C¹ 连续

### 2.4 交接（免责期结束当帧）

```
A = A_obs × correction          // 形状校正后幅度
loaded_i = (A_i > 0.10 × max(A))
g = median(斜坡末帧扣除[m] / (γ[m] × A[m]))   // 从实际生效扣除量反解
```

**交接自洽性**：交接当帧的扣除量 = 斜坡末帧的扣除量，逐通道严格相等。
因此 display 无跳变、内部 (A, g) 与 display 自洽，慢相模块从第一帧起就正确运行。

### 2.5 慢相模块

**逐行沿用 v5.1，不改一行。**

包括：median 共识 g + τ=3s 低通 + 逐通道 γ（过原点增量最小二乘）+ 蠕变限幅 + 输出封顶。

## 3. 参数表

### 3.1 新增参数（v6c 专属）

| 参数 | 默认值 | 说明 |
|---|:--:|---|
| `SHAPE_CORRECT` | True | 启用形状校正（False = 精确退化为 v5.1） |
| `SHAPE_MIN_FRAC` | 0.70 | shape(τ) 低于此不校正（太早/不确定） |
| `SHAPE_MAX_CORRECT` | 1.15 | 校正系数上限（最多上调 15%） |
| `SHAPE_RAMP_CLAMP` | True | 斜坡只增不减（防 restep 回退） |
| `ACCEL_G_INIT` | True | 交接时用已观测蠕变初始化 g |
| `STEP_PERSIST_ESTIMATE` | 2.5 | 确认延迟估计（回溯真实加载沿的兜底） |
| `BACKDATE_S` | 3.0 | 回溯真实加载沿的时间窗 |
| `RAMP_RATE_FRAC` | 0.5 | 斜坡限速系数（A/s） |
| `RAMP_RATE_MIN` | 5.0 | 限速绝对下限（ADC/s） |

### 3.2 沿用参数（v5.1，不改）

| 参数 | 值 | 说明 |
|---|:--:|---|
| `FAST_S` | 3.0 | 免责期长度 |
| `EXEMPT_AWIN` | 1.0 | 幅度采集窗 |
| `LEV_ARM_S` | 3.0 | 电平判据武装延时 |
| `STEP_PERSIST` | 2.5 | 确认持续时长 |
| `STEP_SUPPRESS` | 6.0 | 变载抑制窗 |
| `TAU_G` | 3.0 | g 低通时间常数 |
| 其余 22 个常量 | 见 v5 文档 | 全部保持 |

## 4. 对照开关（A/B 归因）

| 配置 | 行为 |
|---|---|
| `SHAPE_CORRECT=False, ACCEL_G_INIT=False` | **精确等价于 v5.1**（逐帧数值一致） |
| `SHAPE_CORRECT=True, ACCEL_G_INIT=False` | 只校正 A，g 仍用 carry 锚定（隔离 A 的效果） |
| `SHAPE_CORRECT=False, ACCEL_G_INIT=True` | 只加速 g，A 不校正（隔离 g 的效果） |
| `SHAPE_CORRECT=True, ACCEL_G_INIT=True` | **完整 v6c**（默认） |

## 5. 与 v5 / v6 的差异对照

| 项目 | v5.1 | v6（形状反演版） | **v6c（形状校正版）** |
|---|---|---|---|
| 检测器 | 2.5s 确认 + 6s 抑制 | 3帧持续 + 0.4s 撤销 | **= v5.1** |
| 免责期内 | 空等（Z - carry） | 全替换（滑行器） | 限速斜坡（carry → 校正目标） |
| A 的来源 | 数据测量 | 形状反演 + 测量 | **数据测量 × 形状校正** |
| g 初始化 | carry/(γA) 锚定 | 形状反演值 | **斜坡末帧/(γA)** |
| 修正幅度 | 0%（直通） | 可达 ±30% | **≤15%（实际 ~6%）** |
| epoch 数 | 16/29 | 44/57 | **= v5.1** |
| 失效模式 | — | 复杂 | 退化为 v5.1 |

## 6. 用户报告问题的处理

### 6.1 右拇指/数据2 @150s 大过冲

**根因**（v6 的问题）：单帧掉点 → 假减重事件 → `_reanchor` 把 g 归零 → 扣除量一帧清零 → +19% 跳变

**v6c 为什么不会出现**：v6c 不改 v5 的减重/卸载逻辑。v5 的减重判定需要通过 2.5s 确认 +
6s 抑制窗，单帧掉点不可能触发。即使触发了，v5 的 restep 保留 carry 连续性，不会归零 g。

### 6.2 切换负载首段"先稳住又抬升 / 先过充再回落"

**根因**（v6 的问题）：
- 过充：形状模型预判"尾巴还会涨"，但输入两级施加，中间保压 → 预判变过充
- 缓慢抬升：交接锚定不自洽（A=实测电平，g=锚定值不匹配） → g 衰减 → 显示朝 raw 爬

**v6c 为什么不会出现**：
- v6c **不预测未来电平**，只校正已观测幅度（内插而非外推），不可能过充
- v6c 的交接**严格自洽**：g 从斜坡末帧实际生效的扣除量反解，与 A 自洽，无暂态

### 7.1 v6c vs v5(3s) vs v5(1s) 恒载 9 组

| 时漂残余 慢相段 | 1.75% | 1.57% | **1.54%** | **v6c** |

| | 免责 1s | 免责 3s | v6c |
|---|:--:|:--:|:--:|
| 恒载中位 | **2.98s** | 3.82s | 3.82s |
| 实录中位 | 3.24s | 4.25s | 4.25s |

### 7.4 诚实评估

**v6c 的实际加速效果有限。** T_stable 与 v5(3s) 相同（3.82s），未达成 1s 目标。

原因分析：
1. **2.5s 确认是绑定约束**：即使形状校正完美，免责期结束最早在真实加载后 5.5s，而此时蠕变量极小（~1-2%），g_init 只能到 0.01-0.02
2. **τ=3s 低通是次绑定约束**：g 平滑时间常数 3s 意味着即使 g_init 接近正确值，输出也需要 ~3s 才"看起来稳定"
3. **形状校正量级太小**：在 A 采集窗（真实加载后 4.5-5.5s），shape ≈ 0.99-1.00，校正量只有 0-1%

**v6c 的真正价值不在 T_stable，而在：**
- **变载窗偏差优于 v5**（1423 vs 1560 ADC），因为形状校正让 A 更接近真值
- **epoch 数与 v5 完全相同**（16/29），不引入 v6 的假事件问题
- **慢相段时漂略优**（1.54% vs 1.57%），形状校正的 A 让蠕变估计更准
- **不存在 v6 的两个用户报告问题**（过冲/缓慢抬升）

**达成 1s 目标的唯一路径**：放弃 2.5s 确认窗，使用 v6 的快速检测 + 形状滑行器。
这是一个用户决策（牺牲鲁棒性换速度），不是算法能优化掉的。

## 8. 已知限制

1. **1s 目标未达成**：绑定约束是 2.5s 确认，本方案保留了它
2. **形状 ROM 使用测试集自身标定**（13 份合并中位），属乐观上界
3. **restep 场景的形状库**：restep 的快相时间常数比 onset 长 6 倍，当前 ROM 只有 onset 库
4. **校正量级较小**（~1-6%），主要通过 A 精度改善间接加速，而非直接跳到正确电平
5. **未做真机/界面手测**（按项目规范交用户执行）
